# 用量统计审查问题修复计划

> 按已确认的三个问题顺序在 main 实施；每项先复现、再修复、再验证。

**Goal:** 修复已知推理费用漏算、速度分组查询过长及请求分页清空旧结果。

**Architecture:** 计价继续使用固定价格版本，并使旧费用汇总失效。复杂统计读取通过 POST 请求体传递，短 GET 查询继续兼容；默认速度全选保持隐式。请求明细按会话身份保存完整结果，同会话翻页整体替换。

**Tech Stack:** TypeScript、Fastify、React、SQLite、Node test、无头 Chrome。

### 1. 已知推理费用

- 修改 `src/usage/pricing.ts`，仅在总输出未知而推理分项有效时计算已知推理小计，保留部分覆盖和冲突限制。
- 更新价格规则版本，避免命中旧费用缓存。
- 在 `tests/usage-pricing.test.ts` 添加缺输出、缺输入、零推理、完整输出及冲突分项回归。
- 验证：先运行新增测试确认失败，再修复并运行计价、缓存和聚合专项。

### 2. 复杂查询传输

- 为报告和请求明细增加 POST 读取，复用既有输入校验及响应结构；GET 继续可用。
- Web 和 CLI 对长查询使用请求体；短查询继续使用 GET，避免改变普通查询与已有工具兼容性。
- 默认全选不展开到页面地址；显式多选、空选和失效选择恢复仍保留。
- 验证：120 个以上真实合成分组、长服务商／模型名、报告和下钻分页、GET/POST 等价、非法参数、CLI 摘要和完整响应。

### 3. 请求明细分页

- 同会话保留已有结果，固定位置显示更新状态；请求成功后数据及页码一起替换。
- 等待或失败期间暂停旧结果下钻；失败保留旧页及重试入口。
- 结果与会话身份绑定，切换会话或关闭后不显示旧会话数据；取消和过期响应不覆盖新选择。
- 验证：无头 Chrome 的受控延迟、失败重试、快速操作、会话切换、中英文、窄屏和焦点恢复。

### 交付

运行 `npm test`、CLI 测试、`npm run check`、生产构建和相关浏览器专项；执行公开内容和空白检查。只暂存本次文件，直接在 main 提交并 push，回读远端 SHA 和工作区状态。
