# 全局历史自动同步实施计划

**Goal:** 五个页面共享历史自动同步，保持阅读体验，以真实历史验证同步与页面性能后提交推送。

**Architecture:** 应用层历史控制器统一管理周期检查、进度与错误重试。自动检查仅在发布版本变化时通知各页；手动同步继续允许主动重读。地图分析保持独立，资源历史重读不触发管理清单重读。

**Tech Stack:** React、TypeScript、现有可见页面调度器、Radix 控件、本地服务与 Chrome 验收。

## 1. 全局调度与版本联动

- 修改 `web/shared/refresh/useHistoryRefresh.ts`、`history-refresh.ts` 和 `web/app/App.tsx`，移除会话页面专属自动调度和错误展示。
- 保留现有偏好字段、关闭默认值及服务端合并能力；后台页面暂停，恢复可见补查，运行中不重复创建检查。
- 更新 `tests/web-history-refresh.test.ts`，验证无变化、版本变化、手动同步、完成去重和迟到响应；更新两份专项浏览器脚本，覆盖五页与全局重试。

## 2. 资源详情稳定更新

- 修改 `web/features/resources/Resources.tsx`，历史变动仅重读相关数据，保留旧详情与证据直至新结果完整返回。
- 用延迟、失败和重试的合成接口验证详情不清空、读取期间旧下钻暂停，避免同步触发管理清单或本地盘点。

## 3. 真实历史体验与性能

- 使用独立浏览器访问本机真实历史，保存和恢复测试涉及的自动设置；原始历史只读，正常同步仅更新可重建索引。
- 在五页记录无变化检查和真实新增记录的同步周期，检查旧内容保留、DOM 与滚动位置、空白帧、布局变化、浏览器长任务和响应间隔。
- 真实记录、标识、截图及详细测量只保存在忽略的 `.local/`；公开验收文档只保留方法、聚合结果与边界。

## 4. 验证与交付

- 执行类型、翻译、相关单测、生产构建及隔离 Chrome 验收，再运行真实数据测量。
- 对测量或交互中发现的问题做最小修复并复测，不用通过测试的合成结果替代真实性能证据。
- 同步产品、设计、使用说明与 ADR，执行公开内容检查，显式暂存批准文件，在 `main` 提交推送并回读远端。
