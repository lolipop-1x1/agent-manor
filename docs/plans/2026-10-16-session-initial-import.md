# 会话首次导入优化实施计划

**Goal:** 以固定输入比较首次导入前后耗时与资源占用，减少重复工作，并在结果等价的前提下选择解析并发度。

**Architecture:** 原始来源只读，解析与校验可并行，数据库由单个写入者批量提交。来源顺序与完成顺序不改变消息身份、会话归属、搜索计数及完整版本发布。首次导入与日常增量分别验证，已完成来源可校验复用。

**Tech Stack:** TypeScript、Node.js 24 Worker、SQLite FTS5、better-sqlite3。

## 已确认边界

- 在当前主干工作，保留其他已授权改动。
- 沿用字面搜索、精确计数、旧完整版本和来源前缀一致性；不以减少统计或截断正文换取速度。
- 固定文件快照、空数据库、相同功能准备边界下比较。操作系统文件缓存与应用空库分别描述，不主动清空系统缓存。
- 人工样例用于公开测试；真实样本、路径、指标明细与基线代码只放在本机忽略目录。
- 先建立基线，不预设耗时门槛；同时比较完整就绪、首次可浏览、峰值内存与磁盘占用。

## Task 1: 固定输入与基线

**Files:** 本机忽略目录中的原实现快照、样本和结果；必要的通用基准脚本。

1. 固定多个主要来源的代表样本，记录文件数量和字节数。
2. 用空库导入，记录总耗时、发布时刻、写入阶段、CPU、内存和数据库体积。
3. 保存消息、用量、会话元数据与搜索结果摘要，作为前后等价基准。

## Task 2: 减少重复读取

**Files:** `src/sessions/parser.ts`、`src/sessions/refresh.ts`、必要的来源校验模块及解析回归测试。

1. 首次导入将主解析读取与哈希合并，结束时仍校验固定前缀，允许仅追加新内容。
2. 保留适配器依赖、Codex 预扫描、坏行和未完成末行行为，不把所有原生容器当成普通 JSONL。
3. 用追加、截断、已有前缀改写和特殊来源验证一致性。

## Task 3: 有界并行解析与单写入者

**Files:** 新增解析 Worker 与协调模块；修改 `src/sessions/refresh.ts`、`src/sessions/store.ts`；新增对应测试。

1. 同一来源顺序解析，多个来源并行；比较一、二、四个解析 Worker。
2. 批次按条数和字节限制，提交确认后继续解析，防止积压完整历史。
3. 条件允许时把词项编码放入解析线程；数据库触发器和提交仍保持一致性。
4. 验证错误传播、Worker 退出、关闭及原始结果等价。

## Task 4: 首次写入与断点复用

**Files:** `src/sessions/store.ts`、`src/sessions/search-index.ts`、必要的新导入状态模块及存储测试。

1. 对比首次较大事务与次要查询索引后建；保留必要约束，只有收益明确的方案进入默认路径。
2. 不在半成品索引上返回不完整结果，最终发布前验证索引完整。
3. 保存已完成来源的检查点；中断后校验并复用，失效和回收不保留无界孤儿修订。
4. 检查日常增量、失败保留上一版、来源删除与旧版本不回归。

## Task 5: 性能对照与交付

**Files:** 相关设计文档、任务记录与通用验证脚本。

1. 同一固定样本多轮比较，记录各并发度、资源与结果摘要。
2. 根据实测选择默认并发和批次，不把线程数当成验收结果。
3. 执行相关回归、类型、构建、公开内容检查与隔离服务验证。
4. 报告相对收益、适用范围和未测量项；真实测量材料保持本机忽略。
