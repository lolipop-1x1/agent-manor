# 短词搜索与查询隔离实施计划

**Goal:** 单字与双字查询使用字符候选索引，减少重复匹配并隔离搜索执行，保持既有字面结果和完整版本语义。

**Architecture:** 继续使用现有 SQLite，单字与相邻双字词项按原字面规则精确匹配，三字符以上的 trigram 候选由 LIKE 核验。补建和增量维护复用 SessionStore 初始化与刷新入口。计数与分页在同一 SQL 中复用精简候选。独立查询 Worker 使用只读连接，主线程管理去重、有界队列与请求取消。

**Tech Stack:** TypeScript、Node.js 24、better-sqlite3、SQLite FTS5、React。

---

### Task 1: 基线与字符候选选择

**Files:** 本机忽略目录中的测量脚本和汇总；不复制完整真实数据库。

1. 用一致的合成数据与有界本机样本记录字面扫描基线。
2. 对比带位置字符短语、无位置字符交集及单字与相邻双字词项，均与原 LIKE 逐字段对照。
3. 测量建设、查询、候选量和页占用。速度优先，新增空间按实测评估。
4. 真实内容和派生索引仅保存在本机忽略目录，公开测试使用合成内容。

### Task 2: 字符索引与维护

**Files:** `src/sessions/search-index.ts`、`src/sessions/store.ts`、`src/index/maintenance.ts`、`tests/session-store.test.ts`、必要的新索引测试。

1. 添加与原扫描逐字段一致的单字、双字、ASCII 大小写、混合字符、特殊符号与 NUL 测试。
2. 将字符转换为不受 tokenizer 正规化影响的稳定词项；大小写规则与现有 LIKE 一致。
3. 所有写连接注册相同词项函数，触发器随消息事务维护。只读连接只读取已完成索引。
4. 按游标分批回填，完成前继续扫描；完整性与空间整理校验纳入新索引。
5. 运行相关存储与维护测试，验证旧版本及级联删除。

### Task 3: 一次候选匹配

**Files:** `src/sessions/store.ts`、`tests/session-store.test.ts`。

1. 为零结果、越界页、会话总数、记录总数、代表命中和排序添加对照测试。
2. 消息类型在候选阶段过滤，候选 CTE 只保存定位与排序字段，分组总数及当前页复用该候选。
3. 当前页再关联会话 JSON 和正文，避免把完整正文返回 Node。
4. 存在性检查使用首条命中，不生成摘要与可见性画像。
5. 对照优化前后的完整结果、查询计划与分段耗时。

### Task 4: 查询 Worker 与取消

**Files:** 新增 `src/sessions/search-manager.ts`、`src/sessions/search-worker.ts`、必要的契约文件；修改 `src/server.ts`；新增对应测试。

1. 独立只读 SessionStore，固定请求版本，沿用既有错误描述传递方式。
2. 主线程只调度一个执行中的查询，合并同条件请求，并限制待执行队列。
3. 请求断开即取消对应订阅，无订阅时取消执行。验证 SharedArrayBuffer 标志与 SQL 检查点能终止同步查询；不把 Worker terminate 视作已验证中断保证。
4. 测试取消、并发去重、队列、错误恢复、服务关闭和搜索期间轻量接口响应。

### Task 5: 前端、文档与验收

**Files:** `web/features/sessions/Sessions.tsx`、`docs/design/session-history.md`、测试及本任务记录。

1. 存在性请求不依赖分页等无关参数，条件变化同步归第一页，尽早取消旧查询。
2. 保留旧结果、加载反馈、焦点、语言、主题与阅读状态。
3. 执行相关测试、类型检查、`npm run check:public`，再以合成资源做浏览器搜索、跳转、清空及连续输入验收。
4. 补充同条件速度和索引体积结果，记录实际边界。用户选择先有基线后定时限，不以先前 750ms 提议代替实测结论。


## 实施结果

- 选定单字与相邻双字精确词项，沿用 ASCII 大小写与 NUL 终止规则；三字符以上保留 trigram 与字面核验；按消息类型过滤候选，避免额外读取过程正文。
- 计数与分页共享精简匹配；候选临时结果不保存正文，只对当前页读取和处理完整正文，Node 仅接收摘要。
- 搜索线程使用只读连接与完整读快照；同条件订阅合并，队列有界，SQL 检查点支持过期取消，故障后可重建线程。
- 初次补建可续传，事务触发器维护更新；维护检查覆盖两类 FTS 文档键。
- 前端条件变更直接归第一页，输入时取消旧请求，翻页不重查范围，搜索不发隐藏列表请求。
- 单字、双字、特殊字符、类型更新、分页、旧版本、补建及维护通过回归；真实 Chrome 检查请求数、过期取消、零结果、焦点与阅读保留。
- 性能与空间以本机隔离实验建立基线；具体时限按后续实际运行反馈确定。实验数据、完整响应对照与截图只保存在忽略目录。
