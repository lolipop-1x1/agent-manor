# 代码地图查询性能验证

## 问题与改动

活动分布的覆盖与会话列表原先都通过 HTTP 主线程读取完整仓库快照，包含统计不需要的基线正文、工具输入输出和历史源码。`async` 处理器中的同步 SQLite 与同步计算仍会占用服务事件循环。真实请求约 34.8 秒，其间 31 次轻量偏好请求有 30 次超过 1 秒超时；进程采样显示主线程在读取 SQLite 大字段。

本轮把覆盖、地图会话、热点、未观测文件、文件详情、活动、证据及来源查询移入独立查询 Worker，HTTP 主线程仅校验参数、固定版本、管理订阅及返回结果。同条件请求合并，有界排队；取消移除订阅和无订阅的排队工作，已进入同步读取的作业继续完成。不同查询功能已有各自的 Worker，未为每个请求无限创建线程。

紧凑覆盖元数据以 `coverage-v1` 分块保存在现有索引，和完整版本同事务发布。旧版首次读取后可补齐缓存，不改变已发布版本；只读消费者不补写。缓存与版本淘汰、仓库删除同步清理，命中前仍检查版本。缓存写锁争用或空间不足时可以返回完整结果，其他数据库错误继续报错。无需调整索引结构版本或重新导入历史。

元数据保留统计需要的全部文件、事件、来源与映射。工具原文仅对选中的活动分块回读，同一分块内多条活动一次读取；不把精简元数据用作原始证据。文件下钻预建活动到文件的映射索引，避免逐活动扫描整张映射表。

## 真实数据与性能

同一已发布仓库基线含 1233 个文本文件、90954 条活动、31386 条映射及 804 个来源。原完整快照与紧凑快照分别计算默认、全部文本、单客户端、目录、日期和会话六组筛选，结果逐项相等；地图客户端与会话列表、历史活动顺序一致，另回读三条完整活动核对原始字段。默认源码筛选的浏览器结果为 594 个文件，与原统计范围一致。

| 场景 | 本机观测 |
| --- | --- |
| 优化前地图覆盖请求 | 34.8 秒 |
| 优化前并发轻量接口 | 31 次中 30 次超过 1 秒超时 |
| 仅隔离线程，尚未保存紧凑缓存 | 地图约 29.9 秒；193 次轻量请求无超时，最大约 27.5 毫秒 |
| 保留紧凑缓存、服务重启后的首次目标查询 | 约 1.07 秒；7 次轻量请求全部成功，最大约 44.2 毫秒 |
| 同版本重复查询 | 约 0.40 秒；3 次轻量请求全部成功，最大约 22.3 毫秒 |
| 最终真实 Chrome 地图加载 | 约 2.38 秒，包含页面请求、绘制和网络空闲等待 |
| 最终真实 Chrome 文件详情 | 约 0.98 秒，10 条活动完整返回 |

浏览器验证了地图缩放、文件与详情路径一致、切换会话库并返回；页面异常及 API 失败均为零。该次加载观察到两个约 57／72 毫秒的浏览器长任务，不能称为完全没有主线程耗时。早期迭代曾观察到文件详情约 20.8 秒，定位为活动逐一扫描全部映射后改用索引；单独的三万活动／三万映射回归覆盖此路径。

这些结果来自同一台机器的短时观测，包含当时系统与其他任务负载，不能视为其他设备或任意仓库规模的延迟保证。服务重启后的首次查询仍保留磁盘紧凑缓存，区别于无缓存的老版本首次投影。没有紧凑缓存的旧版第一次查询仍需扫描历史大分块；新版发布会预先准备。紧凑缓存保留完整元数据，本样本约 137 MB 加分块定位信息，会增加本地存储；仅保留对应的有效分析版本。真实路径、身份、输入与截图只留在本机忽略目录。

## 自动化验证

全量 1520 项测试通过；随后新增的三万活动下钻回归及查询 Worker 全部五项测试单独通过。回归覆盖主线程禁止读取快照、阻塞真实 Worker 时其他 HTTP 请求仍可响应、同条件合并、取消和队列上限、固定旧版本、淘汰报错、线程恢复、紧凑缓存发布与旧版补齐、只读重开及完整活动恢复。现有 HTTP／CLI 筛选、当前文件变化、符号链接、跨站与证据契约继续通过。

高并行全量运行中曾有一次自动同步时序测试未等到调度状态；该测试不涉及地图查询，单独复核通过，并在四文件并发的完整运行中全部通过，没有修改该测试或调度逻辑。地图加载布局脚本修正了默认入口，并在延迟代理中处理界面取消的旧请求，避免把测试代理的关闭响应当成页面异常。窄屏原样式隐藏了查询进度图标，改为保留固定图标位置；中英文、1440／390 像素、覆盖／会话查询的八组浏览器检查全部通过，加载结束前后统计和地图位移为零。地图会话筛选及完整活动回放 Chrome 回归继续通过。类型、中英文、生产构建与公开内容检查通过。
