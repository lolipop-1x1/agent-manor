# CodeFlicker 桌面版验收

## 范围

新版 MyFlicker 桌面端作为独立客户端 `codeflicker-desktop` 接入，展示为 CodeFlicker 桌面版；现有 `codeflicker` 展示为 CodeFlicker CLI，原 ID 保持兼容。两者贯通代码地图、会话库、搜索、画像和 CLI／API。

公开测试全部使用人工样本。真实本机历史只读核对，原始日志、路径、身份和诊断结果不进入公开文件。

## 自动化与端到端

207 项自动化回归通过，含 8 项新版桌面格式和 7 项旧 IDE SQLite 专项测试。验证独立客户端身份、缓存与原生轨迹去重、数字消息 ID、工具终态及范围矛盾、明确最终回答、旁路标题／cwd／模型更新、后端 Token 口径、压缩记录和来源缺失。

`node scripts/e2e-codeflicker-desktop.mjs` 启动隔离的 CLI／后台／Worker／HTTP 和真实 Chrome，验证：

- 两个客户端在代码地图和会话库中独立筛选，同名原始会话不会合并。
- 人工仓库 2 行精确读取为 100%，1 行精确修改为 50%；原始证据可回读。
- 简易模式 2 条、完整模式 9 条消息，搜索命中可定位正文。
- 原生模型元信息、Skill 调用和 60% 缓存读取比例正确展示。
- 原始缓存内容在测试前后完全一致，浏览器交互未触发页面运行错误。

同一脚本同时加入旧 IDE SQLite 人工历史，验证同库两份会话独立显示，正式标题与项目正确，完整模式 10 条、简易模式 2 条消息，MCP 画像展示正确。地图原始证据保留真实 SQLite 路径与原生键，直接回读成功。JSONL 与 SQLite 共同出现在桌面版筛选中，CLI 保持独立；两个主来源在端到端前后内容一致。

SQLite 专项回归还覆盖已提交 WAL、单个会话键删除、迁移副本去重、只失效改变会话、标题及正式工作区变化、早期关系表问答、竖线／Tab 编号包装、后续工具失败与拒绝编辑不计覆盖。

类型检查、构建与公开内容检查通过。

## 真实历史核对

本机已保存的两份桌面主缓存均找到正式标题、cwd 和模型记录。独立遍历原始缓存与原生请求身份后，请求数、总输入、输出和缓存读取合计与解析结果一致。

包含工具的会话有 47 次原始调用，规范化会话保留 47 次调用，代码地图保留 47 个事件，没有未配对调用；12 个读取事件保留实际范围。另有 12 个事件缺少已核对的成功证明，继续显示未知，不擅自推高覆盖。没有工具的会话保留 3 轮用户消息和明确最终回答。原始来源在核对前后哈希一致。

本地预览的全局会话索引与已登记仓库均已刷新完成，HTTP 画像统计与独立原始核对一致。两份桌面历史的工作目录及工具目标不属于当前已登记仓库，因此这些仓库的桌面来源数和覆盖为零；没有为提高覆盖数字而跨项目归属。

旧桌面／IDE 目录另发现 138 个会话，含 4 个早期问答。独立遍历原生主记录得出 1,996 次工具调用，会话库保留 1,996 次调用、代码地图保留 1,996 个事件；302 个成功读取事件具有可校验的实际范围。136 个会话找到记录标题，48 个通过仍存在的正式工作区元数据确认项目；配置缺失时不把 IDE 缓存地址当成仓库。只读核对前后，主库和标题库的内容哈希一致。

## 限制

有效统计只纳入本机保存的主历史；标题数据库中的未下载服务端会话不当作完整历史。模型镜像仅补充可唯一关联的元信息，不重复计算正文、工具或用量。旧 IDE 的 API 上下文副本不重复导入；当前主历史没有逐请求 Token 记录，累计缓存不能重建逐请求趋势，相关指标保持未记录并保留估算及缺口。没有明确终态或实际返回内容的工具活动继续保留未知或采集缺口。
