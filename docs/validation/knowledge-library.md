## 实际会话与本地模型

只读选取本机实际会话中的三个窗口，分别包含 3 轮、2 轮和 1 轮，原文约 7.3KB、3.6KB 和 3.8KB。前两个窗口用于比较模型响应与失败处理，第三个窗口是技术原则讨论，用于核对有用内容、来源与人工修正闭环。复制到隔离数据目录，保留实际消息身份与工具过程；没有修改正在使用的历史库或真实知识库设置。这里只验证所选窗口，不将其描述为完整原会话覆盖。

实际使用 Ollama 本地运行 `qwen3:4b`、`qwen2.5:3b` 和 `qwen2.5:7b`，另建测试模型实例，保留基础模型。前两种使用 16K 上下文；7B 分别测试 16K 与 32K。32K 的 7B 测试实例在本机报告约 8.2GB GPU 占用，Embedding 另约 1.4GB；这不是整个系统的总内存测量。Embedding 使用 `qwen3-embedding:0.6b`。生成服务的实际上下文与应用预算分别核对，不能只改应用配置便假设模型窗口已变化。

实测发现并保留以下边界：

1. 思考模型可能把全部输出预算用于思考。单纯在提示词加入 `/no_think` 未必生效；在服务支持时显式设置思考强度关闭。默认未配置时不向其他服务强制发送此参数。
2. JSON 模式不保证模型遵从知识结构。小模型曾复述输入对象或返回未闭合 JSON，程序拒绝保存，失败范围不记为已处理。应用控制任务与原始资料分别组织，输出结构和引用继续严格校验。
3. 请求完成、结构正确、来源可回查和语言正确是不同结论。初版实际测试虽然跑通审阅、关键词、向量及废弃过滤，但人工核读发现部分英文目标仍输出中文，并保留了不值得长期保存的任务进度与文件计数。这些结果不能作为知识质量或语言验收通过。

最终复测结果：

| 场景 | 结果与人工核读 |
| --- | --- |
| 前两个真实窗口，3B、4B、7B 的 16K 实例 | 3B 曾把 `no_value` 与非空候选混用；4B、7B 的分段归并也出现不符合字段结构的结果，失败部分未推进覆盖。其他请求虽然完成，仍有语言不一致或进度计数噪声；这些候选不作为高质量知识样本。 |
| 技术讨论真实窗口，7B 的 32K 实例 | 一段完成，生成 1 个英文待审候选。核读确认保留多语言索引的有用原则；人工补充实现示例的适用边界与遗漏的字面/语义区分后发布。保留原始快照与修订历史，发布前旧已审版继续可查询。 |
| 同一真实窗口的检索与来源 | 重复预览待处理消息为 0；人工确认后关键词与本地向量均命中；原始消息按身份与哈希可回查；废弃后旧向量不再返回；人工修改后关键词命中新版。 |
| 合成技术对话，真实 7B 调用 | 中文到中文、中文到英文、英文到中文、英文到英文四种组合均完成，标题与正文语言逐项核读，代码与数字标识保留原文。该结果不代表任意真实长会话都能稳定遵守语言要求。 |
| 合成普通致谢，真实 7B 调用 | 返回合法 `no_value`，候选为 0，没有强行生成知识。 |

技术讨论窗口的连接测试与抽取合计 2 次生成请求，模型报告输入 2,823 Token、输出 174 Token；窗口抽取约 20 秒。未配置单价，费用保持未知。以上为小范围功能验证，模型、窗口和运行负载不同，不作为吞吐或效果排名。

未经人工确认的候选不会成为默认已审知识；不以条目数量证明有用性，也不以语言元数据代替正文核读。小模型仍可能遗漏、过度概括或带入流水记录，审阅需要核对适用范围和原始证据。

## 审查与修复

对实施起点之后的完整变更分别进行 Standards 和 Spec 两轴审查。第一轮发现 2 项规范问题和 3 项规格问题：对话框焦点恢复、产品诊断国际化、生命周期字段判重、手动会话排除范围、适用条件关键词搜索。五项均完成修复、专项回归与原审查者关闭复核；普通弹窗和嵌套确认另由真实 Chrome 验证。源码审查不替代真实模型效果判断。

## 验证边界

- 超长、压缩、多分支、坏模型响应与预算异常主要使用可复现合成输入及假模型，实际会话测试只涉及上述获准小范围窗口。
- 模型选择、提示词及输入规模会影响遗漏、重复、语言和事实准确性；结构及引用校验不证明结论真实，默认待审规则继续保留。
- 未将任意 OpenAI 兼容服务、任意 Embedding 的跨语言能力、长期自然自动运行或超大知识库性能宣称为已验收。
- 公开内容检查覆盖文本；没有把本机真实数据、请求和截图加入提交或发布包。
