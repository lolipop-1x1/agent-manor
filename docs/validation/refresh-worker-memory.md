# 真实历史刷新 Worker 内存耗尽修复验收

验收日期：2026-10-05。环境：macOS arm64、Node.js 24.19.0。原始会话只读，使用默认历史目录与现有预览数据目录，不通过缩小历史范围规避失败。

## 失败与根因

原任务约 55 秒后报 `Worker terminated due to reaching memory limit: JS heap out of memory`，仓库尚无完整结果版本。输入盘点为 Codex 1235 个、Claude 20 个、CodeFlicker 4008 个 JSONL，共约 5.45 GB；这是发现目录的文件总量，已有可靠外部 cwd 的来源会提前排除。

缺少 cwd 的来源先完整解析，再批量判断归属。未关联会话的工具请求、结果、源码片段仍被保留到共享历史合并和解析缓存发布；共享事件深拷贝进一步放大内存。Worker 退出后管理器永久拒绝后续刷新，页面仍在线但无法恢复分析。

缩小的真实调用链回归：24 个无 cwd、绝对路径属于其他仓库的 CodeFlicker 会话，每个成功返回约 500 KB；在 96 MiB 堆限制下稳定报同一 Worker 错误。修复后相同输入完成，进入发布阶段堆占用从约 75 MiB 降到约 10 MiB。

## 修复

- 按来源读取旧缓存，避免一次恢复全部旧正文。
- 未关联来源缓存事件身份、路径、边界与关系证明；完整正文在确认相关后重读。缓存显式标记为归属元数据，不能当成完整证据续读；来源变动会重建解析。
- 保留格式适配器自己的关系证据提取入口。历史 worktree、fork、子会话与手动关联均须恢复完整证据后参与统计。
- 按来源建立事件索引，避免每个会话重复遍历事件全集。
- Worker 崩溃时当前与排队任务仍标失败、保留上一版；下一次明确刷新重建 Worker，旧 Worker 的迟到退出事件不会影响新 Worker。

## 验证结果

- `npm test`：128/128，含受限堆首次分析与重复刷新、异常 Worker 恢复、后补历史 worktree 证明、CLI/HTTP、真实 npm 包外安装。
- `npm run check`、`npm run build`、`git diff --check` 通过。
- 默认真实历史首次重建成功，约 260 秒；分析期间采样的整进程 RSS 最大 1382 MiB。
- 最终版本增量刷新约 74 秒，采样 RSS 最大 1333 MiB；完整结果版本为 `本机分析版本（标识不公开）`。两轮之间有新历史和基线变化，耗时不作为固定同输入算法基准。
- 4094 个解析缓存来源中，4010 个只保留归属元数据。最终刷新实际解析 429 条记录，计算 36 项对应，复用 814 项对应。
- 当前源码基线 60 文件／8688 行；精确读取 39 文件／5914 行，精确修改 50 文件／6145 行。近似与精确分别统计。
- 固定最终版本，CLI 与 API 覆盖响应完全一致；一条成功读取的原始证据回读返回 9 条来源记录。页面显示刷新完成、覆盖率和地图，无 Worker 内存错误。

个人历史正文、数据库、临时探针与内存采样文件不纳入仓库。
