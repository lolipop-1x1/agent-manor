# 全项目可靠性与性能修复验收

日期：2026-10-26。规格见[修复规格](../../.scratch/project-review-fixes-20261026/spec.md)。

## 修复范围

- 知识索引采用独立 Worker、修订分块缓存和无变化内容版本检查；构建、恢复与自动维护互斥。
- 沉淀检查点保存补读证据，恢复核对固定来源与额度；旧检查点缺少必要证据时明确要求重新预览。
- 用量和资源原文入口保留历史版本，来源读取使用一致快照；版本淘汰不能返回部分成功结果。
- 搜索切页结束当前请求忙状态并保留输入，知识列表写入后校正页码，资源盘点按输入版本续扫。
- 历史路径采用可复用前缀查询索引，任务页面使用摘要分页，服务状态使用活动作业窄查询。
- 地图每仓库保留最近 1,000 条终态作业，保留版本最近成功检查、等待者和启动准备引用另行保护；每批最多清理 1,000 条，写权限在批次之间交还。

## 自动验证

- 第一次整合全量测试 1,806 项通过，类型、国际化、CLI 类型、官网类型与构建通过。
- CLI 工作区在与全量测试并行时出现一次 15 秒子进程限时失败，单独完整复跑 47 项通过；未通过延长限时或削弱断言处理。
- 仓库生命周期测试改为等待独立历史任务完成，地图任务完成不再隐含历史任务已经完成。
- 修复专项浏览器 7 项通过，覆盖搜索切页及连续查询、审批末页、实际摘要分页和筛选、旧版用量原文及新窗口链接、资源旧版链接与回调，模型调用为 0。
- 知识库完整浏览器 123 项通过，无页面错误或失败，覆盖中英文、明暗主题、窄屏、焦点及原有沉淀流程；生成模型使用本机模拟响应。
- 独立规范复审无阻断项；独立规格复审发现的知识任务状态解析残留已通过覆盖索引修复，原审查者复核关闭。两条实际查询计划及旧库兼容回归均已验证。
- 最终整合全量 1,807/1,807、CLI 工作区 47/47、正式构建专项浏览器 7/7 通过；最终类型、国际化、官网检查和构建通过。

## 隔离规模测量

| 场景 | 修复前 | 修复后 | 证据边界 |
| --- | --- | --- | --- |
| 2,000 条知识、每条 10,200 字符，暖无变化维护 | 约 952 ms | 三次 0.16–3.35 ms | 所有向量命中，无模型调用；主线程计时器 0.95–1.37 ms |
| 20,000 条已删除历史文件事件筛选 | 约 7.6 s | 约 49 ms | 本机隔离合成事件，不代表所有真实仓库 |
| 100,000 条已完成作业，活动身份查询 | 全量读取过滤约 87.5 ms | 窄查询约 0.17 ms | 不含其他服务状态成本；清理后保留 1,000 条 |

知识冷预览约 1.12 秒在 Worker 内完成；线程启动期间主线程计时器观测约 173 ms，进程 RSS 约 432 MB。RSS 为运行观测值，未进行精确峰值分析；不将暖维护结果泛化为所有初始构建或模型请求性能。

## 本地真实数据

- 使用现有索引只读连接，不初始化、迁移或修改真实数据库。三份已登记仓库来源的同版本完整 JSON 哈希与修复前一致。
- 两页真实会话查询与修复前完整结果哈希一致，真实作业活动查询及分页读取通过。
- 一份真实地图的 620 条事件、3,669 条路径，在 8 组目录和类别范围内与修复前算法结果一致。
- 真实知识库的一致副本包含 11 项知识；暂停、重启恢复、权威检索对照、增量新增及原内容保持通过。编码使用本机可控模型，15 次请求，没有调用真实模型服务商。
- 真实 Skill 文件集合的隔离副本完成扫描中新建与移除来源，返回与缓存正确反映最新输入；原始 Skill 文档哈希保持一致。
- 从真实会话只读取出的一条消息完成补读、持久检查点中断及重开恢复，来源哈希与已用额度保持一致；两次本地响应步骤，不调用外部模型。

真实知识数量较小，因此其结果证明恢复与结果一致性，规模响应性由单独的合成负载补充。详细输入、标识、数据库副本、脚本和日志仅保存在本机忽略目录，公开材料不包含真实正文、路径、原始会话标识或截图。

复审补充的知识任务覆盖状态索引同时服务活动查询和摘要状态筛选。完成任务正文从几 KB 增长到约 63 MB 时，活动查询保持约 0.02–0.03 ms；独立复核确认先使用覆盖索引，不再解析已完成任务的大 JSON。该结论限定于固定任务数的隔离对照。

## 支持边界

本轮没有评估模型抽取准确率、跨语言向量召回、所有原生客户端版本或全部平台；没有运行外部真实模型收费验证。知识恢复、索引互斥、版本一致性和查询性能的结论限定于列出的回归及样本范围。
