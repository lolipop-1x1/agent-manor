## 长会话加载性能复核

- 真实长会话的画像瓶颈来自复制用量关联：单一 `OR` 条件使每条请求扫描会话消息。拆成按消息身份与轮次分别查找后，现有索引即可使用，未新增数据库结构或改变统计规则。
- 对同一结果版本重复三次并发读取列表、简易消息和画像，并逐字段比较响应：全部一致。画像接口中位耗时由约 5.5 秒降至约 0.25 秒；优化后该组测量范围为 0.18–0.73 秒。
- Chrome 真实页面首次加载由两次状态、三次列表／消息／画像请求改为各一次，查询携带已确认版本。简易消息可见时间由约 10.7 秒降至两次复测的 0.14–0.34 秒；消息与真实画像均显示完成为 0.31–1.62 秒。启动刷新和本机资源争用会影响耗时，这些结果不作为跨设备性能保证。
- 合成回归使用 20,000 条消息和 5,000 条用量记录，原画像计算约 6 秒，优化后低于 1 秒预算。覆盖明确复制消息、仅轮次关联、未知消息身份、无关联用量与复制轮次内的独立请求，避免用性能优化改变排除口径。
- `npm run check`、`npm run build`、187 项完整回归和真实 Chrome 端到端通过。端到端新增首次请求次数与版本校验，继续覆盖搜索、消息定位、父子切换和主动刷新改名；真实当前轨迹深链接也完成页面核对。

## 评审及边界

主 agent 对照仓库约定和已确认规格完成本地审查与修复；协作评审不可用后的工作由主 agent 接手，未将其记为完成的独立并行评审。修复包含总输入标签、上下文口径、子步骤归属、重复命中收起、稳定前缀校验、搜索摘要计算和隐藏工作区的尺寸处理。

来源未保存的模型、上下文、缓存、耗时或工具结果显示缺失，不补造。最大单次输入与明确记录的上下文峰值分开；留存文本估算不能用于计费。消息与搜索分页，逐步用量展示前 200 条并说明限制，汇总仍包含全部用量记录。单条超大记录和工具配对缓存限制见 [会话口径](../design/session-history.md)。

后续只读复核发现一个待修复问题：Codex 压缩后的零值用量重置状态可能被计为请求，趋势图因此出现跌到零的点，请求计数也受影响。压缩后实际输入下降有记录支持，但零点不代表上下文真的归零。应按明确压缩关联和请求身份排除重置状态，并保留真实零值；当前版本尚未完成该修复。

首版为字面关键词搜索，不提供语义搜索或完整模型请求重建。完整原始历史只读，本地索引可重建；来源被删除后不保证还能恢复其历史。
