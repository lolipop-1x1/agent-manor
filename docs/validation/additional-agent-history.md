# 七类原生历史接入验收

## 范围与方法

DeepSeek Harness、Pi、WorkBuddy、OpenCode、ZCode、CodeBuddy、Qoder 共用内置来源注册与规范化事件，贯通代码地图、会话库及 Web／CLI／API。公开回归均为人工匿名样例；原生历史、真实仓库、诊断结果和浏览器截图仅保存在忽略目录。

验收将发现清单、原生会话身份、HTTP 列表和 CLI 列表交叉核对；逐会话检查简易／完整／轨迹、搜索、画像及分支成员；抽样重新回读工具原始证据并校验位置及哈希。真实仓库另核对客户端过滤、文件事件与证据访问，跨项目活动不计入该仓库。

## 数据边界

- DeepSeek Harness 同身份 V3／V4 选择可核验的完整来源，保留选择依据与差异；不通过运行客户端触发迁移。
- Pi 的简易模式使用最后持久化分支，完整／轨迹保留其他分支；阅读切换不改变全部实际活动的画像。未写入日志的实时分支切换无法恢复。
- 本机 Pi 样本均只有一个已保存叶节点，多分支和继承去重使用已核验格式的匿名样例验证；不将单分支浏览器结果宣称为真实多分支验收。
- SQLite 使用只读事务，包含已提交 WAL。坏 JSON、未知 schema、读取预算及无法确认的终态保留缺口；临时 I/O 失败不能发布来源删除。
- 原生正文、模型请求尝试及其用量保留各自身份。中断、失败与截断请求不推成最终回答；压缩摘要和自动继续提示不新增用户轮次。
- WorkBuddy 的原生用量记录与同一记录的重复投影去重。用量记录数量不等同于已证实的 provider API 请求数；无法确认输入与缓存桶关系时不计算缓存比例。
- WorkBuddy、Qoder 缺少明确工具成功状态或返回行号时，仍可回查活动及来源，但不补造精确读取／修改片段。不同项目的工具活动也不会计入当前仓库。
- 本机 CodeBuddy 留存样本只有用户正文，没有已记录的模型、工具与请求 Token。缺失指标保持未记录，内容 Token 估算单列。
- 子 Agent 只按明确原生委派证据分类；父来源缺失时仍可筛选、搜索或直接访问。一般父字段、无项目或任务式提示词不能证明委派。

## 交付检查

- 类型检查、生产构建和 260 项回归全部通过。匿名样例覆盖分支、继承、缺父子会话、压缩、混合附件、未知事件保留、失败终态、SQLite WAL、坏记录、读取预算及测试来源隔离。
- 规格轴与规范轴分别评审，发现均经同一修复任务处理；最终复核均无未解决发现。
- 本机发现与 HTTP／CLI 列表核对共 117 个会话：DeepSeek Harness 27、Pi 39、WorkBuddy 25、OpenCode 11、ZCode 9、CodeBuddy 2、Qoder 4。逐会话检查三种模式、标题／正文搜索、画像范围；逐 Pi 分支检查成员和 CLI 一致性。
- 验收索引的冷刷新约 8.2 秒，无变化刷新约 1.8 秒。验收脚本整体峰值约 634 MiB，包含原生读取、索引、查询和分析；不是单独刷新 Worker 的内存测量，也不是所有规模的性能承诺。
- 在已有约 86 万条全文索引记录的本机索引上，按 Pi 客户端搜索同一关键词：正文搜索由约 7.4 秒降至 69–162 毫秒，包含过程搜索由约 45.6 秒降至 70–109 毫秒，分别保持 28／179 条命中。最终 HTTP 查询各测三次；默认全局搜索另一关键词仍保持 37 条命中，耗时约 31–81 毫秒。查询仅在有界元信息探测确认客户端、项目或单会话范围较小时优先缩小消息范围，其他查询保留全文索引路径。以上为同机样本，受缓存与数据分布影响，不代表所有规模的响应时间。
- 原始工具证据按客户端抽样回读，真实仓库检查客户端过滤、活动与证据接口。已发现的主来源文件前后 SHA-256 一致；SQLite WAL 行为另由匿名回归验证。
- 使用已授权的独立 headed Chrome 对七个客户端逐一验收：客户端筛选、简易／完整／轨迹切换、标题与会话内搜索、画像三个面板及父子汇总均通过，未捕获页面运行错误。CodeBuddy 仅留存用户记录，完整与简易内容相同符合来源边界。
- 补充真实浏览器验收通过：明确委派子会话默认隐藏、筛选后可见，关闭筛选后直接链接仍可访问；Pi 当前／全部分支切换、时间线三种排列、键盘定位、Token 悬停数值与纵轴、过程搜索命中定位均可用。七类地图客户端过滤均由对应接口响应确认，Pi 文件活动可回查原始记录并跳转所属会话。
