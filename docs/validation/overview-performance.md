# 总览查询优化验收

验收日期：2026-10-12。本文记录分区查询、持久缓存与按需调查的交付结果，取代初版验收中的性能结论；原始统计口径继续有效。

## 已交付行为

- 移除两期热点比较的界面、接口字段、计算与洞察，保留各仓库所选范围摘要、单期热点与代码地图入口。
- 首页最多五条核心洞察，不为输入片段、失败序列、资源组合或每个对象逐条生成洞察。证据充足时才展示，不补足条数；详细调查按需打开。
- 快照固定版本、价格、时区、日期锚点与筛选。六个分区独立请求、首次分别呈现；已有结果更新时保留完整布局，暂停旧下钻，所有分区完成后整体替换。
- 按不可变会话修订持久化窄事实与活动桶；未变修订跨索引版本复用。常用分区与调查结果另行落盘，重启后可以直接复用。
- 排行、观察、组合、计时与证据先按身份过滤、统计及分页，再恢复页内信息。工具排行按页批量查询原记录，避免逐行重复扫描。
- 会话元数据的关联使用物化结果与明确的文本身份，执行计划回归验证索引连接，避免计时与月度调查逐请求扫描会话集合。
- 模型切换复用全局过程统计，只重新计算相关计时覆盖；总览用量汇总不恢复未使用的请求预览。Worker 设置堆预算并在闲置后释放，core 重建时仍保持事实写入角色。

## 测量方法与结果

使用同一份真实索引、价格、时区与固定日期条件对照旧统计。该索引包含约 7,400 个会话、92 万个事件和 22.6 万个模型请求。原始输入、身份、截图和测量输出只保存在本机忽略目录。最终完整测试与真实负载测量分别运行，避免资源竞争影响结果。

以下时间为本机 HTTP 完整响应体读取结束的耗时，包含服务计算、编码及本机传输，不是首字节时间，也不代表浏览器全部绘制结束。

| 场景 | 测量结果 | 解释 |
| --- | --- | --- |
| 旧实现：事实缓存存在，服务重启后首次报告 | 28.15 秒 | 仍恢复事实并生成完整报告 |
| 固定对照范围：服务重启后持久快照 | 28 毫秒 | 验证索引与固定查询 |
| 固定对照范围：核心概况／活动缓存 | 15 毫秒 | 六项指标与活动分区完整返回 |
| 固定对照范围：六个分区并行读取持久结果 | 15–151 毫秒 | 快照之后分别请求；最慢分区为核心洞察 |
| 固定对照范围：再次查询核心分区 | 21 毫秒 | 同一快照与范围 |
| 固定对照范围：六个分区响应总量 | 1,054,645 字节 | 旧报告约 16.53 MB，缩小约 94% |
| 该固定范围的首页洞察 | 3 条 | 旧报告返回 11,521 条完整洞察；现在最多五条 |
| 最终构建：当前索引新版本首次未命中 | 最慢分区 17.93 秒 | 已有事实，但该版本尚无报告结果；core 为 6.00 秒 |
| 最终构建：同一当前版本生成结果后再次重启 | 快照 30 毫秒；core 12 毫秒；分区最慢 66 毫秒 | 六个分区共 1,057,040 字节；无须重复生成报告 |

上述快速结果依赖有效的持久结果缓存。首次派生回填、首次未命中范围和首次调查仍有计算成本，不能据此宣称所有请求都在一秒内完成。

本轮回填阶段曾测得完整空事实库准备约 69–78 秒；最终 Worker 内存与模型过程复用修正后，未再次清库重跑完整回填。原始会话解码、请求配对、复制排除及按修订写入仍是一次性回填的主要工作。服务重启不清空这些事实；新版本只准备新增或变化修订，相关分区结果按版本重新生成。

工具排行首个 100 条的未命中调查在批量查询后测得约 7.36 秒；修正前两个排行页分别约 28–35 秒。两次排序条件不同，此处只记录定位与修正效果，不作为严格同条件加速比。首次较宽调查仍是后续性能改善方向，已缓存调查可直接读取。

真实计时分布的首次调查曾因会话元数据的重复扫描持续数分钟未返回。修正物化和文本身份后，最终构建在当前真实索引测得 11.31 秒，返回 73 个组中的首 20 组、40,775 字节。执行计划回归验证物化及自动索引，统计 oracle 保持等价。这个未命中场景仍需读取分组样本并计算分位数，速度尚未达到常用缓存查询目标；它按需运行，不参与首页加载。

## 正确性与自动检查

- 最终完整测试：900 项通过，0 失败；限制测试文件并发为 2。覆盖 CLI 安装、完整 SQLite 链路与现有功能回归。
- 类型检查、Web 检查、中英文目录／参数／复数检查及生产构建通过。构建保留既有大 JavaScript 分块提示。
- 对固定真实数据执行 25 组统计差分：六项指标、用量、活动、资源分页与分布、工具结果、委派、使用分布及核心洞察证据与旧统计等价；费用允许不超过 `1e-6` 的浮点求和顺序误差。
- 专项回归覆盖版本失效、跨修订增量复用、连续活动边界、复制排除、缓存损坏／容量、费用未知与小计、观察分页、模型编码、请求分母、默认入口地址恢复、Worker 闲置后读写角色及模型过程复用。
- 规格与规范分别独立评审，发现的问题集中修复后复核。真实输入不进入公开测试夹具。

## 浏览器操作验收

使用内置浏览器访问生产构建与真实本机数据，完成以下操作：

- 默认年度总览、日期范围和客户端筛选；等待中保留旧完整结果，成功后替换，模型局部选择不改变全局概况和资源统计。
- 项目搜索空结果、Escape 关闭及菜单焦点恢复；中英文切换保留选中范围和页面状态。
- MCP 服务器到项目／工具分布、分页使用记录、原会话，再返回总览，调查层与筛选地址保持。
- 计时分布首 20 组、第二页 21–40 组；分页不改变总览日期或图表范围。
- 仓库单期热点只显示所选区间；代码地图跳转保留范围，返回总览保留年度与局部调查选择。
- 中文浅色 1440、1280、390 像素及英文深色 390 像素截图。页面无全局横向溢出，宽表使用局部滚动，字体和共享控件沿用现有页面。

截图和浏览器原始记录仅保存在本机忽略目录，公开文档不附真实历史画面。应用页面按代码流程维护既有设计系统。独立设计复核为 `ship`、没有必要修正项；设计文档核对为 `No changes`，保留 `DESIGN.md` 与 `.impeccable/design.json`，不为已有字号登记差异重写全局规范。

## 支持边界

缓存是可重建派生数据，不回写原始会话。事实库上限为 768 MiB，结果库上限为 64 MiB、96 项、单项 4 MiB；结果按范围和快照身份复用。达到事实容量上限时明确失败并保留已完成修订，不把整库复制到内存，也不反复清库重建。

价格变化只使相关费用结果失效；时区或日期锚点变化重新准备相应时间投影。旧版本不可用时不能仅依赖残留结果返回成功。记录缺用量、缺时间、结果未知或价格不全时仍保留明确语义。

内存改善通过窄查询、有界缓存、Worker 预算和闲置释放落实。本轮没有复现和证明电脑死机的直接原因，不把内存峰值观察解释为已确认的系统故障归因。
