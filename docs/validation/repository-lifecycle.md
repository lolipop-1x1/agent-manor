# 仓库登记生命周期验收

## 方法

使用 `scripts/e2e-repository-lifecycle.mjs` 建立临时 Git 仓库、人工会话历史、独立数据目录和独立有界面 Chrome 会话。脚本为全部客户端显式设置历史根目录，资源盘点使用隔离用户目录；完成后关闭服务和浏览器并移除临时输入。页面操作通过角色及可访问名称定位。

```sh
npm run check
npm run build
node --import tsx --test tests/repository-lifecycle.test.ts tests/service-http.test.ts tests/web-api.test.ts
node --import tsx --test tests/session-store.test.ts tests/session-scoped-refresh.test.ts
node scripts/e2e-repository-lifecycle.mjs
```

浏览器错误、空候选以及延迟响应通过 Playwright 路由注入，仅影响当前验收页面。真实 API 负责登记和删除合成仓库。详细运行输入、页面截图和失败诊断保存在已忽略的 `.local/repository-lifecycle-e2e/`，公开文档仅记录方法和结果。

同路径再登记的组合回归在隔离验收进程中暂存一次 Worker 刷新消息，使新任务保持真实排队；放行后由临时 SQLite 发布触发器制造真实分析失败，再移除故障并正常刷新。另一浏览器页面调用真实 DELETE 和 POST；观察页面的状态请求等待登记完成后放行，确保两次检查之间复用同一仓库 ID。此控制只作用于本次合成服务，完成后恢复消息发送并删除触发器。

## 浏览器范围

| 范围 | 检查行为 |
| --- | --- |
| 会话项目候选 | 全局客户端项目、按最近活动排列、已登记标记、名称及完整路径搜索、同名路径区分、无匹配结果、长列表独立滚动，不列无项目 |
| 登记 | 项目选择填入路径、手动输入、非 Git 路径错误、子目录归根与已有登记复用、空候选及加载失败后的重试 |
| 取消与删除 | 完整名称和路径、清理与保留范围、取消确认、Escape 焦点恢复、失败后重试、切换到剩余仓库及全部删除后的登记空状态 |
| 并发界面 | 关闭登记后的旧候选响应不覆盖新候选；删除后的旧覆盖响应不恢复已删除仓库；其他标签页通过状态检查恢复到剩余仓库 |
| 再登记 | 删除后立即重新登记同路径，创建新分析并显示新结果；另一标签页复用 ID、版本退回无结果时清空旧地图、文件详情、文件选择和会话列表；新分析排队及失败均不恢复旧结果，后续成功自动加载新版本 |
| 显示与交互 | 中文、英文，浅色、深色，桌面及 390px 窄屏；1440×600、760×428、390×500 低高度窗口；鼠标选择、滚轮和键盘项目选择；Escape 焦点恢复；菜单处于视口内且上／中／下区域均可命中 |

## 证据边界

浏览器验证界面、HTTP 交互以及合成登记的排队、发布失败和重新分析后的页面状态。分析中同步计算的协作取消、事务发布和删除的两种顺序、任务等待者收束由后台生命周期专项测试控制时序验证。浏览器路由注入的失败和延迟响应不能证明底层数据库事务回滚。

后台专项测试还检查取消缓存的生命周期：运行与排队任务的既有等待者立即收束，完成消息抵达前的新等待者仍取得取消结果；完成消息、Worker 异常终止及关闭之后取消缓存释放，查询已删除任务恢复为不存在对象的行为。

项目选择沿用共享 `ProjectPicker` 的模糊搜索；名称查询可能额外匹配完整路径中的子序列。验收验证目标可找到、完整路径可区分同名项目和无匹配状态，不要求所有名称查询都只有精确名称结果。

会话项目默认顺序按当前已发布索引中全部客户端会话的最新有效活动时间倒序排列，更新时间无效或缺失时回退到开始时间；无时间的项目在末尾，同时间按完整路径排序。存储回归验证时区与回退语义，以及完整状态、摘要状态和新版本缓存的一致性。资源候选同时包含无会话的已登记仓库，删除登记时验证候选集合及其余资源状态保持不变，不要求并集的显示顺序不变。

用户反馈后补充弹层裁剪回归：仅检查视口边界不足以发现父 Dialog 的 `overflow` 裁剪；现在同时使用 `elementFromPoint` 检查可见区域，并通过真实鼠标滚轮验证列表滚动。登记项目弹层使用顶层 Portal 与 Radix 模态模式，避免父容器裁剪，同时保持滚动锁及焦点约束。
