# 语义搜索验证记录

日期：2026-10-18。功能说明见 [会话语义搜索](../design/semantic-search.md)。

## 环境与方法

在 Apple M3 Pro、12 个逻辑核心、36 GiB 物理内存的 macOS arm64 机器上，使用 Node.js 24.19.0 和本机 Ollama 的 `qwen3-embedding:0.6b`，接口实际返回 1024 维向量。模型下载约 639 MB；测试前已经完成连接测试和模型预热，下载与首次加载时间不计入构建耗时。

以下构建与查询性能采样使用空正文／查询前缀，属于早期已保存连接的编码规则。新增连接现按模型自动适配格式，原有连接继续沿用其规则；这里没有测量不同适配规则之间的检索质量或性能差异。

真实数据直接取自日常已发布会话索引，源连接只读。按最近 30 个本地日期、每会话不超过 500 条消息、最多 40 个非子 Agent／非 Quiet 会话取样，原样复制入新的本机测试数据目录。40 个会话共 7,208 条完整消息；其中 39 个会话、6,728 条消息用于首次构建，另 1 个会话用于增量暂停／恢复验证。完整消息包含工具等记录，语义输入仅纳入合格对话正文。

测试服务使用独立配置、凭据、向量数据库和服务端口，关闭来源自动更新，模型请求只发往本机 Ollama。详细正文、原始身份、查询命中及采样文件留在本机 `.local/`；本记录仅公开方法与汇总结果。

构建期间每 500 ms 轮询语义状态、约每 2 秒同时探测服务状态与关键词查询。服务进程每 100 ms 采样 RSS／累计 CPU，独立 Ollama serve／runner 每 500 ms 采样。首次查询各执行一次，随后各重复 20 次观察缓存。构建性能采样期间不并行运行全量测试或浏览器模型查询。

重复预览耗时 150.46 ms，待编码输入为 0，复用 403 个输入；再次构建新增模型请求为 0。加入留出的真实会话后新增 25 个输入，实际暂停构建期间主动提交未缓存查询，查询请求增加 1 且任务仍处于暂停；恢复后完成 40 个会话、446 个来源位置、428 个唯一向量，数据库与 WAL 约 9.58 MiB。

接口耗时包含 HTTP、配置读取、来源有效性检查、模型请求或查询缓存、本地匹配和结果快照；缓存路径不能解释为纯向量扫描耗时。当前使用精确余弦计算，查询成本随本次筛选后的唯一有效向量数增长，没有验证十万向量或全库规模的延迟。

## 内存和计算开销

首建测试进程 RSS 基线 560.61 MiB、峰值 655.56 MiB，用户态与内核态 CPU 合计约 2.31 秒。此进程同时承担样本复制、服务和测试客户端，基线包含复制正文后未回收的分配，不能作为日常服务常驻内存。独立 Ollama 进程 RSS 峰值之和约 260.06 MiB、累计 CPU 约 4.68 秒；RSS 之和可能包含共享页，未测 GPU 或系统统一内存总占用，CPU 时间不能代表 GPU 计算成本。

另启动全新 Node 服务进程，复用已构建测试库，避免复制正文的分配影响。每阶段完成后等待 500 ms，观察值如下：

| 干净服务进程阶段 | RSS |
| --- | ---: |
| 仅模块导入，尚未启动服务 | 102.36 MiB |
| HTTP 已启动，尚无语义 API／Worker | 296.88 MiB |
| 读取一次语义状态后 | 314.23 MiB |
| 一次未缓存语义查询后 | 360.08 MiB |
| 一次构建预览后 | 473.78 MiB |

这些阶段差值受 GC、分配器、Worker 初始化和缓存影响，不是语义功能精确的常驻增量。HTTP 基线保留服务通常启动的其他 Worker；表中不包含独立 Ollama、GPU或系统统一内存总占用。

## 估算、费用与质量边界

本地 Ollama 没有远端 API 计费，测试单价设为 0；这不表示硬件、内存、磁盘和电力成本为 0。最终实现统一预览、批次、限流和预算的 token 估算口径，按实际接口 usage 另行结算。估算使用每个完整输入的 UTF-8 字节数除以 3 向上取整，再加 4 个预留 token；不是模型 tokenizer。本样本预估 216,043、实测 180,844，预估高约 19.46%。预算预留和预览保持同一口径，不能保证与实际 token 一致，也不保证服务商账单封顶。

实际查询可以返回原始会话片段并跳转消息；浏览器检查结果类型、原文定位和筛选行为。没有标注相关性数据集，没有计算 Recall／MRR／nDCG，也没有将返回候选或某个正例视为模型质量评测。样本按明确范围截取，并非随机样本，不能外推全库首建耗时、存储放大或搜索准确率。

## 可复现入口

先准备用户自己的本地模型并执行 `npm run build`，再运行：

```sh
node scripts/benchmark-semantic-search.mjs --days 30 --max-messages 500 --max-sessions 40 --home .local/semantic-search-validation/home
node scripts/profile-semantic-search.mjs --home .local/semantic-search-validation/home
```

脚本拒绝覆盖已有目标索引；重测使用新的 `.local/` 子目录。可以用 `--endpoint` 和 `--model` 指向其他服务，但真实文本将发送到指定地址，必须按自己的数据范围和服务选择执行。`--serve` 可保留测试服务供浏览器验收，不修改日常服务的语义配置。

### 模型连接简化的后续验证

移除高级连接设置后，新增 6 项适配与兼容回归，51／51 项语义相关测试通过。覆盖已支持模型的明确名称、未知及相似名称回退、切换连接与恢复原规则、已有连接指纹不变，以及 HTTP 测试／正文构建／查询的实际输入格式一致。

类型检查、中英文目录检查、构建、公开文本检查及构建产物检查通过。隔离设置使用本机 Ollama `qwen3-embedding:0.6b` 实际连接测试，返回 1024 维；页面仅保留地址、模型和可选 Key，维度出现在测试结果中。浏览器验证中英文、明暗主题、390px 窄屏和保存流程。未重新进行全库或检索质量评测。

日常服务使用原端口重新启动，重启前后模型连接、凭据设置状态及索引指纹一致，已有语义索引保持可用；没有因这次升级重新编码历史。

### 统一搜索筛选的后续验证

关键词和语义搜索现共用范围组件与后端元数据条件。新增回归覆盖多客户端／项目、关系、执行模式、模型、标题、数量范围、带时区日期、当前分支、旧参数兼容、长范围参数校验，以及 URL 恢复与模式切换。未配置语义搜索时，普通列表与关键词分组仍可使用完整筛选和选项接口。

消息可能已有 `currentBranch` 标记而缺少会话分支目录；回归确认当前分支搜索排除这些非当前消息。已有向量位置没有该标记时，通过只读来源消息核对并使用有界缓存，无需重新编码历史。完整类型与中英文检查、构建通过，最终 `npm test` 为 1,447／1,447 通过。

浏览器使用隔离的合成历史与延迟模型服务，确认加载图标位于搜索按钮内，关键词加载图标占用固定位置，等待时保留旧结果。验证更多筛选内的项目／模型／日期子菜单可见、模型搜索与空结果、长列表滚动、日期选择和清空、共同条件随模式切换保留、关键词独有过程记录开关、非法数量范围的可见错误，以及 Escape 逐层关闭和焦点恢复。覆盖中英文、深浅主题和实际 390px 窄屏操作；筛选区独立滚动，标题和关闭按钮保持可见。

主动提交一次语义查询后，筛选与模式切换验证期间查询编码请求仍为 1，没有新增查询编码。此项使用可控合成服务验证调用边界，不用于模型性能或相关性评测。重启日常服务后，接口确认共同筛选和完整选项可用，原模型连接、凭据设置状态及索引指纹一致，语义状态保持就绪。
