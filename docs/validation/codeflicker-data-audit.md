# CodeFlicker 数据复核

验收日期：2026-10-05。本文保留通用复核方法与修复结论，不公开真实业务仓库、目录、规模、覆盖百分比、会话身份和本机分析标识。原始输入与详细测量只留在本机，不把匿名说明当作可直接复现的公开数据集。

## 复核方法

- 固定修复前后的分析版本，分别查询全部客户端、单客户端、全仓与子目录，确保同范围查询使用相同基线。
- 独立核对当前文件 SHA-256、物理行数、范围边界、去重并集，以及近似范围与精确范围没有重叠。
- 从只读 SQLite 取得映射，核对精确对应行有有效历史片段支持；内容核对不能单独证明位置唯一。
- 流式核对原生 read/edit/write/bash 请求与结果，区分成功、失败、未配对、未知、截断和不支持的格式。
- 检查未关联来源的实际路径证据；目录名称不能替代 cwd 或工具返回的可靠路径。
- 通过 API 回读代表性读写的原始请求与结果，并比较同一版本 CLI/API 的完整响应。
- 在浏览器切换客户端和目录，核对页面分母、覆盖率和结果版本与 API 一致。

## 确认并修复的问题

无可靠 cwd 的相对 read/edit/write 请求，即使成功结果已给出绝对目标，旧规则也可能保留相对路径，导致活动不能归属仓库。

规则 8 使用本次工具返回的绝对路径确认目标，要求它与规范化后的完整相对请求路径后缀相同；错误后缀、仍越出父目录的请求和已知 cwd 冲突均拒绝。返回路径不用于推断会话或后续请求的 cwd，成功终态、范围与补丁校验保持独立。

真实历史中恢复两条成功修改活动：一次常见配置文件编辑，以及一次后来已删除的 HTML 文件写入。恢复活动不改变源码成功读取的覆盖并集。旧缓存按新规则重建与冷解析一致，事件身份保持不变。

## 验证与边界

- 全部 130 项测试、类型检查和正式构建通过，新增回归贯通解析、归属和内容对应。
- 真实后台首次重建与随后增量刷新成功，原有事件无丢失，恰好恢复确认的两条活动。
- 修复前后源码基线、逐文件覆盖范围与汇总一致；独立映射并集、CLI/API 对照、原始证据抽查及浏览器验收通过。
- 未发现已核对原生成功 read 模板的字段别名漏解析。缺少成功终态的 Shell 结果、未知结构、截断、无法唯一定位及计算预算限制仍保留缺口。
- 成功读取覆盖与 AI 编写归因分别定义；搜索、修改或“使用 AI 开发”的事实不自动补成读取覆盖。
