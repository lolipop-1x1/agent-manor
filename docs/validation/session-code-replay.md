# 会话代码活动回放验收

## 自动化与浏览器范围

`tests/replay-api.test.ts` 覆盖明确父子树与 fork 边界、只有子会话有活动的候选、同次多文件与同时间独立调用、重复调用 ID、未定时活动、双版本固定与淘汰、HTTP 错误和 12000 步完整投影；额外通过独立 WAL 写连接覆盖版本检查后、header 读取后淘汰地图，以及会话版本检查后淘汰的竞态。

`tests/replay-model.test.ts` 覆盖多轨共享时间映射、统一折叠空档、向后定位撤销累计状态、路径去重、未定时活动、同轨同刻完整候选及 50000 步索引。测试保留完整活动，不以采样或截断通过性能检查。

`tests/replay-worker.test.ts` 覆盖主线程固定双版本、排队时发布与淘汰、请求合并和有界队列、HTTP 断连取消订阅、异常诊断、线程恢复与关闭。实际 Worker 在同步投影入口阻塞时，独立 HTTP 健康请求仍能响应。取消活动订阅不会立即中断同步 SQLite，只移除订阅及无订阅的排队任务。最终全量 1504 项通过，生产构建、服务端／前端类型、中英文及公开内容检查通过。

`scripts/e2e-session-code-replay.mjs` 在独立临时数据目录、人工仓库和合成历史上运行。使用真实服务及 headed Chrome，检查紧凑工具栏、会话搜索与长列表、主会话加三个子轨、批量多文件同时高亮、同步当前活动、播放／暂停／倍速／拖动／前后定位、向后累计撤销、证据和会话库往返、URL 与同版本观看位置恢复、独立 Tab 状态、中英文、深浅主题、窄屏、键盘及减少动态效果。同轨同刻六调用且均为基线外路径的专项回归，可以展开全部六项并核验第四、第五项原始证据。页面异常与非取消请求失败为零，播放过程没有逐帧请求。

同一脚本另从原生合成历史导入独立的 363 轨／362 步／361 个折叠空档样本。验证全部轨道、末轨滚动可达、动态层高度等于可视区域，以及滚动范围不因叠层扩大；在底部、缩放后与回到顶部，空档帮助均可通过键盘打开，Escape 关闭恢复焦点。压力样本之后继续原四轨的完整交互回归，不使用依赖机器负载的 FPS 阈值断言。

代码地图原有会话过滤浏览器回归覆盖库入口、清除、空活动、详情范围、跨页面视野保留、搜索、同名、长列表、键盘、语言、主题和窄屏。登记与删除回归的 12 组全部通过，使用独立合成资源，不操作真实仓库注册或历史。关闭自动分析时，其他标签页的删除／重登由显式重载读取；测试不依赖关闭状态下的周期请求。

## 真实历史核验

从本机已索引历史选择两个完整多子会话树及两个单会话，复制 12 份原始来源至忽略的本机隔离目录后重新导入，与当前仓库基线分析。没有复制整个大型日常索引，没有改写原始来源。

两个主要样本分别为 6 轨／195 步／624 条活动，以及 4 轨／108 步／271 条活动。895 条活动逐条与原始解析记录核对事件身份、种类、状态和时间，全部对应；同次调用分组核对请求来源位置，纯仓库外活动排除。该真实样本没有未定时活动，缺时、未知顺序和失败边界由合成用例覆盖，不能据此宣称全部客户端格式都已完成真实回归。

真实 6 轨浏览器样本验证了库入口往返、地图与轨道、暂停、倍速、证据对应及原始记录回读。真实标题、路径、原生标识、来源内容和截图仅保存在 `.local/`，不随仓库发布。

## 完整日常索引的性能修复

最终在日常完整索引只读验证时发现，SQLite 曾把 JSON 目标数组 JOIN 排到全部历史消息之后，造成大索引阻塞。修复为按 `(version, session_id)` 复合主键点查，仅提取实际使用的工具请求；零活动轨道无需读取调用元数据。实际 SQL 查询计划进入自动回归。另增加回放专用 JSONB 最小分块投影，避免读取未使用的历史源码片段、覆盖范围和完整来源集合。旧覆盖查询语义保持不变。

同一完整仓库版本的 64,735 条活动、1,077 个文件、21,647 条映射逐项核对身份、来源、路径和缺口，结果一致；完整多轨结果与旧方案深比较一致。早前进程首次最小投影曾记录约 1.17 秒；后续日常后台和只读新进程实际首次观察为约 9–19 秒，不能把较快单次样本当稳定保证。逐块测得事件分块 857 块、原始 JSON 约 1.02 GB，单次事件读取约 11.97 秒，完整投影约 12.34 秒，而进程 CPU 总计约 2.19 秒；主要开销集中在冷页读取。SQL 使用正确的分块复合索引，未盲改 SQLite 配置。按分析版本另外缓存快照，使会话索引版本更新不重复读取相同仓库大分块。实际八轨目标仅取 839 条请求元数据，约 4.5 毫秒。多段投影及会话调用读取采用同一延迟读事务，避免其他连接发布淘汰时返回半份结果。

此前已发布版本中另选最大明确子树，API 返回 363 轨、3236 步、7702 条活动，首次回放约 3.18 秒，缓存后约 27–28 毫秒；不截断步骤或轨道。冷首次准备与缓存后的观看查询是不同阶段。回放证据使用专用接口按事件所属分块只读单条记录，避免点击证据再次加载整仓正文。

这份最大真实子树也完成浏览器验证：轨道与固定版本对应，原始证据成功回读 3 条来源记录，滚动高度为 15,274 像素，最后一轨完整可达。首次播放发现通高动态叠层造成 GPU 卡顿；同页对照中，把叠层临时限制为可视高度后，3 秒采样从约 12 帧恢复到 431 帧。正式修复将播放头和断轴背景限制到滚动视口，随纵向滚动移动可见段，不裁掉任何轨道或活动；并缓存静态轨道、标尺、断轴帮助和会话选择器，避免随播放头反复重建。

最终真实 363 轨页面采样 120 次 `requestAnimationFrame`，帧间隔均值约 6.94 毫秒、95 分位约 7.1 毫秒、最大约 7.8 毫秒；该窗口所有 API 请求为零。末屏叠层高 208 像素，与可视区域一致，滚动高度没有因绝对定位叠层继续扩大。结果同样只代表这次机器与显示环境，不等于渲染 CPU 耗时或其他设备的帧率承诺。

## 冷查询与 HTTP 并发

真实新版本准备曾使同步 HTTP 主线程停顿，导致并发 1 秒健康检查超时。最终将候选准备、回放投影、证据和版本缓存移入惰性只读 Worker；主线程只固定双版本，Worker 再核验保留状态。

最终生产构建在同一日常完整索引上冷请求候选约 6839 毫秒、首次最大回放约 9159 毫秒，缓存重复请求约 74／62 毫秒；完整返回 363 轨、6471 步、14711 条活动。同期 149 次实际 HTTP 健康检查均成功，95 分位约 8.69 毫秒、最大约 40.4 毫秒。首次读取总耗时没有因线程隔离消失，其他接口能继续响应；这些值只代表该次数据与机器负载。

## 性能观察与限制

真实启动分析还复现了原有历史归并的内存溢出。归并之前已经持有完整解析来源，逐事件深复制又持有一份工具正文；修复只复制会变的事件、片段、来源和诊断元数据，输入／输出与片段正文只读共享，不裁剪数据、不提高堆限制。冻结输入、未知升级、来源合并与冲突回归以及独立消费链审查通过。同一 24 MiB 合成正文的归并额外 JS heap 从约 24.10 MiB 降为约 0.04 MiB；这不等于整个真实进程的内存用量。

修复后，在原默认配置与完整日常索引上重新启动分析，当前仓库约 145.98 秒成功发布，三个登记仓库的最新分析任务均完成。观测的服务进程峰值 RSS 为 4632 MiB，包含所有线程，不等于单个 Worker 的 JS heap；全量分析仍有显著资源开销，不能据此承诺任意历史规模均不会溢出。

最终接入回放 Worker 后再次启动分析，当前仓库约 116.07 秒成功发布，观测窗口内服务进程峰值 RSS 为 4925 MiB。该轮复用了 6232 份解析来源和 30703 条映射，处理 106 份变化来源；两次耗时与工作量不同，不能直接视为同一负载的速度对比。

新发布版本的最大真实子树为 363 轨／6471 步／14711 条活动。最终 Worker 构建再次核验双版本、末轨及 3 条原始证据记录；120 次帧回调均值约 6.94 毫秒、95 分位约 7.1 毫秒、最大约 8.6 毫秒，采样窗口所有 API 请求为零。

本机这批真实源的隔离导入和仓库分析约 33 秒，候选查询约 353 毫秒；两段回放冷 HTTP 请求约 18–117 毫秒，重复请求约 3–5 毫秒，响应分别约 306 KB 和 212 KB。该结果只代表所选样本与当次机器状态，不是全量历史耗时或服务承诺。

真实 6 轨播放窗口采样 120 次 `requestAnimationFrame`，帧间隔均值约 6.95 毫秒、95 分位约 8.3 毫秒、最大约 8.6 毫秒。它反映该显示环境中的短时回调间隔，不等于每帧渲染 CPU 耗时；播放器状态本身最多每秒发布 20 次。播放窗口 HTTP 请求为零。大于真实样本规模的完整性主要通过 12000 步后端与 50000 步前端模型测试覆盖。

任一固定版本被淘汰后不能继续回读该版本，需要显式更新回放；来源改写、移动或删除也可能使原始证据不可用。固定当前基线不能还原会话发生时的文件内容。上述限制是产品支持边界，不能用成功样本推导为不存在。
