# 后台任务隔离验收

日期：2026-10-21。

## 验证范围

- 可控地图任务等待时，会话任务独立完成；地图内部仍按原顺序执行。
- 地图与会话 Worker 分别崩溃、单独重试，不将另一类任务标为失败。
- Worker 失败结算暂时遇到写锁时重试，保留原始故障，不由错误回调终止任务管理线程。
- 地图忙碌时后台自动会话同步可提交；异步登记只提交一次，登记失败进入退避，关闭策略撤销后续唤醒。
- 在独立进程持有 SQLite 写锁时，登记仓库、关联来源、刷新、清缓存和删除等待提交，状态及仓库列表在释放锁之前仍可返回。
- 写锁超时回传错误，释放后可重新提交；错误命令不污染后续命令队列。
- 服务内部写者交接期间，长事务不令另一个写者报锁超时；只读快照仍可查询，持有者退出后回收权限，未提交事务回滚。地图查询和用量统计的派生缓存写入也使用相同权限。
- 原有完整发布、仓库删除回滚、旧任务撤销、重登、全局历史保留、服务关闭和重启契约继续验证。

用例位于 `tests/task-worker-isolation.test.ts`、`tests/http-write-isolation.test.ts`、`tests/index-write-gate.test.ts` 及既有任务、HTTP 和生命周期测试。持锁、崩溃和模型响应均使用隔离合成资源；不对真实数据库人为加锁。

## 持锁对比

相同隔离场景中，外部连接持写锁 1.5 秒，并发提交会话刷新和状态查询。修改前状态请求约 1404ms；修改后重复验证为 4–26ms。写请求仍在锁释放后提交成功，未通过跳过落库或缩短写锁超时来获得结果。

## 边界

SQLite 仍只能有一个写事务；任务之间仍可能等待数据库提交，写锁超时仍可能失败。此改动保证索引任务队列和错误结算分离，并将运行期索引写锁等待移出 HTTP 主线程；其他数据库、大型聚合读取和模型调度不属于本次改动。

真实历史只做正常增量与查询验证；详细记录保存在本地忽略目录，不随仓库分发。已有单条历史过大等解析错误应如实保留，不能把任务隔离通过写成所有历史均可成功解析。

真实验证已观察到：会话同步完整发布后，地图仍在自己的队列运行；会话库列表、消息及画像可读取，状态查询保持响应。地图遇到已有单条压缩历史超过 16 MiB 的解析错误时，会话同步结果继续保留，任务管理线程仍可接受请求。此项历史解析限制未在本次修改中放宽。

## 最终结果

- 全量测试 1767 项通过，CLI workspace 专项 45 项通过；包含 npm tarball 包外安装与原生 SQLite、CLI、Web、Worker 闭环。
- `npm run check`、`npm run build`、包入口检查、`npm run check:public` 和差异空白检查通过；保留既有 Web 大 chunk 构建警告。
- 本机安装包更新后，实际客户端范围检查完成 8/8 来源；地图任务运行期间停止约 867ms，重启后继续读取会话。此数字是单次本机观测，不作为跨机器时延保证。
- 真实会话库页面核对了列表、正文与画像；地图页仍可出现上述已有超大历史错误。合成 HTTP 回归覆盖完整地图查询，不能把真实地图解析错误写成地图全量验证通过。

主线程保留的 Store 连接只在监听前初始化数据库，运行期路由仅用它们查询。新增运行期索引写入应继续交给异步任务命令，不直接写入这些主线程连接。
