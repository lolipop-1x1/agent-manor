## 扩展边界

- 客户端信息统一声明，API、CLI、Web 与查询 Skill 使用同一客户端目录。
- 客户端来源发现与历史格式适配分别注册；客户端身份不由工具名或格式推断。
- 格式适配器负责调用配对、成功语义、工具片段、来源引用和可验证的关系；通用层负责仓库归属、覆盖、版本和查询。
- CodeFlicker 使用原生 JSONL，排除 `requests/` 重放与 `file-history/`；不接入 SQLite、MyFlicker、代码补全或采集 Hook。

## 可手算的匿名样本

`scripts/e2e-codeflicker.mjs` 经真实 CLI、后台进程、Worker、SQLite 和 HTTP 查询，不直接调用覆盖实现。仓库三个文件共六行：

| 指标 | 预期 |
| --- | --- |
| CodeFlicker 精确读取 | 3 / 6 行，1 / 3 文件 |
| CodeFlicker 精确修改 | 3 / 6 行，2 / 3 文件 |

测试还覆盖查询版本、原始证据行及哈希、缓存重建、复制来源去重、半行追加、结果补全、来源移走、上一版对照。额外回归使用 2005 字符长行的隐式截断与带绝对 `Directory` 的相对路径 Shell 读取。

## 真实历史核对

只读选择同一个真实项目目录中的 14 份原生 JSONL（13,342,271 字节），排除 `requests/`。代表主来源 A 包含 726 条物理记录、113 次调用和 113 个结果；独立从原始字段统计，再逐项核对适配结果的工具、调用 ID、请求／结果行与哈希：

| 工具 | 调用数 |
| --- | --- |
| read / write / edit | 18 / 9 / 7 |
| bash / grep / glob | 49 / 14 / 2 |
| todoWrite / skill / AskUserQuestion / Agent | 3 / 6 / 4 / 1 |

成功 93、失败 4、未知 16。18 次 read、9 次 write、7 次 edit 均获得成功及内容证据。子来源 A-child 保留 10 次新调用，全部带有父关系与主来源第 490 行的成功结果证明。

真实 Git 仓库登记与两次刷新完成；CLI 与 API 同版本的完整覆盖响应相同，文件详情、当前内容与原始证据可回读。重复刷新后的覆盖、文件与缺口一致；全部 14 个原始文件刷新前后哈希不变。浏览器已完成客户端筛选、地图定位、文件下钻、当前代码跳转高亮、原始记录和来源查询。

最终安装包的真实仓库全部文本基线为 17,094 文件、4,896,481 行。已确认的精确读取 43 文件／11,267 行、近似读取 1 文件／2 行、精确修改 26 文件／4,202 行。仓库由其他任务同时开发，跨验收轮次的基线会变化；只在同一完整版本或本次重复刷新内比较数据。该数字表示现存历史能证明的范围；其中 1 个文件的局部字符差异计算超限，保留 `budget_exceeded` 缺口，不把未确认部分算作已覆盖。

最终保留缺口 188 项：工具不支持 23、范围未知 162、歧义 2、预算限制 1。代表主来源的解析状态与工具数有独立原始答案；整个真实仓库的覆盖没有独立的全行归属答案，因此以上覆盖数字只确认 CLI／API／Web 一致、可回溯且重复刷新稳定，不宣称全仓逐行正确率已经证明。

## 两轴审查

固定起点 `4cc1adb`，初次审查到 `3ab39be`。两名独立审查者分别核对规范与规格；全部问题交给同一实现者修复。

### Standards

初次发现 2 项，最高 P3：

- 流程规范：验收任务开始实现时仍标记 ready-for-agent。后续同步为 claimed，完成后记录 Answer 与 resolved；这不改变此前未及时认领的事实。
- 判断性异味：三个适配器重复维护请求登记状态。提取通用登记函数，格式专属身份仍由适配器提供，并以旧客户端回归约束事件 ID、来源引用与配对。

### Spec

初次发现 3 项，最高 P2：

- 超过 2000 字符的原生读取行会被 producer 隐式截断，未置 `truncated`。识别截断形态，将该行保留为范围未知；完整相邻行仍可参与对应。CLI 端到端用例修复前出现近似覆盖 1 行，构成失败复现。
- 原生 bash 包装的 `Directory` 被丢弃。保留可核实的绝对执行目录到该事件，相对路径读取可以据此归属；不改变整份来源的工作目录。
- 成功 Agent 结果的 `agentId` 未贯通子来源。仅在同客户端、同项目、唯一父身份与子文件／会话身份相符时建立关系，并保留父调用及结果的原始引用；子调用继续作为新活动计数。

第一次复核进一步发现 2 项 P2 边界：

- 固定多文件 sed 调用拆分后的派生活动没有全部继承执行目录。回归在 CLI 端复现第二个文件读取 0 行而预期 1 行；修复将本次目录在拆分前传给调用，各文件活动均保留目录，整份来源目录不变。
- 显式父字段与成功 Agent 原生证明矛盾时，虽然显示歧义仍发布旧父关系。冲突时撤销已确认关系、事件父 ID 与来源摘要父 ID，保留歧义及原始声明；不选择任一候选父。

以上修复由同一实现者完成，解析规则最终升级至 7，旧版缓存自动重建。

Standards 对两个修复提交分别只读复核，无剩余规范问题。Spec 最终独立探针与 38 项定向回归通过，无剩余规格问题。主流程随后使用最终安装包验绿多文件 Shell 回归，并完成上述完整回归与实际页面验收。

## 重现入口

在源码仓库使用 Node 24、Git 执行：

```sh
npm ci
npm run check
npm test
node scripts/e2e-cli.mjs
node scripts/e2e-codeflicker.mjs
```

`npm test` 包含真实 tarball 安装，需要 registry 可访问且允许本机端口监听。两个端到端脚本使用隔离来源目录和临时仓库；可用 `AGENT_MANOR_E2E_CLI` 指向包外安装的 CLI，验证实际交付产物。CodeFlicker 脚本加 `--keep` 会保留临时服务与 `state.json` 供浏览器验收，测试后按该数据目录调用 CLI `stop`。

## 支持限制

验收使用选定的真实项目目录，不能据此宣称全量历史的性能或兼容性已经验证。本机默认来源清点约 1.87 GB、3809 个候选原生文件；未完成该全量范围的性能验收。

本轮保留的 4317 本地预览服务已重启到新后端；CodeFlicker 来源配置限定为上述已验收项目目录。工具本身的默认发现根仍为 `~/.codeflicker/projects`，可用 `AGENT_MANOR_CODEFLICKER_DIR` 指定目录。此预览配置不代表已经导入本机全部 CodeFlicker 历史。

无成功证据、内容不足、隐式截断或父关系歧义继续显示采集缺口。精确读取覆盖不是 AI 创作比例，也不保证所有使用过的代码都能从现存历史恢复。

真实历史正文、个人路径与原始截图只保留在本机隔离目录；仓库仅保存匿名 fixture、验收统计与匿名页面截图。
