# 产品定位与范围

整理日期：2026-10-03。

状态：独立项目、名称和本地优先定位已确定；首版产品规格已确认，聚焦仓库代码活动地图，采用本地后台、Web、CLI 与 Skill 的交付方向。当前尚无业务实现，技术栈和历史格式支持由实施方案确定。

## 要解决的问题

开发者在多个 Agent 客户端中积累了会话、Skill 和 MCP，逐渐难以回答：装了什么、从哪里配置、在哪些项目使用、哪些需要整理，以及 Agent 在代码上做了什么。

AgentManor 面向这些开发者，提供根据真实使用历史管理工作环境的入口。核心产品承诺候选是：知道环境里有什么，解释使用情况，给出有依据的调整建议，帮助完成可恢复的调整。

## 能力全景

| 用户问题 | 计划能力 | 与其他能力的关系 |
| --- | --- | --- |
| 环境是什么样的？ | 客户端、Skill、MCP 盘点；来源、作用范围、共享关系与启用状态 | 为使用统计和修改配置提供对象基线 |
| 实际怎样使用？ | 历史搜索、调用与失败统计、最近使用时间、项目和会话分布 | 为建议提供证据，不单独证明任务质量 |
| 哪些值得整理？ | 重复、失效、闲置和低频候选；项目级建议、预览、停用、隔离与恢复 | 将报告变成可执行的管理操作 |
| 在代码上花了哪些精力？ | 文件读取与修改热力图，关联任务、会话和工具调用 | 为重复探索等现象提供调查线索 |

历史搜索、活动分布、代码地图、CLI、Web、Skill 和 MCP 接口属于整体方向。具体支持范围应在实现前逐项确定。

## 典型场景

以下是产品设想示例，不是已观测的用户数据。

- 某个 MCP 在当前项目的近 30 天没有使用，但在另一个项目经常使用：展示两处证据，建议只在当前项目停用。
- 同名 Skill 存在于多个配置位置：先判断是否共享链接、不同版本或覆盖关系，再提出整理建议。
- 某个文件被多次读取：下钻查看对应任务、失败、代码变化和上下文恢复，帮助用户判断是否需要改进项目说明或工作流。
- 一次整理后任务需要原配置：根据保存的操作记录恢复，并检查客户端是否重新发现资源。

## 当前首版方向

2026-10-03 需求讨论中，用户将首版收敛为“历史会话 → 当前仓库代码活动地图 → 文件与行覆盖 → 原始证据 → Agent 查询”的完整流程。逐轮决定和验收标准见 [首版规格](../../.scratch/repository-activity-map/spec.md)。

1. 指定仓库后发现属于它的 Codex／Claude Code 本地历史，默认使用全部可用历史，并支持时间、客户端筛选与无法归属会话的手动关联。
2. 默认以包含未提交修改的当前工作区为基线，提供文件与行覆盖率；源码为默认统计范围，配置与文档可切换查看。
3. 主要读取覆盖率使用成功返回且范围可确定的内容，精确与近似对应分别展示；修改覆盖率描述历史编辑活动。
4. Web 提供目录矩形树图、文件行高亮和事件证据下钻；CLI 支持同范围的 JSON 查询与刷新，Skill 指导其他 Agent 使用。
5. 本地后台按需自动启动，启动时检查增量更新，支持主动刷新、状态查询与显式停止；关闭页面后仍供 CLI／Agent 使用。首版先在 macOS 验收。
6. 本机保存可重建的分析索引与必要历史片段，原始会话只读，分析不依赖上传历史或调用模型。语言、数据库和 UI 框架尚未选择，架构决定见 [ADR 0002](../adr/0002-local-analysis-service.md)。

Skill/MCP 盘点与环境整理保留为长期管家方向，后续结合使用反馈确认顺序。配置同步、安装市场、多机器同步、知识提炼和多 Agent 调度仍是后续候选。

与代码外传保护的边界由 [ADR 0001](../adr/0001-independent-project-boundary.md) 定义。

## 为什么值得验证

已经有历史搜索、统计、清理和配置同步项目，详见 [竞品全景](../research/competitive-landscape-2026-10-03.md)。单项能力不是空白市场。

值得验证的价值是：把配置来源、跨项目使用、历史证据和可恢复操作连起来，减少用户在多个工具与配置文件之间手动判断的工作。跨客户端解析可靠性和管理操作是否真正生效，可能比新增图表更影响持续使用。

这仍是差异化假设，未被用户研究或竞品运行对照证明。

## 验证标准

当前首版的覆盖统计、精确与近似对应、证据下钻、增量去重和 CLI／Skill 一致性，按 [首版验收标准](../../.scratch/repository-activity-map/spec.md#首版验收标准) 验证。下面保留长期环境管理方向的验证标准。

先使用获准的少量会话和选定项目，对照现有工具回答相同问题：

| 验证对象 | 完成标准 |
| --- | --- |
| 盘点 | 配置来源和作用范围可定位；共享项与同名不同项能区分 |
| 统计 | 可回查事件；已知样本的次数、结果和去重正确；缺失来源明确可见 |
| 建议 | 每条建议有理由、观测窗口和影响范围；跨项目活跃项得到合适处理 |
| 调整 | 变更预览与实际修改一致；目标客户端状态可核验；失败被记录 |
| 恢复 | 所选操作可以恢复；期间发生的用户修改不会被静默覆盖 |
| 需求 | 试用者能发现有用问题、完成调整，并在之后主动回来使用 |

漂亮图表、Star、静态分析通过和配置文件写入成功，分别不能替代上述业务验证。
