# npm 交付、完整 CLI 与配套 Skill

本文记录已确认的目标方案，包括 Commander.js 选型、工程与交付边界、功能范围、启动策略、人工审阅和平台矩阵。命令及 API 对照见 [实施结果](../../.scratch/npm-cli-distribution/cli-engineering-results.md)，实际测试环境与完成边界见 [交付验证](../validation/npm-cli-distribution.md)。本文定义交付契约，不表示已经公共发布。

维护者打包、验收及手动发布的具体步骤见 [npm 发布指南](../releasing.md)。

## 交付与命名

- npm 包名为 `agent-manor`，主命令为 `agent-manor`，缩写为 `am`。两个 bin 指向相同 CLI 实现，参数、输出、退出码及数据目录完全一致。
- CLI 拥有独立工程、命令模块、构建配置与测试边界；对外统一打包 CLI、本地后台、Worker、Web 静态资源和 Skill，整体采用同一产品版本，见 [ADR 0020](../adr/0020-independent-cli-unified-distribution.md)。
- 首版以编译后的 JavaScript 分发 CLI、后台和 Worker，以构建后的 HTML、CSS 与 JavaScript 分发 Web。用户预先安装 Node.js 24，通过 npm 安装产品后直接获得命令和网页服务，无需源码 checkout、TypeScript 或 Vite。
- SQLite 等运行时依赖由 npm 按目标平台安装，其中包含平台相关的原生组件。本轮不交付内置 Node.js 的独立可执行发行包，不将 npm 包描述为无运行时依赖的单文件程序。
- 程序安装位置与用户数据分开。沿用 `--home`、`AGENT_MANOR_HOME` 及默认本地数据目录；切换工作目录、命令别名或升级程序不创建另一份隐含数据。
- 安装和公共发布使用 `https://registry.npmjs.org/`；发布配置明确声明目标 registry，CI 发布也显式指定。正式交付采用 MIT，补齐 LICENSE 与包元数据。仓库仍处于未公共发布状态，实际发布前完成账号权限及包名可用性确认。

公共发布后的使用流程如下；当前先安装构建后的本地 tarball：

```sh
npm install -g agent-manor
am start
am web
am sessions list --json
am skills install
am status --json
am stop
```

## CLI 技术选型与工程结构

CLI 使用 TypeScript 与 Commander.js，延续现有 Node.js 技术栈。Commander.js 负责命令树、参数与选项解析、帮助、用法错误和异步命令调度；本产品统一实现服务发现、任务等待、中英文输出、稳定 JSON、退出码和管理确认。框架不承担业务授权、后台常驻或软件更新的实现。

CLI 在 `packages/cli/` 建立内部 npm workspace，拥有独立 `package.json`、TypeScript 构建配置和测试。内部包保持 `private`，与根产品包同版本，不要求用户另行安装或发布第二个 npm 包。后台、Worker 和 Web 保留现有工程位置，本轮不为目录对称而迁移无关模块。

```text
packages/cli/
  package.json
  tsconfig.json
  src/
    entry.ts           命令入口与退出处理
    program.ts         创建并注册 Commander 命令树
    commands/          按业务领域组织命令
    api/               后台 API 客户端与错误转换
    runtime/           实例发现、启停、日志与程序更新
    output/            人类可读输出、JSON 与进度
    skills/            Skill 安装、核验、更新与移除
  tests/               命令及公共 CLI 行为测试
```

命令模块只声明参数并调用公共能力，不直接操作 SQLite 或重复实现后台业务。`program.ts` 可在测试中独立创建命令树，导入模块不自动启动服务；`entry.ts` 负责读取运行参数、执行命令并设置退出结果。已有共享契约和翻译目录继续复用，产品显示语言不改变命令名和 JSON 字段。

根构建统一执行后台、Worker、CLI 和 Web 构建，将 CLI 产物装入产品 `dist/`，保留 `dist/cli.js` 作为轻量产品入口。根包两个 bin 均指向该入口：

```json
{
  "bin": {
    "agent-manor": "dist/cli.js",
    "am": "dist/cli.js"
  }
}
```

入口保留 `#!/usr/bin/env node`。npm 全局安装时在 macOS/Linux 建立命令链接，在 Windows 建立命令包装文件，由 Node.js 执行 CLI；用户无需自行运行 JavaScript 文件。发布包不依赖内部 workspace 的源码、开发时链接或另一个未发布的内部包，包外安装必须能找到全部运行产物、Web、Worker 和 Skill。

## 工程职责

CLI 工程只负责命令解析、输入校验、服务连接、任务等待、输出和明确的管理确认，不复制 SQL、统计、索引或知识抽取逻辑。按领域分组注册命令，共用连接与输出层；命令主入口保持轻量，帮助、版本和诊断不依赖数据库迁移或模型初始化。

后台继续拥有数据读写、生命周期状态、任务队列、业务校验与 API。Web 和 CLI 使用相同业务契约；缺少 CLI 能力时优先增加命令适配，必要的 API 补充保持两个入口的语义一致。服务启动与停止可使用独立的本机生命周期代码，不要求尚未启动的 HTTP API 执行自己的启动。

不要求用户组合安装多个产品包，也不为本轮引入独立远端服务或公开 SDK。Commander.js 的引入方式与工程边界一并记录于 [ADR 0020](../adr/0020-independent-cli-unified-distribution.md)。

## 命令与页面能力覆盖

按业务操作建立验收矩阵，不把动画、拖拽和地图绘制过程机械转换成命令。可保存的偏好、查询范围、数据读取、导出和管理行为应有对应入口；地图及回放的底层数据和来源可通过 CLI 读取。现有页面、API 和命令的静态差距见 [能力覆盖清单](../../.scratch/npm-cli-distribution/capability-matrix.md)，实施时逐项登记命令和验证结果。

| 领域 | 目标命令组或入口 | 必须覆盖的能力 |
|---|---|---|
| 生命周期 | `start`、`serve`、`web`、`status`、`stop`、`restart`、`logs` | 后台与前台运行、真实状态、就绪等待、打开网页、日志及停止完成 |
| 总览 | `overview` | 默认快照、时间与客户端范围、分区、明细、洞察及证据下钻 |
| 会话 | `sessions` | 列表、关键词与语义搜索、项目及客户端筛选、分页、消息、分支、轮次、执行轨迹、画像、用量、导出与来源定位 |
| 代码活动 | `repositories` 及代码活动命令 | 登记和删除登记、覆盖、热点、文件、目录、事件、原始证据、来源关联、分析任务及活动回放数据 |
| 用量 | `usage` | 报告、趋势、模型及服务商筛选、请求明细、计价映射、价格覆盖和更新状态 |
| 资源 | `resources` | 盘点、搜索、排行、位置、详情、收藏、来源、预览、应用、回收、恢复与操作记录 |
| 知识 | `knowledge` | 直接写入、读取、搜索、范围和标签、修订、来源、差异、人工审阅、废弃与恢复 |
| 沉淀与语义索引 | 知识及会话子命令 | 预览、显式启动、任务历史、进度、过程、结果、暂停、继续、重试、策略及预算 |
| 配置与偏好 | 各领域 `settings`、共享偏好入口 | 模型连接、凭据、提示词、语言、外观及自动同步策略；默认输出脱敏 |
| 自身维护 | `version`、`update`、`doctor`、`skills` | 版本、显式更新、安装诊断、Skill 安装状态、更新与移除 |

上表定义功能覆盖，最终子命令名及旧命令兼容别名在实施清单中逐项固定。已有命令、分析结果版本参数和 JSON 字段保留兼容，程序版本与查询绑定的数据版本分别表达。

会话导出当前由页面读取消息后组织，CLI 优先复用消息 API 与共享导出规则，必要时补充后台接口。读取价格可能触发已有的联网刷新，不能将所有业务 GET 一概描述为无副作用；状态和只读诊断不安排此类更新。会话语义与知识的凭据查看入口统一采用明确管理流程。

## 生命周期与端口发现

| 入口 | 目标行为 |
|---|---|
| `start` | 已有健康实例则复用，否则启动后台；首次显示进度并等待完整数据，之后返回实际地址、PID、版本及日志位置；已有初始化结果时快速返回 |
| `serve` | 前台运行同一个服务，显示阶段与诊断，响应正常退出信号 |
| `web` | 确保后台运行，首次等完整数据准备后再使用实际地址打开浏览器；保留只输出地址的选项 |
| `status` | 只检查实例、健康及准备状态，未运行不创建服务；启动中仍可显示启动阶段 |
| `stop` | 只停止经核验的目标实例，等待停止完成；未运行时明确返回该状态 |
| `restart` | 校验兼容性和在途任务，停止旧实例后由当前安装版本启动新实例 |
| `logs` | 查看或跟随本机日志，不因日志查询启动后台 |
| 版本、帮助、`doctor` | 读取必要的程序或本机元信息，保持诊断只读，不安排同步、迁移、索引或模型任务 |

普通业务查询按需连接或启动后台。每个数据目录只复用自己的实例，以启动锁串行化并发启动，结合实例身份、PID、真实健康响应和协议版本校验，不通过扫描端口范围发现并接管服务。

默认新实例尝试 `127.0.0.1:16666`，占用时顺延。常规默认值为最多尝试 100 个候选端口，只针对地址占用继续尝试；其他绑定错误立即报告。显式指定固定端口时，占用即报告错误，不悄悄改变用户指定值。已有健康实例优先复用，其地址不因当前默认端口变化而失效。

成功绑定后原子保存实际地址和实例信息，`am`、主命令及网页共用该记录。等待超时、用户取消等待、后台真正退出和数据准备失败分别报告；取消等待不等于终止正在运行的后台任务。旧实例文件、PID 复用和地址上的其他程序不能被误认或误停止。

## 服务就绪与数据准备

启动策略见 [ADR 0021](../adr/0021-service-readiness-and-data-preparation.md)。

1. 检查数据目录、单实例锁、必要配置、数据库兼容与一致性；阻断启动的错误保留明确阶段和诊断。
2. 初始化必须可用的服务组件并开放 HTTP，发布服务就绪状态及真实地址。
3. 在后台检查历史变化，发布完整历史版本；搜索索引和用量基础数据按各自依赖补齐。
4. 在依赖版本可用后准备默认总览和常用基础统计，复用有效缓存；其他筛选组合按需计算，不枚举预热全部组合。
5. 按已保存开关恢复自动同步、知识及语义维护策略，继续受范围、静默时间、暂停和预算约束。进程启动本身不新增一次全量生成或编码。

`start`、`web` 首次自动等待本轮全部本地准备，包括默认总览全部首屏面板及最近7天复盘；终端显示阶段、实际数量和耗时。没有登记仓库时跳过地图。首次数据等待默认不限时，可显式设置 `--timeout`；JSON 模式仅返回稳定结果。可选模型任务不进入统一启动门槛。

空库开始时原子保存准备中标记，完整准备成功后改为完成；首次中断或失败后下次仍等待，失败不自动打开网页。已有可查询历史的旧目录不要求补齐新标记才打开，直接快速返回，后台继续增量准备；`--wait-data`／`ready` 可显式等待当前一轮。状态与诊断 HTTP 在准备阶段保持可用；仓库阶段显示完成数、总数、当前名称、处理阶段和该任务的阶段进度。

## 输入、输出与任务

- 默认人类可读输出，帮助按领域分组；`--json` 使用稳定字段、枚举和错误码，产品显示语言不改变 API 标识。保留中英文帮助与诊断。
- JSON 模式的 stdout 只输出约定结果；进度和诊断写 stderr。区分请求已接受、任务进行中和任务实际完成，显式等待以最终任务状态结束。
- 支持现有分页与范围参数，返回下一步读取所需的稳定身份和版本。大正文、批量输入与知识内容支持文件或 stdin，避免依赖复杂 shell 转义。
- 常规CLI请求使用轻量响应：列表摘要、状态计数、写入结果与按需明细分别读取；全局 `--full` 显式保留旧完整字段，`--json` 只选择格式。正文续读、画像明细和价格目录分页见 [CLI响应约定](cli-responses.md)。
- 创建耗时任务返回任务 ID、阶段和后续状态入口；支持按已有能力暂停、继续和重试。关闭终端或等待超时不隐式删除任务。
- 管理操作沿用预览、版本校验和恢复规则；失败、冲突、拒绝和未就绪具有可供脚本判断的退出结果。例行确认不能替代业务授权。

## 知识与人工审阅

直接写入已经整理好的知识不调用生成模型，默认形成待审修订。知识搜索支持关键词和可选语义方式，可按项目、来源客户端、类型、标签、审阅和可用性筛选，默认仍使用已审且有效版本。

CLI 可读取候选、显示与当前发布版本的差异、定位来源，并对具体修订发起用户确认。用户核对并明确确认后才能发布；普通 Agent 提交、调用方自报身份或通用 `--yes` 不将知识改成人工已审。非交互审批必须对应用户明确授予的本次操作，绑定知识和修订，版本变化后重新核对。

交互式提示与终端类型本身不能证明实际操作者是人；管理流程表达和记录明确的用户核对与授权，不能承诺识别同一本机身份下所有进程的真实操作者。最终管理调用机制与字段在接口清单中固定，保持 Web 和 CLI 的人工审阅含义一致。

会话沉淀先预览范围和预计规模，再显式启动；过程、结果、用量及历史可查询。任务完成仍不表示候选已经人工审阅。模型 Key 通过明确的凭据输入入口保存，普通配置输出脱敏；按需查看凭据属于独立的用户管理动作。

## Skill 内容与安装

保留一个主 `SKILL.md`，按会话、知识、总览、代码活动、用量、资源、服务与诊断拆分 `references/`；主文件按任务场景路由，只加载当前分支需要的文档。目录内参考自包含，不使用复制后失效的包外相对路径，也不要求 Agent 直接访问数据库。

| 场景 | Skill 引导 |
|---|---|
| 在一个客户端接着处理另一个客户端讨论过的问题 | 先搜索全局会话库，再读取命中附近的连续对话，按需回读工具过程及来源 |
| 遇到类似问题，想复用已有经验 | 搜索并读取已审有效知识，核对项目与适用条件，必要时回查来源 |
| 已经整理好新经验或纠正旧结论 | 直接提交待审知识或新修订，附来源，不额外调用抽取模型 |
| 调查 Agent 对代码做过哪些读取和修改 | 查询活动范围，保持版本及筛选，读取具体事件和原始证据 |
| 复盘模型投入及估算费用 | 查询用量和计价依据，保留未知、估算与采集覆盖 |
| 整理本地 Skill／MCP 环境 | 盘点真实入口与使用记录，预览后执行可恢复管理 |
| 查询连接不上或数据仍在准备 | 检查服务和任务状态，按范围等待或读取诊断，不反复启动和重建 |

每份参考写明适用场景、必要输入、最短命令流程、筛选与分页、读取范围、结果解读及完成条件。支持跨客户端使用，不根据当前 Agent 推断只能查询同一客户端的历史；原始身份、版本和证据边界继续保留。

`skills install` 提供交互选择和等价参数，支持 Claude Code、Codex、用户级、项目级及自定义目标。按核验的宿主目录规则解析路径，先显示最终位置，再复制整个 Skill 目录；自定义路径按用户选择处理。npm 安装本身不写宿主 Skill 目录或其他客户端配置。

安装记录保留本产品所管理的目标、模板版本和文件校验信息。重复同版跳过；旧版未修改时支持明确更新；用户修改或外来同名目录展示冲突，覆盖前保留备份并由用户选择。移除只处理已核验的本产品副本，修改内容和共享目录分别处理，不删除其他 Skill。程序更新后可提示 Skill 版本状态，实际同步仍通过明确安装／更新操作。

## 更新与日志

产品版本检查、Web／CLI 提醒及安装确认见[产品更新方案](software-updates.md)，实现范围与测试边界见[产品更新验证](../validation/software-updates.md)。

更新先识别全局、本地或一次性运行等安装方式，检查目标版本、平台和协议兼容；不在普通查询时静默替换程序。覆盖正在运行服务的安装目录前，先安排任务停止边界与服务切换，避免旧进程继续加载新旧混合文件。

同一程序安装可以服务多个数据目录。安装级操作锁与当前用户私有的本机临时登记协调启动和升级；登记保留实际安装、数据目录、进程及实例身份。发现该安装的其他数据目录仍在启动、运行或身份无法核验时，更新明确拒绝并列出目标，不替用户停止其他实例。只有核验当前范围并阻止并发新启动后才覆盖安装目录。

有在途任务时显示范围和状态：能保存检查点的任务可在用户选择后暂停；不支持暂停的任务等待完成。非交互更新默认报告忙状态，或由明确的等待选项等待，不自动强制终止。服务原来未运行时，安装更新不自动让它常驻；原来运行时，切换后验证新版本与原数据目录。

迁移前检查数据兼容性并保存必要恢复材料，明确哪些持久数据必须保留、哪些派生数据可重建。更新失败与数据迁移失败分别处理；不承诺任意数据格式均可自动降级，也不通过删库解决兼容问题。

日志保存在本地数据目录，记录阶段、任务身份、耗时和必要错误，限制体积并轮换；常规默认值为每份 10MiB、保留 5 份。默认不记录凭据、完整提示词或会话正文。CLI 进度与后台日志相互可定位，启动失败时能找到对应阶段与日志位置。

## 平台与交付验收

| 系统 | 首版 CPU 架构 | 运行时 |
|---|---|---|
| macOS | arm64、x64 | Node.js 24 |
| Linux | arm64、x64 | Node.js 24 |
| Windows | x64 | Node.js 24 |

Windows ARM64 后续补充。Linux 记录实际验收的发行版和 libc，不能将未测变体表述为已验证。每个支持组合实际安装原生 SQLite 与向量依赖；无预编译包时的构建工具要求和错误须可诊断，不以空壳安装成功代替功能通过。

验收使用构建后的同一 tarball，在源码目录之外安装，并以隔离合成数据验证：

1. 两个命令入口、帮助、版本、中英文、JSON、stdin、文件路径及空格路径。
2. 无服务的状态检查、并发启动单实例、默认端口冲突顺延、固定端口冲突、关闭终端后运行、停止与重启，以及旧实例或其他程序不被接管。
3. 首次数据准备、已有完整版本、更新失败和显式等待；任务状态、缓存与业务数据版本保持一致。
4. 覆盖矩阵中的全部业务能力，包括知识直接写入、抽取、搜索、版本、人工确认和管理恢复；模型验收使用有界输入和预算。
5. Skill 在用户级、项目级及自定义目录的安装、复制后引用、同版跳过、升级、用户修改冲突、备份及移除；从具体自然语言场景走通查询和回读。
6. 程序升级、旧后台握手、在途任务、迁移与失败恢复；保留知识、偏好、操作记录和恢复材料。
7. 包内文件白名单、Web 静态资源、Worker 路径、原生依赖与公开内容检查。测试和发布使用同一个已验收 tarball，实际公共发布不替代上述验收。
