# 产品版本检查与程序升级

状态：Q1～Q9 已确认，已进入实现与验收；验证结论见[产品更新验证](../validation/software-updates.md)。

## 目标与边界

让用户知道是否有可用的新版本、当前安装能否更新，以及更新会影响哪些后台与本地数据。版本检查、提醒和程序安装分别表达，不与会话历史更新、索引维护或页面刷新混用。

本轮实现并测试版本检查、提醒和显式升级，不发布 npm 包、不升级用户现有安装，也不改变仓库可见性。

## 实现约定

以下约定按已确认方案实施。

### 检查触发与缓存

- 本地后台服务就绪后调度异步检查。检查不进入首次数据准备的完成条件，也不阻塞历史解析、业务查询或浏览器打开。
- 同一产品安装成功或失败的一次自动尝试，均记录时间；默认 24 小时内不再自动联网。后台持续运行时到期继续检查，没有运行后台时不另建常驻进程。
- 业务命令可以使用已有后台的调度；帮助、版本、状态和普通缓存读取不为检查更新启动后台。CLI 自动提醒只读取本地缓存，不在命令结束前等待网络。
- Web 主动“检查更新”和 `am update --check` 立即检查；并发主动检查合并为同一个在途请求。自动关闭不禁止用户主动检查或明确安装时所需的版本查询。
- 网络请求设 5 秒超时，无隐式连续重试。显式请求失败报告可重试错误；自动失败只更新诊断，日常命令不因此失败。
- 缓存同时保存有更新和无更新的成功结果；检查结果只存目标发布元信息和检查时间，不持久化由旧程序版本推导的 `updateAvailable`。
- 共享缓存只记录 latest 稳定渠道。显式查询或安装某个版本不覆盖稳定渠道结果，也不修改后续自动检查的目标。
- 自动尝试失败不覆盖上一份成功元信息。过期结果标记为上次结果，不使用它声明“已是最新版”或自动发起提醒；安装前始终重新查询并核验固定目标。
- 跨后台进程通过独立的检查锁合并请求，检查锁不占用程序安装操作锁。更新策略在每次发起请求前重新读取，避免已关闭后仍因旧计时器继续请求。

### 提醒与忽略版本

- CLI 在正常完成的交互式业务命令末尾，用一行标准错误输出提示新版本及更新命令，不改变业务返回值或退出码。同一产品安装对同一目标版本，滚动 24 小时内最多提示一次；多个 CLI 并发结束时原子记录提醒时间，避免重复提示。
- Web 仅在页头入口显示紧凑标记，不自动弹窗。打开面板后才显示版本详情和后续操作。
- 用户可以忽略当前目标版本。`ignoredVersion` 按产品安装保存，Web 和 CLI 共用；它只控制自动提醒，不改变 `updateAvailable`、手动检查结果或安装能力。
- latest 高于被忽略的版本时重新提醒；用户也可以随时清除忽略设置。关闭自动检查时，同时关闭自动提醒，主动检查和安装入口仍可使用。
- 过期缓存、失败后保留的旧结果不触发自动提醒；没有新版本、已经忽略或已升级到目标版本时不显示新版本标记。

### 作用范围与存储

安装身份沿用当前用户和规范化程序安装路径。配置和缓存不写入受 npm 管理的程序目录，也不归属于 `--home` 指定的某个业务数据目录。

建议放在当前用户系统配置目录的 `agent-manor/installations/<installationId>/` 下：macOS 使用 Application Support，Linux 使用 XDG_CONFIG_HOME 或默认 `.config`，Windows 使用 APPDATA。具体路径仅在诊断中按需展示。

| 文件 | 内容 | 生命周期 |
| --- | --- | --- |
| `settings.json` | `autoCheck`、可空的 `ignoredVersion` | 用户偏好，清理缓存时保留 |
| `release-check.json` | 最近尝试、最近成功、最新发布元信息及必要错误 | 可重建缓存 |
| `notice.json` | 按目标版本记录最近一次 CLI 自动提醒时间，过期记录可清理 | 可重建，不含业务数据 |

写入采用原子替换和当前用户权限；同一路径升级保留设置，程序安装移动到其他路径视为另一份安装，不静默继承旧路径身份。现有临时目录中的实例登记和操作锁继续负责运行互斥，不承担持久偏好存储。

新增 `--no-update-check` 与 `AGENT_MANOR_NO_UPDATE_CHECK=1`，仅覆盖本次进程的自动检查和提醒，不改持久设置。连接到已有后台时，本次参数不代表关闭其他进程已启用的周期任务；需要关闭整个安装的自动行为时修改持久设置。

### 版本和安装兼容性

- 默认查询官方公共 registry 的 `agent-manor/latest`。只将合法、非预发布且比当前版本更高的版本作为稳定版更新；不推断 Git 提交或构建时间代表新发布。
- 显式 `--to` 固定合法发布版本。首版自动渠道不包含测试版；显式指定预发布版本也先报告不支持，避免隐式切换渠道。
- 目标相同返回无需更新；目标更低返回降级不支持；当前版本比 latest 更新时显示该关系，不提示安装旧版。
- 检查目标的 Node.js、系统及架构要求；发现新版本但运行环境不兼容时保留版本信息和原因，不呈现为可直接安装。
- 版本元信息缺失、包不存在、发布被移除或检查失败分别报告，不当成无需更新。安装前重新核验已确认的版本，不能把后发布的另一个 latest 静默替换为安装目标。
- npm 安装继续使用固定精确版本、官方 registry 和引擎校验，安装后的包版本必须与确认目标一致。

### CLI 入口

CLI 提供以下入口：

| 命令 | 含义 |
| --- | --- |
| `am update --check` | 主动检查发布版本，不安装；保留已有入口 |
| `am update status` | 只读本地检查结果与设置，不联网、不启动后台 |
| `am update settings get` | 读取同一产品安装的更新设置 |
| `am update settings set --data '{"autoCheck":false}'` | 修改安装级开关；不混入数据目录偏好 |
| `am update settings set --data '{"ignoredVersion":"0.2.0"}'` | 忽略示例版本的自动提醒；设置为 null 则恢复提醒 |
| `am update --dry-run` | 主动检查并预览安装目标、运行实例、备份位置及阻断原因，不停止服务或执行安装 |
| `am update` | 主动检查并预览，交互确认后安装 |
| `am update --to 0.2.0` | 以示例中的精确版本预览并安装，仍检查版本和环境边界 |
| `am update --yes --wait --json` | 明确授权非交互安装，等待目标后台的在途任务，并返回结构化结果 |

默认 JSON 与人读格式使用相同的核心字段。对于真正安装的请求，`--json` 或非交互环境不读确认输入；缺少 `--yes` 时返回预览及 `CONFIRMATION_REQUIRED`，不开始安装。检查、状态读取和 `--dry-run` 不需要安装确认。帮助、版本、纯读状态、JSON、CI 和非交互输出不插入自动版本提醒。

Skill 可以读取状态、主动检查并解释结果。安装仍需要用户明确要求，不自行补上 `--yes`。产品包中的 Skill 随版本变化；已经复制到宿主的 Skill 沿用显式 `skills update` 及用户修改冲突保护，程序升级不静默覆盖。

### Web 入口

页头增加一个紧凑的“版本与更新”入口，不新增一级导航页。普通状态不铺提示条；发现更新时在入口增加标记，点击后打开共享对话框。

面板显示运行后台的当前版本、已检查的最新版本、上次检查时间、安装支持情况、主动检查按钮、自动检查开关和可复制的命令。存在更新时提供“忽略此版本”；已经忽略时显示“恢复提醒”，手动检查仍呈现该版本。数据目录为非默认目录时，复制的命令保留相应 `--home`；路径按当前系统的命令引用规则输出。

复制命令在 macOS／Linux 使用 POSIX shell 引用，在 Windows 明确标注 PowerShell；验证空格、引号及非 ASCII 路径，不将原始路径直接拼接为可执行命令。

Web 不提供程序安装 API。修改更新偏好沿用同源管理写入边界；读取状态不触发联网。网络错误只影响该面板，保留其他页面完整结果。所有状态、帮助和可访问名称提供中英文，使用现有对话框、焦点和动效规范。

### 接口与状态

CLI 和后台共用安装级检查、配置和版本判断模块。纯 CLI 检查或管理更新设置不要求先启动后台；Web 通过当前本地后台访问同一产品安装的信息。

| 接口 | 行为 |
| --- | --- |
| `GET /api/v1/update/status` | 读取安装级设置和缓存，不联网；当前运行版本从运行进程取得 |
| `POST /api/v1/update/check` | 主动检查 latest，合并同一安装的在途请求；失败附稳定错误和原始诊断 |
| `PATCH /api/v1/update/settings` | 修改 `autoCheck`、`ignoredVersion`，返回安装级作用范围；不修改数据目录偏好 |

核心返回包括 `currentVersion`、可空的 `latestVersion`、`checkState`、可空的 `checkedAt`、`stale`、可空的 `updateAvailable`、安装类型、是否支持自更新及兼容性原因。`checkState` 区分 `unknown`、`checking`、`ready` 和 `failed`；没有有效检查结果时 `updateAvailable` 为 null，不补 false。

状态同时返回 `autoCheck` 和可空的 `ignoredVersion`。调用方按版本关系、缓存有效性及提醒设置决定自动提醒是否可见；CLI 额外读取本地提醒时间。提醒节流不修改版本检查结果，也不在状态接口内登记一次提醒。

当前版本比 latest 更高单独表达为 `ahead`；发现新版但不兼容时保留版本关系与阻断原因。诊断详情按需读取，不在每次状态响应中附上完整路径、备份文件列表或历史日志。CLI、后台和页面资源发生版本不一致时，使用既有兼容性检查与重启／刷新入口，不由提醒组件擅自安装或切换后台。

### 安装与恢复流程

1. 解析安装类型，查询并固定目标版本，检查版本关系、运行要求和实际安装位置。
2. 预览目标后台、同一安装的其他运行实例、在途任务、备份位置、预计体积和可用空间。普通用户确认前不停止后台、不备份或改写程序。
3. 用户确认后取得安装操作锁并重新核验安装版本、实例身份和预览条件。条件发生实质变化时重新预览，不凭旧确认覆盖另一份程序或后台。
4. 同一安装的其他数据目录仍有后台运行或启动时拒绝，并给出对应停止命令；不自动停止其他目录。目标后台有任务时默认拒绝，`--wait` 只等待该目标，超时不安装。
5. 停止经核验的目标后台，按现有边界备份选定数据目录，保留配置、凭据、知识和恢复材料。磁盘空间或备份失败时不进入安装；原程序完整未变时恢复原运行后台。
6. 安装固定版本，核验安装结果；仅在升级前运行了目标后台时重启，并保留原目录、端口及允许的启动参数。
7. 分别报告程序安装、后台启动和数据准备状态。新版本尚在准备数据时显示实际进度，不把 HTTP 可连接当成全部完成。

预检、备份、安装和重启分阶段显示实际进度及可查看日志；无法计算的阶段不伪造百分比。更新失败保留恢复材料、安装日志和当前服务状态，不自动用旧程序打开可能已迁移的数据，也不默认承诺程序或数据库自动回滚。终端中断不能留下无法判断归属的安装操作；实施时验证信号和锁清理边界。

### 安装方式

| 安装方式 | 主动检查 | 自动检查建议 | 程序升级 |
| --- | --- | --- | --- |
| npm 全局 | 支持 | 按安装设置 | 支持 |
| 普通 npm 本地安装 | 支持 | 按安装设置 | 支持，预览明确项目和依赖文件影响 |
| 源码目录 | 支持 | 默认不自动检查 | 给出源码更新方式，不覆盖源码 |
| 临时运行环境 | 支持 | 默认不自动检查 | 给出持久安装方式，不覆盖临时缓存 |

复杂 workspace 或无法唯一判断安装范围时，先报告不支持的原因，不回退到全局安装。本地依赖更新还需核验 package.json 和锁文件的改变符合预览范围。

### 联网与隐私

检查只访问发布元信息，使用固定包名和必要标准请求头。不发送会话正文、提示词、项目名、本机路径、数据目录、安装身份、使用统计或模型凭据，不为更新检查增加遥测。用户可以关闭自动检查，并在明确主动检查时单次联网。

## 验收范围

| 范围 | 必测行为 |
| --- | --- |
| 版本 | 相同、更高、更低、预发布、非法或缺失元信息、运行环境不兼容 |
| 检查 | 24 小时内有／无更新均复用缓存，主动检查刷新；失败、超时、过期不误报最新版 |
| 并发与设置 | 多数据目录合并请求，不同安装分离；关闭后旧计时器不请求，配置不随程序安装或缓存清理丢失 |
| 提醒 | 同一目标版本滚动 24 小时节流及并发去重；Web 不弹窗；忽略、恢复与更高版本重新提醒；JSON、CI、非交互不混入提醒；中英文一致 |
| 授权 | 普通交互先预览确认；非交互无 --yes 拒绝；--dry-run 不停服务、不安装 |
| 服务 | 他目录后台、目标在途任务、启动中实例、身份不符、等待超时、原端口恢复 |
| 失败恢复 | 空间不足、备份失败、npm 失败、目标版本校验失败、后台重启或数据准备失败 |
| 交付 | 全局／本地／源码／临时环境、复杂 workspace 边界、包内与宿主 Skill 的独立版本 |

测试使用隔离安装与合成数据；必要的真实数据核验只公开方法和汇总结果，输入与详细日志保存在本机忽略目录。测试截图与完整输出保存在本机忽略目录，公开验证记录说明 mock 范围和未验证边界。
