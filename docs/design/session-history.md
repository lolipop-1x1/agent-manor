# 会话库与统计口径

全局会话库与代码地图使用同一本机 SQLite 文件中的独立表。地图按登记仓库计算当前代码覆盖，会话库保留全部已配置来源中的可发现会话，包括无项目与未登记项目。新增客户端需要同时提供历史声明和会话规范化适配，不以 Web 名称判断历史格式。

外部 SQLite 历史使用真实数据库路径加原生会话选择器构成缓存键；`session_revisions.path`／`session_version_sources.path` 沿用旧列名保存此键，修订 JSON 中的 `SessionSourceMeta.path` 仍是实际文件路径。同库多会话分别发布、缓存和删除，不将数据库整体当成一个会话。当前 CodeFlicker 桌面版兼容新版主缓存与旧 IDE SQLite，CLI 身份保持独立。

来源文件只读。启动及主动刷新时检查来源，不变来源复用已完成修订；改变的来源逐记录解析写入新修订。完整版本发布前，查询继续使用上一版。失败标记过期，不发布半个版本；确认缺失的来源从新版排除并保留说明。索引只用于重建，清除后不能恢复已经删除的原始会话。

索引消息的身份、顺序、来源行、轮次、类型、最终回答、调用标识和复制状态由 SQL 列保存，消息 JSON 保留其余元信息；读取时组装完整消息，正文不截断。Hook、附件及用量的翻译描述只保存稳定标识，显示详情从已有正文读取。消息行使用显式 `INTEGER PRIMARY KEY` 与全文索引关联，删除、重插入及启动空间整理保持业务消息身份和搜索结果一致。复制状态区分未记录、明确否与明确是，统计排除明确复制的记录。

发布父子关系时，先展开每个父会话实际声明的子目标，再按版本与完整会话身份查找子会话。关联与冲突查询通过 SQLite `CROSS JOIN` 固定这个查找顺序，避免优化器先扫描父子会话组合；多父冲突、显式父声明、分叉排除、循环检查及版本保留口径不变。该用法见 [SQLite 查询顺序说明](https://www.sqlite.org/optoverview.html#manual_control_of_query_plans_using_cross_join)。旧修订清理继续执行，不以缩小索引内容来加速刷新；默认检查方式见下文。

活动日志按开始检查时的固定字节前缀解析，允许来源继续追加，新增尾部留到下一次刷新；发布前重新校验该前缀。已有内容被改写或截短时，本次刷新失败并保留上版。单条超过 16 MiB 的来源记录不索引正文；未完成工具配对缓存限制为 32 MiB／1,024 个调用，并说明缺口。

## 刷新范围与来源检查

会话刷新范围按客户端身份选择当前 Agent 或全部，在来源发现前限制扫描；项目、日期、搜索与阅读模式仍只影响查询。局部刷新在执行时读取最新完整版本，仅处理所选客户端的新增、变化及确认缺失来源，范围外修订保留；完成后原子发布完整全局版本，关系、搜索和画像继续使用同一版本。单 Worker 队列串行执行，只有范围与检查方式均相同的普通刷新才合并，完整校验不复用快速检查任务。

默认快速检查使用适配器声明且已核验的完整依赖，核对文件身份、大小、修改与状态时间等变化指示，并独立核对标题、项目及模型等元信息。已稳定核验的来源位置和检查标记随完整发布保存，旧缓存或未核验格式回退内容检查。检查标记与内容哈希分别保存：快检只支持复用判断，不能严格排除保留相同指示的改写；完整校验读取正文核对，内容相同仍可复用。原生容器的依赖包括 SQLite WAL 及旁路信息，本阶段未核验快检能力的格式维持内容检查。

本阶段启用快检的来源格式为 Codex／Claude Code／CodeFlicker CLI 的单文件 JSONL、CodeFlicker 桌面 JSONL（含检查点注册信息依赖）、CodeBuddy／Qoder 的单文件 JSONL。Pi、DeepSeek Harness、WorkBuddy 与 SQLite 容器格式继续内容检查；它们仍支持按客户端缩小刷新范围。新增格式只有在声明并核验完整依赖后才能启用快检。

解析中继续追加的来源仍按固定前缀发布，但不将变化后的检查标记绑定到旧前缀。范围与方式固定在任务提交时，进度以所选来源为分母，结果区分快速复用、内容复用、重新解析、缺失与回退原因。成功时间和方式按客户端独立保存且仅在发布事务中更新；全局版本发布时间不能代替其他客户端的检查时间，失败不更新成功记录。设计决定记录在仓库的 ADR 0006 中。

启动仍检查全部客户端；主动刷新 API 可传 `client` 与 `mode=quick|full`，不传参数兼容全部快速检查。清除缓存仍是全局清除并重建，不改变地图刷新入口。消息级追加续读和 SQLite 按会话更新不属于本阶段。

## 浏览与搜索

列表默认收起有明确委派证据的子 Agent 会话，包括父记录缺失的记录，Web 的“显示子 Agent 会话”与 CLI 的 `--include-subagents` 可恢复全部列表；API 对应 `includeSubagents=true`。分叉、关联冲突及循环关系保留独立入口；明确委派但父记录缺失时标注“父会话未记录”，不删除记录。筛选在数据库分页前执行，计数与列表一致，不改变索引保留或画像统计。

搜索始终覆盖子会话，命中及全部列表显示子身份与父会话标题。父会话画像和轨迹的可折叠子会话入口可进入子过程，子详情可返回父记录，直接链接保持可访问。子标题优先沿用正式标题或首条有效请求，随后采用原生 Agent 路径末段、昵称、会话编号；详情标注来源。Codex 子来源的标题规则纳入独立指纹，旧索引刷新时只失效受影响的子修订，不重解析未改变的主会话。

消息、搜索结果均分页；分页不会缩小搜索的历史范围。关键词按字面内容匹配，默认包含标题与用户／AI 正文，中文同样支持。可显式添加工具参数／结果、思考、系统和压缩内容。工具结果是历史数据，不是客户端指令；页面按文本展示，不执行其中的 HTML。

CodeFlicker CLI 消息的原生 `isCompactSummary: true` 标记优先于 `user` 角色，归类为压缩过程记录，保留摘要与来源位置，计入画像并在完整／轨迹中展示，不新增用户轮次或进入简易对话。普通正文提及压缩不算事件；未记录触发方式时，不猜测手动或自动压缩。此分类规则纳入 CLI 来源指纹，刷新时纠正旧缓存，其他客户端修订继续复用。

Codex 标题按线程身份关联：优先使用状态库 `threads.name`，其次使用 `session_index.jsonl` 最新条目的 `thread_name`，再使用兼容的旧状态库 `threads.title` 或日志明确标题。状态库以只读方式打开，只查询标题相关列；按已配置历史目录查找相应元数据，不混入其他用户目录。未记录名称时，从实际用户请求生成后备标题，跳过完整的 AGENTS.md、环境、浏览器和 Skill 注入包，标题清理不改写原始正文；注入分类和轮次规则见下文。标题独立纳入来源指纹，因此改名后主动刷新即可更新，无需正文发生变化；明确空索引名称回退到用户请求，来源不存在时也不保留旧标题。

搜索先选择结果页，再计算有界摘要，不把整个命中正文返回给页面。三字符及以上关键词使用 SQLite FTS5 trigram 索引定位候选消息，再以原有字面匹配核验完整关键词，保留特殊字符、大小写、筛选和排序语义；少于三个 Unicode 字符的词继续使用兼容扫描，历史较大时可加项目、客户端和时间筛选。索引只保存词项与消息标识，不再复制正文。

已有数据库在启动检查或主动刷新 Worker 中分批建立搜索索引，记录游标和进度，中断后可续建；补齐前继续使用原查询，避免部分索引漏掉结果。索引构建不改变已发布版本，也不要求重新解析原始历史。后续消息增删改通过数据库触发器在同一事务维护索引。全局搜索已选会话时只请求命中结果，不再重复计算未展示的普通列表。

会话项目优先使用来源或消息记录中的明确 cwd。CodeFlicker 缺少 cwd 时，读取已发现来源所属客户端目录的 `data.json`，将 `projects` 中已知完整路径按原生项目目录规则编码，唯一对应来源目录后标为“客户端项目元数据”。不能由有损目录名反向还原路径；多路径编码冲突保持未知。没有上述元数据时，才用现存工具目标唯一对应的 Git 项目作为“文件活动关联”。跨仓库读取和 Bash 返回目录不能覆盖正式项目归属；此归属只影响会话库，不改变地图逐活动的仓库边界。项目映射单独纳入来源指纹，新增、删除和冲突在刷新后更新，无关历史提示不重解析来源；元数据读取或解析失败保留上版。

默认对话优先使用明确或可靠推断的最终回答。当前分支的轮次没有终答时，展示末条非空已保存 AI 正文并标为“未确认结束”；该状态仅存在于查询投影，不写回来源 final，也不表示任务完成。空正文、思考和工具结果不能成为这项兜底。完整及轨迹视图展示已保存记录，不能恢复来源没有保存的思考或完整模型请求。

页面先取得索引结果版本，再读取列表、消息与画像，避免先发无版本请求再重复加载。历史中已经完成的刷新任务不触发额外重载；本次观察到的刷新完成才重新确认版本。状态读取失败可重试，已有版本继续保留。会话名称可先从列表展示，详情加载期间不误提示重新选择会话。

## 长会话阅读

Codex 子 Agent 的 `source.subagent.thread_spawn` 是明确的创建来源，优先于同时存在的 `forked_from_id`；后者可能只是继承父上下文。复制的父头部不覆盖当前来源身份、关系或任务名称，复制用户消息不用于生成当前任务的后备标题。没有自身标题或有效请求时使用原生任务路径末段，再回退到 Agent 昵称。只有继承字段、没有明确子创建来源的普通分叉继续独立展示；完整共享字节边界仍保留用于地图的调用去重。子来源缓存独立升级，下一次刷新修正旧关系和标题，未改变的主会话继续复用。

桌面使用窗口内的三栏工作区：列表、对话与画像独立滚动，查看模式、搜索和轮次导航保持可见。侧栏可收起及调宽；窄屏将列表与画像放入侧边抽屉，通过按钮、遮罩或 Escape 返回对话。

Web 每页返回 10 个完整轮次，不在同一轮次中间截断。轮次按来源中的首次出现顺序排列；初始上下文随第一页返回且不计轮次，无法归属轮次的记录保留“轮次未记录”标识。默认对话展开用户与终答或未确认结束的末条回复，完整模式默认折叠轮次与过程内容。轨迹模式使用独立事件账本，按轮次展开紧凑节点，可逐组或全部折叠；正文只在选中的局部检查器中展示。消息定位自动载入所在页并展开对应记录；手动展开其他内容不会重新拉回定位消息。


### 执行轨迹账本

参考 DSH 的事件账本、工具请求／响应关联、局部检查器和可见行渲染。账本保留原始事件序号、轮次、类型／模型、输入／参数、输出／结果、时间／已记录耗时及可关联的用量。只有同会话、同轮次中唯一且顺序正确的调用身份才合并工具请求与响应；重复身份、名称冲突、缺失身份或未配对结果保留独立记录。合并节点同时显示两侧摘要，检查器可切换输入与结果，定位结果时直接选择对应结果正文。原始记录总数与合并后的节点数分别显示。

轮次的记录数与单行摘要便于折叠浏览；思考、压缩及初始上下文保留独立事件。选择节点后，正文、来源记录行、调用身份、关联文件与用量在有高度限制的检查器中独立滚动。账本仅渲染可见行和缓冲区，不将长轮次的全部正文加载到 DOM；鼠标选择与上下方向键、Home／End 切换本页已展开节点，不重新查询消息页。原有搜索、请求图表、资源证据及地址定位会自动打开相应事件。

不同客户端的历史未必保存 DSH 的模型步骤、请求头、系统提示词快照、完整工具目录、重试或首 Token 时间，因此不根据邻接消息补造这些结构。用量只按明确消息身份关联画像返回的全部明细，不按轮次分摊或把缺失值当零。完整模式继续用于按来源顺序阅读所有消息，轨迹侧重执行概览和局部检查。

用户和 AI 正文渲染 Markdown，原始 HTML 不执行，图片显示替代文字，不自动读取外部图片。长正文先显示预览，用户可以展开全部内容。代码块与工具等过程保留等宽格式；记录身份、关联文件放在可展开的详情中。

全局命中显示在左栏，会话内命中显示在搜索区下方的浮层，避免挤走正文。更换关键词或筛选时不显示旧查询的命中。清除会话内搜索后恢复搜索前的模式、页码及阅读位置。消息定位、查看模式、分页与轮次跳转同步到地址；父子会话切换可以返回，浏览器后退也恢复地址对应的视图。

画像分为概览、调用和用量。用量趋势覆盖当前画像范围的全部已记录请求，请求表每页 12 条并支持到首末页，缺失值留空，真实零值保留；图表和请求编号可以定位对应事件。工具与资源名称可以定位首条证据，包含子会话时按明确关系搜索相应子记录。明细与汇总使用同一请求集合，不截取前 200 条。

长会话的曲线保留全部数据点，仅在请求数据变化时重新计算；图表使用共用交互层按横轴位置定位请求，不为每个请求创建交互节点。未打开用量页时不渲染曲线和明细表。

用量趋势的纵轴以零为起点，标注 Token 单位与等距刻度，三条曲线共用比例尺。悬浮或键盘聚焦显示当前请求的编号、模型、时间及输入／缓存读取／输出精确值；未记录字段不在浮层重复展示。参考线和数据点与数值同步，浮层限制在图表宽度内。键盘使用左右方向键切换请求、Home／End 到首末请求，Enter／空格定位记录。

## 会话画像

用量中的复制记录排除分别按明确消息身份与缺少消息身份时的轮次查询，使用已有消息索引；不把两种关联写在同一 `OR` 扫描中。该优化不改变 Token、留存内容估算、父子汇总或未知值口径。

- 模型概览展示已记录的名称和出现次数，不根据客户端名称猜模型。
- 请求用量与留存内容估算分开。估算基于本机保存的文本体量及公开方法，不能用于账单或断言实际请求上下文大小。
- Codex 的缓存读取属于输入子集；Claude Code 的普通输入、缓存读取及缓存写入归一化为总输入；CodeFlicker CLI 保存的输入为总输入，缓存属于其中的子项。
- 缓存读取占输入比例只使用同时有可确认输入和缓存字段的请求。API 保留记录范围和缺失字段；Web 只在输入与缓存覆盖完整且分母有效时显示比例。部分累计值直接标明具体记录数量，没有值的可选卡片、列和图例隐藏，真实零值保留。
- 输入／输出的累计用量与单次用量不能重复相加。重复发射和流式快照按请求／消息身份及累计进度处理，不能仅因两个请求数字相同就丢弃其中一个。
- 推理输出若包含在总输出中，单列说明，不再额外加到总输出。最大单次输入由请求输入记录计算；上下文峰值仅接受明确保存的上下文计数。旧 Codex event_msg.token_count 的 last_token_usage.total_tokens 表示当次活跃上下文，可作为兼容字段；累计 total_token_usage 和新 token_usage_record 的 total_tokens 不用于该兜底。
- Tool 计实际调用；成功、失败和未记录结果分别展示。耗时必须有记录依据。MCP 从实际工具身份解析服务器；Skill 明确调用与读取 `SKILL.md` 的证据分别展示，提及名字不计调用。
- 默认统计会话自身；包含子会话只遍历有明确关系的子记录。fork 与缺少原始身份的复制历史不根据正文相同而合并，不能承诺缺失日志下的全局去重。
- 请求步骤与统计共同包含所选画像范围的全部用量记录，并排除有明确复制依据的记录。步骤携带所属会话身份；点击子步骤进入子会话的实际记录。

Web 与 CLI 查询使用版本化 REST API，保持相同索引版本。来源行与工具 call ID 支持代码地图定位所属会话；会话项目尚未登记时，先登记再进入地图。

## 轨迹总览与注入上下文

轨迹上方的输入、模型、工具三行总览覆盖整段会话，可按事件顺序、轮次或已记录时间排列。总览通过 `/sessions/:id/timeline` 读取同一索引版本的定位元信息，不返回正文；工具请求和响应只按唯一调用身份合并。点击或用左右方向键选择节点，会跳到对应消息页并展开记录详情。用量记录依据消息身份放在模型轨道；没有时间的节点在时间排列中单独提示数量，不补造时间或耗时。

轮次导航使用实际用户轮次，初始上下文的 `position` 为 0，随完整／轨迹第一页返回，不计入 `totalTurns`。跳转会对齐并高亮轮次标题，清除上一节点详情。详情采用与事件表一致的排版，支持请求／结果、内容预览与原始正文切换，短内容少占高度，长内容在面板内滚动。

Codex 会把部分自动注入内容保存成 `role=user`。优先采用 `internal_chat_message_metadata_passthrough.content_item_kinds` 的明确分类：已知的指令、环境和页面注入识别为 `context`；含 `user.text`、未知类型或无效分类时仍保留为用户消息。旧日志未保存该分类时，仅从独立、完整闭合的已知包格式推断。普通提及、引用、未闭合内容或带真实请求后缀的混合消息不能靠关键词判定为注入。

上下文保留原文、源身份、`contextSource` 和 `contextEvidence`，不计用户提问，也不进入简易对话；详情分别说明“客户端元信息明确标记”或“按完整包格式推断”。过程搜索仍可检索上下文。规则版本变更会在下一次刷新中重新解析来源，原始历史保持只读。

## 桌面与 CLI 的身份边界

CodeFlicker CLI 保存执行入口、客户端版本与记录位置。已核查的 0.3.26 版本将 quiet 入口记录为 sdk-cli，界面显示 Quiet 模式标签，版本与原始依据放在悬停说明中。未核查版本不套用映射；恢复会话的多个入口保留，混合或未知入口不认定为纯 Quiet 会话，入口不用于推断父子关系。

会话列表默认排除已确认 Quiet 的会话，可切换常规会话、仅 Quiet 模式或全部会话。Web 类型筛选同时用于列表与全局搜索，计数与分页遵循筛选；直接链接与会话内搜索仍可访问 Quiet 历史。HTTP 与 CLI 支持 executionMode 为 regular、quiet、all；CLI 列表默认 regular，未指定类型的 API／CLI 搜索仍覆盖全部历史。筛选改变展示，不删除原始来源或索引记录。

CodeFlicker CLI 继续使用 `codeflicker`，CodeFlicker 桌面版使用 `codeflicker-desktop`。同名模型、底层引擎或相同会话字符串不会合并两个客户端。新版桌面的消息缓存为主来源；SQLite 只读取会话标题命名空间，模型只按原生消息 UUID 关联。简易、完整、轨迹、搜索、画像和地图联动共用规范化会话与稳定客户端身份。

桌面执行后端单独决定用量口径：`CLAUDE_CODE`、`DEEPSEEK_HARNESS` 的普通输入须加缓存读取和写入，`MY_FLICKER`、`CODEX` 采用已规范化输入；后端不明或分项缺失时不计算无法确认的总输入。输出和可确认的缓存分项仍保留，缓存比例只使用同口径完整分母。桌面的累计运行 duration 不当作单次工具耗时。

只有本机已保存的主消息日志进入有效索引，云端分页缓存不表示完整下载的会话。旧 IDE 的 SQLite 历史仍属于后续独立来源任务。

## 原生事件分支

新增 DeepSeek Harness、Pi、WorkBuddy、OpenCode、ZCode、CodeBuddy、Qoder 复用来源注册与规范化事件，代码地图和会话库共享原生身份、工具配对及证据定位。压缩事件流有界解码，SQLite 使用包含已提交 WAL 的只读事务快照，来源格式及元信息参与指纹。

Pi 等事件树来源保留叶分支成员和持久化当前分支。简易默认当前分支，完整／轨迹默认全部；阅读分支选择通过 `branch=current`、`branch=all` 或原生叶身份传入 API／CLI，不改变画像和代码活动的全部实际活动口径。共享祖先只存一次；真实历史不会因压缩摘要消失。搜索覆盖全部已索引分支，命中定位切换全部分支，未采用过程仍可回查。


## 吐字速度与计时区间

单次模型请求的速度使用来源输出 Token 除以对应区间的耗时。历史估算以 `≈` 标注；客户端原生计时保留记录依据，不代表服务端逐 Token 时钟。只计算输出不少于 200 Token、耗时不少于 1 秒且明确或可靠推断完整结束的请求；取消、部分响应及缺失边界保留原因，不补零。思考与回复可以共享同一次请求速度，独立推理用量不重复加入输出，工具执行时长独立展示。

Codex、Claude Code、CodeFlicker CLI、CodeFlicker 桌面原生镜像、Pi、WorkBuddy、OpenCode、CodeBuddy 和 Qoder 根据已校准的历史边界估算响应区间，ZCode 使用原生单请求计时。DeepSeek Harness 使用首个输出片段至流结束的客户端计时，界面直接标明“输出阶段”。响应区间包含首字等待，输出阶段排除首次输出前的等待；两类分别求平均。

来源已接入不表示每条历史都具备计算条件。CodeBuddy 只使用单次模型请求且没有工具调用的完整回合计时；桌面只通过 UUID 或唯一父子关系关联镜像，缺镜像、用量冲突和歧义时不计算；WorkBuddy、Qoder 缺输出用量或可靠结束证据时保留缺失。桌面累计 duration 与整轮复杂执行时长不能代替单请求耗时。

对话与全部记录的轮标题显示当前会话、轮次和查看分支内合格请求的合并速率，模型卡片显示明确所属请求的紧凑速度标记。执行轨迹在输出与时间之间显示速度列，选中请求的详情提供代入算式、起止记录与完成依据；右侧请求用量沿用当前会话／包含子会话范围，提供速度明细与平均值。平均值使用同一批合格请求的总输出除以总耗时，部分可计算时显示覆盖数量；没有合格记录时隐藏速度列并显示数据不足。

算法说明复用各区域的统一问号帮助入口；完整公式与范围说明按需打开。原始历史只读，旧索引缺少计时字段时保持未知，正常刷新后由来源解析规则回填。

## 会话级搜索与查找恢复

Web 全局搜索通过 `/sessions/search/groups` 以会话分页，返回会话总数、记录命中总数和每个会话至多三条代表命中；展开后用已有记录级 `/sessions/search?sessionId=…` 分页读取全部命中，并定位原记录。标题与消息各算一条命中，同一条消息内关键词重复不增加命中数。分组在全量候选上完成，不在前端合并一页消息。CLI 和既有记录级搜索契约不变。

关键词、客户端、项目、日期、过程范围、子会话和会话类型保存在会话地址。修改查找条件保留当前阅读；`/sessions/:id/matches` 按实际条件判断范围，不用当前列表页判断归属。条件移除入口在对应筛选旁，清除全部限制后显示所有类型与子会话。各会话的阅读位置保存于当前浏览器会话，旧消息和轮次地址继续有效。

问题目录通过轮次导航按钮按需打开，`/sessions/:id/turns` 仅读取当前查看分支的用户问题短片段和对应位置；顺序与轮次分页一致，跨页读取，不新增常驻面板。概览只提供失败调用、压缩记录与最大单次输入三个证据入口；失败与压缩列表从右侧对应统计项弹出，名称与记录时间分行，浮层有界并独立滚动，不改变阅读区位置。选择记录后关闭并定位原消息，Escape、关闭按钮和点击外部可关闭并按统一规则恢复焦点；读取错误在浮层内提供重试。复制的父记录不重复进入证据列表。失败次数表示调用结果，不等于任务失败。

## 界面减噪与对话复用

默认三栏开合与宽度保持原状。按用户反馈恢复左侧常驻搜索、过程与子会话选项、客户端、项目、日期及会话类型。中间对话、全部记录、执行轨迹和导出直接可见，窄屏换行。右侧恢复原有模型统计、请求用量、会话内容、子会话列表和用量明细结构；失败、压缩和最大单次输入定位融入对应统计项。右侧展开时箭头向右收起，收起后箭头向左展开，与其他右侧面板一致。

完成刷新的细节、来源与导入诊断按需展开，诊断按相同原因收敛；当前读取或刷新失败、过期状态、未确认结束和部分累计范围直接可见。原有统计分区恢复时仍保留可选缺失字段隐藏与不完整缓存占比隐藏，不把缺失当作零。

回复、代码块和本轮问答可复制完整已保存内容。代码复制从原始 Markdown 代码块取值，屏幕预览截断不截断复制正文。当前分支 Markdown 导出包含全部轮次的用户问题、终答或标明未确认结束的末条回复；不包含思考、工具、压缩或子会话。全部分支查看时导出来源的当前分支，具体分支查看时导出所选分支。读取使用固定索引版本和分支，取齐并校验页数与消息身份后才保存文件；失败不下载半份文件。

仅 CodeFlicker CLI 的原生 hidden 或 isMeta 用户注入标记可直接归类为客户端上下文，不新增用户问题与轮次；原始内容保留在完整记录和检索中。此规则与旧 Codex 当次上下文兼容字段分别纳入对应客户端缓存指纹，正常刷新纠正旧缓存，不要求清空索引或修改其他客户端来源。
