# 会话首次导入性能对照

日期：2026-10-16。原实现已在实施前冻结，所有测试使用固定来源与新的隔离空数据库。

## 测量范围

- 固定 74 个来源文件，约 122 MiB；覆盖 Codex、Claude Code、CodeFlicker CLI、Pi 四类来源。
- 每种方案三轮，顺序交错，未主动清空操作系统文件缓存。测量期间不同时运行其他基准或测试任务。
- 时间从创建隔离索引开始，包含发现、解析、前缀校验、用量事实、全文索引、辅助索引及完整版本发布。
- 首次可查询与完整就绪为同一边界。该时间不含整个应用启动、浏览器渲染或其他页面派生缓存首次计算。
- 下表为三轮中位数；内存为各轮导入阶段峰值 RSS 的中位数，包含本进程解析 Worker。主库与 WAL 每 25 毫秒采样，同步写入可能延迟采样，因此磁盘列为采样峰值。

| 方案 | 完整就绪 | 相对原实现耗时降低 | 峰值 RSS | 主库与 WAL 采样峰值 | CPU 总耗时 |
|---|---:|---:|---:|---:|---:|
| 原实现 | 22.06 秒 | 0.0% | 431 MiB | 120 MiB | 20.99 秒 |
| 优化后串行 | 20.55 秒 | 6.9% | 445 MiB | 118 MiB | 19.44 秒 |
| 优化后两个解析 Worker | 17.73 秒 | 19.6% | 675 MiB | 120 MiB | 20.63 秒 |
| 优化后四个解析 Worker | 16.98 秒 | 23.1% | 847 MiB | 120 MiB | 21.57 秒 |

默认两个解析 Worker：与四个相比少约 172 MiB 峰值 RSS，中位耗时相差约 0.76 秒；少于八个来源直接解析。SQLite 仍只有一个导入写入者。

## 等价检查

12 轮均得到 74 个会话修订、22,672 条消息、3,726 条用量记录。按来源与稳定消息身份排序比较完整正文、消息元信息、用量、会话元数据、指纹及六组搜索结果，摘要完全相同。两类 FTS 的完成状态与文档数量均核对通过。

六组查询为中文单字、双字及英文样本，包括“锁”“的”“事务”“你好”“transaction”“commit”。摘要覆盖 API 返回的分组、命中和精确计数；不以相同总数代替结果内容检查。

JSONL 流读取次数由 247 次降为 183 次，记录的流读取字节由 381.36 MiB 降为 267.61 MiB，减少约 29.8%。这包含受监测来源流的重复检查与解析，不表示物理磁盘实际读取量，也不包含其他 SQLite、目录或旁路元信息 I/O。

## 采用的改动

1. 首次主解析读取同时计算字节哈希，保留结束时固定前缀校验。
2. 有界解析线程预计算字符词项，批次确认后继续；数据库保留单写入者与触发器。
3. 首次导入较大批次提交，辅助查询索引统一后建，首次发布仍等待完整就绪。
4. 保存已校验来源检查点，中断后核验复用；未完成来源清理，成功发布和来源缺失时回收。

批次按条数或估算字节触发提交，单条大消息可超过批次目标，仍沿用解析器单条来源记录上限。

## 结论边界

代表样本的默认路径耗时降低约 19.6%，同时增加约 244 MiB 峰值 RSS。四线程耗时降低约 23.1%，内存更高。该结果不直接外推为整份真实历史的重建时长，也不表示所有客户端、文件分布与机器均有相同比例的收益。已有完整索引的普通启动与全量重建分别看待。

真实路径、来源清单、原实现与逐轮 JSON/日志仅保存在本机忽略目录。
