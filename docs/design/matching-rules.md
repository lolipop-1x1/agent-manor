# 当前内容对应与覆盖规则

规则版本：`matching-v1`。实现见 `src/analysis/matching.ts`、`coverage.ts`、`ranges.ts`，人工可核对样本见 `tests/analysis-matching.test.ts` 与 `tests/analysis-coverage.test.ts`。

## 对应位置

`matchEvent(event, file)` 只接收调用方已经可靠归属的一个当前基线文件；不根据相同内容跨 clone、改名或跨文件找候选。成功读取只使用 `read` 片段；成功编辑使用 `added` 和 `deleted` 片段。失败、未知结果、搜索或没有实际源码片段的事件不产生覆盖。`completeLines: false` 的片段保留未知，不直接计入整行。

精确要求完整行内容一致并且当前位置唯一。CRLF、LF、CR 是物理行分隔符，不属于行内容；不 trim 空白。末尾换行不形成额外行，实际空白行仍是源码行。内容版本继续核对原始字节，不能把新代码套用旧范围。

历史起始行仅帮助判断上下文先后，不能将它直接当作当前行号。算法先查找完整精确块；多个候选即使某一个靠近历史行号也保留 `ambiguous`。短片段必须有唯一上下文，或它就是当前整个文件；有效独立精确片段至少有 16 个非首尾空白码点。

无法完整精确对应时，使用当前文件中实际存在的历史首尾内容锚点，以及上下文片段的唯一位置限制局部候选。候选内做逐行 diff，保留未变化行的精确对应；新插入行没有历史对应，不计读取。重复行数量变化时不任意选一个重复位置覆盖，而保留这些行未知。

`context` 片段只用于定位，永不计入编辑范围。删除片段只有当前仍存在的唯一精确内容可对应，例如编辑撤销后恢复原行；删除行不存在时不以相似邻行补足范围。编辑活动次数与最终 Git 改动无关。一个事件可保留部分精确／近似范围，并同时带有未能对应的原因。

## 近似门槛与校准

Unicode 字符指码点，而非 UTF-16 code unit。局部变化量 `D = 插入码点 + 删除码点`，替换一个字符计 2。相似度 `S = 1 - D / (N历史 + N当前)`；空片段不能仅凭比例获得覆盖。jsdiff 用行数组和码点数组比较；全文件平均相似度不参与接受判定。

| 局部行 | 同时满足的默认门槛 |
| --- | --- |
| 两侧较短长度 < 24 码点 | `D <= 2`、`S >= 0.75`，且有已唯一定位的外部上下文，或局部块有两条不同的未变内容锚点 |
| 两侧较短长度 24–255 码点 | `D <= 8`、`S >= 0.94`，且有上述上下文；无外部上下文时，最长不变连续内容至少 16 码点且在当前文件唯一出现 |
| 两侧较短长度 >= 256 码点 | `D <= 16`、`S >= 0.94`，位置条件同上 |

变化组内只接受双向唯一的一行对应。历史一行改为两行时，若只有其中一行满足局部门槛，可对应该行；新插入行仍不覆盖。两个新行都可解释同一历史行时保留未知。内容变化永远归近似，不因通过门槛而改称精确。

门槛通过以下合成样本校准；这些是规则验收样本，不声称代表所有真实项目。

| 样本 | 人工预期与实际结果 |
| --- | --- |
| 历史 `const existingValue = true;` 前新增一行 | 移动后的原行精确；历史行号 100 不参与选择 |
| 3 行块中插入新行 | 原 3 行精确；插入行无覆盖 |
| 两条唯一锚点间 `const value = 1;` 改为 `2` | 变化行近似；两个未变锚点精确 |
| 唯一长行 `const previouslyRecordedValue = 1;` 改为 `2` | 不变字符上下文唯一，变化行近似 |
| `x=1;` 改为 `x=2;`，两侧有唯一上下文 | `D=2`、`S=0.75`，短行近似；上下文不算编辑 |
| 无上下文的短行／重复长片段 | 未知；不按历史行号选位置 |
| `😀` 改为 `😎` | 字符差异量为 2，不是 4 |
| 唯一长上下文间完全替换一行 | 变化行未知，不让周围未改行稀释局部差异 |
| 重复 `}` 新增一行 | 不把任意一个重复行算成历史读取 |
| 删除行消失／编辑后撤销 | 前者当前范围未知；后者恢复行精确且编辑活动保留 |

## 计算预算

精确候选扫描最多 20,000 个起点、1,000,000 次行比较、64 个候选。近似片段最多 3,000 行、200,000 码点；完整精确块不受近似片段长度限制。候选长度与历史长度的差最多 32 行；外部上下文与目标距离最多 64 行。局部字符比较每行最多 4096 码点。

jsdiff 行 diff 最大编辑长度为 256；字符 diff 最大编辑长度为 64。这些是计算预算，与接受门槛 2／8／16 不同。预算返回 `budget_exceeded`，不假装匹配成功；大幅重构、内容或上下文不足返回 `range_unknown`，多候选返回 `ambiguous`。同一个基线文件的行索引在内存中复用，避免为每个历史事件重复建立索引。

`mappingCacheKey(event, file)` 包含规则版本、文件路径与内容哈希、事件身份／类型／状态／路径／cwd 和全部片段；变化使已有对应结果失效。来源引用追加、客户端／时间查询筛选不改变对应关系本身，统计仍按事件和筛选重建。

## 筛选与统计

`buildCoverage(snapshot, filters)` 保持输入结果版本与基线哈希，先应用客户端、时间、目录、类别筛选，再并集对应范围。默认类别为 source；时间窗口有边界时，事件发生时间缺失或非法不进入窗口。时间起止包含边界，API 层负责拒绝非法筛选值。

行范围是一基闭区间，返回实际当前行号。每种活动的精确范围先取并集，近似范围并集再减去该活动的精确并集，分别计算分子；读取与编辑相互独立。分母是筛选后当前纳入文件数与物理行数。

summary 中 `readExact.files`／`editExact.files` 是有非空精确范围的文件数，即精确读取／修改文件覆盖率分子；成功活动但范围未知的文件仍有 `readCount`／`editCount`，不能声称它没有活动。空文件分母为一份文件、零行，不凭缺失内容创造精确行。

次数按事件 ID 去重，每文件一次，不按片段、范围或来源引用增加。`activityCount` 记录选中事件总数；`readCount`／`editCount` 记录成功活动，即使范围未知或后来撤销仍保留；`searchCount` 记录搜索请求；`failedCount` 记录失败；`unknownCount` 包含结果未知，以及成功读取／编辑存在未知范围。后几列可能重叠，不相加当总活动次数。

热点按 `activityCount`、`readCount` 或 `editCount` 排序。未观察到读取使用 `readCount === 0`；仅有近似或未知范围的成功读取文件不会被称为未观察到读取。来源采集缺口和局部对应缺口继续返回，统计零值不替代采集覆盖说明。

当前边界：不推断跨文件移动／改名，不用历史请求范围补全截断输出，不对无唯一位置的片段强行排序选择，也不让纯删除映射当前邻行。真实客户端历史的跨层验收由发布验收任务完成。

## 代表性大文件记录

2026-10-03，macOS、Node 24.19.0、tsx 测试加载器，一次合成样本：15,000 行、682,780 字节；单进程首次和重复匹配测量如下。数值不构成固定性能承诺，不代表个人真实历史规模。

| 输入 | 耗时 | 对应结果 |
| --- | --- | --- |
| 全文件未变化 | 6.750 ms | 15,000 行精确 |
| 中间 129 行片段，单字符修改 | 4.457 ms | 128 行精确，1 行近似 |
| 修改后对应旧的整份大文件 | 4.467 ms | 近似片段预算超限，保留未知 |
| 同一文件连续 1000 个独立读取事件 | 5.493 ms | 1000 次精确对应，复用行索引 |

测试进程峰值 RSS 为 117,632 KiB，包含 Node、tsx、依赖与样本数据。超预算的整份大文件不会退化为将全文件旧范围套在当前内容上；较小的局部历史片段仍能进行对应。
