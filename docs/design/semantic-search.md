# 会话语义搜索

语义搜索是默认关闭的可选能力。关键词搜索保留原有实时查询；语义搜索需要用户在会话库的“搜索设置”中配置 OpenAI 兼容 Embedding 服务，选择范围，预览规模后显式开始构建。保存连接不会编码历史，首次选定范围完整构建后才可查询。

## 设置与操作

会话库的关键词和语义搜索复用同一套搜索范围：客户端及项目多选、会话关系、执行模式、日期、已记录模型、标题、消息数／轮次数区间和当前／全部分支。两种模式切换时保留共同范围；默认排除已确认子 Agent 和 Quiet，会话关系／执行模式缺失可单独筛选。未选择客户端、项目或模型表示全部，选项来自完整已发布会话库，不随当前搜索结果或分页收缩。

关键词独有“搜索过程记录”，语义独有相关性排序及索引覆盖说明。分支条件约束消息或语义片段；标题属于整个会话，不因当前分支筛选而消失。维护范围与本次搜索范围继续独立。

模型、项目等子菜单在父筛选浮层上方显示，通过 Portal 避免滚动裁剪；父浮层标题和关闭入口固定，条件区域独立滚动。Escape 逐层关闭并恢复焦点。关键词加载反馈位于输入框的图标槽，语义反馈位于搜索按钮内部；更新保留上一份完整结果，暂停旧结果下钻，失败可见。

关键词接口新增 `scope` JSON 参数，完整范围优先于旧单值筛选；不传 `scope` 的旧 API 和 CLI 调用保持原有默认行为。`/api/v1/sessions/facets` 只读取会话元数据，提供共同筛选候选，不依赖模型连接或向量构建。

同一个对话框提供模型连接、范围与构建、调用策略三个页签。服务地址支持服务根地址、`/v1` 基址或完整 `/embeddings` 接口地址。连接测试发送固定合成文本，验证向量数量、实际维度、有限数值及非零向量；它不证明检索质量。首版不安装或启动推理服务。

模型连接只显示服务地址、Embedding 模型及可选 API Key，不提供高级连接设置或手动编码前缀。实际向量维度在测试成功结果中展示。新连接根据明确支持的模型名称自动选择正文与查询格式，测试使用对应查询格式；构建、查询和 token 估算继续使用最终输入。

| 模型名称 | 正文格式 | 查询格式 |
| --- | --- | --- |
| Qwen3 Embedding 0.6B／4B／8B，含官方名称和常见本地服务名称 | 原文 | 检索历史会话的英文任务指令 |
| multilingual-e5-small／base／large | `passage: ` | `query: ` |
| BGE small／base／large 的 en／zh v1.5 | 原文 | 对应英文／中文检索指令 |
| nomic-embed-text、nomic-embed-text-v1.5 | `search_document: ` | `search_query: ` |
| 其他名称 | 原文 | 原文 |

适配依据为模型官方说明：[Qwen3 Embedding](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B#usage)、[多语言 E5](https://huggingface.co/intfloat/multilingual-e5-large#usage)、[BGE](https://huggingface.co/BAAI/bge-small-en-v1.5#usage-for-embedding-model)、[Nomic Embed Text](https://huggingface.co/nomic-ai/nomic-embed-text-v1.5#task-instruction-prefixes)。不根据名称片段推测自定义别名、微调模型或其他变体的规则；未知模型直接使用通用输入格式。

自动适配结果保存为连接中的编码规则快照，读取配置、升级或仅修改 Key／调用策略时不重新推导，旧版保存的空前缀及自定义规则也继续沿用。新增连接或更换服务地址／模型时选择当前规则；改变最终编码输入仍按不兼容变化处理，已有索引不能自动切换到新规则。

Key 可选，独立保存在数据目录的 `semantic/credentials.json`，目录权限 0700、文件权限 0600，内容为明文。页面默认遮罩，按用户操作读取完整值并支持复制、替换与清除；普通设置响应只返回是否已设置，Key 不进入浏览器持久存储。连接和调用策略保存于独立配置文件，清除语义索引保留连接与凭据。

维护范围支持全历史或最近 N 个本地日期、多个项目与客户端、会话关系、Quiet 模式、已记录模型、标题、日期、消息数、轮次数及当前／全部分支。同组多选取并集，不同条件取交集。默认排除已确认子 Agent 与 Quiet；未知属性保留。首次时间范围必须主动选择。时间条件按会话区间相交判断，选中后处理该会话的合格正文，不按消息时间截断。

查询筛选独立于维护范围。移出维护范围的有效向量默认保留，继续可搜索；“清理时间窗口外的索引”默认关闭。开启时在发布新计划时撤销窗口外位置，仅删除没有其他有效位置引用的编码结果，原始会话不受影响。

“暂停后台构建”停止发出新的正文编码请求，已发出的请求收尾并保存；主动语义查询照常，但仍受预算约束。“关闭语义搜索”同时停用查询和构建，保留索引；“清除语义索引”单独确认后移除派生数据。关闭网页不终止本地服务中的任务；停止服务后任务恢复为暂停，用户可继续。新历史的发现沿用既有历史同步机制，语义维护本身不新增来源扫描。

## 正文、复用与发布

正文读取已发布的本地会话索引，原始历史只读。默认纳入用户与助手对话正文，排除思考、工具输入输出及已识别的上下文注入。按可靠轮次、分支组织用户问题与助手回复，未知轮次单条处理，不跨会话或分支拼接。

默认每块最多 1200 个 Unicode 字符，重叠最多 120 字符，优先寻找附近换行。角色分隔和指令前缀属于实际输入，保留原始空白和代码缩进。字符限制不等于模型 token 上限；可靠的输入过长响应触发当前失败输入缩块，不能缩到有效块时明确失败。

完整模型输入、编码用途与编码空间指纹共同生成 SHA-256 复用键。指纹覆盖标准化服务地址、模型、实际维度、文档／查询前缀和切块规则。相同输入只编码一次，不同会话、消息和分支保留各自原文位置。修改 Key、并发、限流或超时不改变编码空间；模型或编码规则变化停用不兼容索引，用户预览后重建。

`semantic/vectors.sqlite` 独立保存 float32 向量、位置映射与持久化构建计划，使用 SQLite WAL。正文扫描／编码计划与向量排序分别运行在 Worker，模型请求使用异步 HTTP。增量构建保留上次完整发布结果；新计划完整完成后原子发布，不逐批暴露半成品。来源变更先核验已有位置，编辑、删除或分支不可达的旧正文不继续返回；未变位置可继续使用。

历史版本在计划期间改变时拒绝发布旧计划，用户重新预览后复用已完整保存的编码。失败与中断保留检查点；不能保证远端请求恰好执行一次，异常请求保守计入估算消费。

## 查询与排序

语义查询由 Enter 或搜索按钮提交，输入和模式切换不调用模型。后台先取查询向量缓存，未命中时编码查询文本；然后在本地对满足本次筛选的有效位置对应向量计算余弦距离，按会话最佳片段排序。

当前采用 `sqlite-vec` 精确余弦计算，没有近似最近邻索引。先筛选有效来源，再计算对应唯一向量的距离。每次取相关性最高的最多 200 个候选会话，切换最近更新只重排这批候选；每组返回最多 3 个原文片段。界面不将相似度作为正确率，也不将候选数称为全部语义命中总数。

查询向量缓存最多 256 项、有效期 30 分钟，仅位于服务内存，键包含完整查询输入与编码空间；相同在途查询合并。最后一个等待者取消才中止共享查询请求。结果快照最多 16 项，绑定历史版本、编码空间、筛选与排序，发布后失效。筛选、排序和分页只允许复用查询编码；缓存过期时提示重新提交，不因改变筛选偷偷发起模型请求。

Web 的语义搜索和 CLI 的 `sessions search --mode semantic` 共用本地后台、配置、索引、预算和查询缓存。服务端同时保留分组结果与 CLI 扁平命中接口；结果跳转遵循当前已发布历史版本和原始消息位置。

## 调度、费用与规模

默认并发 1、每批最多 8 个输入、估算 token 上限 8192、请求超时 60 秒、暂时性失败最多重试 2 次。查询优先于等待中的构建，不抢占已经发出的请求。每分钟请求数／token 限制、批次、超时、重试、单价和每日预算均可在界面修改。

默认静默 5 分钟后维护变化，持续变化最多延后 30 分钟；手动“立即更新”跳过等待。每日预算采用本机自然日，所有构建、查询、连接测试及重试请求在发出前预留估算消费，已知实际用量结算，未核实请求保守保留估算。预算仅覆盖本功能，不保证服务商账单封顶；未设置单价时费用保持未知。

预览区分来源位置、唯一输入、已有编码复用和待编码 token；实际用量按请求保存，不伪造逐块实测 token。索引存储除了向量还包含正文、位置映射、索引、日志及计划临时数据。原始向量载荷约为唯一向量数 × 维度 × 4 字节，不能用它代表数据库总大小或内存峰值。

真实历史与本地模型的性能验收见 [语义搜索验证记录](../validation/semantic-search.md)。当前数据只覆盖受限样本，不能外推全库吞吐、十万向量查询延迟或检索准确率。
