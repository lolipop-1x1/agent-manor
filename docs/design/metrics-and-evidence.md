# 指标与证据口径

整理日期：2026-10-03。状态：分析与管理能力的设计约束。代码活动地图首版已实现，结果与支持边界见[验收记录](../validation/acceptance.md)；其余管理能力仍属于设计范围。

术语见 [CONTEXT.md](../../CONTEXT.md)。本文件定义统计如何解释，不冻结数据表、字段名或工具实现。

## 一项统计应带什么

统计结果应说明客户端和解析版本、项目与配置作用范围、观测窗口、支持的事件类型、来源是否缺失，以及证据位置。

推荐保留的概念信息包括来源定位、会话关系、事件时间、工具名、结果状态、资源归属和归属依据。真实参数或结果正文可含源码与秘密；是否保存正文、保留多久和如何导出仍需明确。

## 工具与 Skill/MCP

| 指标 | 口径 | 解释边界 |
| --- | --- | --- |
| 调用次数 | 去重后的工具请求数 | 一次 Shell 工具请求可运行多个命令；不能自动拆成相同精度的工具调用 |
| 成功／失败／未知结果 | 依据可配对的结果分别统计 | 没有结果的调用归未知，不能默认为成功 |
| 使用会话数 | 观测窗口内有该使用证据的不同会话数 | 与调用次数不同；子会话是否合并须声明 |
| 最近使用时间 | 有效使用事件的发生时间 | 只能取得文件 mtime 时，标为来源更新时间 |
| MCP 工具使用 | 按工具名及对应服务器聚合 | 服务器用过一个工具不代表其全部工具都使用过 |
| Skill 显式调用 | 客户端明确的 Skill 请求或对应命令 | 尝试调用与调用成功分别呈现 |
| Skill 正文读取 | 明确读取结果，或命令中可识别的 SKILL.md 路径 | 参数路径推断需要标记；出现路径不证明读取成功 |
| Skill 提及 | 消息中出现名称或文字标记 | 作为弱证据单列，不与显式调用混算 |

同名 Skill 的全局与项目版本、符号链接和插件资源应先明确身份与来源再合并。别名也应有归一化依据。

会话使用率的候选公式是“使用会话数 ÷ 所选且能观察该项的有效会话数”。分母需要说明客户端、项目和配置在当时是否可用；只有总会话数时，结果是有限估计。

低频可以按次数、使用会话数、使用率或距上次使用的时间定义，但界面必须写明规则。采集覆盖不足时展示未知或待检查，不将其归为零使用。

## 文件读取与修改

| 观察 | 能支持的结论 | 不能自动支持的结论 |
| --- | --- | --- |
| 显式 Read 请求 | 对所述路径发起读取 | 成功读取、读取整个文件、模型理解内容 |
| 可配对的成功读取结果 | 工具报告读取成功；存在的内容和范围可单列 | 系统所有实际读取都已采集 |
| Grep 或目录搜索 | 在某路径范围发生搜索，或返回了部分文件命中 | 目录中所有文件都被读取 |
| Shell 参数中的路径 | 可能涉及该资源的命令证据 | 任意脚本内部的完整文件访问清单 |
| Edit／Write／补丁请求 | 修改尝试及可取得的执行结果 | 最终 Git 改动量、业务正确性 |
| 会话文本匹配当前源码 | 当前版本有内容可对应 | 历史版本相同、发生真实读取或外发 |

代码热力图按选定的读取请求、成功读取、修改或错误指标分别绘制；时间热力图按日期或小时绘制。避免将两个图的“热度”视作同一指标。

“未观察到读取”需要项目文件清单、明确时间窗和支持范围作为基线。项目版本、依赖／生成目录排除、符号链接、历史缺失和间接访问都会改变分母。

高读取频次可能来自核心入口、多个任务、正常复核、修改后重读或上下文恢复。关联任务和事件后可以提出原因假设，次数本身不裁决代码质量或死代码。

### 仓库代码活动地图的已确认口径

本节记录 2026-10-03 需求讨论中已确认的口径，完整规格与验收标准见 [首版规格](../../.scratch/repository-activity-map/spec.md)。具体算法和格式支持由实施方案确定。

- 分别展示文件覆盖率与行覆盖率；重复活动增加次数，不重复增加已覆盖文件或行。
- 主要读取覆盖率统计成功返回且能确定范围的内容。搜索命中、失败请求和结果缺失分别呈现，不默认覆盖整个文件。
- 默认采用分析时的当前工作区作为仓库基线，包含未提交修改。内容变化后，刷新时重新计算历史范围与当前内容的对应关系。
- 主要百分比统计精确覆盖，近似对应单独展示，不混入精确覆盖。汇总近似范围时排除已经精确覆盖的部分；不能确定的行范围保留未知。
- 支持对单字符修改等小改动建立近似对应，前提是有足够的历史内容和可确定的位置。多个合理候选不能只凭相似度强行选择；定位与局部差异比较的算法路线已确认，实现细节和门槛仍需校准。
- 修改覆盖率描述历史编辑活动，不等于最终 Git 改动。撤销修改不抹去历史活动；行覆盖只统计能对应当前代码的范围，尝试及结果状态继续保留。
- 源码作为默认统计范围，配置与项目文档可切换查看，按所选类别分别计算分母。地图保留整体目录结构，依赖、生成产物和二进制默认排除；具体分类与排除规则尚待实现方案确定。

后续技术讨论已确认：使用文件路径、可取得的历史行号和实际返回内容定位候选，再结合唯一上下文与局部差异比较建立对应。历史行号不直接作为当前行号，请求范围不替代实际返回范围。近似采用局部相似度、绝对增删字符量与唯一上下文的组合门槛，默认数值由样本校准；内容存在差异时继续归近似，不放宽精确覆盖口径。

当前基线盘点已确认包含当前存在的已跟踪文件和未被忽略的未跟踪文件，再应用类别与排除规则；已删除路径不计入当前分母。行数按文本物理行计算，包含注释、空白行；空文件为 0，末尾换行不额外增加一行。worktree 分别建立内容基线，子模块独立处理，符号链接默认不跟随盘点内容。具体分类清单和格式支持矩阵仍需用样本核对。

## 去重与事件关联

- 同一来源未变文件再次导入，应保持相同统计；追加、截断和替换需要分别处理。
- 工具请求与结果按客户端可用的关联标识配对；无法配对时保留未知。
- 重复呈现的 event_msg、消息或结果不应额外增加调用次数。
- 分叉复制的历史与真实的新调用分开处理；保留父子关系，避免汇总时重复计算。
- 相同文件内容不是可靠的全局事件身份；源码匹配范围并集也不是调用去重方法。

技术讨论已确认事件身份与来源记录分开：关联标识可能重用，需要结合客户端、会话、原始消息身份与调用出现位置；分叉复制只有能确认共同来源时才合并。追加从完整记录边界续读，截断、替换和解析版本变化重建受影响来源，当前文件变化重算相关对应关系。整轮刷新按 [ADR 0004](../adr/0004-publish-complete-analysis-versions.md) 发布完整结果版本。

原始来源已缺失时，新版本从有效统计中排除该来源，保留采集缺口、统计变化原因和上一版对照。临时读取错误按刷新失败处理，保留上一版且标过期；不把读取失败直接当作历史已经消失。源文件移动后可靠关联到同一历史时，不重复增加活动。

上述规则需要用已知输入构造少量样本验收，不能只通过导入没有报错来确认。

## 上下文与成本

| 来源 | 标注方式 | 可归因范围 |
| --- | --- | --- |
| 服务商报告的 Token 和缓存计数 | 实测用量，注明来源和粒度 | 通常是消息或请求；未必能归因到单个 Skill/MCP |
| 字符、字节或 tokenizer 计算 | 估算，注明算法和模型 | 内容体积，不证明内容实际进入每次请求 |
| 配置库存或工具 schema | 声明规模／估算开销 | 实际加载受客户端的懒加载、选择和缓存行为影响 |
| 用量乘模型价格 | 估算费用，注明价格日期和缺失量 | 不等于供应商最终账单 |

Skill 描述与完整正文可能在不同阶段加载；不能用删除整个目录的字节数宣称减少等量常驻上下文。MCP 工具声明与工具结果也应分别观察。

配置调整前后比较应尽量控制任务、模型、客户端和窗口，列出样本差异。只比较两组不同调用的平均估算 Token，不能单独证明调整造成节省。

## 管理建议与执行证据

建议应带候选对象、理由、观测窗口、保护条件、影响范围和来源证据。频率规则首先生成候选，再根据项目差异、新安装宽限、样本不足、手动保留和依赖关系决定是否适合调整。

停用、隔离、移除注册、卸载与永久删除是不同操作。管理实现需要给出实际修改位置、变更预览、备份或恢复记录、执行结果，以及客户端是否应用的检查结果。

写入配置成功不等于客户端接受配置；恢复文件成功也不等于客户端重新发现资源。期间发生的用户修改需要显式处理，不能直接覆盖。

本地优先意味着用户历史默认留在本地。可选模型提炼、共享、遥测或远端同步若被纳入范围，应说明传出的数据；“本地存储”不自动等于所有分析完全离线。

当前代码活动地图首版只在本机保存分析索引和所需历史源码片段，保留原会话定位，原始历史只读；支持清除缓存后重建。首版分析在本机完成，不依赖上传历史或调用模型，后台生命周期见 [ADR 0002](../adr/0002-local-analysis-service.md)。

## 资源总览指标

Skill／MCP 总览保留调用次数与使用会话数，默认按调用次数展示。Skill 的产品调用次数合计显式调用和成功正文读取，失败或无法确认的读取不计入；MCP 调用次数按工具请求计数，包括失败请求，配对结果不重复计数。使用会话数按同名资源的会话并集计算，多次使用只计一个会话。

详情保留原始证据类型和次数。API 的 `calls`、`reads`、`sessions` 保持原有口径，新增 `uses` 指标及排序用于上述合并调用次数；未记录或观测不足继续显示未知，不补成零。
