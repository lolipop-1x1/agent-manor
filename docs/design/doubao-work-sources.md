# 豆包工作本机来源与支持范围

客户端 ID 为 `doubao-work`，历史格式为 `doubao-work-indexeddb`，与普通豆包客户端及其使用的模型分别识别。核查日期为 2026-10-16：初次缓存调查时安装版本为 2.25.17；验收期间检测到安装版本已变为 2.32.12，后者仍可读取此前的缓存。兼容依据是已核验的存储结构，不是对所有版本的承诺。

## 来源与读取

默认发现操作系统 home 下 `Library/Application Support/DoubaoWork/Default/IndexedDB` 中启动页与聊天页的原生 LevelDB `CURRENT` 文件。`AGENT_MANOR_DOUBAO_WORK_DIR` 或显式 roots 可覆盖发现目录；显式空数组关闭该客户端。

原生来源是 IndexedDB／LevelDB 与同级外置 blob，不是 JSONL。读取器使用 Node.js 直接校验 MANIFEST 活动表、当前及前一活动 WAL、序号、删除标记与 CRC32C，解开 Snappy、IndexedDB／Blink 包装及已核验的 V8 对象。只反序列化账号分区下的 `conversations` store，不打开数据库、不创建锁或迁移文件，也不要求 Python。

来源读取有文件数、目录深度、总字节、单值、解压与对象结构预算。成员或读取前后元信息变化、缺失 blob、损坏或未知格式均失败，保留上一完整索引；不能把读取错误发布为空会话集。读取不访问登录凭证，不调用云端历史接口，也不主动启动或操作豆包工作。

## 会话与原始证据

缓存值是会话聚合响应，使用账号分区与原生会话身份定位。启动页和聊天页可能保存不同投影；同一会话只选择一个来源，优先消息较多的投影，不拼接不一致快照。两个有正文的投影冲突时保留歧义诊断，消息多不代表历史完整。

消息按原生 `index_in_conv` 排序，数字身份保留为字符串。真实用户消息与已核验的回复引用建立轮次；缺少或无效引用的回复保留正文和未关联状态，不归入最近用户轮次。会话内共享的 `section_id` 不作为轮次身份。项目采用原生明确工作目录，不把产品项目 ID、授权目录或目录名当作 Git 根。

| 能力 | 当前支持与边界 |
| --- | --- |
| 会话列表、正文、搜索、对话导出 | 覆盖已发现缓存；仅摘要会话仍可列出，未缓存正文不能补齐 |
| 过程阅读 | 文字、过程父链、文件卡片、附件与未知内容块；未知结构可回查原始记录 |
| 分支、子会话、压缩、取消及重生成 | 缺少已核验原生关系或状态时保留未知，不凭相同正文或接近时间建立关系 |
| 模型请求、Token、费用与速度 | 当前缓存字段不足以形成已确认请求；上下文占用、显示计量及首包字段不转换为逐请求用量、估算费用或首 Token |
| 工具与代码地图 | 文件卡片保留路径和内容；缺少工具身份、成功状态及范围时不构造工具调用或精确代码覆盖 |
| 总览 | 有可靠时间的用户与回复活动进入既有统计；请求、压缩和资源指标遵循各自采集覆盖 |
| Skill／MCP 历史使用 | 技能选择、卡片出现或当前安装不证明执行；当前来源未提供可靠调用或成功读取证据时保留覆盖缺口 |

缓存消息状态尚不足以确认原生终答；对话导出沿用未确认结束的末条回复规则。原始证据位置为所选会话按原生顺序排列的消息序号，每个引用保留该消息与会话元信息的哈希；回读重新选择真实容器记录并校验。来源变化或消失时返回证据不可用，不生成永久原生历史副本。

内容指纹以所选会话完整内容为准，无关会话变化或 LevelDB 压缩不会单独强制重解析；读取一致性仍检查实际物理依赖。未声明不完整的快速依赖集合，快速刷新会安全回退到内容校验。

## 本地资源与管理

| 入口 | 盘点与管理 |
| --- | --- |
| profile 下 `.doubaowork/agent_mode/workspace/.skills`、`.user_skills` | 按顶层入口盘点，托管保护；原生安装、watcher、上传和删除同步可能产生远端副作用，不开放文件回收或停用 |
| 用户与已知项目 `.agents/skills` | 按顶层入口盘点；普通文件／链接入口可预览回收与恢复，沿用共享本体、收藏、保护及冲突规则 |
| MCP | 未确认可靠的本地自动注册入口；helper、连接器和其他客户端导入模块不能替代 MCP 注册证据 |

本地资源的原生启停偏好、附加兼容根和最终加载选择未核验，盘点状态保持未知；不创建豆包配置或自动重启客户端。嵌套 `SKILL.md` 说明文档不重复计独立资源。托管根在读取正文前检查真实路径边界，普通共享入口保留合法符号链接。

## 缓存生命周期

真实合成任务已在客户端完成读写、成功与失败命令，也能在任务页回看；但完成、重开任务、重载页面及正常退出重开应用后，已解析的聚合缓存仍未包含该任务。因此本机可发现范围可能落后于客户端界面；不会把缓存读取成功描述为完整或实时同步。

本轮没有确认固定 TTL、定期清理或容量回收规则。缓存中未发现任务，不证明远端任务被删除。有效来源确认消失时沿用可重建索引的生命周期，从新版有效结果移除；临时失败保留上一完整结果，不新增长期归档或云端补全。

验收方法与结果见 [豆包工作接入验收](../validation/doubao-work.md)。
