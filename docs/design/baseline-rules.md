# 当前仓库基线规则

规则版本：`baseline-v1`。实现见 `src/analysis/baseline.ts`，样本见 `tests/analysis-baseline.test.ts`。

## 身份与文件清单

`getRepository(path)` 用 Git 取得 worktree 根目录和 common dir，再分别取 realpath。仓库 ID 为 `[根目录, commonDir]` 的 SHA-256 前 24 位。关联历史时只能以同一个本机 common dir 确认 worktree 关系；相同 remote 的独立 clone 不自动合并。各 worktree 的路径、身份和当前内容基线独立。

`scanRepository(path)` 盘点 `git ls-files --cached` 和 `git ls-files --others --exclude-standard` 的并集，再读当前存在的普通文件。已跟踪但当前删除的路径记录 `deleted_from_worktree`，不计入分母。未提交修改、未被忽略的未跟踪文件进入基线；未跟踪且被 Git ignore 的路径不进入清单。Git 已跟踪文件不因后来加入 ignore 而消失。

子模块的 Git 索引模式 `160000` 记录为 `submodule_independent_repository`，不遍历其内容；单独登记子模块才能建立基线。符号链接与父目录为符号链接的路径记录 `symlink_not_followed`，不读取其目标。活动原始证据可以保留这些路径，覆盖分母只使用纳入的当前普通文本文件。

其他 I/O 错误向调用方抛出，使整轮刷新失败。`ENOENT` 表示盘点时当前路径已不存在。Git HEAD 可在尚无首次提交的仓库缺失；分支可在 detached HEAD 缺失。`dirty` 来自 Git 当前状态，包含未跟踪变化。读取 Git 命令设置 `GIT_OPTIONAL_LOCKS=0`，避免状态查询顺带刷新用户索引。

## 行数与版本

物理行分隔符明确为 CRLF、LF 或 CR。注释行与空白行均计入；空文件为 0；末尾分隔符不额外产生一行。例如 `a\n\n` 为 2 行，`\n` 为 1 行。

文本按严格 UTF-8 解码并保留 BOM；含 NUL 或无法解码的文件记为 `binary_or_non_utf8`。文件 `content` 保存原文本，`hash` 是原始字节 SHA-256，所以行尾、BOM、空白和末尾换行变化都会改变内容版本。基线哈希包含规则版本、worktree 身份、按路径排序的纳入文件路径／类别／行数／内容哈希，不用 mtime 或大小代替内容核对。

对应算法使用上述行分隔符拆分后的行内容比较；行分隔符本身不属于行内容。CRLF 与 LF 可对应同一文本行，但字节版本仍不同；不 trim 行内、行首或行末空白。详见 [匹配规则](matching-rules.md)。

## 分类与排除

默认统计类别为 `source`；`config`、`docs`、`unknown` 均保留可选择的文件清单，查询按选中类别重算分母。未知扩展名不会被静默算成源码。

| 类别 | 规则 |
| --- | --- |
| source | TypeScript／JavaScript、Java／Kotlin、Python、Go、Rust、C／C++、C#、Swift、Ruby、PHP、Vue、Svelte、HTML／CSS、Shell、SQL、Protobuf、R、Lua、Perl、Elixir、Erlang、Clojure、Scala、Dart、Fortran 的实现中列明扩展名 |
| config | JSON／JSONC／JSON5、YAML、TOML、INI、CFG／CONF、properties、XML、env、Gradle／CMake；Dockerfile、Makefile、Procfile、常见 Git／编辑器／npm 配置文件名 |
| docs | Markdown、文本、reStructuredText、AsciiDoc、TeX；README、LICENSE、NOTICE、CHANGELOG、AUTHORS 文件名 |
| unknown | 以上未覆盖的 UTF-8 普通文本 |

目录任意层级的 `.git`、`node_modules`、`vendor`、`dist`、`build`、`coverage`、`target`、`out`、`.next`、`.nuxt`、`.svelte-kit`、`.turbo`、`.cache`、`__pycache__`、`.venv`、`venv` 排除为 `dependency_or_generated_directory`。这是一组明确默认规则；名称相同的自有源码目录也会被排除，当前没有猜测式分类或用户覆写配置。

依赖锁文件（npm、Yarn、pnpm、Cargo、Poetry、uv、Pipenv）、`.DS_Store`，以及 `.min.js`／`.min.css`、`.map`、`.tsbuildinfo`、`.pyc`、`.class` 文件排除为 `generated_file`。前 2048 字符中的注释行以 `@generated`、`Code generated ... DO NOT EDIT` 或 `<auto-generated>` 开头时，排除为 `generated_header`；普通文本中的这些词不会触发规则。

## 已核对样本与边界

Node 24.19.0、macOS 的临时 Git 仓库样本已核对：未提交内容／未跟踪／忽略／删除、二进制／非法 UTF-8／未知类别、普通和父目录符号链接、submodule 单独盘点，以及 worktree 和独立 clone 身份。内容相同重扫哈希不变，字节内容变化后哈希改变。

本规则不把 Git HEAD 当作工作区内容版本，不推断改名／跨文件移动，不跟随链接，也不读取其他仓库的工作区。Windows 和 Linux 尚未完成安装与文件系统实际验收。
