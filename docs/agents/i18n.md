# 国际化开发

产品显示语言使用 `src/i18n/` 的共享目录，Web、CLI 与服务端消息标识使用同一组文案。注释、开发文档和原始数据保持原文。

## 添加文案

按用途在 `locales/en/`、`locales/zh-CN/` 的 `common`、`codeMap`、`sessions`、`resources`、`diagnostics` 或 `cli` 文件中添加稳定标识。英文是运行时回退；未知标识显示“翻译不可用”的本地化文案，不向用户泄露标识。

动态内容使用参数，不拼接翻译片段。数量使用 `count` 和语言复数规则：英文补齐 `_one`／`_other`，简中使用 `_other`。数字插值可用 `{{count, number}}`；日期、百分比、图表刻度通过统一格式函数呈现。日期筛选仍使用本机时区的 `YYYY-MM-DD`，不改变 ISO 查询边界。

React 组件调用 `useI18n()` 订阅语言更新；模块级配置保存文案标识，在渲染时求值，不缓存已翻译的字符串。非 React 的展示函数可使用 `web/i18n.tsx` 的动态帮助函数。不要为语言变化重建组件、编辑器或地图，也不要将语言加入与查询无关的请求依赖。

服务端保持原始 `message`／`reason`／`error` 字段，同时在生成点附带 `MessageDescriptor { key, params }`。经缓存、Worker、组合原因及错误转换后保留描述。客户端渲染时翻译，无法识别的旧诊断或外部错误保留原文并标明“原始详情”；不按中文句子匹配或替换。CLI JSON 不执行翻译。

## 新增语言

1. 在 `src/i18n/types.ts` 声明语言，补齐六个本地目录，并接入 `catalogs.ts` 与 `index.ts` 的启用语言配置。
2. 在 `registry.ts` 注册名称标识、格式语言、日历配置及一周起始日，更新语言校验与自动检测规则。
3. 接入 `web/DatePicker.tsx` 对应的日历 locale；更新偏好和 CLI 校验文案及测试。菜单从注册表读取，完成验收后才启用新语言。
4. 运行 `npm run check:i18n`。检查目录对应、非空文案、参数一致性、语言要求的复数类别及源码字面量标识；动态标识另由针对性测试验证，运行时回退不能代替完整性验收。
5. 运行类型检查、自动测试、构建和真实浏览器验收，覆盖原文保留、共享偏好、日期边界、可访问名称、状态与地图视野。管理写操作只用隔离合成资源。

共享手动偏好独立保存在每个数据目录的 `preferences.json`，不放入可重建索引。CLI 单次覆盖不写回；一次命令执行期间语言固定。开发自动化明确设置语言，避免依赖测试机器的系统或浏览器默认值。

完整合成验收入口为 `node scripts/e2e-i18n.mjs`（先执行 `npm run build`），使用独立数据目录和真实 Chrome，覆盖三个模块、Web／CLI 共享与状态保留；产物写入忽略的 `.local/i18n-e2e/`。已有端到端脚本显式指定显示语言，不修改个人偏好。
