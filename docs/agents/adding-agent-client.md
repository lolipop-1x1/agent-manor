# 新增 Agent 客户端接入指南

本文用于新增一种 Agent 客户端，或扩展已有客户端的历史格式、资源来源和管理能力。这里的接入指 AgentManor 读取、分析及管理客户端的本地数据；模型供应商和模型名称本身不是新的客户端。

每次接入都要核对会话、代码活动、用量、资源使用、配置盘点和可恢复管理。各项能力可以分批交付，但必须分别记录已支持、部分支持、未记录、待适配及其依据，不能用“能导入会话”概括全部支持。

开始前阅读 [PRODUCT.md](../../PRODUCT.md)、[CONTEXT.md](../../CONTEXT.md) 和本次涉及的 ADR；界面变更同时读取 [DESIGN.md](../../DESIGN.md)。本指南给出工作顺序，具体统计定义继续以链接的设计文档为准。

## 1. 先固定证据与交付范围

在 `.scratch/<feature>/` 按[任务约定](issue-tracker.md)记录规格和任务，至少回答：

| 核对项 | 必须记录的内容 |
| --- | --- |
| 客户端身份 | 正式名称、稳定客户端 ID；CLI、桌面版、兼容引擎是否属于同一客户端 |
| 证据版本 | 已核验客户端版本、schema、核对日期；上游源码固定提交或官方格式说明；闭源客户端记录可靠导出或本地样本依据 |
| 历史来源 | 默认根、原生 home／profile／state 覆盖规则、文件或数据库结构、旁路元信息、归档及迁移副本 |
| 会话语义 | 原生会话和事件身份、项目、标题、时间、分支、分叉、明确委派、压缩、取消和终态字段 |
| 统计能力 | 请求身份、用量粒度、缓存和推理桶、计时边界、Skill／MCP 身份及工具成功依据 |
| 当前资源 | Skill／MCP 的加载根、配置格式、优先级、作用范围、信任与插件／系统来源 |
| 管理能力 | 原生控制字段及实际作用范围，哪些入口可停用、回收、恢复，哪些保持只读 |

先构造最小合成样例：一个真实用户输入、一次模型响应、一个成功工具请求和结果；再按原生能力补齐失败、分支、子会话、用量与资源样例。真实历史和私有定位材料只留在 `.local/` 或仓库外，公开内容遵循[公开内容约定](public-content.md)。

核验格式不需要安装或启动客户端。需要真实客户端运行验证时，单独明确操作范围；不要通过运行客户端、迁移命令或可能启动进程的探测命令改变来源。

**完成条件：** 每项承诺都有字段或原始记录依据，缺失能力明确列出；“源码核验”“合成测试”“真实来源读取”“客户端实际加载／生效”分别记录。

## 2. 注册身份与发现入口

先核对以下入口，再增加客户端专属实现：

| 入口 | 接入职责 |
| --- | --- |
| [`src/clients.ts`](../../src/clients.ts) | 客户端 ID、名称、排序、地图缩写及共享枚举 |
| [`src/history/adapters/index.ts`](../../src/history/adapters/index.ts) | `HISTORY_CLIENTS` 的来源声明与 `HISTORY_ADAPTERS` 的格式实现注册 |
| [`src/history/adapters/types.ts`](../../src/history/adapters/types.ts) | `HistoryClient`、`HistoryAdapter` 及可选钩子的契约 |
| [`src/history/types.ts`](../../src/history/types.ts) | `SourceLocation`、原生选择器和关系证据 |

客户端身份与历史格式分开：同一客户端可以读取多代格式，不按模型、文件后缀或内部引擎改写客户端身份。会话身份带客户端命名空间；消息、工具调用、模型请求和来源副本分别确定身份，同一个 call ID 在新事件中重用不等于重复活动。

在来源声明中限定候选文件，排除请求镜像、搜索投影、缓存和非主转录；有多个原生副本时用 `selectSources` 表达选择规则，并保留依据。多会话容器用实际文件路径加 `selector` 区分来源和缓存，复用 `sourceLocationKey`，不制造临时 JSONL 作为另一份来源。

目录优先级沿用显式 roots、`AGENT_MANOR_<CLIENT>_DIR`、已核验原生覆盖规则和默认根；显式空数组应关闭该客户端。原生 home 变量可能指用户 home、状态根或会话根，须逐项核验，不能统一追加相同后缀。发现遵循现有普通文件、符号链接和读取预算边界。

**完成条件：** 隔离样例能被发现，空 roots 不读取默认目录；重复副本不增加会话数，同一容器内不同会话不互相覆盖，客户端和格式身份贯穿后续链路。

## 3. 实现原生读取、消息与代码证据

新增适配器放在 `src/history/adapters/`。优先复用 [`normalized.ts`](../../src/history/adapters/normalized.ts) 的 `createNormalizedAdapter`、`normalizedRecord` 和 `normalizedSnapshot`：原生快照转换为共享事件，让代码地图与会话库使用同一套来源、工具状态及资源证据。保持格式规则在适配边界内，避免向共享 parser 添加新的客户端分支。

- JSONL 复用有界读取，保留坏行、未完成尾行和超预算缺口。JSON、压缩流及多文件来源分别限定读取规模，未知 schema 和事件保留诊断或过程记录。
- SQLite 复用 [`sqlite-readonly.ts`](../../src/history/adapters/sqlite-readonly.ts) 的只读事务与预算，包含已提交 WAL；不迁移数据库，不把原生库改造成产品索引。
- 标题、cwd、模型和关系取自身份一致的记录或旁路元信息。路径规范化复用现有实现；缺少可靠 cwd 时保留未知，不用进程 cwd、目录 slug 或相似路径猜项目。
- 原始消息映射为 `user`、`assistant`、`thinking`、`tool_call`、`tool_result`、`system`、`context` 或 `compression`。真实用户需求与工具结果、注入、自动继续、取消控制及压缩摘要分别分类。
- 保留当前分支与其他已保存分支；父子委派、分叉和继承复制分别核验。一般 parent 字段和相同正文不足以证明子 Agent 或复制边界；缺父来源仍保留子会话自身活动。
- 工具请求与结果按原生身份配对，重复投影去重；并发同 ID、缺失结果、错误、取消和截断保留明确状态。最终回答依原生终态确认；需要推断时保留推断性质，中断或待完成工具不能补成正常结束。

代码范围提取复用 [`extraction.ts`](../../src/history/extraction.ts) 和已核验的工具规则。成功返回的路径、正文、行号或补丁共同决定片段；请求参数只能证明尝试，当前文件不能补齐历史返回。读取、搜索、修改、删除与补丁上下文分开，修改快照不自动等于净差异。未知工具仍可在轨迹中查看，不能凭名称相似直接套用另一客户端的成功模板。

原始引用保留实际路径、格式、选择器、位置和原文哈希，接入 `readHistoryEvidence`。物理 JSONL 行、解压后行和容器内虚拟记录序号须按格式说明；回读重新定位并校验哈希。来源消失或记录改变时返回证据不可用，不拼造旧正文。

**完成条件：** 同一合成来源同时通过 `parseSource` 和 `parseSessionSource` 验证；成功工具的实际片段与原始记录一致，失败和未知不产生精确覆盖，证据可回读且来源改写后失效。

按需查阅：[历史支持矩阵](../design/history-support.md)、[会话统计与阅读](../design/session-history.md)、[指标与证据口径](../design/metrics-and-evidence.md)、[匹配规则](../design/matching-rules.md)。

## 4. 核对用量、计时与资源使用

以 [`SessionUsage`／`SessionRequestTiming`](../../src/session-contracts.ts) 为契约，在适配器内解释原生字段：

- 请求身份独立于回复片段和工具调用；用 `requestKey` 关联同次模型响应，`usageKey` 去重用量。没有用量的已记录请求可以保留，只有消息数量时不能宣称完整 API 请求数，也不能补出未留存重试。
- 核对输入是否包含缓存、缓存读写是否互斥、推理是否为输出子集；缺失值保持未知。上下文估算、逐请求用量与轮次／会话累计报告分开，累计值放入 `usageReports`，不再加进逐请求统计。
- 保留原生模型、provider、思考设置和原生费用的依据。provider 不从客户端名称推断；原生费用、AgentManor 估算费用与实际账单分开。沿用统一价格目录，避免在适配器中添加单独的模型价格或别名规则。
- 明确时间单位、时区、发生／保存时间、请求开始、首 Token 和响应结束。`timing` 区分原生与估算、完整响应与输出阶段；工具执行时间不充当模型耗时，响应时长或 tok/s 不当作 TTFT。新增 `method` 时同步契约、中英文动态文案及显示测试。

Skill／MCP 使用沿用 [`src/sessions/resources.ts`](../../src/sessions/resources.ts)；原生命名不符合通用规则时，在适配器提供已核验的资源身份。显式 Skill 调用、成功正文读取／原生展开与 MCP 请求分别保留，配对结果只补状态而不重复计数。配置存在、普通文本提及、写入或列举 Skill 都不能补造使用；哈希化名称无法还原时保留缺口。

**完成条件：** 样例在会话画像、用量统计、总览和资源使用中保持相同请求与事件身份；重复投影、继承复制、缺字段和累计报告不造成重复累计，未知指标不会显示成已测得的零。

具体口径见[用量与估算费用](../design/usage-statistics.md)和[Skill／MCP 历史解析](../design/resource-history-parsing.md)。

## 5. 接入刷新、指纹与旧索引复用

复用 [`src/history/index.ts`](../../src/history/index.ts)、[`src/sessions/refresh.ts`](../../src/sessions/refresh.ts) 和既有后台生命周期，不为单个客户端增加另一条导入／发布通道。

- 内容指纹覆盖主转录、旁路元信息、来源选择、分支、复制关系及影响统计的报告。记录位置改变也要使旧证据定位失效。多会话容器优先按所选原生会话计算内容指纹，避免无关会话修改导致全库重解析。
- 只有完整依赖已核验时才声明 `quickCheck.dependencies` 和版本；主文件、SQLite WAL、标题／项目／模型等旁路及可选依赖的新增删除都要覆盖。无法证明完整性时沿用内容检查回退。
- 核对冷导入、无变化、追加、截断、替换、解析期间改写、单个容器会话删除、旁路变化与读取失败。确认缺失才从新版排除；临时 I/O 失败保留上一完整结果。
- 单客户端刷新保留范围外数据和成功检查状态；全局同步纳入新客户端。检查完成与完整结果发布时间分别保留，继续原子发布，失败或重启后的断点复用不能暴露半成品。
- 影响已有来源语义时，检查地图的 `PARSER_RULE_VERSION`、会话指纹／规则版本及相关派生缓存失效；用旧索引验证升级。统一轮次规则变化同时遵循 [ADR 0014](../adr/0014-unified-round-rule-upgrade.md)，不依赖用户清空全部数据修复。

测量冷刷新、无变化检查及大来源的耗时和峰值内存；发现、旁路读取与完整校验也计入。当前规范化快照不走普通 JSONL 解析池，不能仅凭已有 Worker 或并发参数宣称新格式已并行解析。优化仍须维持读取预算、检查点及单写入发布约束。

**完成条件：** 无变化结果可复用，真实变化被检出；失败保留旧版、重试可完成，局部刷新与旧索引升级有回归覆盖，性能结论对应实际来源和测量范围。

相关决策：[完整发布](../adr/0004-publish-complete-analysis-versions.md)、[可重建会话索引](../adr/0005-rebuildable-global-session-index.md)、[按客户端刷新](../adr/0006-scoped-session-refresh-verification.md)、[增量复用与生命周期](../adr/0010-incremental-refresh-and-space-reclamation.md)。

## 6. 独立接入当前资源盘点与可恢复管理

历史中发现 Skill／MCP，不代表已找到当前加载入口。先依据原生 loader 和配置构造盘点，再逐项开放已核验的管理动作。

盘点接入 [`src/resources/inventory.ts`](../../src/resources/inventory.ts) 的实际 planner 调用及相应 `native-*.ts`，按现有契约返回来源、实际入口、本体、作用范围、选择／覆盖、原生设置与缺口。检查 [`coverage.ts`](../../src/resources/coverage.ts) 对新增诊断的相关性分类，将资源证据缺口与正文、用量等无关缺口分开。明确用户、项目、祖先、兼容、插件、系统和托管来源及信任条件，不遍历任意目录猜配置。

同名、同内容不合并管理身份；共享本体按实际路径核验，符号链接保留入口与原始链接文本。MCP 对外只投影名称、transport、设置状态及配置定位，命令、URL、环境变量、headers、凭证和整份配置正文不进入公开快照或日志。

管理复用 [`management.ts`](../../src/resources/management.ts)、[`config-editor.ts`](../../src/resources/config-editor.ts) 和恢复材料机制。原生停用、仅用户触发、回收入口与移除注册分别判断；控制作用范围独立于资源文件位置。不存在已核验逐项开关时，可只交付盘点，或仅开放有证据支持的回收／恢复。

开放写能力必须同时具备具体预览、执行前重新核验、恢复材料、执行后回读及冲突处理。插件／系统／托管、路径越界、损坏配置、复杂未核验语法或控制范围不明时保持只读。恢复只撤销目标变更并保留后续无关编辑；写入成功与客户端实际加载／生效分别记录。

**完成条件：** 合成资源能完成声明范围内的盘点、预览、执行和恢复；保护、共享引用、符号链接及外部修改冲突均被验证，历史统计不受当前安装或配置变化改写。

详细规则见[资源来源支持矩阵](../design/resource-support.md)；完整接入实例见[原生客户端来源与证据](../design/native-client-sources.md)。

## 7. 贯通产品入口并更新支持说明

注册后沿以下入口逐一检查。共享注册表已派生的枚举继续复用，只修补确有缺口的位置。

- **CLI／API：**核对 [`src/cli.ts`](../../src/cli.ts) 和 [`src/service/`](../../src/service/) 的客户端过滤、刷新范围、资源手动来源及参数校验；覆盖会话、地图、用量、总览和资源查询。稳定 ID 与 JSON 字段不随语言变化。
- **Web：**各页筛选、标签、图标、状态帮助、详情及跨页跳转。复用统一筛选和主题组件；切换客户端、语言、主题或刷新后保留已有完整结果、阅读位置及筛选语义。
- **国际化：**新增标签、产品诊断、计时方法及可访问名称按[国际化约定](i18n.md)补齐中英文；原始标题、正文、模型、工具和配置保持原文。
- **支持说明：**按实际能力更新 [README](../../README.md)、[使用指南](../usage.md)、[历史支持矩阵](../design/history-support.md)、[资源支持矩阵](../design/resource-support.md)、[资源历史解析](../design/resource-history-parsing.md)和随包 [Agent Skill](../../skills/agent-manor/SKILL.md)。需要版本、来源和控制规则细节时记录在来源设计文档，不把未完成能力写成已支持。
- **验收与打包：**新增或更新 `docs/validation/` 中的记录并链接到[验收索引](../validation/README.md)；新增运行依赖或随包必读文档时核对 `package.json` 的依赖、`files` 及包检查。

以下规则独立于客户端注册表，尤其需要核对：

| 位置 | 容易遗漏的规则 |
| --- | --- |
| [`src/overview/weekly-review-facts.ts`](../../src/overview/weekly-review-facts.ts) | `compressionClients` 单独声明周报压缩统计能力；识别压缩消息后仍须核对支持与完整性判断 |
| [`web/features/resources/Resources.tsx`](../../web/features/resources/Resources.tsx) 与 `src/resources/inventory.ts` | MCP 手动来源的前后端默认 `keyPath`；原生状态字段的解释不能只沿用其他客户端特判 |
| `src/resources/management.ts` | `nativeDisable`、`writable` 等能力判断与具体控制定位；注册客户端不会自动开放写入 |
| [`SessionSpeed.tsx`](../../web/features/sessions/SessionSpeed.tsx)、[`UsageSpeedTrend.tsx`](../../web/features/usage/UsageSpeedTrend.tsx) 及相关测试 | `sessions.speed.method.*` 是动态翻译键，新增方法还要检查测试中的显式方法列表 |

**完成条件：** 新客户端从正常入口可选择、可查询、可下钻，未支持项如实展示；文档、帮助、客户端能力声明与实际行为一致。

## 8. 按能力完成分层验收

测试使用 [`isolatedHistoryRoots`／`isolatedHistoryEnvironment`](../../tests/helpers/history-roots.ts)，默认关闭其他所有客户端，显式传入合成来源；资源测试使用独立 home、项目和管理目录，不改进程 `HOME` 或个人配置。

| 层次 | 必须取得的证据 |
| --- | --- |
| 适配器 | 发现、身份、消息／轮次、工具状态、原始回读；失败、缺失、歧义、截断、超预算和未知格式的反例 |
| 语义与统计 | 分支／子会话／复制、请求与累计值、缓存桶、时间边界、Skill／MCP；来源缺少的能力验证其缺失展示 |
| 刷新与存储 | 冷导入、无变化复用、旁路变化、追加／替换／删除、SQLite WAL、失败重试、局部范围和旧索引升级 |
| CLI／API | 同版列表、搜索、阅读、画像、用量、地图、资源及证据结果交叉核对，不只检查 HTTP 成功 |
| 浏览器 | 中英文客户端筛选、三种阅读模式、搜索命中、画像／轨迹、跨页证据、主题和窄屏；新增筛选遵循 `AGENTS.md` 的键盘与焦点验收 |
