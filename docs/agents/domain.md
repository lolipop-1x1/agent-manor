# Domain Docs

本仓库采用 single-context 领域文档布局。

## 探索代码前的读取规则

- 阅读根目录 `CONTEXT.md`。
- 阅读 `docs/adr/` 中与当前工作相关的架构决策。
- 如果存在 `CONTEXT-MAP.md`，按其中索引阅读相关上下文文档。

文件不存在时静默继续，不提醒缺失，也不提前建议创建。
由 `domain-modeling` 在领域术语或决策明确后按需创建。

## 文件布局

- `CONTEXT.md`：领域概念和术语。
- `docs/adr/`：编号的架构决策记录。

这些路径是约定；本次配置不创建空的领域文档或 ADR。

## 使用领域术语

需求标题、方案、假设和测试名称应使用 `CONTEXT.md` 定义的术语，
避免使用其中明确排除的同义词。

需要的概念尚未收录时，先判断是否引入了项目不用的术语；
确有缺口时，记录为 `domain-modeling` 的待处理项。

## 明确指出决策冲突

输出与已有 ADR 冲突时，明确指出相关 ADR 和重新讨论的理由，
不要静默覆盖已有决策。
