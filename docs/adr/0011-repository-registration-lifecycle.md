# 仓库登记与全局会话库保持独立生命周期

本决定记录用户已确认的需求与取消语义，具体实现和验收状态见关联规格。

用户已确认：代码地图删除已登记仓库时，同时删除该仓库的分析结果版本、来源与映射缓存、任务记录、手动来源关联及分块正文。全局会话库、资源数据、本地 Git 目录和原始历史文件保留。会话库继续纳入未登记仓库的历史，与 [ADR 0005](0005-rebuildable-global-session-index.md) 的来源生命周期一致。

登记弹窗提供会话库项目选项，同时保留手动输入及修改绝对路径。会话项目只是历史归属线索，不保证当前存在或属于 Git 仓库，不能直接视为已核验的登记对象。选择项目填入路径后，仍由用户触发“登记并分析”。

用户选择展示全局项目候选并在提交时校验，不预先批量筛选有效 Git 仓库。子目录解析到所属仓库根目录，不同 worktree 独立登记；重复提交已有仓库时切换到已有登记，不重复发起分析。项目名称与完整路径都可搜索，“无项目”不作为登记候选。

这一边界意味着删除仓库不等于删除会话项目：保留的会话项目仍可能出现在项目候选与资源项目范围中。重新登记可从现有源码及历史重建分析，但被清理的任务记录和手动来源关联不自动恢复。

用户选择分析中立即删除，取消目标仓库的旧任务并阻止旧结果回写，其他仓库和全局会话任务继续运行。最小方案利用每次新建的任务 ID：删除清理旧任务行，完整发布事务在任何写入前核对任务仍存在、归属正确且仍在运行。同路径重登虽然可能复用仓库身份，新任务 ID 与旧任务不同，因此旧任务不能影响新登记。取消与回报按任务 ID 处理，缺行作为取消终态处理，不能阻断共享 Worker 队列。

立即删除无需等待整轮分析结束；不可打断的同步阶段只能在检查点退出，事务内有效性检查负责保证旧结果无法发布。删除后允许立即重登，取消结果不在已清理的任务表中永久留存。用户已确认这一取消边界。

删除入口位于仓库下拉菜单底部，针对当前仓库。确认弹窗展示名称、完整路径及清理与保留范围，点击一次删除按钮即可确认。删除后切换到第一个剩余仓库，全部删除后回到登记空状态。

代码地图完整版本发布继续遵循 [ADR 0004](0004-publish-complete-analysis-versions.md)，物理空间回收继续遵循 [ADR 0010](0010-incremental-refresh-and-space-reclamation.md)，删除数据库记录不承诺即时缩小数据库文件。

需求树见[仓库生命周期规格](../../.scratch/repository-lifecycle/spec.md)，实现与运行证据见[验收记录](../validation/repository-lifecycle.md)。管理验收使用隔离合成数据，本 ADR 不授权删除运行环境中的真实仓库数据。
