# 刷新完成后发布完整的分析结果版本

历史导入和当前代码对应关系可以增量计算，但每轮刷新完成后才发布一个完整的分析结果版本，Web 和 CLI 的统计、下钻及证据查询绑定该版本。相比每解析一个来源或文件就立即让查询看到结果，这会增加发布状态管理，却能避免分母、覆盖范围和证据来自不同阶段；刷新失败保留上一版并标记过期。

内容版本、解析规则变化和来源替换会使对应派生结果失效；索引保留来源记录与事件身份的区别，避免把重复导入当成新活动，也不因源码相同合并真实重复调用。具体表结构、保留旧版数量和 API 字段继续在 [技术讨论](../../.scratch/repository-activity-map/map.md) 中细化。
