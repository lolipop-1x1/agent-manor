# 分离历史同步、地图分析与索引命令

会话历史同步和代码地图分析各自使用一个按需启动的长期 Worker。地图仍在自己的队列内串行分析多个仓库；历史仍按覆盖范围、检查强度和清理意图复用任务。两类任务不互相排队，Worker 崩溃只结算本类在途任务，下一次明确刷新只重建对应 Worker。

历史自动同步只等待历史队列，不等待地图分析。保留 [ADR 0017](0017-backend-history-sync-scheduling.md) 的完成时间基准、必要补查、失败退避与只读状态观察；异步登记期间不重复提交，登记失败也进入退避。

HTTP 主线程不再直接写入运行中的 `index.sqlite`。独立索引命令 Worker 负责仓库登记、删除、来源关联、任务登记及异常结算。短命令串行提交，解析与分析交给各自 Worker。HTTP 通过异步命令等待提交结果，查询继续读取完整发布的版本。数据库初始化仍在服务监听之前完成。

登记和关联成功后才派发分析，任务写入成功后才向调用者返回 ID。删除事务成功后才取消旧任务，事务失败不取消；发布仍在事务中复核仓库及任务身份。保留 [ADR 0004](0004-publish-complete-analysis-versions.md) 的完整版本发布及 [ADR 0011](0011-repository-registration-lifecycle.md) 的删除边界。

SQLite 仍是单写者。后台可写连接通过共享写权限交接，写语句及提交事务串行，解析和只读快照继续并行，避免服务内部长事务让其他写者耗尽 SQLite 锁超时。管理线程异步等候写权限，仍可处理任务线程退出并回收其权限；任务线程退出后才释放对应权限。空闲回收遇写者直接跳过。

本次将写权限及数据库锁等待移出 HTTP 主线程，不改变 SQLite 锁超时、事务原子性或已发布数据语义。外部连接占锁时短命令仍可能等待或失败，但不能因此阻断状态请求。此决定不包含其他数据库、模型调用队列或大型读取聚合的进一步拆分。

验证覆盖可控慢任务、双向 Worker 故障及重试、自动同步异步登记、跨进程持锁下的 HTTP 并发读取、错误后继续写入、仓库删除与重登，以及停止和重启。详细结果见[验收记录](../validation/backend-task-isolation.md)。
