# 分开表达服务就绪与启动数据准备

本地后台完成必要的数据库兼容、一致性检查并开放 HTTP 后，报告服务就绪，供状态与诊断使用。面向用户的 `start`、`web` 在首次初始化时继续等待历史、搜索索引、用量与默认总览全部首屏缓存完成；`web` 随后打开浏览器。终端持续显示阶段、实际处理数量与耗时，不用来源数量比例推算准确剩余时间。

空库开始初始化时先原子保存准备中标记，全部就绪后改为完成。首次历史已发布但缓存尚未完成时，中断或失败后的下一次启动仍等待。已有可查询历史的旧目录，即使没有新标记，也直接快速返回，后台增量更新期间继续提供已发布结果。这个兼容边界避免把旧数据升级误判为从零初始化，取代只检查完成标记的判断。显式 `--wait-data` 或 `ready` 可以等待当前启动检查。首次默认不限数据等待时间，显式 `--timeout` 可缩短等待，超时或中断终端不停止后台。

默认总览准备包括概况、用量、资源、工具、项目摘要、筛选项、项目分布和最近7天复盘，不枚举所有筛选组合。没有登记仓库时跳过地图；已有登记时等待对应分析。模型任务只按已启用策略和预算执行，进程启动本身不额外安排全量生成或编码。JSON 模式不输出人类进度，保留稳定结果与错误。

发现阶段按客户端记录扫描目录和候选来源数，发现结束后汇总最终选中的来源。导入阶段显示实际已解析、复用数量、解析并发及当前来源。目录进度合并保存、终端按阶段和定时心跳刷新，不逐文件刷屏，也不为进度额外读取正文。

仓库准备在精简状态中给出本轮完成数、总数和当前任务的名称、阶段描述及阶段进度。终端显示这些实际状态，任务切换及时更新；百分比表示该仓库任务的阶段进度，不推算准确剩余时间，也不把整份任务列表或完整路径塞入状态响应。

本决定细化 [ADR 0002](0002-local-analysis-service.md) 的按需启动，保留 [ADR 0017](0017-backend-history-sync-scheduling.md) 的后台同步及完整版本发布边界。
