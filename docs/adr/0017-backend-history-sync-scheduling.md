# 将历史自动同步的调度责任移到本地后台

用户希望关闭全部网页后仍继续自动同步，并让多个网页观察同一后台任务。已决定由每个数据目录对应的本地服务持有历史自动同步策略并统一调度，网页通过只读状态轮询观察任务，保留策略配置和手动同步；读取状态不触发来源检查，也不将网页数量作为同步次数。首版复用现有状态查询路径，不增加 SSE 或 WebSocket 订阅生命周期。

这项已接受的设计调整 [ADR 0010](0010-incremental-refresh-and-space-reclamation.md) 中历史同步由可见网页周期触发、所有页面隐藏时停止新增自动检查的约定。迁移后接受无人打开网页时的来源检查开销，以及已开启语义维护按既有策略消费新历史的模型调用。本轮只迁移全局历史自动同步，代码地图自动分析、资源盘点和价格更新维持各自范围；历史与地图偏好仍独立、默认关闭。

沿用已有历史自动同步开关与周期，原来关闭的保持关闭，原来开启的交由后台接管。后台继续按需启动并支持显式停止，本轮不增加系统登录自动启动；已开启的策略在后台运行期间生效，不依赖网页连接。

日常周期从一次成功的全局检查完成时计算，首次开启立即检查，后台启动复用原有启动检查，睡眠恢复后已到期只补一次。关闭策略取消未来周期和未开始的自动补查，保留在途检查及手动任务。任务按实际覆盖范围和检查强度复用，覆盖不足最多合并一轮必要补查；整项失败自动退避，成功后恢复原周期，用户可手动立即重试。这些选择控制后台持续运行时的负载和任务积压，同时保留全局检查覆盖。

Q1—Q9 与完整规格均已确认，具体时序、观察、兼容和验收见[完整规格](../../.scratch/backend-sync/spec.md)。实现通过轻量摘要返回自动策略、全局成功基准、实际任务和重试时间；网页忙时约每 1.1 秒、空闲时约每 5 秒观察，隐藏时停止读取，恢复可见立即观察。旧自动检查接口仅返回足够覆盖范围的在途任务，不再创建检查或推动截止时间。验证方法与结果见[历史更新验收](../validation/refresh-workflow.md)。

完整发布与来源只读继续遵循 [ADR 0004](0004-publish-complete-analysis-versions.md)；局部检查与全局覆盖继续遵循 [ADR 0006](0006-scoped-session-refresh-verification.md)。历史检查与语义索引维护保持各自策略，后者以已发布历史为输入。
