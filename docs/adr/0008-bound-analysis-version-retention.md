# 完整保留会话内容，限制代码地图分析版本

存储优化保留会话正文、工具参数与结果、思考、上下文和用量，减少副本而不缩小统计、搜索与证据范围。每个仓库只保留最近两个成功发布的代码地图分析版本；发布失败不淘汰有效版本，查询已淘汰版本时明确不可用，不静默切换到当前版。

全部地图版本的完整快照永久保留会使重复内容随刷新累积；两版保留支持当前查询与短期对照，但不再承诺无限历史版本回查。此决策补充 [ADR 0004](0004-publish-complete-analysis-versions.md) 的保留数量边界，不改变完整版本原子发布或事件身份；相同正文不表示同一次调用。首版处理已确认的重复字段与副本、版本保留和空间回收，跨模块长正文共享作为后续任务。

项目处于开发阶段，本次不实现旧索引结构迁移或兼容层。正式产品的新安装直接初始化新结构，后续启动复用该索引，不执行封存旧库或全量重建。会话来源生命周期继续遵循 [ADR 0005](0005-rebuildable-global-session-index.md)，不将会话库改为长期归档。

当前开发环境仅做一次旧索引封存与重建验证：保留仓库登记、手动关联及已知历史文件定位，从当前来源重新生成分析数据，不复制旧正文或统计，接受原始来源已消失的旧历史不再保留。该次 `.bak` 在验证成功后删除，失败或中断保留；此操作不进入正式启动流程。资源管理状态、语言偏好及回收／恢复材料保持其独立生命周期。

日常成功发布自动淘汰旧地图版本，物理空间整理仅在本地服务实际启动时检查：空闲页至少 1 GiB 且占比至少 20%，距离上次成功整理至少 24 小时，才在正常查询与索引写入开始前执行。运行期间不整理，不增加专门手动入口，也不在每次启动生成 `.bak`。整理必须保持正文、结果及搜索索引关联完整；空间不足或失败时保留可用索引并反馈原因。实现和验收边界见[存储优化规格](../../.scratch/database-storage-optimization/spec.md)。
