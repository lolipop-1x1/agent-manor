# 跨客户端统一用量画像

Type: task
Status: claimed
Blocked by: 10

## 目标

用户要求各 Agent 的右侧用量保持统一，不能只给豆包增加另一套上下文面板。直接在 main 开发、真实数据验证后推送，沿用本机来源和公开内容边界。

## 验收规格

- 所有客户端共用一个 Token 用量摘要组件和相同指标网格，移除独立的 ContextWindowSnapshots 主面板。输入、输出以及上下文最近占用、容量、比例和快照峰值保持相同位置，缺失显示未知；分项和快照收进展开明细，不为缺少快照的来源隐藏整组通用字段。
- 概览与用量页遵循既有分区，帮助入口合并；沿用统一主题、窄屏和中英文，不增加客户端 UI 分支。
- 请求用量、原生累计报告、上下文占用和留存文本估算维持各自统计口径；上下文数据不制造请求、输入／输出、费用、缓存命中或速度。缺字段显示未知，不补零。
- 共享上下文快照允许缺少容量和分项；能接入其他来源已核验的同事件上下文快照时沿用该契约，不能从模型名称或当前配置猜历史容量，也不能累计请求用量得到占用。
- 用真实豆包与 Codex 来源核对字段与生产 API，覆盖仅请求、仅上下文、两者都有、部分数据和子会话；中英文、深色、390 px 及既有请求趋势定位有浏览器回归。
- 类型、国际化、相关回归、全量测试、正式构建及公开检查通过，独立两轴审查后 main 提交推送并回读远端。

## 任务分工

共享 UI 负责统一摘要、明细、文案及合成浏览器回归；主 Agent 负责共享契约、可靠来源适配、存储集成、真实来源与运行验收。只读调查核对当前本机来源，原始数据仅留在忽略目录。

## Answer

所有来源改用共享 `SessionUsageSummary`，移除独立上下文主面板；前六格位置一致，缺失显示未知，快照分项和逐条记录进入展开明细。共享快照允许容量和分项缺失，Codex 的原生同事件占用与容量接入快照，自身压缩快照保留原始时间并按响应去重。请求与快照峰值范围不同时分别保留，不能覆盖或相加。

正式服务已按新规则检查 396 个 Codex 来源；豆包 7 条快照和范围外客户端数量保持一致。真实 API 与页面对照、语言主题恢复及 390 px 验收完成。全量 1345 项、相关 74 项、最终 UI 17 项、正式 Chrome 11 项及中英文请求趋势／费用回归通过。独立两轴审查的峰值和压缩时间问题均已修复复核；类型、国际化、正式构建和公开检查通过。

剩余 main 提交推送及远端回读。方法与边界见 [验收记录](../../../docs/validation/doubao-work.md)，真实材料仅保留在忽略目录。
