# 原生操作记录与共享画像呈现

Type: task
Status: claimed
Blocked by: 09

## 目标与证据

用户发现豆包中间过程与右侧画像缺少其他客户端已有的可读结构。生产适配复现：18 张原生过程卡全部展平为 context，失去卡片类型与结构。安装包已核对原生 View／Create／Edit／List／Replace 枚举、标题和正文；卡片呈现完成不代表执行成功，标题中“运行”也不证明工具类型。

## 实现边界

- 在共享消息模型增加可选 operation 元数据；原生卡继续区别于工具请求和结果，保留原始卡正文结构、证据及顺序，不根据自然语言猜工具身份。
- 共享执行轨迹、时间线及完整记录明确显示原生操作类型和未知执行结果；不丢卡片正文，不把卡片正文强分成命令输入／输出。时间线的操作轨道可同时承载工具调用与原生操作，图例区分。
- 画像沿用现有调用页签，单列原生操作条数和原生类型分布，支持定位首条证据；工具次数、成功率、Skill／MCP、请求用量、费用与精确代码覆盖均不增加。
- 上下文快照使用既有两列指标网格，保持快照与请求统计分离，不创建豆包专属页面或客户端判断。
- 中英文、摘要／完整／聚合时间线、子会话范围、搜索／分页／导出、来源升级和未知类型有回归；生产缓存与浏览器验收后在 main 提交推送。

## 任务分工

适配器负责原生卡语义和合成来源回归；UI 负责共享轨迹与画像及文案；主 Agent 负责共享契约、存储投影、升级与集成验收。

## Answer

新增共享 operation 元数据，原生卡正文保留完整 JSON；轨迹、时间线、完整阅读和画像调用页均明确区分原生操作与真实工具，卡片分类、首条定位和未知结果可达。聚合时间线将操作与普通上下文分别分桶；画像独立统计并排除复制记录，支持明确子会话范围。上下文窗口改用现有两列指标网格，未加入客户端 UI 分支。

真实来源复现从 18 条均丢失结构变为 18／18 保留结构；生产专项刷新核对 12／6 条操作、完整与聚合投影、未知统计及范围保留。真实浏览器完成定位、卡正文、标准网格及 390 px 验证；正式 Chrome 11 项、全量回归 1332 项通过。独立规范和需求审查无未处理发现，现场发现的普通上下文定位文案及“关联调用文件”名称也已修正。

检查与正式构建通过，剩余 main 提交推送及远端回读。公开方法与结论见 [验收记录](../../../docs/validation/doubao-work.md)，私有快照、标识、路径、正文及截图仅保留在忽略目录。
