# CodeFlicker Hook 附件过程记录丢失

Type: bug
Status: resolved

## Scope

CodeFlicker CLI 的 `role: attachment` 使用对象内容保存本地 Hook。原生来源可以仅包含启停 Hook，既有会话解析器未将对象内容写入索引，导致完整、轨迹与画像均为零且无解释。

## Acceptance

- 已核验的 Hook 附件保留原始内容、身份、记录位置、状态与耗时，归入过程；未知附件保留内容及缺口。
- 不新增用户轮次，不把本地 Hook 当作模型工具调用或模型请求。
- 简易版缺少对话时给出说明及完整记录入口。
- 默认列表隐藏仅包含 Hook 的来源；现有全部会话筛选与直接链接保留回查，后续出现真实对话后恢复默认展示。
- 仅使 CodeFlicker 会话来源缓存失效；其他客户端缓存规则不变。
- 匿名解析／刷新回归及原始会话的 HTTP、浏览器核验通过，真实内容留在忽略目录。

## Comments

已通过匿名样例稳定复现：纯 Hook 来源索引为零；混合来源只剩用户／助手记录。修复后应保留 Hook，纯过程来源的简易视图仍保持零条真实对话。

用户确认纯 Hook 不属于普通对话，默认列表应隐藏。本次仅排除已确认全部记录均为本地 Hook 的来源，不凭无项目、零轮次或未知附件隐藏其他来源。

## Answer

对象附件被旧解析器按文本数组处理，静默丢弃。现在保留已核验 Hook 的内容、原始身份、位置、状态及耗时；未知附件保留为过程并标注格式缺口。附件携带的模型字段不计入模型统计，也不增加工具调用和模型用量。

仅升级 CodeFlicker 来源缓存指纹。真实来源刷新后，HTTP 与独立浏览器均验证完整和轨迹保留五条 Hook，简易版没有补造对话，并提供完整记录入口。默认列表排除该来源，全部会话仍可回查；原始文件哈希和已有仓库登记、代码地图结果未改变。

类型检查、构建、262 项回归测试、公开内容检查及差异检查通过。浏览器验证三种视图切换、Hook 标签、状态、耗时及原始角色说明，无页面运行错误。详细诊断资料仅保留于本机忽略目录。
