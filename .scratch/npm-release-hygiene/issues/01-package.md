# npm 发布包收尾

Type: task
Status: resolved

## 范围与验收

- 为实际进入产品 Web 产物的第三方代码和字体保留完整版权及许可文本，根目录声明随 npm 包分发；README 不增加第三方许可链接。
- 构建从干净的 dist 开始，历史声明、source map 等残留不进入发布包。
- 中英文 README 准确说明空库首次启动的终端进度和完整准备等待。
- 验证声明生成及缺失许可失败路径、npm 包清单、旧文件清理、实际包外安装与跨平台 CI。验证只使用隔离合成数据，不执行 npm 发布。

## 计划

1. 核对实际打包依赖，收集原始许可文本并加入生成及检查流程。
2. 清理正式构建输出，更新中英文首次启动说明。
3. 执行构建、打包、许可缺失回归、隔离安装及必要回归，提交并推送 main。

## Answer

- 使用生产构建的实际依赖清单生成根目录完整许可声明，覆盖 158 项 Web 代码与字体；声明随 npm 包分发，缺失正文、过期内容及漏配文件白名单均阻断打包。
- 一个依赖发布包未附许可文件，按精确版本补充固定公开上游全文，记录来源及无法核实历史原文件的边界；未知版本不套用。
- 正式构建先清理 dist。注入旧声明及 source map 后执行真实 npm pack，验证旧文件已删除；新包 1,139 个文件，包含完整声明及构建许可清单。
- 中英文 README 同步空库首次启动的终端进度及完整准备等待，不添加第三方许可链接。
- 新增 6 项许可及清理回归；全量 1,752 项、CLI 45 项测试通过，类型、国际化及公开内容检查通过。
- 实际 tarball 在项目外隔离安装，通过许可内容、双命令入口、原生 SQLite/向量、端口冲突、后台/Worker/Web/停止与 Skill 安装验收；现有五平台安装 CI 复用同一验收脚本。
