# 资源标签与 Skill 移除

## 本轮范围

用户要求在已恢复的原版本上，先优化难懂的状态标签和本地 Skill 无法移除的问题。本轮只处理这两项；上一轮整体简化方案保留在 stash，不整体恢复。

沿用现有列表、地图、筛选、右侧详情、统计指标及排序，按最新要求移除总览状态列。没有单独确认的无样本统计卡片、默认页面和布局调整不纳入本轮。

## 已确认

- Q1 最初确认 A；最新用户要求取代该展示决定：移除总览状态列，并移除资源页各视图中的“统计不完整”标签和概括提示。使用筛选、原始统计及管理限制保留。
- 文件移除继续沿用此前确认的实际文件位置操作：普通共享 Skill 的完整目录或文件可以一次移入应用内回收区，确认展示已发现的相关客户端；不改原生启停配置，链接只移除所选链接，系统／插件／托管保护不扩大。

## 设计前沿

Q2 已确认 A：文件操作按钮放在现有管理弹窗的实际路径旁，同一文件／目录只提供一次回收操作。客户端停用与链接移除保留各自入口。设计前沿为空，按这两项开始实现。

同一符号链接被多个来源或范围发现时，按链接路径只显示一次移除按钮；客户端原生停用仍保留各自入口。链接预览只列同一路径的已发现入口，目标目录及其他链接不作为本次移除对象。

## 已核对事实

- 常驻标签混合使用情况、数据缺口、历史关联和管理保护；受保护不能单独说明为什么不能操作，仅历史不证明磁盘上不存在文件。
- 当前共享目录／文件被共享引用保护统一禁止回收；客户端原生配置适配条件又约束了独立文件操作。符号链接已有单入口回收／恢复，文件与目录已有备份及恢复分支。
- 文件回收与入口回收需要不同操作范围；归档须保存已发现的受影响入口，恢复冲突不覆盖，预览执行前复核引用及保护。
- 只读核对已完成，不采用仅开放单文件、仍禁止目录的建议，因为正常 Skill 以包含正文和附带文件的目录存在。

## 验证目标

用户能看懂使用情况及移除限制；普通本地 Skill 有直接可恢复的移除入口；共享影响、符号链接、保护资源及恢复冲突保持明确。管理写操作用隔离合成资源验证，真实本机仅只读核对，中英文同时检查。
