# 模型吐字速度趋势

## 目标

跨会话按日期观察同一模型的吐字速度变化，确定图表在现有页面中的入口和位置。

## 已作决策

- 2026-10-13：用户确认优先查看跨会话的日期趋势，用于观察同一模型最近变快还是变慢。单会话内按请求顺序查看速度变化不属于当前主目标。
- 2026-10-13：用户选择将主入口放在用量统计页的时间分析区域。
- 2026-10-13：用户确认复用现有时间主图，新增“吐字速度”指标；切换后展示速度折线，纵轴使用独立的 tok/s 单位。
- 沿用[现有术语](../../CONTEXT.md)与[吐字速度规格](../session-output-speed/spec.md)：响应区间与输出阶段分别统计，历史估算保留估算属性，缺失计时不当作零。
- 现有合格请求门槛、身份去重与平均公式继续作为设计基线；日期桶中的平均值需采用同一批合格请求的输出 Token 总和除以对应耗时总和。

## 事实核对

- 现有吐字速度规格明确将独立速度曲线留在首版范围之外，Token 纵轴不混入 Token/s。
- [总览统计约定](../../docs/design/overview-dashboard.md)要求请求计时按客户端、原始模型、响应／输出窗口、原生／历史估算及具体方法分组，只比较相同依据。
- [全局用量页](../../docs/design/usage-statistics.md)已有日期、客户端、模型等筛选及时间趋势；当前趋势指标为 Token、估算费用和请求数。
- [总览计时实现](../../src/overview/analytics.ts)已有按客户端、原始模型、计时区间、依据和方法分组的速度均值与分位数，但未提供日期桶序列。
- [用量事实](../../src/sessions/usage-facts.ts)与[趋势契约](../../src/usage-contracts.ts)尚无速度计时聚合。用量页新增速度图需要补充请求计时与日期桶数据，不能只增加前端选项。
- 以上为源码与文档核对；本轮未进行运行时数据覆盖测量或浏览器验收。

## 放置方案

- 入口：用量统计页的时间分析区域。
- 布局：在现有 Token／估算费用／请求数指标选择中增加“吐字速度”，复用原主图位置。
- 选择速度时展示跨会话的日期折线，纵轴为 tok/s；切换回其他指标恢复其已有图表语义。
- 本轮已确定目标、入口与布局。模型及计时分组的具体交互、日期归属和数据聚合接入属于后续实现规格。

## 讨论记录

### 第一轮

Q1：优先跨会话按日期看同一模型的速度变化，还是单会话内按请求顺序看变化？

用户选择：跨会话按日期看同一模型的速度变化。

### 第二轮

Q2：主入口放在总览现有请求计时区域、用量统计时间分析区域，还是总览独立区域？

用户选择：用量统计页的时间分析区域。

### 第三轮

Q3：复用现有时间主图增加速度指标，还是在现有时间趋势下方新增独立速度图？

用户选择：现有主图新增“吐字速度”指标，切换到速度后展示折线并使用独立的 tok/s 纵轴。

放置方案已收敛，用户于 2026-10-13 授权开发与测试。
