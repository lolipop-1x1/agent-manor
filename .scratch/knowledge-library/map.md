# 知识沉淀设计访谈

Status: claimed
Type: grilling

十八项访谈问题已逐项确认，完整设计见 [知识库设计方案](../../docs/design/knowledge-library.md)，需求范围见 [spec.md](spec.md)。用户已确认完整方案与四张界面设计，并授权在 main 实现与测试。

## 已明确的边界

- 三条知识写入路径：会话库手动抽取、用户或 Agent 直接提交、后台自动抽取。
- 直接提交已整理正文，不再次调用抽取模型生成。
- 独立一级入口，支持项目、客户端及审阅状态筛选，支持关键词和可选语义搜索。
- 抽取模型单独配置；知识 Embedding 可以复用现有连接或单独配置。
- 本阶段不开发 CLI 和 Skill。

## 决策树

- 使用闭环：已确认 Web 与本机 HTTP 提交、搜索、读取接口，CLI 与 Skill 后续处理。
  - Agent 读写入口与第一阶段交付边界：第一轮已确认。
  - 调用方标识、幂等提交、写入权限与读写契约：待上层决策。
- 审阅含义：区分人工审阅与生成、保存。
  - 各写入来源默认状态、默认查询范围：第一轮已确认，模型与 Agent 提交待审，人工明确确认后已审；默认只查已审。
  - 审阅后修改、拒绝、替代：第三轮已确认保留有效版本，修改待审；并发更新和旧向量处理细节进入整体方案。
- 知识归属：已确认来源与适用范围分开，指定项目或显式个人全局。
  - 项目适用范围与来源客户端：第一轮已确认。
  - 跨项目检索、多项目条目和自动推断：待上层决策。
- 自动抽取策略：首版一套独立策略，支持范围多选、回填与增量。
  - 单套全局策略或多条独立规则：第一轮已确认单套策略。
  - 范围筛选、触发时机、回填与静默时间：第三轮已确认默认及可配置策略；手动任务同样支持预览和进度。
- 保存与来源：已确认独立保留知识和必要证据摘录，来源消失时标记不可回查，见 ADR 0018。
  - 来源消失时知识和最小证据摘录的保留方式：第一轮已确认。
  - 正文、修订、来源和可重建索引的存储及恢复：待上层决策。
- 知识内容：已确认六类长期知识、重要事件及未决事项，采用 Markdown 正文与轻量元数据。
  - 浏览入口：已确认全部知识、个人记忆、项目记忆和通用经验；首版不管理具名 Agent 身份。
  - 内容类型、适用范围与来源分别表达；第三轮确认事件、未决事项和知识时效分别记录，已审知识可废弃。
  - 抽取粒度：整会话或选定轮次，长会话有界分段后归并；只有摘要时保留限制，时间窗口只沉淀新增或变化信息。
- 界面与模型：已明确需要，细节待上述决策。
  - 导航命名、列表与详情、审阅操作、设置组织。
  - 生成连接、Embedding 继承或覆盖、费用与暂停恢复。

## 第一轮决策

用户已明确选择全部按建议推进；知识分类的完整性继续展开。这里确认设计方向，不构成功能实施授权。

1. 使用闭环：首版交付 Web 管理和本机 HTTP 知识提交、搜索、读取接口；CLI、Skill 及自动注入随后处理。
2. 审阅默认值：模型抽取和 Agent 提交均待审；人工编辑通过明确确认动作标为已审阅；默认检索已审阅，可显式查待审或全部。
3. 归属：区分来源与适用范围；项目知识限定项目，可由不同客户端消费；全局知识显式指定。
4. 自动策略：首版采用一套独立的知识抽取策略，支持多选范围和调用控制。
5. 保存：知识独立保留，来源消失时标明不可回查；保存必要证据摘录及版本定位，不复制完整历史。新增持久化数据边界记录于 ADR 0018。
6. 内容：采用正文与轻量元数据，不把所有类型强制套入操作步骤模板。分类在第二轮进一步确认。

## 第二轮分类决策

用户已确认第二轮全部采用建议：

- 六类长期知识为事实、偏好、规则与约束、决策、方法与流程、经验与教训。
- 首版纳入重要事件与未决事项，保留时间与处理状态；日常进度和原始执行轨迹不逐项形成长期知识。
- 知识库提供全部知识、个人记忆、项目记忆和通用经验视图，来源客户端作为独立筛选。
- 首版不引入具名 Agent 的身份、人格、职责和工具配置管理。
- 内容类型、描述主体、适用范围、来源分别表达，标题或摘要、正文与证据按需读取。

问题 7、8 已解决。最终规则见 [知识分类与浏览](../../docs/design/knowledge-library.md#知识分类与浏览)。

## 第三轮行为规则决策

用户确认问题 9—14 全部采用建议，并补充：

- 长会话可能多次压缩并超过生成模型窗口，需设计分段及跨段归并，不能仅重用最后摘要。
- 需要查看知识的每个版本及历史内容，完整修订快照后续已在 ADR 0019 确认。
- 手动沉淀支持选择最近时间范围、预览、开始，并在界面观察后台进度，不依赖自动策略开启。
- 已审知识仍可以废弃或过期，可用性与审阅分别记录。
- 知识支持可编辑标签，辅助主题分类与检索。
- 知识和具体历史版本可回查对应原始会话及工具证据；直接提交允许没有会话引用。

问题 9—14 的已确认规则及详细设计见 [抽取与更新规则](../../docs/design/knowledge-library.md#抽取与更新规则)。具体算法与存储细节仍属于待整体审阅的方案。

## 第四轮已确认边界

用户确认全部采用建议：

15. 来源只剩压缩摘要或关键证据不足时，允许形成明确标注来源限制的待审候选，不得声称动作或结果已经原始证据核验；缺少足够依据时返回需要上下文。
16. 手动选择最近时间范围时，只沉淀窗口内新增或变化的信息，较早历史可按需作为上下文；预览分别呈现目标范围和额外上下文规模，整会话入口仍可完整处理。

知识完整修订快照的建议也已确认，ADR 0019 转为 accepted；其他实现细节仍待整版方案审阅。

## 第五轮增量与提示词决策

- 增量需要记录会话已处理位置，但近期窗口和选定轮次会形成非连续覆盖，不能只保存最大的消息序号。
- 区分任务检查点、已完成处理覆盖和知识审阅状态；新增内容结合相关任务线索、旧知识及必要回读处理纠正。
- 无价值或重复结果也计入已处理；失败不冒充完成，配置变化不默认导致全历史重跑。
- 已确认高级设置中的抽取要求、归并要求、恢复默认与试抽取；程序保持输出结构、来源引用及写入约束。

17. 已确认提示词定制进入首版，并保存每次任务使用的要求版本；新配置只影响新任务，不自动重抽历史。

## 第六轮语言支持

用户要求中英文支持，并提出将知识返回语言独立配置后加入提示词。已明确：

- 产品显示语言、知识输出语言、原始资料与自定义要求语言分别处理。
- 支持中文和英文知识生成，语言要求加入抽取及归并请求；界面切换不改写历史正文。
- 原始证据、代码标识符、命令和错误信息保留原文；直接提交不被自动翻译。

18. 已确认首版提供简体中文与英文，首次按界面语言初始化后独立保存；新知识使用任务设置，补充旧知识默认沿用其原语言，主动改写语言形成待审新修订。
