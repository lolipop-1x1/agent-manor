# 知识库需求规格

Status: needs-info

十八项访谈决策已逐项确认，整版设计已整理，当前等待整体审阅。本文只记录需求范围及交付状态，不表示已授权功能实现。

## 目标

建立知识产生、保存、审阅、检索、后续使用与更正的完整链路。用户可以从历史会话沉淀，也可以与 Agent 直接提交已整理知识。

## 首版范围

- 独立一级入口知识库，提供全部知识、个人记忆、项目记忆、通用经验视图。
- 会话库整会话或选定轮次主动沉淀、按范围手动预览和开始、后台自动增量。
- Web 与本机 HTTP 的知识提交、搜索和读取，直接提交不调用抽取模型。
- 六类长期知识，以及重要事件和未决事项；Markdown 正文与轻量元数据。
- 人工审阅、编辑、确认、拒绝、废弃、恢复、有效时间和版本历史。
- 标签及项目、来源客户端、类型、审阅、可用性筛选。
- 关键词检索与可选知识语义索引，支持复用会话 Embedding 连接或独立配置。
- 独立生成模型、提示词定制、恢复默认和小范围试抽取。
- 会话及具体历史版本的来源回查，含原始消息、工具证据及必要摘录。
- 中英文界面、独立知识输出语言、任务进度、暂停恢复、重试及调用预算。

## 已确认的关键规则

1. 模型抽取和 Agent 提交默认待审；人工明确确认才发布已审版本，默认查询已审且当前有效内容。
2. 类型、适用范围、来源和审阅分别表达。来源客户端不限制其他客户端消费同范围知识。
3. 知识及必要证据独立持久保留；来源消失不删除知识，也不伪造原始内容。
4. 内容修订使用完整快照，审阅绑定具体修订；待审修改不覆盖当前有效版，恢复旧版形成新修订。
5. 已审内容可废弃、过期或被替代，默认关键词及语义查询均排除不可用版本，历史仍可查。
6. 长会话有界分段、保留跨段线索、按主题分批归并，应用后续纠正，关键结论按需回读证据。
7. 只有摘要时允许形成带限制的待审候选，不能冒充执行或验证依据；不足以支持候选时返回需要上下文。
8. 时间窗口只沉淀窗口内新增或变化信息，较早内容只作必要上下文；整会话入口可完整处理。
9. 记录实际处理覆盖及可恢复检查点；非连续范围不以最大序号冒充全部完成，零新增也可计为处理完成。
10. 自动策略首版一套，默认关闭；范围可配置，默认每小时检查、活动安静 30 分钟后处理，手动任务不依赖自动策略开启。
11. 提示词、输出语言或模型变化不自动重抽全历史，不清空已处理覆盖，不覆盖已审内容。
12. 首版知识输出语言为简体中文和英文，首次按界面语言初始化后独立保存；新知识采用任务语言，补充旧知识沿用旧语言。
13. 界面切换不翻译正文；证据、技术标识与直接提交保持原文。主动改变旧知识语言形成新的待审修订。
14. 暂停、失败及预算停止保留已完成结果和检查点；抽取、审阅及向量就绪分别记录。
15. 同输入重复结果跳过；相似和冲突由模型提出修改建议，人工确认；已拒结果不被定时重跑反复提交。
