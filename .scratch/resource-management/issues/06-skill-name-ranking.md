# Skill 排行按名称组织

Type: task
Status: resolved
Blocked by: 05

## 目标

Skill 使用排行以记录的完整名称为唯一展示维度，跨 Agent、项目和路径汇总，Agent 作为筛选。项目、路径及真实来源留在详情，不再拆分排行行。

## 验收

- 同名 Skill 合并后，使用会话数取并集，调用与成功读取次数分别累计。
- Agent 筛选保持 Skill 标识稳定；Skill 排行不受旧项目筛选限制。
- 详情保留真实来源、Agent／项目分布和分页证据，跳转会话轨迹后返回保持筛选。
- 旧历史标识仍可回查，旧来源收藏可继承及取消；本地入口与本体收藏保持独立。
- 本地管理按已确认的真实来源关联，不根据相同名称合并安装对象。MCP 组织方式保持原有语义。
- 完成类型检查、自动化回归、真实 Chrome 和现有本机索引只读验证；真实配置不参与写操作。

## Comments

用户在资源管理页面要求只按 Skill 组织，Agent 用于筛选；这是对使用排行展示维度的调整，本地操作仍遵循来源与引用关系。

## Answer

- [使用聚合](../../../src/resources/usage.ts)区分名称排行和实际来源，跨 Agent、项目及路径的同名 Skill 合并，会话数取并集；完整限定名称保留，缺失名称不依占位文案推断同一资源。
- [资源页面](../../../web/Resources.tsx)移除 Skill 排行的项目／路径副标题及项目筛选，Agent 筛选沿用统一组件；详情保留分布、实际来源和部分未关联状态。
- 旧来源标识和收藏保持兼容；取消名称收藏清理历史别名，保留独立本体收藏。本地关联历史仍使用实际来源 ID，精确回查具体入口，不引入名称合并的写对象。
- 325 项自动化测试及 25 组真实 Chrome 验证通过，覆盖名称汇总、会话并集、Agent 筛选稳定标识、旧项目筛选不再限制排行、收藏保护与证据跳转返回。两条审查线发现的缺失名称误合并及本地回查范围问题已修复并加入回归。
- 当前本机索引只读验证：Skill 排行由 1,147 行合并至 387 行，5,687 次活动和 1,639 个使用会话全部保留；MCP 的 60 行及完整统计保持一致。本地服务已加载最终版本，真实配置未参与写入。[验收](../../../docs/validation/resource-management.md)。
