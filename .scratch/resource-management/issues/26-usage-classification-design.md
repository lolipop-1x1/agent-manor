# 资源使用分类与管理保护分离

Type: grilling
Status: resolved
Blocked by:

## 已明确需求

- Skill／MCP 页面取消独立“待检查”分类。
- 未发现使用结合当前本地资源清单和所选范围的历史使用记录判断，不把首次发现不足七天变成独立分类。
- 低频及长期未用按已有使用记录正常展示，不能因思考正文、附件、项目或父子关系等无关缺口统一排除。
- 沿用调用次数和使用会话数；Skill 显式调用及成功正文读取计入合并调用次数，MCP 按工具请求计数。调用结果未知不否定已记录请求。
- 此任务讨论并完善规格，不执行管理操作或开始实现。

## 已确认决策

- T1：收藏、系统和插件资源正常参与全部使用情况分类，管理动作继续单独保护。
- T2：低频沿用默认不超过两个使用会话，阈值可调整；主界面继续默认展示调用次数。
- T3：照已找到的记录展示分类和次数，真正影响资源统计的缺口保留“部分记录”状态及来源详情；思考加密、附件等无关缺口不阻断资源分类。
- T4：长期未用沿用最后一次使用距今至少九十天，天数可调整；无使用记录归未发现使用，有调用但缺日期直接标明时间未记录，不猜时间。
- T5：Skill／MCP 总览、本地筛选及地图全部取消待检查入口，正常无使用记录的本地资源进入零指标区，旧页面筛选回到全部；读取、缺失、只读等关键来源状态仍保留。
- T6：总览继续按完整名称聚合；具体本地本体不凭同名强行关联。没有可确认路径时保留使用记录未关联状态，不将同名已有使用证据误判成某本体从未使用。
- T7：分类沿用当前 Agent／日期／关键词范围，新发现的本地资源立即参与未发现使用；读取失败明确报错，正常查询无记录才显示零。旧参数兼容、必要 API 字段保留及隔离验收边界已确认。

## Answer

- T1–T7 已全部确认，设计前沿为空；使用情况分类与管理保护分开，无关采集缺口不阻断分类。
- 领域词汇已补充未发现使用、使用情况分类、使用记录未关联、低频使用与长期未用；没有新增管理生命周期或安装身份决策，无需新增 ADR。
- 规格新增“使用分类更新”章节，替代原有待检查分组、七天观测门槛及以保护／采集完整统一阻断分类的规则。原始证据、统计范围、日期和安装本体身份保留。
- 实施任务为 [27 分类计算](27-usage-classification-data.md)、[28 界面与兼容](28-usage-classification-interface.md)、[29 综合验收](29-usage-classification-validation.md)。当前仅完成设计文档，应用代码未修改。

## Comments

- 当前分类以采集完整和不受保护为前提，导致使用情况与整理保护混在一起；更新后的分类语义应与已有管理预览、保护及恢复边界分开讨论。
- 当前存在可读取使用事件却因加密思考或其他无关采集缺口被阻断分类的场景；不得据此补造事件、成功结果或时间戳。
