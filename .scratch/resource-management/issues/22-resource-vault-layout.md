# 来源可辨认的恢复目录与回收兼容

Type: task
Status: resolved
Blocked by: 21

## 目标

- 新材料按 backups 或 trash、资源类型、名称与来源标识、独立操作 ID 存放。
- Skill 来源基于所选入口；MCP 来源基于配置路径与注册项，同名及重复操作不覆盖。
- 回收区兼容旧备用档案和调用，保留恢复及单独确认永久清除能力。
- 原目录、共享入口、权限、冲突及备份校验保持正确；提供可复用的材料路径函数用于迁移。

## Answer

- 新恢复材料按 `resource-vault/{backups|trash}/{skill|mcp}/{名称}--{完整来源哈希}/{预览ID}/material` 保存，名称去除分隔符及控制字符，UTF-8 长度限制为 80 字节。Skill 原入口路径形成来源身份；MCP 使用配置路径、注册定位及服务器身份，不按客户端或同名合并。
- `src/resources/vault-path.ts` 导出纯函数 `resourceMaterialPath`，供新操作和显式数据迁移共用。`management.ts` 导出 `resourceMaterialFingerprint`，复用原有内容指纹，迁移不另写一套校验算法。
- 原生停用保存到 backups；回收及兼容备用调用保存到 trash。所有材料父目录限制为 0700，内容沿用受限权限与原权限恢复；永久清除仅移除本次操作目录，其他来源或重复操作材料不受影响。
- `archives("trash")` 包含旧 standby 档案，`archives("standby")` 仍可使用；保留旧目录的恢复能力和单独确认永久清除，不在管理器启动时全量搬迁旧材料。
- 21 项定向自动化验证通过，覆盖同名不同入口、重复回收、多个 MCP 注册、父目录权限、恢复及永久清除隔离、旧备用查询和旧目录兼容。测试使用人工隔离资源，没有修改真实客户端配置。
- 任务 24 负责显式迁移，任务 23 负责页面与旧备用展示；本任务不迁移真实数据或修改 UI。
