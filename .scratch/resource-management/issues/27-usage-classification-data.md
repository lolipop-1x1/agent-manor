# 按本地资源与已有历史计算使用分类

Type: task
Status: resolved
Blocked by: 26

## 目标

实现规格最新“使用分类更新”，将使用情况分类与管理保护分离。Skill 和 MCP 使用同一规则，不补造事件、时间或具体路径关联。

## 验收

- 总览本地存在且当前统计范围未找到使用证据的资源进入未发现使用，新发现即参与，不设七天等待；已确认使用记录继续计入调用次数与使用会话数。
- 低频按正使用会话数不超过所选阈值判断，默认二；长期未用按最近已记录使用时间距今达到所选天数判断，默认九十。零使用不混入低频或长期未用；缺日期不猜时间。
- 收藏、系统、插件及托管资源正常参与分类，管理能力与预览保护不因分类命中改变。
- 无关缺口不使资源统计变未知或使整个客户端分类清零；相关缺口保留部分记录和可定位诊断，不否定明确请求。查询或盘点失败直接反馈，不伪装成零记录。
- 维护名称统计与具体本体关联的差别：历史按名称合并，本体按可确认路径及客户端／范围关联；同名未关联活动不将具体本体判为未使用，也不累加名称统计。
- 兼容旧 review 查询参数为全部；保留必要 API 字段的结构兼容，不再返回待检查候选或分组。类型、共享服务、Web／CLI／API 使用同一语义。
- 合成回归覆盖新发现零记录、已有调用无结果、加密思考／附件缺口、相关来源缺口、保护资源、阈值边界、缺日期、同名不同本体及读取失败。


## Answer

- 已按最新规格分离使用分类与管理保护：新发现有效本地入口立即参与未发现使用；低频只接受正使用会话数，默认不超过二；长期未用使用可确认最近时间，默认达到九十天。收藏、系统、插件与只读保护不再排除分类，管理预览及执行保护保持原逻辑。
- 资源采集相关性依据稳定诊断标识；加密思考、附件、Token、项目与明确父子关系缺口保留原诊断，不再统一影响资源分类。调用未完成和分叉去重边界仍标记相关部分记录；明确请求照计，读取仍只计确认成功。
- 真正来源读取失败保留未知统计；索引未就绪和查询失败直接反馈错误。首次失败且没有历史修订的原生来源可依客户端标识前缀限定影响范围，未知归属继续保守保留。名称使用与本体关联分开，无路径同名记录不会给具体本体制造零使用。
- LocalRow／OverviewRow 新增 partial、usageUnassociated、missingTimeEvents；MapNode 新增 usageUnassociated，沿用 partial 与 missingTimeEvents。旧 candidate=review 查询全部，counts.review 恒为零、map.review 恒为空。地图无面积紧凑区保留 value=null 的未知节点，share=null，不将其称为零。
- 针对性后端与 HTTP／CLI 合成回归六十六项全部通过；另补同名多本体无路径回归并通过地图套件。check:server 与 git diff --check 通过。未修改真实历史、客户端配置或索引，未启动实际 MCP，未提交 Git。
- 界面采用新状态字段与 null 指标显示由任务 28 接续；全量和真实浏览器验收由任务 29 接续。本任务不宣称浏览器界面已更新。
