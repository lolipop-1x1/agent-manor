# 会话语义搜索设计访谈

Status: needs-info
Type: grilling

本记录用于逐轮明确需求、取舍和领域用语。功能尚未实现，推荐项不代表已接受决策；本记录不授权下载模型、访问真实模型服务、发送历史正文或构建真实语义索引。

## 已明确的需求

- 为全局会话库增加语义搜索，兼顾效果、性能、成本和页面展示。
- 通过界面配置模型服务地址、API Key 等连接信息，以及调用模型的策略；日常使用不要求编辑配置文件。
- 采用设计访谈逐轮澄清，并随确认结果整理领域术语和必要的架构决策。
- 接入用户提供的本地或远端 OpenAI 兼容 embedding 服务，首版不负责模型下载、安装和启动。
- 默认为用户消息和助手对话正文建立语义索引；思考、工具输入输出及系统注入不默认进入语义索引，现有字面搜索继续覆盖原有范围。
- 支持用户按全历史／最近多少天、会话项目、Agent 客户端、会话关系、执行模式等可靠属性设置索引范围，并在开始前展示规模和预估成本。项目和客户端支持多选，同组任一匹配、跨组同时满足；首次明确选择时间范围，不默认采用最近 90 天。
- 时间按会话区间与所选窗口相交判断，纳入入选会话的对话正文；子 Agent 和 Quiet 模式为独立筛选维度。默认排除已确认子 Agent 和已确认 Quiet，保留普通分叉及未知属性，其他筛选使用已记录元数据。
- 保存连接不开始构建，首次由用户显式开始；之后对范围内的历史变化延迟增量维护，并支持暂停与继续。
- 搜索功能提供关键词搜索和语义搜索。由本地后台调用配置的模型服务，索引构建和提交语义查询时均允许调用；关键词搜索不调用模型。默认关键词实时查询，语义查询通过 Enter／按钮提交；查询向量在服务内存中有界复用，仅修改筛选可复用，模型配置变化后失效。混合搜索尚未确认。
- Key 使用独立的本地凭据文件保存，目录权限 0700、文件权限 0600，文件内容不宣称加密。普通偏好、浏览器持久存储和日志不保存 Key；界面默认遮罩，可由用户点击显示完整值，并支持复制、替换和清除。
- 默认低占用策略，后台构建并发 1，前台查询优先；批次、token 预算、速率、超时及重试限制在高级设置中调整。
- 允许设置本功能的每日估算费用预算，默认不填写。达到阈值后停止新的模型请求，保留缓存查询和关键词搜索；预算不代表服务商实际账单封顶。
- 会话库搜索旁提供搜索设置对话框，分模型连接、索引范围与构建、调用策略与用量，状态详情按需展开。
- 首次完整构建后启用语义搜索；构建进度在设置对话框展示，搜索入口旁可打开状态，更新时保留上次可用版本并排除失效内容。
- 语义文档按真实用户轮次组织提问与本轮助手对话正文，长轮次切块，归属不明时保留单条；默认按相关性排序并可切换时间。
- 模型、维度或编码规则变化时停用不兼容旧向量，提示预估成本并由用户显式开始重建，期间关键词可用。
- 超出维护范围的有效向量默认不删除，继续可搜索，时间窗口滚动与主动取消项目、客户端等条件遵循相同规则；用户可独立开启清理窗口外向量。搜索按查询时筛选执行，不自动继承维护条件。此策略不授权删除原始会话。
- 纳入全部已保存分支的独有正文，对能够确认的继承副本避免重复编码；用户提出按内容 hash 复用完全相同输入的结果，具体键结构和来源映射作为技术方案整理。
- 本地服务运行期间，关闭网页不停止已启动构建及已发现历史版本的维护。暂停后台构建不阻止主动语义查询编码；没有有效缓存的新查询需要调用模型，已有有效缓存可以复用。
- 文档仅描述本产品的需求、事实和决策。

## 当前事实

- 当前搜索为字面搜索：长查询使用 FTS5 trigram 候选及原文字面校验，单／双字符查询另有词项索引；尚无 embedding 或语义排名。
- 当前结果按会话更新时间排序；现有接口尚无语义／混合模式字段。
- 会话页已有全局搜索、单会话搜索、会话分组命中及消息定位。全局输入停顿 240 毫秒后查询，单会话为 200 毫秒。
- 查询 Worker 已有相同请求合并、队列上限及取消机制；语义请求、限流、用量和密钥管理尚未实现。
- 现有页头有自动同步、语言和外观设置，没有通用设置页或模型连接入口。
- 现有共享偏好保存语言、外观及自动刷新设置，尚无模型密钥字段或专门凭据存储。
- 当前会话日期筛选按会话时间区间与查询区间是否相交判断，使用 started_at／updated_at 及回退值；没有按消息时间截取正文。界面按本地日历日生成边界，再传 UTC 时间。会话页项目和客户端目前单选，规划中的语义索引维护范围已确认采用多选。
- 产品文档及 ADR 0002、0005 当前描述分析不依赖上传历史或调用模型。可选模型服务会引入新的能力边界，需要明确同意后记录其适用范围，不静默覆盖既有决策。

### 已确认的调用边界

- 后台索引构建可以预先计算历史正文向量。
- 标准 embedding 检索还需要在收到新查询后，用兼容的查询编码模型计算查询向量，之后再在本地进行向量匹配。
- 用户确认由本地服务在索引构建及提交语义查询时调用配置的服务；使用远端 endpoint 时，历史正文与查询编码均可能产生远端请求。
- 浏览器向本地服务提交操作，模型请求由本地服务发起。
- 查询缓存减少重复编码，不能预先覆盖任意未知查询；语义查询采用显式提交。
- 未选择“搜索时不访问远端”的额外约束；混合模式仍未作为需求接受。

#### 事实与边界

- 会话关系和执行模式是独立属性；当前只有部分来源能明确识别 Quiet，不能把所有未标记项都称为已确认常规。
- Fork 与子会话分别定义；已确认复制是消息级内容状态，不等于整个分叉会话无效。
- 已记录模型是会话内多值集合，空集合表示未记录，不代表没有使用模型。
- 分支和复制属于内容策略，与会话筛选分开表达；已确认覆盖全部已保存分支的独有正文，明确继承副本避免重复编码，不将整个分叉会话排除。
- 现有真实用户轮次和消息定位可复用，但历史记录不能可靠证明此刻仍在运行或已成功完成，不以文件末尾的推断终态作为唯一维护依据。
- 向量文档稳定身份不能只依赖可能重排的轮次序号，需保留原始消息身份、内容版本及块位置。

### 维护范围、保留覆盖和查询筛选

- 维护条件限制自动纳入新增或重新编码的范围，不自动删除或隐藏已经生成的有效向量；时间窗口滚动与主动取消项目、客户端等条件遵循同一保留规则。
- 默认关闭“清理窗口外向量”；开启时只清理语义向量及对应派生数据，不删除原始会话。
- 保留的窗口外内容继续参与语义搜索，搜索按本次客户端、项目、时间和会话属性筛选执行。
- 保留有效向量不延长原始来源生命周期：来源确认消失或内容发生变化后，对应旧内容的位置映射失效，不能继续返回过时正文；仍有其他有效位置引用的共享向量不因此失效。

### 第四轮：已确认的使用边界

用户确认 Q18A、Q19A、Q20A；Q21 经查询编码与后台构建边界的澄清后确认 A：

| 编号 | 决策 | 当前结论 | 状态 |
| --- | --- | --- | --- |
| Q18 | 非时间维护条件收窄 | 同时间窗口一样保留有效向量且可搜索，维护范围只约束后续处理，删除为独立操作 | 已确认 A |
| Q19 | 分支和继承副本 | 纳入全部已保存分支的独有正文；确认的继承副本不重复编码并保留原文定位；增加按完整输入内容 hash 复用的技术方案 | 已确认 A，内容复用细节待审阅 |
| Q20 | 关闭网页后的任务 | 本地服务运行期间继续已启动构建及对已发现历史版本的维护，重开页面可查看状态 | 已确认 A |
| Q21 | 暂停后台构建 | 只暂停正文构建及维护，已有索引可搜索，主动查询仍可调用模型编码；有效查询缓存命中时复用 | 经澄清后已确认 A |

Q19 不依据标题或内容相似度推断会话复制关系。精确内容复用只证明实际模型输入相同，不证明原始会话相同；一个编码结果允许关联多个有效位置，筛选、分组和原文跳转继续使用位置身份。建议在切块后以输入内容 SHA-256 与向量空间及编码规则的指纹建立复用键，已有有效结果和执行中相同任务分别复用、合并；不能因去重丢掉唯一可用正文。具体技术设计见 [spec.md](spec.md)。

Q20 只约束本地服务中任务的生命周期，不新增持续检查历史来源的承诺；关闭网页后能否发现新历史仍取决于既有历史更新机制。推荐内容变化后静默 5 分钟再维护，持续变化最多延后 30 分钟，两项均可在界面调整，手动立即更新可跳过等待；这些数值是待确认的设计默认值，不是性能实测结论。

共同方案仍建议将关闭语义搜索与清除语义索引设为不同动作：前者停用语义搜索及其构建、保留连接和索引，后者仅清理派生索引。此动作细节随完整方案审阅；每日预算规则始终约束新增模型请求。

- 语义索引维护：把范围内的对话变化更新到语义索引，与检查历史来源的历史更新区分。
