# P2：七天排行的 unknown 身份冲突导致明细漏项

Status: resolved
Type: task

## 触发条件与现象

同一七天窗口内存在两条请求，一条模型原值明确为字符串 `unknown`，另一条缺失模型。思考程度字段也有相同问题。

排行生成一条 `key=unknown`、`count=2`、`requests=2` 的记录，但点击后明细只有一条字段缺失的记录，`total=1`。如果只有明确字符串值，明细将为空。

## 证据

- `src/overview/weekly-review.ts:168` 用 `row.model ?? "unknown"` 和 `row.reasoningEffort ?? "unknown"` 聚合，两种身份被合并。
- 同文件 `:229-231` 在明细筛选时把 `detail.key=unknown` 转为 undefined，只命中缺失字段。
- `src/usage/dimensions.ts:2-8` 已有区分缺失值、字面 `unknown` 及 `literal:` 前缀值的编码约定。

内存合成事实复现同时验证模型和思考程度，均得到排行 2、明细 1。脚本只保存在本机忽略目录，不含真实会话数据。

## 预期与建议

复用既有维度身份编码并在下钻时对应解码，保留原始值。排行显示、摘要计数和明细使用一致身份；派生结果缓存需要按实际改法失效，避免修复后仍返回旧排行。

## 验收条件

覆盖缺失值、字面 `unknown`、字面 `literal:unknown`、普通字符串及其混合输入；分别验证模型和思考程度的排行计数、明细记录与原始值一致，中英文显示不改变查询身份。


## Answer
