# 核查 CLI 原生写入流程

Type: research
Status: resolved

## 范围

只读核查与目标来源记录版本一致的本机 CLI 安装包源码，追踪历史记录字段、项目元数据写入及 SDK／原生 Agent 身份边界。真实来源、私人路径及安装包摘录仅保存在本机忽略目录，公开记录使用匿名路径和机制结论。

## 验证

每个归属判断回到原生写入逻辑，并与最新来源字段交叉核对；分清源码确认、日志观测和推断，避免以执行入口或工具工作目录替代明确父身份。

## Answer

- 本机发布包版本与目标记录一致，为 0.3.26。发布包入口导入 dist/cli.mjs；本轮未执行客户端或 Hook。
- quiet 分支使用 sdk-cli 标记，普通独立 CLI 会话也会采用该值，不能据此确认 SDK server 或子 Agent。
- 原生 Agent 创建流程使用 agent-<id> 会话身份，并在运行时传递父身份。消息追加器不会自动把全部运行时上下文写入 JSONL，父工具结果可以提供明确子身份。
- 当前解析器遗漏后台任务通知的注入标记。本机复现确认：应为 1 个真实用户轮次，重新解析却得到 5 轮，其中 4 条是后台通知。本轮只分析，尚未修复。
- MyFlicker CLI 默认沿用原配置根，项目目录编码规则与本项目实现一致。项目元数据由显式历史或仓库信息操作登记；quiet 分支没有这些调用，普通消息写入也不会自动登记项目。
- 基础消息与默认配置不保存 cwd，但通用配置 setter 允许写入该字段。目标来源确实没有 cwd，项目映射无对应项，工具目标又涉及多个仓库，故归属未知有证据依据。
- 原生父身份存在于 Agent 运行时和 Hook 输入，不能等同于全部落入子 JSONL。目标的普通会话身份与 quiet 主会话格式一致；外部自动化是否把它当作子任务，现有来源无法证明。
- 安装包与实际来源已交叉核验；子任务的历史写入审计已完成并整合。详细源码位置及原始证据保存在忽略目录，没有复制客户端源码到公开文档。本轮没有修改运行代码或原始历史。
