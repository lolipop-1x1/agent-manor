# 桌面来源、适配与验收

Type: task
Status: resolved
Blocked by:

## Scope

核对新版桌面端的原生轨迹、缓存投影与项目／会话元数据，接入代码地图和会话库。现有客户端展示名改为 CodeFlicker CLI，新增独立的 CodeFlicker 桌面版，复用通用事件与查询管道。

## Validation

合成回归、类型检查、构建、公开内容检查、隔离后台 CLI／HTTP／真实 Chrome 端到端、本机真实数据只读核对。

## Comments

仅实现用户指定的新版桌面端历史，不擅自将旧 IDE SQLite 或其他执行来源合并为桌面端。

## Answer

现有 `codeflicker` ID 保留、展示名改为 CodeFlicker CLI；新版 MyFlicker 桌面端独立注册为 `codeflicker-desktop`、展示为 CodeFlicker 桌面版。发现和适配复用通用注册表、Worker、HTTP、CLI 与 Web 查询管道，无需为查询入口分别增加客户端分支。

桌面缓存为主来源，正式 cwd 由身份一致的检查点注册表补充；只读 SQLite 会话标题命名空间和按 UUID 关联的原生模型元信息，不重复索引原生正文。消息、工具结果、数字 ID、轮次终态、压缩和 Skill 调用均已适配；用量按已确认的执行后端归一化。标题、cwd 和模型旁路变化只失效相应来源，失败保留上一版，删除来源从新版排除。

200 项完整自动化回归、类型检查、构建、公开内容检查及隔离后台的真实 Chrome 端到端通过。端到端核对 2 行读取、1 行修改、两个客户端身份隔离、简易／完整消息、模型／缓存／Skill／搜索与证据回读。本机两份桌面历史的调用数及请求用量与原始记录一致，含工具的会话 47 次调用全部索引，原始缓存哈希不变。验收与范围限制见 [验收文档](../../../docs/validation/codeflicker-desktop.md)。

本地预览服务已更新，全局会话索引与已登记仓库增量分析均已完成发布。真实日志、路径、身份与核对报告仅留在忽略目录。
