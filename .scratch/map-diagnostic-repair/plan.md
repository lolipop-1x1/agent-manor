# 代码地图诊断修复实施计划

**目标：**修复已复现的诊断根因，再移除页面入口。

**架构：**历史解析器仅提取已保存证据，仓库分析按可靠归属筛选来源，范围未知保留语义；诊断继续可通过 CLI/API 读取，日常页面展示可用地图和可操作失败。

**技术：**TypeScript、SQLite、React、Node test、隔离 Chrome 验收。

1. 读取实际来源与覆盖诊断，仅本机保存；按消息标识统计并定位关键复现。
2. 在 tests 下加入 Shell 选项、逻辑运算与路径模式的失败回归，修正 src/history/extraction.ts 等最小模块并运行相关测试。
3. 根据来源范围和客户端审计补回归，再修 src/index/refresh.ts、src/history/index.ts 或客户端适配器。解析规则变化纳入缓存版本。
4. 删除 CodeMapPage.tsx 来源与缺口入口及孤儿前端代码，检查现有来源归属 API 和按需证据入口。同步翻译、文档及浏览器断言。
5. 运行 check、相关测试、build、check:public 与合成浏览器验收。
6. 重算实际仓库，对照修复前后缺口与统计；记录仍不可恢复的历史限制，不伪造覆盖。
