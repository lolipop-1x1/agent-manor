# CodeFlicker 本地资源兼容设计树

## 已作决策

- C1：CodeFlicker CLI 与 CodeFlicker 桌面版同时补齐 Skill／MCP 自动盘点及历史使用关联。
- C2：已核验的资源入口进入本地列表，包含已停用项；内置、插件及客户端托管来源保留保护标签。未被当前发现规则或安装登记引用的残留副本只进入来源诊断。
- C3：同名覆盖按已核验选择规则表达，主列表展示选中的入口，被覆盖项进入来源诊断；移除上层入口可能露出下层项，管理预览保留此影响。
- C4：普通独立 Skill 及 CLI 配置型 MCP 的文件操作，须核验来源／恢复方式并通过隔离测试后开放；桌面 MCP 首版只读并提供客户端管理引导，内置／插件／客户端托管资源继续保护。
- C5：按用户默认范围和每个已知项目分别计算覆盖关系，再合并展示有效入口；保留各范围诊断，不猜测未保存的临时命令行配置。
- C6：状态、只读扫描、历史关联和隔离验收边界已共同确认，规格完成。
- 沿用现有资源本体、资源入口、配置作用范围和使用证据术语；相同真实目标可共享本体，同名不证明身份相同。
- 沿用逐来源核验的管理边界、插件保护、具体入口预览确认与恢复冲突规则。
- 产品名称继续使用 CodeFlicker CLI／CodeFlicker 桌面版，不因安装程序改名创建第三个客户端。

## 设计树状态

- 覆盖范围 → C1 已确认。
- 实际加载来源 → 两路调查及补充均完成；[来源矩阵](../../docs/design/codeflicker-resource-sources.md) 记录版本、静态可确认格式与未确认项。
- 来源与版本 → C2／C3／C5 已确认；实现按用户默认和已知项目分别投影，再汇总入口。
- 状态与管理 → C4／C6 已确认；桌面 MCP 消费差异保留待核验状态，首版只读。
- 关联与展示 → 依据路径／原生身份关联，不改写历史；来源诊断及关键状态直接可见。
- 验收 → 已明确合成读写回归、真实本机只读核验及中英文浏览器端到端验证。
- 当前设计前沿为空，规格已确认；产品代码尚未开始修改。
