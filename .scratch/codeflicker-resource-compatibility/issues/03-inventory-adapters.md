# 适配两种客户端的资源来源与范围投影

Type: task
Status: resolved
Blocked by: 01, 02

## 目标

在现有资源盘点层适配已核验 CLI／桌面版来源，覆盖普通 Skill、静态内置／托管来源、插件登记、自定义目录与 MCP 注册。保留来源读取状态、客户端、作用范围、设置状态及保护条件。

## 验收

- 新旧发行根分别正确，改名不导致 npm CLI 误扫桌面目录；登记引用与残留缓存分别表达。
- CLI 名称状态和桌面标记独立适配；仅用户触发不算停用，MCP 消费字段未确认时保留未知。
- 按用户默认和各已知项目计算选择与覆盖，再合并入口；同级冲突、不存在、不可读、断链和未知格式有诊断。
- 静态读取不执行 loader／hook／插件／服务，不下载；不回显 MCP 注册值。
- 合成回归通过，其他客户端现有结果保持一致。

## Comments

- 复用现有盘点和契约，新增格式能力按实际需要扩展，不另造资源管理系统。
- 桌面 disabled／disable 消费关系须核验具体消费者；不能把未知字段当成已确认开关。

## 完成记录

- 已加入 CLI 与桌面版的独立来源规划：配置与数组状态、显式路径、兼容目录、安装登记引用及静态插件 manifest、远端材料、桌面 YAML 自定义目录和 MCP 注册。
- CLI 按用户默认及已知项目上下文计算名称覆盖，普通同名覆盖保留路径诊断；同级冲突与不能核验的插件间优先级保留未知，不自行选择。桌面精确目录保留所有可独立选择的同名项。
- 仅用户触发作为 invocationMode 展示；停用、配置读取失败、托管保护及共享真实路径身份分别保留。桌面配置含 disabled 时不推断 disable 消费语义。
- 新增诊断投影仅包含来源、名称、路径、范围和稳定入口身份；MCP 命令、URL、环境和 headers 不进入公开快照。动态 hook／内置虚拟元信息无法静态完整确认时保留缺口，不执行资源。
- 同一快照缓存配置解析、SKILL 正文、物理目录、stat 和 realpath，项目上下文复用读取，仅重新计算原生状态及选中关系。
- 用户级来源与入口按实际持久位置保留一份，已知项目中的选中状态、原生设置和控制位置放入 selectionScopes；项目目录来源仍独立。仅在项目上下文有效的用户入口继续保留真实用户来源，项目查询从有效上下文匹配。
- 新增 50 项目夹具验证用户入口数量有界、稳定身份、逐项目停用／仅用户触发及覆盖关系，并验证共用服务的项目过滤不会重新暴露被覆盖用户入口。真实本机只读核对确认入口不随项目数量成倍复制；私人结果留在忽略目录。
- 插件 manifest 的 Skill 引用按原生规则区分具体 Skill 文件／目录与立即子目录容器；容器不生成不存在的 SKILL.md 本体，重叠默认来源不会重复计入。
- 验证：20 项盘点及范围测试通过（12 项新增兼容／服务场景、8 项原有客户端回归）；服务端类型检查通过。实际管理操作与浏览器验收由后续票据覆盖。
