# CodeFlicker CLI／桌面版本地资源兼容

Status: ready-for-agent

## 目标

补齐 CodeFlicker CLI 和 CodeFlicker 桌面版的 Skill／MCP 自动盘点及历史使用关联，让本地资源列表展示已核验入口，清楚区分不存在、来源无法读取、未适配和残留副本。

本次沿用现有资源总览、列表、地图、Agent 筛选、调用次数和使用会话数，不改变已有历史统计口径。产品名称与客户端 ID 保持稳定，不因发行程序改名增加新客户端。当前支持平台继续为 macOS。

## 已确认决策

- C1：两种客户端的 Skill 和 MCP 一起兼容；相同真实目标共享本体，各客户端入口和作用范围独立保留。
- C2：本地列表展示已核验的资源入口，包括已停用项。内置、插件及客户端托管资源保留来源与保护标签；未被当前发现规则或安装登记引用的旧目录或版本副本进入来源诊断，不作为当前入口。
- C3：同名资源按已核验优先级选择，主列表展示选中的入口；被覆盖项保留在来源诊断中，管理预览说明移除上层入口可能露出下层项。
- C4：普通独立 Skill 的停用／回收／恢复、CLI 配置型 MCP 管理，在来源和恢复方式核验并通过隔离测试后开放；桌面 MCP 首版只读并引导到客户端管理，不绕过 Client Daemon 的修订号约束。
- C5：按用户默认范围和每个已知项目分别判断选中入口，再在全部项目视图中合并展示；同一入口可以在某范围被覆盖而在另一个范围有效。
- C6：已共同确认本规格的状态、只读扫描、历史关联及隔离验收边界，可以拆分实施任务。
- 沿用既有逐来源核验的管理能力、具体入口选择、操作预览／确认、持久恢复材料及恢复冲突规则。

## 来源盘点

- 来源依据客户端实际发现规则、配置引用及安装登记核验，不能只根据目录名称猜测客户端归属。
- 同时处理已核验的新旧来源形态。迁移副本只有仍被对应版本的发现规则引用时才构成当前入口，不自动将旧路径映射成新路径。
- 扫描范围限用户来源、已知项目及配置明确引用的资源路径；不全盘遍历，不执行客户端 loader、Skill 脚本、插件代码或 MCP 服务，不下载远端资源。
- 显示来源、客户端、作用范围、原位置、可确认版本及配置设置状态。文件存在、登记或 enabled 设置不能证明运行客户端已加载。
- 同名覆盖与来源优先级按已核验规则表达，无法确定时保留未知；不能将覆盖副本的历史使用算给当前同名实例。
- CLI 的“仅用户触发”不等于停用，保留独立状态标签。桌面 Skill 的 `.disable` 标记与 CLI 的名称选择规则分别适配，不套用其他客户端的开关。
- CLI 普通 Skill 与插件 Skill 的原生名称分别保留，插件命名空间不剥除；当前入口的原生名称与历史保存名称各自保留，通过可核验身份／路径关联，不改写原始证据。
- 只读取静态可确认的内置元信息、插件登记和 manifest 引用，不执行动态 Skill hook；无法确认的动态来源记录采集缺口，不以静态目录数宣称完整运行清单。
- 缺失、损坏、权限、断链、未知格式和引用越界分别保留诊断；不静默吞掉读取错误，不把读取失败显示为零资源已完整确认。
- MCP 页面与 API 只投影服务器名称、注册定位、类型及设置状态，不返回命令、URL、环境变量、headers 或注册正文。

## 身份与历史关联

- 独立目录即使内容相同仍是不同本体；多个入口指向同一真实目标时共享本体。
- 历史统计和当前安装清单独立存在。关联仅使用历史保存的路径及可核验原生身份、客户端和项目范围；同名、内容相同、迁移推测不形成确定关联。
- 当前配置变化不能改写已保存的历史名称、原始路径、调用次数或使用会话数。历史独有、部分未关联与歧义继续可见。
- 移动和迁移后的路径不是历史路径的自动别名；旧来源证据可继续展示，只有独立证据能证明引用关系时才形成确定关联。
- 所有页面与 Web／CLI／API 使用同一盘点及关联结果；只刷新资源清单无需全量重建会话索引。

## 管理与展示

- 管理能力按实际来源声明，未核验写法保持只读。插件、系统和客户端托管材料不通过直接修改缓存提供操作。
- 共享本体无法独立停用一个入口时不开放该入口操作；预览显示所有已发现受影响范围。CLI 同名规则和桌面共享标记不能被包装成仅影响一个目录的操作。
- 总览列表、地图详情及本地资源复用现有具体入口管理面板；明确只读原因，不能显示无效管理按钮。
- 已停用、回收、操作记录、收藏及共享入口影响沿用既有生命周期，不因资源清单刷新丢失。
- CLI 名称设置按原生 disabled／userOnly／enabled 的优先级处理，停用与恢复只编辑对应作用范围的目标规则并保留原状态；无法确认跨范围影响时不开放写能力。
- 桌面普通 Skill 的标记或隔离操作仅在独立、非托管、可恢复来源上开放；不能因修改共享目标的标记而声称仅影响一个入口。
- 空状态直接区分没有匹配资源与来源待适配／无法读取；只显示影响理解的关键状态，说明放入现有来源详情与帮助入口。
- 中英文、键盘、触屏、窄屏与深浅主题沿用统一控件和现有交互规范。

## 验收草案

1. 使用合成用户／项目来源验证新旧根、配置引用、共享链接、独立副本、同名覆盖、安装登记、内置／插件保护和残留缓存诊断。
2. 使用合成 MCP 配置验证定位、状态、优先级、未知字段、损坏来源及敏感值不进入 API／日志；任何新写能力以隔离合成资源测试预览、确认、冲突、恢复与不影响其他注册。
3. 关联回归验证正确路径、客户端与项目范围，路径缺失和歧义保持未关联；现有历史总数及其他客户端结果不回归。
4. 真实本机只读验证两个客户端资源清单、来源诊断及历史关联；不修改真实配置或资源，不启动 MCP 服务。
5. 浏览器端到端验证两种客户端下的 Skill／MCP 列表、Agent 筛选、总览／地图详情、管理能力／只读理由、空结果、刷新及中英文呈现；写操作使用隔离合成数据。
6. 运行相关回归、类型、翻译完整性、构建及公开内容检查；公开材料只保留方法、结论和支持边界。
