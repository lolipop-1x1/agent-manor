# 单仓库数据库清理与任务取消

Type: task
Status: resolved
Blocked by: 01

依据 [规格](../spec.md) 和 [共同契约](../map.md)，拥有 `src/index/store.ts`、`src/index/refresh.ts`、`src/index/worker-manager.ts`、`src/worker.ts`，后台 diagnostics 的中英文目录，以及相关后台测试。实现事务清理、登记 created 结果、按旧任务 ID 取消、检查点退出、事务内发布检查、缺行通知及等待者收束。

验证完整清理、保留其他数据、事务回滚、排队和运行删除、立即重登、旧结果不可写回、其他地图／会话任务可继续。使用隔离合成资源。

## Comments

- 与其他任务共享 `main`，不得撤销他人修改；公共契约由主任务维护。

## Answer

- `AnalysisStore.registerRepositoryResult(path)` 返回仓库和 `created`；原登记方法保持兼容，子目录继续解析到 Git 根，不同 worktree 保持独立身份。
- 删除事务使用 SQLite 写锁，收集旧任务并清除登记及全部七类专属表；最终删除失败时完整回滚。全局会话表、其他仓库、本地源码与原始历史保持完整。
- 发布事务在任何写入前验证任务仍存在、属于该仓库且处于运行中。删除后同路径重登不能恢复旧任务；迟到的失败处理对缺失任务直接收束。
- Worker 按旧任务 ID 接收取消消息，跳过排队任务；运行任务在扫描、发现、解析和映射批次检查点让出执行权并检查任务身份。等待者得到内存 `cancelled` 结果；已提交但尚未收到完成通知的任务也能正常收束，数据库不留下旧任务。
- `tests/repository-lifecycle.test.ts` 使用真实 Worker 和共享原子屏障，覆盖运行中、发布前、发布完成后但通知前的删除／立即重登，其他地图和会话队列继续，以及删除事务失败不撤销任务。
- 定向验证：原索引／Worker 测试 24/24、新生命周期测试 7/7；服务端类型检查、双语翻译检查、公开内容检查及修改文件空白检查通过。
- 界面、HTTP 集成、资源管理独立存储和真实浏览器验收由后续任务合并验证。同步解析、映射及已开始的事务仍在当前操作完成后的检查点退出。
