# 登记弹窗项目列表被裁剪

Type: task
Status: resolved
Blocked by: 06

用户反馈登记弹窗内项目下拉框展示不全。实际复现发现项目 Popover 挂载在带 `transform` 和 `overflow: auto` 的 Dialog 内容中，弹层处于视口内，但超出父 Dialog 的部分被裁剪。

## Comments

- 先前验收仅检查视口边界和 DOM 滚动，未检查父容器裁剪及可见区域命中。
- 修复弹层挂载边界，保留统一 ProjectPicker、对话框焦点约束、列表独立滚动及关闭后的焦点恢复。
- 验证桌面、窄屏、低高度窗口下的搜索、鼠标命中、滚动和键盘；管理写操作继续使用隔离合成资源。

## Answer

- 登记项目弹层使用默认顶层 Portal，不再挂载在 Dialog 的滚动内容内；移除本次实现引入且已不再使用的 Dialog 内容引用。
- 共享 ProjectPicker 透传 Radix 的 `modal` 参数，登记弹窗启用该模式，保证外置弹层仍有独立的滚动锁与焦点约束。其他使用处沿用默认行为。
- 当前内置浏览器复现并确认：修复后项目列表底部可命中，真实鼠标滚动改变列表位置，Escape 仅关闭项目列表并恢复触发按钮焦点。
- 合成 Chrome 回归增加弹层上／中／下可见区域命中检测及鼠标滚轮检查，覆盖 1440×600、760×428、390×500，并验证完整路径选择和焦点恢复。原有中英文与深浅主题、登记、删除和并发场景保持通过，最终 12 组全部通过。
- `check:web`、`build:web` 通过；详细截图和日志仅保存在已忽略的 `.local/repository-lifecycle-e2e/`。本次为前端弹层修复，后台测试结果仍见任务 06。
