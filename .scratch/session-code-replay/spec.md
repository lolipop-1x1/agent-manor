# 会话代码活动回放

Status: complete

用户已授权按本规格与紧凑版界面方案直接在 main 实现、使用真实历史迭代测试，并完成推送。任务图见 `issues/01-replay-api.md` 至 `issues/07-query-worker.md`；实现时采用已讨论的推荐默认值，必要调整记录验证依据。

## 用户明确提出的体验

- 在代码地图内提供常驻、独立的活动回放 Tab，允许直接进入并选择一个会话。
- 从会话库选中某个会话，进入对应仓库的代码地图。
- 像观看视频一样，播放该会话在仓库中的文件读取与修改活动。
- 提供时间轴、播放、暂停、慢速和倍速控制。
- 直观看见已记录活动的顺序或轨迹。
- 所选会话及其明确关联子会话各占一条轨道，共用播放头，展示并行子会话的文件活动。

本文件保留需求讨论与决策。已依据用户实施授权落地，推荐默认交互采用当前实现；接口与支持边界见 `docs/design/session-code-replay.md`，验证证据见 `docs/validation/session-code-replay.md`。

## 功能入口与页面层级

用户已明确要求：活动回放是代码地图内独立可进入的功能，通过新增 Tab 承载；会话库跳转是快捷入口，不是使用回放的前置条件。

- 代码地图下设置现有分析视图与活动回放两个同级 Tab。标签暂建议“活动分布／活动回放”，现有分析视图标签仍可调整。
- 界面设计采用单行紧凑工作区工具栏，将标题、仓库选择、两个 Tab 和右侧操作同行组织；用户已明确要求压缩原先标题与 Tab 分两行形成的大块留白。具体设计见 [界面方案](design.md)。
- 直接进入流程：选择已登记仓库 → 活动回放 Tab → 选择一个会话 → 加载该会话及明确子会话的多轨回放。
- 会话库快捷流程：活动回放动作 → 定位对应已登记仓库 → 打开活动回放 Tab 并选中目标会话；播放器及数据来源与直接进入一致。
- 回放以一个所选会话及其明确子树为目标，不扩展成拼接多个无关会话的编辑器。
- 不依赖先在会话库打开目标会话，也不依赖现有分析视图预先选中会话。

待确认的默认交互建议：

- 仓库选择在两个 Tab 之间共享；分析筛选与回放会话选择、播放位置、地图视野各自保存，避免历史日期、目录或搜索条件意外裁掉回放。
- 回放选择器默认列出自身或明确子会话在当前仓库有可回放活动的会话，支持搜索；不能仅按会话项目路径相等筛选，主会话自身没有文件活动时也不能漏掉有子会话活动的目标。
- 初次直接进入时提示选择会话；再次进入恢复上次目标与播放位置，保持暂停。切换 Tab 时暂停播放。
- 切换仓库后核对并清理不属于新仓库的回放目标；没有候选会话时显示明确空状态，不自动回放其他仓库活动。
- 返回分析视图保留其筛选、选择和视野；会话库原有代码地图动作继续用于分析，活动回放使用明确的动作入口。
- 页面地址记录当前 Tab、仓库和回放目标，使直接进入和快捷跳转使用同一个可定位页面；具体路由字段尚待实现设计。

## 现有领域与架构约束

- 现有“执行轨迹”包含会话消息、模型步骤和工具事件；本功能聚焦其中与仓库文件有关的活动，称为“会话代码活动回放”，定义见 `CONTEXT.md`。
- 仓库基线是一次分析使用的文件集合及其内容版本，不等于会话发生时的完整工作区。
- 会话项目与已登记仓库具有不同身份和生命周期；跳转不能把历史项目路径自动认定为可用仓库。
- 文件读取请求、成功读取、文件修改请求和已确认结果保留各自证据含义，缺失结果不能展示为成功。
- 地图、活动与证据绑定同一个完整分析版本。刷新失败保留旧版，旧版被淘汰时明确不可用，不静默换版。

依据：`CONTEXT.md`、`PRODUCT.md`、`DESIGN.md`、`docs/design/metrics-and-evidence.md`、`docs/design/baseline-rules.md`、`docs/adr/0004-publish-complete-analysis-versions.md`、`docs/adr/0008-bound-analysis-version-retention.md`、`docs/adr/0011-repository-registration-lifecycle.md`。

## 第一轮已确认决策

### Q1：播放节奏（后由 Q9 调整）

- 用户选择活动顺序模式：每次活动有可辨认的展示时间，倍速改变观看节奏；原始时间单独保留。
- 1× 表示标准观看速度，不代表实际经过时间。具体节拍长度尚待设计。
- 本次不采用按原始间隔推进或压缩原始空闲区间作为默认播放规则。

以上为单会话阶段的初始决定。引入多会话同步后，用户在 Q9 明确选择共享原始时间轴并统一跳过长空档，取代独立按步骤推进的播放时钟。当前节奏以 Q9 为准。

缺失时间、相同时间、并行事件及稳定顺序的具体规则，待源码核对后继续讨论。

### Q2：还原范围

- 用户选择活动回放：在选定分析版本的固定仓库地图中，展示会话文件活动和证据。
- 地图不随进度还原历史工作区或逐步重建文件内容。

## 后续待展开的设计树

- 会话范围：所选会话自身、明确关联的子会话、分叉继承活动。
- 地图范围：整个仓库、目录及文件类别筛选；已删除和基线外路径的访问方式。
- 活动单位：一次多文件工具调用、成功／失败／未知结果、重复来源及同一时刻活动。
- 播放交互：拖动定位、前后活动、点选文件／事件、原始证据和返回会话位置。
- 地图表达：当前活动、累计痕迹、视觉连线的含义、缩放与平移、窄屏及减少动态效果。
- 数据与生命周期：完整活动序列、版本绑定、长会话性能、刷新、失效和空结果。
- 验收范围：人工合成活动、顺序与定位一致性、状态恢复、中英文、键盘和真实浏览器。

尚未选择的规则不写入领域词汇表或已接受 ADR。

## 第二轮已确认决策

- Q3：当前活动醒目高亮，并保留已经发生的读取／修改的较淡累计痕迹。
- Q4：默认覆盖基线中的源码、配置、文档与其他文本类别。现有会话跳转已将类别设为 `all`，可复用。

## 源码核对：导航与地图

以下为静态源码结论，尚未验证实际浏览器运行。

- `web/features/sessions/Sessions.tsx` 的 `mapForSession` 已将选中会话和可选项目／文件路径传给 App。
- `web/features/code-map/CodeMapPage.tsx` 的 `openMap` 按路径选择已登记仓库，以 `client` 和 `clientSessionId` 设置会话筛选，同时清空目录／时间／搜索并将文件类别设为 `all`。无匹配仓库时显示登记提示，不自动登记。
- `web/app/App.tsx` 当前只写入 `#map`，目标会话保存在组件状态。可恢复的回放目标及播放位置需要另外设计。
- `web/features/code-map/map-layout.ts` 的 `layoutMap` 以正物理行数分配矩形面积，相同文件集合、行数和路径产生确定布局；零行文件没有地图面积。
- 当前代码地图的活动列表围绕选中文件分页加载；已有事件详情和原始证据到会话消息的回链，缺少跨文件的会话播放指针。
- 会话执行轨迹已有顺序／轮次／时间投影和选择定位，但展示采样／聚合机制不能直接当作完整文件活动序列。

## 第三轮讨论结果

- Q6：用户希望所选会话及明确子会话分轨，多个子会话并行时共用播放头，要求核对可行性；不采用仅所选会话的首版边界。
- Q7：用户确认有可靠调用身份时，一次调用涉及的多个文件作为同一步同时高亮；缺少关联依据时单独呈现。
- Q8：用户确认纳入可靠归属仓库的读取、修改与搜索活动。失败与未知结果始终保留真实状态。

## 多轨同步已确认决策

- Q9：各轨按共享原始时间轴对齐，共用播放头；统一跳过所有轨道都没有可展示文件活动记录的长区间，倍速作用于整个回放。
- 不对每条轨道独立压缩时间或独立按一步一秒播放；跳过区间只表示没有可展示的文件活动记录，不代表 Agent 没有执行或思考。
- Q10：有时间的活动参与同步；无法可靠对齐时间的活动保留在所属轨道的独立区域，暂停后可按可确认的记录顺序查看，明确说明无法时间对齐。
- 同一次调用的多文件分组与多轨时钟分别处理，调用身份相同不等于有完整执行时长。

## 源码核对：活动数据

以下为静态源码结论；尚未逐客户端验证原生顺序和调用身份的可获得性，也未运行真实历史扫描。

- `src/contracts.ts` 的 `HistoryEvent` 保存事件身份、客户端／原生会话身份、可选父会话／发生时间、工具、类别、状态、路径、片段和来源引用。模型没有统一的会话顺序、起止时间、消息关联或调用分组身份。
- `src/server.ts` 的仓库 `/events` 接口可按精确会话身份分页取回固定分析版本中的活动，默认每页 50、最多 200，没有总条数硬上限；当前先过滤再直接切片，返回顺序不等于可靠的全会话活动顺序。
- `src/history/index.ts` 在调用完成时可能将多文件证据拆成多个事件。来源引用可保留原生调用 ID，缺少身份时不能仅按工具名、参数或相同时间强行合并。
- 现有父会话筛选不自动包含子会话；分叉继承活动按已确认的原始身份归属，不将副本当作新活动。
- 当前基线外的历史文件活动可能仍有原始事件，但没有可绘制的基线文件或行映射；无法可靠归属仓库的外部路径不在该仓库快照中。
- 会话库保留按 `ordinal,id` 排序的消息时间线，但地图事件与会话消息之间没有可以直接假定相同的事件 ID。

### 多轨关系与时间证据

- `src/sessions/store.ts` 在版本化关系表中建立明确 child 关系，检查父声明冲突、多个父目标及循环；fork 不作为委派子会话递归纳入。
- `profile(..., { includeChildren: true })` 可在固定会话索引版本中递归返回确认的子树 `sessionIds`。未找到的目标及关系缺口另行保留，不能按标题或时间接近补造轨道。
- 现有 `/timeline` 针对单会话；默认返回完整事件，`maxEvents` 触发的聚合投影不能作为精确回放流。单会话 `ordinal` 不构成跨会话时钟。
- 父会话的工具请求／结果可能包含明确子目标，但关系表没有统一保存 spawn 调用关联。主会话等待、子会话创建／结束没有跨客户端一致的生命周期事件契约。
- `startedAt`／`updatedAt` 来自观测到的消息时间极值，不代表准确的会话执行起止或持续忙碌。
- 轨道以活动点为基础；只有能核验调用开始／结束或明确耗时依据时才画执行区间。仅有事件时间时不能补出操作持续时间。
- 当前 `TraceTimeline` 的三条 lane 按用户／上下文、模型、工具分类，仍属于一个会话；多会话轨道、共享播放头及地图临时高亮需要新增。
- 回放分别固定会话索引版本、仓库分析版本和轨道成员集，两个模块的版本身份不能混用。播放高亮与用户选中文件分开，避免每次播放推进都触发文件详情请求。

尚待合成验证：部分来源父工具目标与子历史身份可能不同，尤其不能假定原生 agent 标识等同于可查询会话身份；各支持来源的时间精度及工具调用关联仍需逐项验收。本轮不扫描真实历史或修复解析器。

由此需要新增完整、固定版本的回放投影：可靠顺序、调用分组、文件事件列表及证据定位；现有接口返回顺序和会话时间线的采样结果不能直接替代该投影。具体字段与可用来源边界待设计收敛后制定。

## 实现方向草案（待整体确认）

### 回放数据

- 一个回放目标绑定仓库、所选主会话、明确子会话集合及完整分析版本；各轨保留自己的客户端和原生会话身份，会话库返回定位另行保留。
- 一条轨道属于一个明确会话，轨道间共用原始时间坐标与播放头；分叉关系不能自动当作子 Agent 关系。
- 一个活动组记录可核验的来源顺序依据、可选原始时间、调用身份（若可用）、相关文件活动和证据定位。多文件分组使用 Q7 已确认规则。
- 优先使用原生会话记录的请求顺序及可靠来源位置；时间戳是补充证据。相同时间不代表同一次调用，缺少时间不代表没有记录顺序。
- 无法确定先后的活动保留为顺序不明，不按事件 ID 或解析完成顺序伪造轨迹；具体展示方式需确认。
- 回放投影保存轻量活动信息，完整工具输入／输出与原始记录按需读取，避免每个动画帧查询服务端。
- 长会话必须保留准确总步骤及全部有效活动；分页和预取不能形成隐性截断。会话时间线的采样结果只用于概览，不充当回放来源。

### 播放器与地图

- 地图布局由固定文件集合与行数生成，播放只更新各轨当前活动及已播放累计痕迹；同一时刻允许多条轨道同时高亮不同文件或同一个文件。
- 进度条与轨道按共享历史时间定位，倍速及跳过区间影响观看推进方式，观看耗时与原始时间跨度分别表达。
- 共享播放位置是地图、累计状态、活动列表和详情的共同依据。向后拖动时按目标位置恢复累计状态，不能留下未来活动的痕迹。
- 当前步骤可能关联多个文件；点选文件或活动后暂停，详情仍可回到原始会话消息。
- 当前基线没有矩形的活动，例如历史已删除路径或零行文件，保留列表与证据访问，不伪造面积或丢弃活动。无法可靠归属仓库的外部路径不混入该仓库回放。

### 待确认的交互默认值

- 回放 Tab 支持直接选择会话；会话库跳转时预选目标。首次选择新目标后停在起点，恢复既有目标时保留位置并保持暂停，播放结束自动暂停。
- 提供 0.25×、0.5×、1×、2×、4×、8×；非跳过区间按统一速度推进，进度显示原始时间定位，并可查看活动计数。跳过阈值及展示细节待确认。
- 支持拖动定位、前后一步、回到开头及结尾；原始时间缺失时不补造时间。
- 默认保持仓库全景，允许手动缩放平移；不在每一步自动移动相机。
- 读取／修改／搜索使用可辨认的标记；失败和未知不显示为成功完成，累计修改与最终 Git diff 保持不同语义。
- 切换仓库或会话时结束当前回放并建立新目标；切到其他页面或隐藏浏览器时暂停。
- 背景分析完成不替换正在回放的版本；证据版本已淘汰或查询失败时暂停并显示可重试／更新入口，不能混入新版证据。
- 使用已有主题、共享地图层与弹层；键盘可控制进度和动作，减少动态效果时保留步骤切换及明确高亮。

### 验收方向

- 合成会话覆盖顺序、缺少时间、同时间、批量多文件、重复来源、失败／未知、已删除路径、零行文件和无活动。
- 自动播放、暂停、倍速及前后定位使用相同顺序；向前／向后拖动后的当前步骤与累计痕迹一致。
- 已有会话跳转、文件详情、原始证据、返回会话位置及完整分析版本约束继续成立。
- 浏览器验证中英文、深浅主题、窄屏、鼠标、键盘及减少动态效果；真实历史样例只留在本机。

顺序与调用身份尚需按支持的历史格式验证；本草案不承诺所有来源都已具备同等精度。
