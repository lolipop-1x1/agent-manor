# 回放冷查询隔离 HTTP 主线程

Status: complete

Blocked by: 06

## 问题与范围

- 新分析版本的真实候选首次准备约 5.9 秒，首次大回放约 6.3 秒；同步 SQLite 计算期间并发健康检查超时。
- 将既有只读 ReplayService 运算及其版本缓存移入惰性独立 Worker，保留 API、完整活动、双版本与证据语义。
- 主线程固定版本，Worker 再核验版本保留状态；相同请求合并、有界队列、断连订阅清理、失败恢复及关闭沿用项目既有 Worker 模式。
- 不提高堆上限、不改 SQLite 全局参数、不调整历史或仓库刷新策略。

## 验证

- Worker 与 HTTP 错误、版本固定、关闭与主事件循环响应回归。
- 全量类型、构建、单测与回放浏览器回归。
- 用真实大索引并发执行首次回放准备和健康检查，记录读取耗时及健康检查延迟；两者分开评价，不将异步等同于读取本身变快。

## 结果

- 新增 6 项 Worker 回归，独立审查与回放 API 合计 18 项通过；完整 1504 项单测、生产构建与类型／中英文检查通过。
- Worker 接入后的完整浏览器回归通过，含 363 轨压力、四轨交互、原始证据、同轨同刻、语言、主题、窄屏及键盘。
- 真实日常冷查询：候选准备约 6839 毫秒、首次 363 轨回放约 9159 毫秒，重复请求约 74／62 毫秒。并发 149 次健康检查全部成功，95 分位约 8.69 毫秒、最大约 40.4 毫秒。
- 仍完整返回 6471 步和 14711 条活动；读取耗时仍取决于真实工作集与机器状态，不承诺固定完成时限。
