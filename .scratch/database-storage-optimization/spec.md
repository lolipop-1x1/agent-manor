# 数据库存储优化

Status: ready-for-agent

## 目标

减少明确的存储冗余，限制代码地图版本累积，并在启动时自动回收满足条件的空闲空间。正文、搜索、轨迹、画像、Skill／MCP 统计及当前地图的证据保持完整。新用户直接使用新数据库结构；项目处于开发阶段，本次不实现旧索引结构迁移或兼容层。

本次仅完成规格，尚未修改代码或真实数据库。

## 已核验的问题

- 代码地图每次成功发布保存完整快照，当前没有版本淘汰策略，长正文、工具参数／结果及代码片段会随版本累积。
- 同版快照与来源响应保存相同的缺口数组。
- 消息正文已从消息 JSON 分离，但 Hook／附件及部分用量记录又将正文详情复制到翻译参数。
- 消息身份、顺序、轮次、类型等字段同时保存在 SQL 列和消息 JSON 中。
- 解析缓存承担增量解析，全文索引保存搜索词项；它们有功能价值，不能作为无用副本直接删除。
- 删除记录释放 SQLite 页，不保证数据库文件缩小。消息搜索以主表 rowid 关联 FTS，空间整理不能破坏这种关联。

真实路径、原始会话标识、正文、截图和测量明细仅保留在本机私有验证材料中。

## 正式功能

### 1. 紧凑存储与完整读取

- 删除已经有权威 SQL 列的重复消息 JSON 字段，读取时由同一行完整组装消息对象；保留可选字段、来源定位、分支、复制前缀、工具配对和原始正文的含义。
- `textDescriptor.params` 不保存正文副本。使用稳定文案标识和必要参数，展示详情时引用已有正文；中英文显示及原始诊断保持完整。
- 同版地图缺口只存一份，由快照与来源查询共用；不丢失缺口、来源关系或展示信息。
- 完整保留用户／AI 消息、思考、上下文、工具参数／结果、用量和代码活动证据。不新增截断、过滤或搜索范围缩减；正文相同不表示同一次活动，不据此合并调用。
- 保留当前增量解析缓存及全文搜索能力。跨模块共用长正文不在首版实现。
- 新结构为 FTS 关联的消息行定义稳定数据库键；若继续以 rowid 查询，显式声明 `INTEGER PRIMARY KEY`，业务身份仍以来源修订和消息标识唯一约束。空间整理前后必须验证键与搜索关联一致，不依赖普通隐式 rowid 在 VACUUM 后保持不变。
- 当前 Web／CLI／API 从新结构读取完整结果；不新增旧索引格式双读、逐版本迁移或兼容写入。客户端历史格式的支持范围不因内部存储变化而减少。

### 2. 地图仅保留最近两版

- 每个仓库保留最近两个成功发布的完整分析版本，以成功发布顺序判断，不将进行中的或失败的刷新作为保留版本。
- 新版发布与旧版淘汰保持一致性；发布失败不淘汰有效版本，查询不看到半个版本。少于两版时保留已有成功版本。
- 淘汰版本的快照、来源响应及仅供该版本使用的派生记录一并释放，共享配置、解析缓存及会话数据不随之删除。
- 已淘汰版本不能继续查询，也不以当前版冒充；Web／CLI／API 明确反馈所选版本不可用。不增加旧库版本兼容层或历史版本归档。
- 日常刷新只淘汰记录，不触发物理整理。连续刷新后保留版本数有界，空间收益与文件是否缩小分别记录。

### 3. 仅在服务启动时自动整理

- 检查发生在本地服务实际启动、持有生命周期锁后，正常查询及后台 Worker 写入开始前；连接已运行的服务不再次触发检查。CLI 普通查询或刷新不直接执行整理。
- 同时满足空闲页占用至少 **1 GiB**、占主数据库页空间至少 **20%**、距上次成功整理至少 **24 小时**时才执行。空闲量通过页大小和空闲页数量计算，比例以主数据库页数为分母；WAL 等伴随文件另计磁盘占用。
- 未记录过成功整理时间时，满足空间条件即可执行；未达到阈值或时间间隔时直接正常启动。成功后持久化完成时间，失败不更新为成功。
- 实际执行前按当前数据目录所在卷核验临时空间需求，排除其他索引写入者；空间不足或无法取得安全维护条件时跳过并说明原因，继续使用可用索引，不清空数据。
- 整理使用 SQLite 支持的安全方式，保证失败／中断后索引可用；临时工作文件仅用于本次整理，不形成永久备份管理功能，也不在正常流程中生成 `.bak`。
- 整理完成检查数据库完整性及 FTS 与消息关联，确认原有查询结果完整后进入正常服务。若实现无法保证搜索关联稳定，必须重建并验证搜索索引后才标记完整，不把不完整 FTS 当成可用搜索索引。
- 服务运行期间不检查或执行物理整理，不增加定时整理、专门 Web／CLI 维护入口或自动清理原始客户端文件的功能。
- 产品生成的进度、跳过与错误反馈使用中英文稳定消息标识；原始错误详情保持原文。遵循现有反馈入口，不增加常驻解释文字。

### 4. 新安装与后续启动

- 空数据目录直接创建新结构，不寻找旧库、不生成 `.bak`、不执行迁移，也不出现无意义的整理等待。
- 按现有启动配置发现会话来源；没有已登记仓库时地图显示正常空状态，用户登记仓库后沿用正常分析流程。
- 已有新结构索引在重启时复用，正常启动检查与增量刷新沿用既有生命周期；本次整理不额外触发清空、全量重建或结果版本发布。启动整理按上述条件独立判断。
- 资源管理数据库、收藏、管理操作记录、手动盘点来源、语言偏好和回收／恢复材料保持独立生命周期；索引重建或整理不能清除整个数据目录。

## 一次性开发环境验证

下面流程只适用于当前开发环境，由实施任务执行，不写入产品启动路径，不作为用户升级功能。

1. 停止当前服务及索引写入，阻止检查期间自动启动；确认 SQLite 连接关闭、WAL 与主库状态一致，以及实际可用空间足够。
2. 提取仓库登记元信息、手动关联和已知历史文件定位。扫描目录仍使用当前启动配置；不复制旧正文、版本、快照、用量或解析缓存。
3. 将该次旧索引封存为唯一命名的 `.bak` 恢复材料，不覆盖已有备份；只处理索引及其必要伴随文件，不碰资源数据库、偏好和回收材料。
4. 初始化新结构，导入最小配置及定位，重新读取实际来源生成会话索引和各已登记仓库地图。已知定位在默认扫描目录外仍重新检查；真实缺失与读取失败明确区分，失败不伪装成正常零数据。
5. 完成数据库完整性、来源处理和关键功能验证，记录重建耗时、新库占用及重复刷新后的增长。不要求恢复已消失来源的旧历史，也不以新旧总行数必须相等替代来源核验。
6. 全部验证成功后删除仅属于该次操作的旧库恢复材料。失败或中断保留旧库，修复后继续验证；删除前确认使用的是已验证的新库，不清理其他备份或原始来源。

这是对本机旧分析数据的开发清理，不要求给以后安装用户提供旧结构兼容、恢复向导或数据搬迁入口。

## 验收

| 场景 | 成功标准 |
| --- | --- |
| 紧凑格式 | 合成数据读写前后完整对象及正文一致；SQL 与 JSON 冗余消失，翻译参数没有正文副本，地图缺口只保存一份 |
| 完整功能 | 中文搜索、简易／完整／轨迹、画像、用量、Skill／MCP 调用与会话数、地图证据和版本查询结果正确；分支及复制前缀统计保持原口径 |
| 版本保留 | 多个仓库连续成功刷新各保留两版；发布失败、读写并发及共享记录不误删；淘汰版本查询明确不可用 |
| 启动整理 | 阈值边界、时间间隔、首次检查、空间不足、锁冲突、失败和中断均按规则处理；运行期间及普通连接不触发 |
| 搜索关联 | 整理前后消息键稳定且中文搜索结果一致；包含删除造成的行号空洞、工具正文、上下文及分支消息，不能只检查行数 |
| 新安装／重启 | 空目录使用新结构正常启动，无 `.bak` 或迁移；第二次启动复用数据，没有意外全量重建；自定义数据目录同样成立 |
| 数据隔离 | 资源管理、语言偏好和回收材料内容不变；原始历史和客户端配置只读 |
| 端到端 | HTTP／CLI 与真实浏览器覆盖三个模块、中英文、筛选、分页、轨迹下钻、资源列表／地图和错误反馈；管理写操作仅使用隔离合成资源 |
| 空间收益 | 同一组合成输入证明减少重复存储，连续刷新不无限增加地图版本；真实开发重建记录文件、WAL、空闲页及耗时，不承诺固定大小或等同其他产品 |

全套必要测试、类型检查、构建及公开内容检查通过。真实历史验收只公开方法和结论，详细数据留在本机私有材料中。
