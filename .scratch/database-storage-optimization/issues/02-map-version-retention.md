# 地图保留最近两版

Type: task
Status: resolved
Blocked by: 01

## 目标

按[规格](../spec.md)在成功发布后自动淘汰该仓库超过两版的完整地图结果，控制反复刷新的空间增长。

## 范围

- 在现有完整版本发布路径落实最近两次成功发布的保留策略，保持事务与查询一致性。
- 释放淘汰版的快照、来源响应和专属派生数据；共享解析缓存、仓库登记、手动关联、跟踪来源和会话索引保持独立生命周期。
- 处理 Web／CLI／API 对不可用版本的反馈，不将当前版本返回为所请求旧版，不新增无限历史归档或旧库兼容层。
- 日常刷新不执行物理空间整理。

## 验收

- 零版、一版、两版及连续多次成功发布均正确；多个仓库独立保留。
- 失败／中断发布及并发查询不误删当前或上一版，不查询到半个版本。
- 淘汰后专属数据不残留；共享来源及配置仍可用于下一次刷新，会话正文和资源统计不变。
- 保留版完整可查，淘汰版明确不可用；中英文产品提示完整。
- 连续刷新证明保留记录有界，分别记录逻辑删除与物理文件大小，不声称删除记录即完成文件缩小。

## Comments

- 2026-10-08：保留策略只涉及代码地图版本，不减少会话历史内容。

## Answer

- 地图版本使用独立的 `publication INTEGER PRIMARY KEY AUTOINCREMENT`，按成功发布顺序为每个仓库保留最近两版，版本名称及创建时间不参与排序。
- 新版发布、仓库指针更新、任务完成与淘汰在同一事务内执行；淘汰版的快照和来源分块一同删除，仓库登记、手动关联、跟踪来源及解析／映射缓存保留。
- 淘汰版查询保持 `VERSION_NOT_FOUND`，中英文描述明确说明版本不存在或已淘汰，API／CLI 不回退到当前版。
- 验证：连续发布、两个仓库独立保留、创建时间倒序及版本名称乱序、专属分块无残留、缓存配置保留通过；淘汰触发失败时完整回滚新版、分块、仓库指针及任务完成状态，保留原两版。
- HTTP 保留版证据回查及淘汰版 404、CLI 中英文错误与稳定 JSON 通过。相关七组自动化测试共 115 项通过；任务 04 继续核验启动与物理空间行为。日常发布只删记录，不执行 `VACUUM`。
