# 启动时自动空间整理

Type: task
Status: resolved
Blocked by: 01

## 目标

按[规格](../spec.md)在服务实际启动、正常读写开始前自动判断并回收空闲空间；运行期间不整理。

## 范围

- 与 `src/server.ts` 生命周期锁和 Worker 启动顺序衔接，排除其他索引写入者。连接已运行服务及普通 CLI 查询不重复执行。
- 空闲页至少 1 GiB、比例至少 20%、距成功整理至少 24 小时；未有成功时间时仅判断空间条件。成功时间可靠保存，失败不记成功。
- 按实际数据目录核验临时空间需求，选择 SQLite 支持的安全整理方式，失败／中断保持可用索引。
- 核验整理后的数据库完整性、稳定消息键和 FTS 关联；必要时重新灌入搜索索引并验证，不能把不完整索引标为完成。
- 反馈阈值不满足、空间不足、锁冲突及真实错误，产品消息同时支持中英文。
- 不创建正常流程 `.bak`、旧库迁移、定时任务或专门手动维护入口。

## 验收

- 隔离库与可控制时钟覆盖阈值两侧和相等边界、无成功时间、冷却期、连续重启、自定义数据目录。
- 空间不足、维护竞争、错误和中断保留有效数据库；不以删除数据解决失败。
- 服务运行中、刷新结束、查询连接和原有 Worker 不触发物理整理。
- 删除产生行号空洞后整理，正文、行身份及中文搜索结果完整一致；不仅检查消息数和 `quick_check`。
- 资源数据库、偏好和回收材料不变；工作文件不无限积累，只有成功整理更新完成时间。

## Answer

- 新增独立启动维护模块，服务取得生命周期锁后、打开查询及 Worker 连接前调用一次。新安装直接初始化，连接已运行服务及普通查询不重复检查，运行期间没有物理整理任务。
- 使用页统计和成功时间判断 1 GiB／20%／24 小时边界；数据库与临时目录所在卷空间不足时跳过。独占 SQLite 连接排除读写竞争，使用 SQLite 事务安全的 `VACUUM`，没有正常流程备份或旧结构迁移。
- 维护前后核验完整性、外键、显式消息身份、FTS 文档键和全部逻辑表内容摘要；中断的搜索补建先补齐。只有内容校验和时间持久化均成功才报告完成。
- 启动状态提供稳定标识、中英文描述及原始错误；活动信号与持生命周期锁的活 PID／随机身份关联。后台连接只在确认维护仍活跃时延长等待；信号消失或进程死亡后恢复有界失败判断。
- 隔离测试实际删除产生行号空洞，再执行整理，正文及中文搜索结果完全一致；覆盖新安装／重复启动、阈值相等及两侧、磁盘不足、探测失败、读写锁竞争、搜索补建、维护等待与真实 `VACUUM` 阶段强制中断。管理库、语言偏好和恢复材料保持不变，不记录失败的成功时间。
- 验证：新增维护测试 9 项通过；维护与 HTTP／CLI／Worker 回归共 23 项通过；中英文目录及前后端类型检查通过。真实开发库封存与重建前后的一致性仍由任务 05 单独执行。
