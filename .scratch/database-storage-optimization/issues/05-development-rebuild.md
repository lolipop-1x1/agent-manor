# 一次性开发索引重建验证

Type: task
Status: resolved
Blocked by: 04

## 目标

新实现通过隔离验收后，按[规格](../spec.md)对当前开发索引执行一次封存、重建和空间收益验证。这是开发操作，不增加产品旧库兼容、迁移或备份管理功能。

## 执行边界

- 重新核验当前索引路径、运行服务、实际磁盘余量和恢复材料范围；排除自动启动与其他写入，关闭连接并保证 SQLite 主库及 WAL 状态一致。
- 仅带过仓库登记、手动关联和已知历史文件定位，使用当前扫描配置重新读取实际来源，不复制旧版本、正文、统计或缓存。
- 旧索引及必要伴随文件封存为该次唯一命名的 `.bak`，不覆盖已有备份；新库通过新结构正常初始化。
- 缺失文件保留缺口，读取失败直接说明；新旧来源结果差异须能解释，不能用总行数相同代替核验。
- 确认新库完整性、来源处理、中文搜索、轨迹、画像、Skill／MCP 统计、各仓库地图和中英文反馈正确，记录新库大小、WAL、空闲页、重建耗时及重复刷新增长。
- 全部验证成功后删除仅属于此次操作的旧库恢复材料；失败或中断保留，并确认服务仍能使用有效索引。资源数据库、偏好、回收材料和原始客户端文件不变。
- 一次性脚本及真实路径／数据留在仓库外或私有验收目录，不将此流程接入正常服务启动。

## 验收

本机开发服务使用已验证的新库，来源差异有明确说明，空间收益有实际测量；该次旧库仅在成功后删除。失败不得宣称优化完成。

## Comments

- 2026-10-08：用户已授权当前开发旧库可重建、验证成功后删除；明确 `.bak` 不属于以后用户的正常流程。

## Answer

- 关闭旧服务与 SQLite 连接，检查 WAL 状态、磁盘余量和来源存在性后封存旧索引。仅保留 2 个仓库登记、手动关联及 1,005 项已知历史定位；使用 schema 4 从真实来源重建，会话和两个地图任务全部成功，首次重建耗时 1,121 秒。
- 原库当前版本包含 6,408 个来源、1,392,912 条消息；初次重建为 6,442 个来源、1,400,268 条消息，没有来源缺失。6,401 个未变化来源中的 1,315,455 条消息，完整字段、原始正文、用量及会话摘要一致；仅规格允许删除的正文翻译参数副本做规范化比较。
- 对另外 7 个变化来源按原消息身份逐条比对，原有消息全部保留，正文没有改变、序号没有变化。新增 1,875 条消息及 34 个新来源中的 5,481 条消息，共解释新增的 7,356 条；一项变化来源只有指纹变化，没有正文差异。
- 在相同未变化来源范围内，4 个全文查询经 FTS 候选过滤后的最终匹配消息集合、顺序及正文摘要一致；10,312 条 Skill／MCP 使用记录和 441 项资源的完整聚合统计一致。6 个原生来源通过真实 HTTP 验证完整消息、画像和搜索，两个仓库的地图及来源响应均有有效数据。
- 两个仓库连续各刷新两次，每个仓库仍保留最近两版，会话消息数没有改变。后续正常后台重启约 1 秒开始服务；自动刷新复用 6,189 个快速命中与 251 个内容校验命中，只解析 4 个新增或变化来源，无来源缺失。正常重启、自动刷新及最终完整性验证共 306 秒，不将这段验证耗时等同于服务启动时间。
- 最终主库为 8,510,193,664 字节（约 7.93 GiB），旧主库为 23,688,556,544 字节（约 22.06 GiB），减少 64.1%；WAL 已检查点落盘并归零。最终 4 个地图版本，主库空闲页 66,738 页（页大小 4,096 字节）；未达到启动整理阈值，正常跳过。
- 新库 `quick_check`、外键检查和关键查询通过；收藏、归档、操作记录、手动来源、语言偏好及恢复材料保持不变。资源盘点的正常观测时间更新与管理状态分别核验；没有修改原始客户端历史和配置。
- 全部验证成功后只删除本次唯一命名的旧库及其伴随文件，其他材料不清理；正常后台服务继续使用已验证的新库。详细输入、脚本和结果仅保留在本机私有验收目录，没有接入正常产品启动流程。
