# 紧凑存储与完整读写

Type: task
Status: ready-for-agent
Blocked by: none

## 目标

按[规格](../spec.md)实现新结构，消除消息字段、翻译参数正文和地图缺口副本。保留当前功能，不实现旧索引结构迁移或双格式读写。

## 范围

- `src/sessions/store.ts`：消息 JSON 省略已由 SQL 保存的身份、顺序、来源行、轮次、类型、最终回答标识、调用标识和复制状态；所有读取路径完整组装，保留可选值含义。
- `src/sessions/parser.ts` 及相应描述读写：Hook／附件／用量等产品消息不在翻译参数复制长正文；原始详情引用正文，中英文仍可查看。
- `src/index/store.ts`、`src/index/refresh.ts`：同版快照与来源响应共用一份缺口，不丢失来源与缺口关系。
- 为 FTS 关联定义稳定消息数据库键，业务消息唯一性不变；更新必要读写和初始化路径，不迁移旧消息行。
- 梳理共享服务、搜索、轨迹、画像及资源统计中的读取路径，避免只修主消息列表而遗漏后台统计或证据下钻。

## 验收

- 合成数据覆盖完整正文、思考、上下文、工具参数／结果、Hook、附件、用量、分支、复制前缀和可选字段；新格式读回的完整业务对象保持一致。
- 数据库实际存储没有已确认的字段及正文副本，来源查询与快照查询返回相同完整缺口。
- FTS 使用的消息键在删除与重插入场景中正确关联；新库初始化和所有现有查询可用。
- 原始客户端文件只读；当前历史适配范围、统计口径、搜索范围和正文长度保持不变。
- 不增加旧 schema 升级路径，不通过清除必要缓存换取表面空间下降。

- 2026-10-08：用户明确开发阶段不考虑旧数据库兼容。真实旧库的封存与重建单独由任务 05 处理。
