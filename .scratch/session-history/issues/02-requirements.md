# 历史会话与消息轨迹需求讨论

Type: grilling
Status: resolved

## Scope

- 对照已有领域术语和 ADR，按设计树分轮讨论；参考行为不直接作为本项目决策。
- 记录已确认含义，再更新领域术语；只有满足真实取舍及变更成本的决策才新增 ADR。
- 完整需求收敛后向用户确认共同理解，确认前不开始功能实现。

## 第一轮

- H1：推荐本机全部可发现历史，保留客户端／项目／时间筛选及无法归属项目的入口；另一方案为仅已登记仓库关联历史。
- H2：推荐参考 DSH 轨迹并沿用现有三个客户端；另一方案为本次同时新增 DSH 历史来源。
- 用户已确认 H1、H2 的推荐项。

## 补充诉求

- 会话详情展示并可视化模型、Token、缓存及 Skill／MCP／Tool 使用等相关数据。
- 逐项明确原始记录值、可推导值、估算值与缺失值；具体统计口径和视图待后续轮次确认。

## 第二轮

- H3：用户确认记录值、估算值和缺失分开。无依据的模型、缓存和资源调用不补造；基于留存内容的 Token 估算另列。Skill 读取属于读取证据，仅有明确调用时计为调用，文本提及不混算。

## 第三轮

- H4：推荐简易对话优先使用明确的最终回答标记，缺少标记时允许依据消息顺序推断并标注；未完成轮次不补造回答。另一方案为只显示明确标记的最终回答。
- H5：推荐按用户轮次组织可折叠的消息轨迹，联动事件时间线；展开后查看留存的模型步骤、思考、工具、结果、压缩及子会话关系。另一方案为默认平铺所有已记录事件。
- H6：推荐全局及会话内关键词搜索默认检索用户和 AI 正文，工具参数／结果、思考和系统内容可按内容类型加入；搜索命中可跳转并展开对应过程。另一方案为默认搜索全部已记录文本。
- H7：推荐缓存读取占输入 Token 比例，缓存读取 Token 除以归一化后的总输入 Token，并单列缓存写入及用量记录覆盖范围；不能确认分母时不计算。另一方案为以请求是否命中缓存统计请求命中率。

- 用户确认 H4、H5、H7 推荐项；H6 确认默认正文并补充会话标题搜索，过程内容可选。

## 第四轮

- H8：推荐会话画像默认统计当前会话自身，另提供包含已确认子会话的汇总；明确区分父调用、子会话活动和分叉复制历史，缺失子会话保留缺口。另一方案为默认父子合计。
- H9：推荐沿用可重建本地索引，保存浏览及搜索所需消息内容，原始来源只读；原始来源消失时从新版有效结果排除并说明原因，清除索引可从现有来源重建。另一方案为独立长期归档，包括已删除来源。
- H10：推荐沿用服务启动检查更新与主动刷新，统一刷新全局会话索引，完成后发布新版本；不默认持续监听。另一方案为页面打开期间定时检查并增量更新。

- 用户确认 H8、H9、H10 推荐项。

## 第五轮（随整体方案确认）

- H11：推荐留存内容的 Token 体量按用户、AI、工具结果、思考与系统等内容类型拆分，保留估算方法及适用范围，与实际请求用量分开展示。另一方案为仅展示会话留存内容的总量估算。
- H12：推荐会话概览、逐步指标与统计图联动轨迹；包含已记录的全部模型及变化、消息与轮次、用量和缓存、工具状态与耗时、Skill 证据类型、MCP 服务器及工具、压缩与子会话等。另一方案为首版仅提供会话级指标汇总。
- H13：推荐独立会话库入口，代码地图证据可跳转对应会话位置；Web、CLI 与 API 共用列表、搜索、详情、轨迹与画像查询，Skill 文档说明其他 Agent 的使用方式。另一方案为首版仅 Web 会话库。

## Answer

用户认可产品概念图并授权按方案开发；H11–H13 采用推荐项。完整范围见 ../spec.md。
