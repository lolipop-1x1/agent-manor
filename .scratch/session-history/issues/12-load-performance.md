# 长会话加载性能
Type: task
Status: resolved
Blocked by:

## 问题

长会话打开时，列表、消息与画像长期处于加载状态。真实接口已复现画像查询明显慢于列表及简易消息。

## 验收目标

- 定位主要耗时及重复请求，优化必要查询与加载行为。
- 保持消息、Token、复制记录排除与父子汇总的统计口径。
- 用真实长会话对比修改前后接口及页面耗时，验证切换与加载反馈。
- 合成数据覆盖性能问题对应的正确性边界，完成端到端测试。
- 真实数据及测量明细只保存本机，公开记录只包含方法与汇总结论。

## Comments

开始测量：列表与简易消息很快，画像接口约 5 秒。接下来分别核验用量关联查询、文本估算及页面初始化请求。

## Answer

已定位并修复两处瓶颈：用量关联中的 `OR` 导致每个请求反复扫描会话消息；页面初始无版本请求、版本到达与历史完成任务又触发重复加载。画像改用既有索引分别关联消息与轮次，页面先确认版本，并只响应本次观察到的刷新完成。标题可从列表先显示，状态失败提供重试。

在同一真实索引版本核对所有响应字段完全一致。画像 API 三次测量的中位耗时从约 5.5 秒降至约 0.25 秒；Chrome 中列表、消息、画像各一次请求，简易消息由约 10.7 秒降至 0.14–0.34 秒。完整画像显示完成的复测范围为 0.31–1.62 秒，本机启动刷新及资源争用仍会影响耗时。

187 项回归、类型检查、构建和真实 Chrome 端到端通过；复制消息及轮次排除、父子汇总、搜索和主动刷新均已核验。本机服务及当前轨迹页面已更新，详细数据、诊断脚本和截图仅保存在忽略目录。

验收见 [会话历史验收](../../../docs/validation/session-history.md#长会话加载性能复核)。
