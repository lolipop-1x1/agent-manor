# 会话索引刷新性能

## 已完成：发布阶段优化

优化多会话历史的刷新耗时，优先复现发布阶段停留在 99% 的问题。该阶段维持来源内容校验、当前与上版结果一致性、缺失来源排除、父子关系、搜索及画像口径；不修改原始历史。

验收及历史测量见 [任务 01](issues/01-publish-performance.md)。已完成阶段的耗时不能用作后续版本的当前性能基线。

## 新阶段：刷新范围与快速检查

状态：R1～R5 已逐项确认，整体规格待最终确认；生产代码尚未修改。

目标：减少日常会话刷新对无关 Agent 的发现、读取和重复核对成本，继续原子发布完整的全局会话库结果。所有当前支持的 Agent 均能按范围刷新；是否跳过正文读取取决于来源格式的可核验依赖，不由客户端名称直接决定。

### 已确认的产品行为

1. 首版只做按 Agent 选择刷新范围与未变化来源快速跳过；SQLite 按会话更新、JSONL 追加消息续读另立后续任务。
2. 日常刷新默认快速检查，另提供完整校验。完整校验读取内容核对，内容未变仍可复用；不清缓存，不强制重新解析全部来源。
3. Web 主按钮跟随客户端筛选：选择一个 Agent 时刷新该 Agent，选择全部客户端时刷新全部。菜单始终提供刷新全部，并提供对应范围的完整校验。首版不增加独立多选范围。
4. 刷新进度及完成结果明确展示本次范围和方式，保留各 Agent 最近成功检查的时间与方式。只检查某个 Agent 不改写其他 Agent 的检查时间；全局版本发布时间不能代表所有客户端都刚检查过。
5. 只有已确认完整来源依赖的格式才启用快速跳过。缺少快检记录、依赖无法确认或变化时回退到现有内容检查，并在任务结果中说明；不承诺所有格式都可免正文读取。

### 范围、生命周期与一致性

- 刷新范围是 Agent 客户端身份；页面项目、日期、搜索和阅读模式仍只影响查询，不缩小刷新范围。
- 来源发现必须在扫描前限制客户端，不能全局发现后再过滤。多个客户端共用的格式、文件容器或内部引擎不改变客户端身份。
- 局部刷新仅判断所选 Agent 的新增、变化和来源缺失，保留其他 Agent 的有效来源修订及检查状态。未选择的来源即使已经变化或消失，也要等该 Agent 被检查时处理。
- 保持单队列执行；不同范围或检查方式不能错误复用同一任务。执行时采用最新已发布版本为基础，避免连续两个局部刷新相互覆盖结果。
- 本次所选范围完成后，连同未选客户端的保留数据原子发布一个全局版本。搜索、会话、轨迹、画像及父子关系仍查询一致版本；失败保留上一版，也不提前更新客户端成功检查时间。
- 来源确认缺失才排除；暂时无法读取不能当作删除。完整校验及快速检查沿用同一来源生命周期规则。
- 服务启动继续检查全部 Agent，采用默认快速检查；Web、CLI、API 主动刷新采用一致的范围和方式语义。未传范围或方式的既有调用继续表示全部 Agent 的默认检查。
- 清除会话缓存仍是现有的全局清除与重建操作，不因新增范围选择改变其语义；刷新会话库不刷新代码地图。

### 快速检查的实现约束

- 检查来源文件身份、大小、时间等变化指示，以及解析规则和影响标题、项目、模型、会话关系的元信息依赖。文件内容哈希与快检指示分别保存，不用指示冒充内容证明。
- SQLite 检查依赖必须覆盖主库与已提交 WAL，以及相关索引库或元信息库；普通日志也要覆盖旁路元信息。未核验的格式保持内容检查。
- 首次刷新、已有缓存缺少快检信息、规则改变或依赖改变时执行内容检查。正文相同但元信息改变时，相关派生结果也必须更新。
- 一次来源检查过程中若来源继续变化，不发布与读取内容不一致的快检标记；具体稳定性处理沿用现有来源快照边界。
- 快速检查不能严格排除保留相同变化指示的内容改写，完整校验负责提供主动核对入口。任务结果区分快速复用、内容检查及重新解析，说明回退数量或原因。
- 复用现有适配器注册边界声明格式依赖能力，保持保守回退；本次不创建外部插件加载框架，也不改变消息配对、用量及分支统计口径。

### 交互与状态

- 复用项目统一 Radix 组件及现有主题，不添加原生下拉框。当前 Agent 与全部范围、快速检查与完整校验在执行前后均可辨识。
- 各 Agent 显示最近成功检查时间及方式；旧索引没有这些记录时显示未记录，不从全局版本时间推造。
- 范围和方式在提交任务时确定，执行中改变页面客户端筛选不改写已提交任务。
- 进度以本次所选来源为分母，结果说明复用、检查、解析及缺失情况。显示当前任务范围与最新全局结果的区别，避免把未检查 Agent 显示为刚更新。

### 验收

1. 范围隔离：选一个 Agent 不发现或读取其他 Agent 来源；先后局部刷新保留其他客户端消息、搜索结果、画像和检查时间，未选来源缺失不误删除。
2. 快检效果：同一数据连续刷新，无变化且依赖已核验的来源无需正文读取或重新解析；缺少检查记录或不支持快检的格式自动回退，完整校验实际核对内容。
3. 变化检测：覆盖追加、截断、替换、同大小改写、解析规则变更、元信息单独变更、SQLite WAL 提交及来源缺失。主动保留快检指示的内容改写通过完整校验发现。
4. 结果一致：新增与变化来源按既有解析规则更新；父子关系、副本、分支、工具与 Token 口径不变；失败、临时读取错误及排队任务不发布部分更新或成功时间。
5. 各入口一致：Web、CLI、API 默认调用与范围／方式参数符合规格，完整校验不误复用快速检查任务，旧调用兼容。
6. 真实端到端：在本机现有历史验证当前 Agent／全部及完整校验、进度、检查时间和筛选切换，核对代表性会话与查询结果。先测当前版本基线，再在相同来源稳定度与范围下对照阶段耗时和正文读取数量；不预先承诺固定倍数。
7. 公开边界：真实历史、身份、来源路径、详细计时及截图只保存在本机忽略目录；公开测试与文档使用匿名合成样本，原始来源只读。
