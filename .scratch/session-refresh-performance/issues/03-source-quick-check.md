# 来源范围与快检能力

Type: task
Status: resolved
Blocked by: 02

## 目标与验证

负责来源发现前按客户端限制；在适配器注册边界声明已核验快检能力；生成包含文件身份与稳定性指示的检查标记；未核验格式回退。验证文件变化、范围隔离与来源元信息依赖。

具体行为与边界见 [规格](../spec.md)。

## Answer

- `discoverSources` 在遍历客户端目录前限制范围；缓存位置仅在已核验依赖标记相同后复用，避免无变化 JSONL 再读头部。空客户端范围与显式空 roots 均不扫描。
- 快检能力声明在格式适配器中。标记区分客户端、格式、原生选择器及能力版本，检查文件身份、大小、纳秒级修改／状态时间；旁路元信息缺失也参与标记，新建、变更及删除都会重新发现。
- 首批支持 Codex、Claude Code、CodeFlicker CLI、CodeBuddy、Qoder 的单文件格式，以及 CodeFlicker 桌面 JSONL 和其 checkpoints 注册信息。会话刷新层继续单独核对标题、项目及模型等已存在的元信息指纹。
- Pi 父文件读取、DeepSeek Harness 副本选择、WorkBuddy 向上查找元信息库，以及 OpenCode／ZCode／桌面 IDE SQLite 暂未声明完整快检依赖，继续内容检查；不只凭主数据库时间或客户端名称跳过。
- 新增 6 项合成回归覆盖范围隔离、warm 头部零打开、追加／截断／同大小改写／替换、选择器、未核验格式、符号链接及桌面注册信息变化。新测试 6/6、相关适配器回归 20/20、服务端类型检查通过。刷新前后稳定性及元信息复用由任务 04 集成验证。
