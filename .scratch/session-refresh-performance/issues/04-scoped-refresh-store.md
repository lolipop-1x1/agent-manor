# 范围刷新与发布存储

Type: task
Status: resolved
Blocked by: 02

## 目标与验证

负责来源检查复用、范围外修订保留、完整校验、计数及客户端检查时间的原子发布。验证排除范围内缺失、失败恢复、队列基础版本、旧缓存兼容、元信息与快检变化。

具体行为与边界见 [规格](../spec.md)。

## Answer

- 按任务范围发现与检查来源，执行时读取最新已发布基础版本，保留范围外来源及客户端检查记录；范围内缺失从新版排除，暂时读取错误保留前版。
- 来源位置、快检及元信息指纹分开持久化，旧缓存没有检查记录时回退；完整校验读取正文但允许复用相同修订。各 Agent 成功检查时间与全局版本原子发布，失败不更新。
- 发现前后核对来源依赖，并把发现时的稳定标记与刷新、保存时的标记联动。发现窗口或首次检查前元信息变化时不保存快检标记；该瞬态标记不进入位置缓存或元信息指纹，下次重新发现获得新归属。
- 合成快检与范围刷新回归 15/15、适配器及存储回归 47/47、服务端类型检查、公开内容及 diff 检查通过。新增回归直接覆盖发现期间及发现后首次检查前的注册信息改写，验证后续刷新采用新项目且稳定后可再次快检。

## Comments

- 按已确认规格直接在主干开发，不创建开发分支。
- 已实现按任务客户端限制发现、执行时读取最新基础版本并保留范围外修订。完整校验读取正文，相同内容允许复用；默认快速检查核对来源变化指示、解析规则与旁路元信息，依赖不足自动回退。
- 来源位置、变化指示及元信息指纹以可空字段迁移；旧缓存首次回退内容检查，不从全局版本时间推造客户端检查记录。客户端成功检查时间及方式与完整版本原子发布，失败保留前版和原检查时间。
- 新增 7 个合成回归覆盖范围隔离、连续局部刷新、实际正文读取、旧缓存／表迁移、内容与标题变更、规则失效、错误变化指示下的完整校验、活动追加、旁路读取失败和全局清缓存重建；与既有存储／项目回归共 36 项通过，服务端类型检查通过。
