# 发布阶段性能与一致性

Type: task
Status: resolved

## 验证

用真实 publish 调用构造匿名多会话规模场景，记录各 SQL 耗时与查询计划；同数据对照优化前后。验证副本择优、父子声明冲突、循环、缺失来源、上版对照、搜索及画像一致。真实本机的刷新阶段时间与诊断材料保存在忽略目录。

## Answer

瓶颈为子目标关联查询的连接顺序：查询计划先按版本扫描子会话，再扫描父会话，最后展开父声明的目标，即使没有实际目标也产生大量无关组合。关联与显式父冲突查询改为先展开目标，再使用版本和完整会话身份查找；没有更改父子识别或统计规则，不增加数据库表，也不使来源缓存失效。

2,000 个合成会话的原始发布对照为约 3.7～4.0 秒，修改后约几十毫秒；包含稀疏子声明的正式性能回归先以约 4.2 秒失败，修改后通过 1 秒预算，并检查列表、搜索、父子画像及上版结果。23 项存储回归和 2 项 HTTP／Worker 回归通过，构建、类型检查、公开内容检查与 CLI／HTTP／Chrome 端到端通过。

数千条真实会话的刷新从约 130 秒缩短到约 35 秒，发布阶段从约 96 秒缩短到约 5 秒；移除临时诊断后的正常服务再次核对通过。未变会话的摘要和父子关系保持一致，正在追加的来源按既有规则更新。来源仍完整校验，当前与上版仍原子发布；旧修订清理也继续执行，因此首次重建及大量旧修订清理不能套用上述增量耗时。详细时间和真实身份只留在本机忽略目录。
