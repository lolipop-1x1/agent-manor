# 刷新范围与快速检查规格

Type: grilling
Status: resolved

## 目标

缩小会话刷新来源发现范围，减少未变化来源的重复读取，同时保留全局会话库的结果一致性与来源生命周期。

## 已确认

- R1：先实现 Agent 范围选择与快速跳过，不同时做消息级或会话级续读。
- R2：默认快速检查与完整校验入口，完整校验仍可复用相同内容索引。
- R3：当前 Agent／全部两种范围，主按钮跟随客户端筛选，菜单提供全部刷新。
- R4：范围与方式可见，各 Agent 独立记录最近成功检查的时间及方式。
- R5：仅完整依赖已核验的格式启用快检，其余保守回退并说明。

## 验证

规格覆盖未选来源保留、缺失判断范围、队列任务去重与发布时基础版本、SQLite WAL、标题／项目／模型依赖、失败恢复与快检可信度边界。详细行为与端到端验收见 [规格](../spec.md)。

## Comments

- 已复核来源发现、缓存核对、版本发布和 Worker 队列：现有发现循环覆盖所有客户端，现有发布以本次来源集替换全局结果；实现范围限制时必须同时修正发现与发布，不能仅过滤最终列表。
- 环境事实由只读探索核验，逐项问题均已回答。待整体共同理解确认后将本任务标为完成并进入开发。

## Answer

用户明确要求按 implement-spec 开始开发，整体规格确认。实现采用现有单队列及版本发布机制，按客户端限制来源发现并保留未选修订；各格式依赖核验与性能结论在实现任务中记录。
