# 总览查询与洞察优化

状态：用户已确认实施。基点为 `1294115`；本规格覆盖旧总览规格中的两期热点、完整洞察列表与集中查询约定，其余统计口径继续有效。

## 用户结果

- 移除代码活动的两期热点比较、前期覆盖字段、切换控件及相关洞察。保留各仓库当前范围摘要、单期热点与代码地图入口。
- 每个范围最多五条核心洞察，兼顾用量变化、项目／模型分布变化、资源习惯变化及有依据的过程调查；无价值或小样本不补足。取消完整洞察列表。输入片段、失败后续调用及资源组合继续作为按需调查，不逐条生成洞察。
- 六项概况、活动、用量、资源、过程、仓库及核心洞察分区请求。首次可分别呈现完整分区；全局筛选／更新仍保留上一完整报告和布局，固定进度、暂停旧下钻，同一快照准备完成后替换。模型只影响既有局部分析，范围和版本不混用。
- 完整排行、资源分布、观察、组合、计时及项目月份／模型路径使用服务端分页或对象级按需查询；首页只返回摘要和所需前几项，不能先计算完整细项再截断。

## 数据与缓存

- 复用现有结构化用量事实及持久化小时汇总。新增活动、工具、资源派生事实按不可变会话修订保存，未变修订可跨完整版本复用，新增或变化只重建相应修订。
- 常用统计在可重建 SQLite 派生库保存。版本、统计规则格式、价格、时区、日期锚点、筛选和仓库版本进入适当缓存身份；缓存命中仍先检查版本可用。费用变化不重建原始 Token 事实。
- 核心概况和活动通过窄事实／时间桶聚合，避免每次解压全历史或读取完整请求 JSON。记录配对、复制排除和真实活动规则不放宽，原事件仍按身份读取。
- 对正常查询合作调度，耗时细项不能堵住核心区域。相同在途请求合并；缓存有界、原子写入、权限受限，损坏或不可写可回退，派生数据不含消息正文或工具参数。
- 原始会话保持只读，不自动登记或重新分析仓库，不停止其他服务，不修改客户端配置。

## 公共 API 合约

- `GET /api/v1/overview/snapshot`：固定查询版本、价格、时区、日期锚点及范围。
- `GET /api/v1/overview/panel?panel=core|usage|resources|process|repositories|insights`：使用明确快照条件返回一个完整分区。
- `GET /api/v1/overview/detail?detail=<JSON>`：固定快照中的排行／对象／派生调查分页。
- 既有 evidence 继续用于具体记录分页与原事件。既有 report 入口保留为兼容完整统计入口，但不得重新生成海量洞察。
- 类型见 `src/overview-contracts.ts`。分区的 `data` 只包含该分区字段；首页行数和完整行数分别由 `counts` 表达。具体规则与未知状态按帮助查看，不增添常驻解释小字。

## 成功标准

1. 核心洞察不超过五条，不生成片段／序列／组合／两期仓库洞察；每条结论可回查，有样本与范围。
2. 两期热点计算、返回字段和界面均移除；单期代码地图路径与版本仍正确。
3. 同一真实索引、价格、时区、日期下，六项指标、活动、用量、资源与过程数量等价；覆盖、未知、连续和父子去重保持。费用求和误差只能是已记录的浮点顺序差异。
4. 真实数据区分首次派生回填、重启后读取、未命中范围和重复查询；目标同版本重启后首屏一秒以内，常用缓存查询半秒以内。未达到继续定位并修复，不把后台总耗时或页面外壳可见当成指标就绪。
5. 首屏数据量显著缩小；详细调查、筛选、返回、刷新、中英文、深浅主题与窄屏在内置浏览器操作验收。
6. 类型、国际化、相关及完整测试、公开内容检查通过；真实身份、截图和测量原始输出仅留本机忽略目录。
