# 首次初始化性能与终端进度

## 已确认行为

- 空库开始时保存准备中标记，首次中断后仍等待完整初始化；已有可查询历史的旧目录即使缺少新标记也快速打开。
- `am start`、`am web` 首次等待完整历史、搜索索引、用量与默认总览首屏缓存；后者在完成后打开浏览器。
- 空目录没有已注册仓库，跳过地图；已有仓库时准备对应地图。
- 已有完整数据时快速返回，后台增量检查；显式等待仍可使用。
- 终端持续呈现阶段、实际数量及耗时，列出客户端扫描目录与来源数，导入展示当前来源、解析／复用数及解析线程数；JSON 标准输出保持可解析。
- 不因启动额外创建全量知识生成或向量任务。失败保留诊断与可复用来源，不打开浏览器。

## 实施顺序与验证

1. 固定真实来源样本保存优化前基线，所有详细材料留在忽略目录。
2. 冷导入为对话保留精确全文索引、全过程使用字符索引并延后普通索引，合并批次内同一消息重复写入；验证正文、元数据、短词及长词搜索、中断续建、热增量。
3. 预热默认总览全部区域及周复盘；添加完整初始化标记，检查失败、中断、零仓库、零历史。
4. CLI 冷启动等待并显示双语阶段进度，验证热启动、显式等待、超时、错误、JSON 输出与后台独立生命周期。
5. 每轮按 CPU 与内存选择 1～4 个解析线程，验证低配边界与性能；移除未引用头图并保留本机备份。
6. 实际 CLI、服务与浏览器检查；记录耗时、资源、数据等价及验收边界。

## 约束

仅实现本产品方案；文档不叙述外部项目。保留原始历史与完整发布边界，不使用截断工具内容换取速度。不删除用户现有数据；全局命令更新时只重启已核验实例并保留端口。
