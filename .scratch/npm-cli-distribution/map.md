# npm 交付与完整 CLI 需求访谈

Type: grilling
Status: resolved

本轮梳理 npm 安装、CLI 工程、后台生命周期、启动数据准备与功能覆盖。用户要求先讨论方案；当前只记录需求和决定，不实施代码、不调整发布配置，也不发布 npm 包。

## 已确认需求

- 一次 npm 安装即可获得 CLI、本地后台、Worker 和已构建 Web；用户无需从源码构建前端或常驻终端。
- CLI 需要独立、完整的工程组织，覆盖服务生命周期、版本、状态、更新及页面已有业务能力，包括知识的读写与沉淀。
- CLI 与 Web 复用本地后台业务 API；实际服务地址必须可自动发现。
- 后台启动输出可查看的阶段日志；关闭终端后继续运行，提供停止命令。
- 启动阶段需要规划历史同步、索引与常用分析结果的准备。
- 设计文档只描述本产品自己的方案。
- 默认端口已确认改为 16666；占用时顺延，最多尝试 100 个候选，仅地址占用继续尝试。显式固定端口冲突则报告错误；成功绑定后持久记录实际端口。
- 同时优化现有配套 Skill，以主 SKILL.md 和按功能拆分的 references 随 npm 包交付；CLI 提供安装命令，支持 Claude Code、Codex 的发现目录，以及用户自定义路径。
- Skill 从实际任务场景引导使用 CLI，而非只列命令。例如从一个 Agent 客户端回查另一个客户端的历史，通过会话库搜索后读取具体对话及工具依据。已将“跨客户端会话回查”补入领域术语。
- 首次交付正式支持 macOS、Linux 和 Windows，三平台安装、后台生命周期和原生依赖均须验收；不能以未验收的实验支持代替。
- 第一轮 Q1、Q2、Q3、Q7 已确认按建议：独立 CLI 工程、统一同版本交付；显式命令安装 Skill；保护用户修改；显式更新并处理旧后台和在途任务。
- 第一轮 Q4、Q5 已确认按建议：普通查询按需启动，状态等命令只读；服务先就绪，数据和缓存后台准备，支持显式等待。已开启策略按原开关与预算恢复。
- Q8 已确认保留人工审阅；CLI 和 Web 核对具体修订后单独确认，非交互审批需用户明确授予该次操作，普通 Agent 提交默认待审。
- Q9 已确认首版矩阵为 macOS arm64/x64、Linux arm64/x64、Windows x64，Node.js 24；Windows ARM64 后续补充。
- 名称已确认：npm 包名 agent-manor，主命令 agent-manor，缩写 am。安装与发布面向 npm 官方公共 registry。
- Q10 已确认正式交付采用 MIT，许可文件与包元数据在实施阶段应用；没有提前修改当前发布状态。
- CLI 技术选型已确认使用 TypeScript 与 Commander.js，在 packages/cli 建立内部私有 workspace；根产品统一构建并分发编译后的 JavaScript，使用 Node.js 24 运行。两个命令共用 dist/cli.js，包内包含 Web、Worker 和完整 Skill，不要求用户安装另一个内部包或自行构建。

## 已核对现状

- 根包已有 Commander.js、bin、后台及 Web 构建与打包入口，也有本地 tarball 包外安装测试；当前包仍 private，许可元数据仍为 UNLICENSED，未公共发布。MIT 是已确认的实施目标，尚未应用到发布文件。
- CLI 已覆盖部分会话、仓库及资源操作；知识、总览、用量和完整设置等仍需命令适配。
- 同一数据目录已有实例记录、启动锁和健康核验；默认动态端口，尚无默认端口顺延策略。
- 后台已可脱离终端运行，但子进程输出丢弃；缺少完整的 start/restart/logs/update 体验，status 当前会自动拉起服务。
- 已有 ADR 0002 要求 Web 与 CLI 共用本地后台，ADR 0017 将已启用的历史自动同步交给后台；本轮没有推翻这些决定。
- 知识管理 API 当前将人工审阅与普通 Agent 写入区分，完整 CLI 需设计明确管理入口，不能靠伪造浏览器请求绕过约束。
- 包内现有 Skill 只包含主文件与宿主元信息；正文的相对 CLI 和文档路径依赖仍处于包目录，复制安装后需要改为自包含引用及可验证的 CLI 定位方式。

## 决策树

- 工程和交付边界：已确认独立 CLI 工程与统一同版本产品包，见 ADR 0020。
  - 已确认 Commander.js、packages/cli 内部 workspace 和 JavaScript 交付；按已记录结构实施构建、兼容入口与安装测试。
- 命令执行边界：已确认普通查询按需启动，状态与诊断只读。
  - 后续细化命令帮助、退出码、JSON、超时和任务等待。
- 启动准备：已确认服务先就绪，数据准备单独表达，见 ADR 0021。
  - 后续细化历史检查、FTS、用量、总览预热、模型任务恢复和失败重试。
- 业务操作对等：CLI 覆盖全部页面业务能力。
  - 已确认人工审阅含义，后续细化知识发布及其他管理动作的确认、批量与非交互流程。
  - 已整理按领域的 Web/API/CLI 静态差距，实施时逐项登记命令与验收结果。
- 发布支持范围：已确认 macOS、Linux、Windows 三平台正式支持。
  - CPU 架构、Node 范围、包名和 MIT 已确认；后续细化原生依赖、CI 安装矩阵及发布账号。
- 更新与运行中后台：已确认显式更新，检测旧后台，保留在途任务处理选择。
  - 后续细化版本握手、任务停止边界、迁移、备份、失败处理和不同安装方式。
- Skill 分发：已确认随包交付、场景引导、按功能拆参考及可选安装路径。
  - 已确认显式 skills install，支持目标和范围选择及自定义路径；重复安装同版跳过，用户修改先展示差异并保留备份，由用户明确选择覆盖。
  - 后续细化安装清单、版本兼容、更新、移除与引用完整性验证。

## 当前决定与后续方案

已确认范围整理于 spec.md，完整设计与命令覆盖矩阵进入 docs/design/npm-cli-distribution.md。

页面业务操作和当前 API／CLI 差距已静态核对，见 capability-matrix.md。主要新增工作为总览、用量、知识、偏好、价格与语义管理、导出及回放数据；现有仓库和资源命令继续保留兼容。该清单不代表已完成运行或跨平台验收。

- 普通数据命令按需启动；status/version/help/doctor/logs 等不启动服务。
- 必要初始化完成即可提供服务，本地数据更新与常用缓存准备后台进行；支持显式等待，已有完整结果继续可读，首次准备中明确呈现。
- 已配置自动策略按原有开关和预算恢复，进程启动不额外新建全量模型任务。
- 当前有效 npm registry 与项目 .npmrc 均指向官方公共源；锁文件已核对无其他 registry 下载地址。公共 registry 暂未查到可公开读取的同名包，不等同于已取得发布权限。

CLI 管理操作继续保留明确确认、版本校验及既有恢复能力；普通 Agent 提交知识默认待审，非交互审批需明确授予该次操作。MIT 已确认，实际发布账号仍需在发布阶段核验；端口、日志和运行策略采用整版方案记录的默认值。
