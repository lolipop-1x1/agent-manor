# 后台生命周期与启动数据准备

Type: task
Status: resolved
Blocked by: none

规格：[整体方案](../../../docs/design/npm-cli-distribution.md)，[能力覆盖清单](../capability-matrix.md)。

## 范围

src/service/runtime.ts、src/server.ts、生命周期和启动状态测试及必要契约

## 验收

默认 16666 冲突顺延、实例身份与版本校验、后台日志轮换、停止等待、服务与数据准备分别表达，保留自动策略和完整版本。提供 CLI 可复用的 lifecycle 函数。

管理写入与运行验收使用隔离的合成数据，禁止改变真实数据目录、模型 Key 或正在使用的服务。

## 实现与验证

- 生命周期公共入口位于 `src/service/runtime.ts`，状态检查和日志读取保持纯读，按需启动校验身份、产品版本及生命周期协议；更新锁期间拒绝重新启动。
- 新实例默认尝试 16666 至 16765，显式固定端口冲突直接失败；启动通过数据目录锁串行化，停止等待实例记录清理且不按端口误停其他进程。
- HTTP 就绪后在后台顺序准备历史、用量和默认总览，状态包含绑定版本、阶段及任务身份，失败保持 HTTP 和已发布历史；模型策略沿用保存配置。
- 日志只记录生命周期元信息，单份默认 10MiB、总计五份，并限制本机文件权限。
- `tests/service-lifecycle.test.ts` 八项覆盖纯读、端口、准备与超时、失败、错误身份与旧版本、日志、更新锁及首次 Worker 初始化中关闭；与 HTTP、会话、维护回归共 33 项通过。
- 默认分析 Worker 延迟到首次实际任务创建，停止时等待原生模块初始化握手；Worker 队列、异常重试及仓库删除／发布边界的 26 项组合回归通过。
- `tests/service-cli.test.ts` 五项通过，实际运行源码及包外编译产物命令，覆盖并发启动、数据返回一致性、Worker、静态 Web、停止和重启。
- 当前运行验收为本机平台；其他平台由发布矩阵执行，不把源码分支覆盖视为已运行平台验证。
