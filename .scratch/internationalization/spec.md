# 中英文切换与语言扩展

## 状态

I1–I12 已全部确认，01–08 已完成实现、独立评审及验证。详细结果与支持边界见 [验收记录](validation.md)。

## 目标与范围

首版为 AgentManor 提供简体中文与英文产品显示语言，覆盖全部 Web 和 CLI 人类可读输出。后续通过同一翻译目录与语言注册方式扩展，不为每种语言重写页面交互。

| 展示面 | 首版覆盖 |
| --- | --- |
| Web 共用部分 | 顶栏、导航、主题／语言入口、筛选、日期、分页、弹层、Tooltip、帮助、加载／空态／错误、可访问名称 |
| 代码地图 | 仓库导航、筛选、地图控件、图例、统计、详情、刷新状态、采集缺口 |
| 会话库 | 列表／搜索、简易／完整／轨迹、分支与轮次、时间线、消息类型、画像／用量图表、刷新状态与缺口 |
| 资源管理 | Skill／MCP 列表／地图、排行／诊断、筛选、统计、使用证据、详情、管理预览／结果、收藏与操作记录 |
| CLI | 命令帮助、参数描述、已有的人类摘要、产品生成的错误及反馈 |

多数 CLI 命令目前默认输出 pretty JSON，`--json` 输出紧凑 JSON。首版不将这些命令改成人类表格，也不改变输出契约。项目源码注释与开发文档继续使用中文，不在本次范围内自动翻译。

## 内容与协议边界

- 会话标题与消息、搜索片段、Skill 正文及来源描述、MCP／工具／模型名称、路径和配置值保持原文。
- 产品生成的“未命名”“未记录”“无项目”等显示标签可翻译；必须根据来源字段或明确的状态生成，不通过比对某段原文来猜测。真实标题即使恰好等于这些词，也不替换。
- API 字段、标识、枚举、路由及参数，CLI 命令名／参数名，JSON 中的数值、时间戳与原始诊断不随语言改变。
- 可以为现有产品诊断增加可选的消息标识与参数，但保留既有字段；同一数据的 JSON 不因显示语言不同而改变。
- 搜索继续匹配原始标题、正文、名称与路径，原始排序和并列项规则保持一致。

## 语言入口与自动检测

- 顶栏主题按钮附近提供全局语言菜单，复用现有 Radix 菜单及主题／焦点规范。
- 菜单提供“自动（跟随浏览器）”“简体中文”“English”，显示当前选择；名称与可访问名称随当前语言呈现。
- 自动检测优先使用浏览器语言列表中的首个已支持语言系列：中文系列映射 `zh-CN`，英文系列映射 `en`；没有匹配项时回退英文。
- 手动选择立即更新当前 Web 页面与 HTML `lang`，不刷新页面、不重建索引。切回自动移除共享手动覆盖，并重新检测浏览器语言。
- 初始加载先取得共享偏好再确定产品语言，避免把尚未读取的偏好当成自动模式。偏好读取失败时仍可按自动规则展示，并如实反馈失败。

## Web／CLI 共享偏好

- 偏好写入当前本地数据目录中的独立设置文件，不依赖可重建的代码地图、会话或资源使用索引；服务重启、清除索引后继续保留。不同数据目录互不影响。
- 首版共享设置只记录手动显示语言；自动模式表示没有手动覆盖。使用本地服务的设置读写入口，保存失败不得显示为已保存。
- 当前页面立即切换；其他已打开页面在重新获得焦点时重新读取共享偏好。各页面处于自动模式时按自身浏览器环境解析。
- CLI 每次命令启动读取该数据目录的最新偏好，一次命令执行期间保持同一语言。
- CLI 优先级为 `--lang` → `AGENT_MANOR_LANG` → 共享手动偏好 → 系统语言环境 → 英文；参数与环境变量只影响本次执行，不写回设置。
- `--lang` 支持 `zh-CN`、`en` 和 `auto`；显式 `auto` 按系统语言环境检测，不采用较低优先级的共享手动偏好。无效参数明确报错，不能默默回退。
- CLI 自动检测依次使用非空的 `LC_ALL`、`LC_MESSAGES`、`LANG`，识别语言系列并忽略编码后缀；未支持语言及 `C`／`POSIX` 回退英文。无效的显式环境覆盖如实报错。
- 帮助输出也遵循以上规则；读取偏好所用数据目录与 `--home` 等现有运行配置一致，不引入另一份语言目录配置。

## 本地化呈现

- 数字、百分比、日期时间、图表刻度、日历及数量单复数统一按当前显示语言格式化。
- 日期使用清晰、不易混淆月日的展示格式；日历中的月份、星期及自定义可访问名称一起切换。
- 保持既有统计时区和本机日期筛选语义。日期值仍为 `YYYY-MM-DD`，相同日期产生相同 ISO 查询边界；统计范围、查询条件、排序不因语言变化而改变。
- 缺失、估算、近似、部分记录和失败等关键状态保持直接可见；辅助公式与说明继续放入统一帮助入口，不新增常驻解释性小字。

## 目录、提示与扩展约定

- Web、服务端产品提示与 CLI 共用 `src/i18n/` 下的语言目录与消息描述契约；按共用、代码地图、会话、资源、诊断和 CLI 划分文案，使用稳定标识、参数插值和语言复数规则。
- 启用语言由统一注册表确定，注册表包含显示名称、格式语言与日历配置；菜单只展示已经通过验收的语言。
- 推荐使用 i18next 与 react-i18next 支持本地目录、回退、复数和 React 运行时更新。实施时核验兼容版本并锁定公开依赖，不使用远程翻译服务。
- 产品错误、刷新阶段、采集缺口、管理预览与反馈由生成端附带稳定消息标识及参数，Web／CLI 渲染时翻译；不靠客户端替换中文句子。
- 原始 `message`／`reason` 等字段继续保留。外部程序错误与无法识别的旧诊断原样显示，配合本地化的“原始详情”标题；不声称未保存的旧数据已经完整翻译。
- 已有索引可包含旧诊断。语言切换无需重建索引，也不为翻译主动读取全部历史；没有描述标识的旧文本沿用原始详情规则。
- 中英文目录须完整，开发检查对缺失键、参数差异和不符合本语言的复数项失败；运行时意外缺失优先回退英文，不把翻译键直接展示给用户。
- 新语言须补齐目录、参数／复数、日历与格式配置，并通过界面和可访问验收后才启用。首版不承诺尚未验收语言或书写方向的布局效果。
- 后续开发约定写入 AGENTS.md，页面与同类控件继续复用现有统一组件。

## 状态与交互稳定性

切换语言保留当前路由、模块、选中会话／资源、阅读模式、分支、消息定位、筛选值、分页、展开状态、地图缩放／平移与刷新任务状态。语言变化只更新产品呈现，不重置数据视图，不触发语言无关的历史查询或管理操作。

保存设置失败时明确说明偏好未持久化；不能用成功提示掩盖失败。异常及原始详情沿用统一弹层／错误反馈规范，不增加逐字段说明。

## 验收标准

1. 中英文下全部三个模块与共用控件可用，导航、帮助、空态、产品错误、图表提示和可访问名称完整切换；HTML `lang` 正确，英文长文案在深浅主题与窄屏中可读。
2. 支持手动选择、回到自动、重新打开与服务重启。不同数据目录隔离；清索引后偏好保留。其他 Web 页面重获焦点同步，CLI 新命令读取最新选择。
3. CLI 参数／环境／共享偏好／系统环境的优先级和无效参数报错有测试。帮助、摘要与产品错误双语可读；单次覆盖不写回设置，执行途中语言不变。
4. 同一输入在不同语言下，现有 pretty JSON 与 `--json` 的字段、枚举、原始文本、数值及时间戳相同；新增可选描述标识也与显示语言无关。
5. 原始消息、标题、资源正文／描述与名称、路径、配置值及搜索片段不翻译；产品兜底标签可切换而真实同名内容不被替换。
6. 数字／百分比／单复数与日历随语言更新，日期筛选值与查询边界相同；原始排序、统计范围、Token 与调用等数值不变。
7. 切换前后核对路由、筛选、分页、选中项、展开状态、消息定位和两种地图视野；无需重新加载历史，不触发索引重建。鼠标／键盘菜单选择及 Escape 焦点恢复正常。
8. 产品诊断通过稳定标识翻译，外部／旧诊断保留原始详情；保存失败不显示成功，运行时缺失回退英文，目录缺失或参数不匹配使开发检查失败。
9. 真实浏览器覆盖三个模块、日历、搜索／空结果、分页、帮助、统计和资源管理预览／结果。所有管理写操作使用隔离合成资源，测试不改真实客户端配置。
10. 类型检查、自动测试、构建、双语端到端与公开内容检查通过，新增文案和语言扩展规范有开发文档。

## 实现前现状与依据

前端没有现成国际化目录或专用依赖；HTML 固定简体中文，日历使用固定中文 locale，数字／日期格式分散在多个组件。已有主题入口可用于统一语言菜单样式，日期筛选采用本机时区与 `YYYY-MM-DD`。

服务端错误、解析缺口、刷新阶段和管理反馈包含自由中文文案，部分直接进入 Web；仅替换前端字面量不足以完成覆盖。CLI 无语言参数或环境处理；已有覆盖摘要为人类中文，其余多数命令默认为 pretty JSON。这些是设计阶段的静态源码基线；实现与运行时验收结果记录在任务图及 08 中。

候选依赖依据为 i18next 的[回退规则](https://www.i18next.com/principles/fallback)、[数量复数](https://www.i18next.com/translation-function/plurals)和 react-i18next 的[组件翻译接口](https://react.i18next.com/latest/usetranslation-hook)。实现已锁定公开的 i18next 依赖，React 通过共享 Provider 订阅语言偏好与呈现更新。
