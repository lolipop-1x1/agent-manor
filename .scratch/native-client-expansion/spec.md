# 七个原生客户端的完整接入

Status: resolved

## 目标与已确定范围

新增 Gemini CLI、Qwen Code、新版 Kimi Code CLI、Oh My Pi、Grok Build、Reasonix、Codewhale 的独立客户端身份与原生来源适配，覆盖现有产品全部能力。

首轮按固定上游版本核对生产写入、读取、配置加载和迁移规则，使用人工合成来源完成验收。原生客户端运行、实际权限及配置重载效果单独记录为未验证。当前平台边界保持 macOS，不扩大为跨平台运行承诺。

版本采用当前正式发布版，Grok Build 固定源码提交；不额外增加旧代际适配。各版本及来源特点见 [来源支持矩阵](source-matrix.md)。

## 产品行为

| 能力 | 成功标准 |
| --- | --- |
| 来源发现 | 自动发现已核验默认入口，支持明确目录覆盖；禁用来源时不读取该客户端目录 |
| 会话库 | 保留实际客户端身份、原生会话及消息身份、项目、消息顺序、终答状态和缺口，支持搜索及对话导出 |
| 执行轨迹 | 按原生身份配对工具请求和结果，保留失败、取消、缺少结果与未确认结束；不将后台事件变成用户需求 |
| 分支与子会话 | 仅依据明确父链、委派、分叉或回退记录建立关系，不按相同正文或接近时间猜测 |
| 代码地图 | 从成功工具返回及实际补丁提取活动与可确认内容；失败、截断、搜索和位置未知分别保留 |
| 用量与总览 | 按可确认模型请求去重，逐来源核对输入、缓存、输出及推理桶口径；时间不足不补造速度，费用继续采用既有估算规则 |
| 资源使用 | 从显式调用、成功正文读取和结构化工具身份提取 Skill／MCP 使用证据，名称汇总与实际入口保持区分 |
| 资源盘点 | 按客户端配置加载层识别用户、项目、兼容、插件、系统及托管来源，保存选择顺序、原生状态和覆盖原因 |
| 资源管理 | 预览实际目标及原生控制范围，保存恢复材料；普通入口按已核验方式停用、回收和恢复，冲突不覆盖当前内容 |
| Web 与 CLI | 共用客户端声明和统计语义；中英文显示、可访问名称、筛选与已有页面状态继续一致 |
| 历史刷新 | 完整依赖未核验时读取内容；元信息、旁路文件和数据库提交状态参与已开放的快速检查 |
| 原始证据 | 规范化后仍可回到原始文件或容器记录并校验内容哈希，不生成另一份原生会话副本 |

## 已核对的格式特点

- Gemini JSONL 包含元数据更新、消息补丁和回退记录，必须按写入顺序解释；项目路径可通过原生项目登记和目录旁标记关联，不能从哈希反推。
- Qwen Code 保存独立工具结果、父消息链和明确压缩事件，不能按其他客户端的同源引擎推断相同格式。
- 新版 Kimi Code CLI 按工作区、会话和子 Agent 分层保存状态与 wire 记录；版本以当前新版的写入端为准。
- Oh My Pi 的 JSONL 事件树包含独立用量记录，并有辅助标题索引；不能直接以已有 Pi 规则替换客户端目录。
- Grok Build 以更新日志恢复会话，另有派生对话和用量文件；派生副本不重复计活动。
- Reasonix 在存在旁路事件日志时以其为权威来源，检查点和元信息分别保留依赖。
- Codewhale 以 journal、父链与当前叶节点保存会话状态；兼容 messages 投影不重复导入。
- Gemini、Qwen 转录没有可靠的逐请求身份；统计记录能够确认的响应流用量及覆盖，不按消息行数补造实际 API 请求数。

## 实现边界

- 优先复用现有历史适配器契约、规范化事件、资源入口和恢复流程，不另建平行索引或统计链路。
- 历史格式、工具证据和原生配置规则放在适配边界，不把客户端判断散落到各页面。
- 原生字段缺失时明确保留未知，不用文件修改时间替代消息时间，不将未留存内容当作完整记录。
- 原始历史只读；资源写入只面对明确预览的具体来源，系统、插件及托管保护继续遵循现有规则。
- 本产品保存的恢复材料不描述为客户端原生回收站；修改完成与客户端实际生效分别记录。
- 原生停用按名称作用于全局或多层入口时，预览保留真实影响范围；不承诺只影响被点击的一个入口。
- Kimi 与 Codewhale 的普通 Skill 没有已核验逐项停用开关，使用既有回收与恢复流程；不把隔离描述为原生停用。
- 客户端读取其他客户端资源目录时，优先使用当前客户端自己的控制设置；外部、插件、系统及托管来源继续遵循保护规则。
- 文档、代码、任务记录与提交信息只描述本产品的能力、证据和决策；合成样本不包含私人数据。

## 验收矩阵

1. 每客户端使用符合固定版本生产 schema 的人工来源，覆盖发现、正文、工具、元信息和原始证据回读。
2. 覆盖成功、失败、取消、未完成尾行、未知类型、工具结果缺失、重复身份、回退或分叉、父来源缺失，以及来源变更和确认删除。
3. 独立核对模型请求身份与用量桶；覆盖缺失、真实零值、冲突、缓存分母和推理输出的包含关系。
4. 将同一合成来源接入会话库、代码地图、总览及用量接口，核对这些入口消费一致的完整结果版本。
5. 使用隔离资源配置验证层级选择、同名覆盖、原生停用、回收、恢复、共享入口、保护来源和恢复冲突。
6. 使用真实浏览器验证新增客户端的筛选、搜索、轨迹、下钻与资源管理预览，覆盖中英文及现有主题。
7. 完成类型、国际化、相关回归、公开内容及打包检查；分别记录源码核对、合成验收、浏览器验收和原生运行的结果。

## 实施顺序

1. 登记客户端与来源，按原生写入规则实现历史、工具证据、关系和用量转换，完成逐客户端合成回归。
2. 按配置加载与控制规则接入资源盘点、状态、停用、回收和恢复，完成隔离资源与冲突回归。
3. 接通既有 Web、CLI、总览与统计入口，完成中英文浏览器验收、公开内容及打包检查，更新支持与验收记录。
