# 用量统计性能验收

日期：2026-10-11。

## 方法

从本机已发布索引取得固定版本快照，保持原始会话只读。数据规模为数千会话、数十万条请求。原实时分析与新后台分析读取相同版本、价格快照和时区；真实输入、输出、具体身份和详细测量只保存在忽略目录。

对照近 30 天、近 7 天、模型筛选、请求指标、翻页、另一时区、费用精确路径、ISO 精确边界及请求明细。请求集合、计数、Token、筛选项、顺序与页内证据一致；费用与比例合并容许低于显示精度的浮点误差。

HTTP 测量包含首字节和完整正文，采用独立启动的服务及已准备的同一快照。以下是本机单次运行和连续三次缓存读取，不能代表所有设备或并发场景的保证。

旧实时路径在同一快照中读取原请求约 15.28 秒，随后分析约 1.97 秒。首次给旧索引补齐事实和汇总约 29.17 秒，属于一次性后台准备；不能把重复读取结果用于宣称首次旧库迁移同样迅速。

直接调用后台管理器时，首次另一时区约 3.29 秒，费用精确路径约 4.56 秒，ISO 精确区间约 2.54 秒。这些与上表的 HTTP 测量层次不同。精确费用和时间边界仍遍历结构化事实，避免阈值与同金额排序的浮点重排。

进程 RSS 在本轮完整查询集后仍达到约 1 GiB；缓存设置了容量上限，但目前不以本轮单点数据宣称整体内存问题已解决。
