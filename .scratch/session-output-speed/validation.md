## 验收输入与证据

[合成样本](../../scripts/session-speed-fixture.mjs)包含八份原生历史，经来源发现、Worker 解析、索引发布与 HTTP Profile API 进入页面。Codex、Claude Code、CodeFlicker CLI 三类首版来源均有正常响应、同请求的思考与正文、工具调用、短输出、未知结束和取消响应。另有 Codex 的门槛等号与缺失样本、父子会话、110 轮长历史，以及 Pi 的原生分支样本。

两份直接索引样本单独验证界面分支范围与旧索引兼容性：它们显式提供模型消息关联，或故意保留只有用量的旧字段，不替代三类来源的原生计时验证。Pi 没有新增生产计时支持，其分支均保留“速度数据不足”。

| 输入 | 可核对结果 |
| --- | --- |
| 三类来源的两个合格请求 | 480 Token ÷ 12 秒 = 40 tok/s；600 Token ÷ 30 秒 = 20 tok/s |
| 每个来源的五个请求 | 两个合格请求；总输出 1080 Token、总耗时 42 秒，平均约 25.714 tok/s，界面显示 `≈ 26 tok/s` 与 `2/5 次可计算` |
| 原生父会话包含子会话 | 六个请求中三个合格；1480 Token ÷ 52 秒，界面平均 `≈ 28 tok/s`；父轮仍使用自身的 `≈ 26 tok/s` |
| 200 Token／1 秒、200 Token／999 毫秒 | 前者合格并显示 `≈ 200 tok/s`；后者不计算并保留耗时门槛原因 |
| 缺失输出或起始时间、未知结束、取消响应 | 保留请求与具体原因，没有速度数字或伪造代入算式 |
| 110 轮／660 请求 | 每个请求均为 200 Token／1 秒；轮次分页、轨迹虚拟滚动、请求明细第 55 页和第 660 请求定位均使用完整请求集 |
| 直接索引的两条阅读分支 | 旧分支轮平均 20 tok/s、当前分支轮平均 40 tok/s；右侧完整 30 请求平均约 26.667 tok/s，不随阅读分支缩小 |
| 只有用量的旧索引 | 输出 400 Token 保留，计时字段没有被查询补造，显示 `0/1 次可计算` |

工具结果在请求完成后还等待了 48 秒；第一请求耗时仍为 12 秒。计时没有延伸到下一条用户输入、工具结果完成或整轮结束。

## 支持边界

本次验证的是已确认规格中的历史估算。首字等待、请求准备和日志写入延迟可能影响估算耗时，跨客户端仅供参考；结果保留 `≈`，没有宣称精确首 Token 计时。没有足够请求关联或结束证据时继续显示数据不足。第一版支持上述三类来源，桌面镜像计时仍属后续范围。
