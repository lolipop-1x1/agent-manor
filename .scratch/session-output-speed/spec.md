# 会话库吐字速度与执行轨迹

状态：已确认，首版实现与综合验收完成，独立代码审查中。确认日期：2026-10-09。

依据：[可行性研究](issues/01-feasibility.md)、[设计访谈](issues/02-design-interview.md)、[术语表](../../CONTEXT.md)。本文件记录已确认规格；实际验证结果见[综合验收任务](issues/06-validation.md)。

## 目标与已确认范围

基于原生历史中的输出用量和可解释的请求计时边界，展示单次模型请求的历史估算吐字速度。一次请求的多个模型片段共享同一请求速度，汇总按请求身份去重。

展示覆盖对话、全部记录、执行轨迹与右侧用量。轮次标题显示本轮平均值，模型记录与请求用量记录显示所属请求速度；两种数值明确区分。采用合适位置的帮助图标说明算法。用户可见标题统一使用“执行轨迹”。

## 单请求算法

`历史估算吐字速度 = 输出 Token × 1000 / 估算响应耗时毫秒`。

输出 Token 取来源记录的该请求用量，合并分块快照后使用最终有效值，不按正文字符数换算；单独报告的推理用量不重复加到输出。估算响应耗时由该请求的有效起始边界至结束记录计算，包含首字等待，可能包含请求准备与记录写入延迟。各来源独立校准，不能直接用整轮时长、工具执行时长或桌面累计时长代替。

### 已确认的合格条件

- 输出不少于 200 Token。
- 有效估算耗时不少于 1 秒。
- 模型调用有明确结束证据，或能够依据经过校准的历史边界可靠推断结束；模型调用本身被取消且只保存部分输出时不计算速度，也不进入平均值。
- 已经完成的模型请求不会因为所属轮次后来中断而被整体排除。
- 请求身份与起止边界能够解释，时间有效且顺序一致；重复快照、继承复制、压缩重置不产生新的速度样本。

不合格请求仍保留原始用量及记录，在详情说明缺失或过滤原因。

### 请求结束与轮次结束

工具调用响应可以是一次已经结束的模型请求，后续工具执行和下一次模型请求仍属于同一会话轮次。当前消息的最终回答标记不能充当每次模型请求的完成证据；工具结果的失败、超时或后台运行也不能直接证明模型调用被取消。

逐请求完成状态按来源保留。Claude 的 `stop_reason`、原生流式最后快照，以及各客户端的中断事件须按来源分别校准；Codex 轮次级中断不能将同轮全部请求都标为中断。用户已确认接受明确结束或可靠的历史边界结束推断，计时依据保留结束判断及其证据；仅凭“未见中断”或“存在用量”不能自动判定完整。

来源校准需要分别覆盖：Codex 现代与旧用量顺序、延迟补写及工具结果；Claude 同请求片段的终止原因与最终快照；CodeFlicker CLI 原生助手历史的完成写入语义及可关联的中断字段。明确结束、推断结束与未知结束分开保留，未知结束不计算速度，也不伪装为明确中断。可靠推断成功后仍显示 `≈`，不改称直接计时。

## 首版来源范围

第一版支持 Codex、Claude Code 和 CodeFlicker CLI 的合格历史请求。各来源仍须通过边界校准与合成验收，不能因为已登记客户端就默认每次请求均可计算。

CodeFlicker 桌面原生镜像作为下一阶段，第一版不扩展镜像计时读取；其已有用量与会话展示保持原有能力，速度显示数据不足。旧 IDE 和其他未核验来源同样保留缺失，不使用累计时长或文字长度补算。

## 平均值与范围

`平均吐字速度 = 同范围合格请求的输出 Token 总和 × 1000 / 同一批请求的有效耗时毫秒总和`。

不直接平均各行 Token/s，不将全部输出量除以仅部分请求的耗时，不将缺失当作零。轮级平均绑定当前视图的会话、轮次和分支范围；右侧用量的平均值沿用“当前会话／包含子会话”范围。部分可计算时直接显示请求覆盖数量。并行请求仍按请求耗时求和，结果不表示整项任务相对于墙钟时间的处理速度。

可计算数量的分子是合格请求数，分母是该范围内已识别、去重并排除复制历史和重置事件的模型请求数；缺少输出量、计时或结束证据的已识别请求仍在分母中。这个数量描述已识别历史，不承诺未保存请求的全量覆盖。

## 展示基线

| 位置 | 展示 |
| --- | --- |
| 对话／全部记录的轮次标题 | `平均 ≈ 32 tok/s`；部分可计算时附 `3/4 次可计算` |
| 明确关联的 AI、思考或请求用量卡片 | `请求 ≈ 40 tok/s`；共享请求的多个模型片段显示同一值 |
| 执行轨迹表格 | 在“输出／结果”与“时间／耗时”之间增加“速度”列 |
| 执行轨迹的选中详情 | 标题旁显示请求速度，详情提供输出用量、耗时与计时依据 |
| 右侧用量 | 请求明细增加速度列，统计区域显示平均值与可计算范围 |

近似值直接带 `≈`。速度采用整数显示，小于 1 tok/s 时保留一位小数；汇总使用未舍入的原始量。与请求的关联不明确时，不为模型卡片补猜测值。工具执行和工具结果不显示模型吐字速度；其工具耗时仍独立展示。

### 缺失与过滤状态

| 场景 | 紧凑显示 | 详情原因 |
| --- | --- | --- |
| 合格单请求 | `请求 ≈ 40 tok/s`；表格单元格可省略“请求” | 用量、有效耗时、起止记录与明确／推断结束依据 |
| 已关联请求，无法计算 | 卡片 `请求速度 —`；表格 `—` | 根据具体原因展示，不将未知值当作零 |
| 输出不足 200 Token | `—` | `输出少于 200 Token，未计算速度` |
| 耗时不足 1 秒 | `—` | `响应时间过短，未计算速度` |
| 请求被取消或部分响应 | `—` | `响应未完整结束，未计算速度` |
| 结束无法确认 | `—` | `响应结束未确认，未计算速度` |
| 起始边界或有效耗时缺失 | `—` | `缺少有效计时依据` |
| 输出用量缺失 | `—` | `未记录输出 Token` |
| 一轮有请求但均不合格 | `速度数据不足` | 已识别请求保留，按实际原因说明 |
| 一轮没有已识别模型请求 | 不显示速度标记 | 不制造零值或请求数 |
| 请求与模型卡片的关联未确认 | 卡片不补速度值 | 保留独立请求用量记录的定位及缺口 |

轮级平均全部可计算时仅显示平均值，部分可计算时附覆盖数量。对话／全部记录的轮次折叠不隐藏平均值。右侧用量与执行轨迹的速度列仅在所选范围至少有一条合格记录时出现；全部无法计算时通过区域状态显示数据不足，表格保持原布局。明确无请求的轮次不受该区域状态影响。

## 算法帮助图标

要求已确认：通过可点击、键盘及触屏可用的图标解释算法；复用现有统一帮助组件，每个区域合并为一个帮助入口。采用区域帮助与单请求详情两个层次，消息卡片保留紧凑速度标记，不逐条堆叠问号。

| 区域 | 帮助入口 |
| --- | --- |
| 对话／全部记录 | 在视图顶部工具区放一个问号图标，名称为“吐字速度说明”；切换这两个视图复用同一入口，解释轮级平均与请求速度 |
| 执行轨迹 | 复用现有轨迹说明入口，合并轨迹与速度算法；问号图标名称为“执行轨迹与速度说明”，正文分段解释，不另加每行问号 |
| 右侧用量 | 合并到现有统计帮助入口，用问号图标打开统计口径；原有缓存、范围说明与新增速度说明保留分段 |

现有 [HelpPopover](../../web/HelpPopover.tsx) 已使用 Radix Popover 和问号图标，支持点击与键盘；当前还显示文字标签。实施时只增加可选的纯图标呈现方式，为触发按钮保留明确可访问名称、焦点提示、Escape 关闭与焦点恢复；沿用 Portal、主题和视口内定位，现有调用默认外观不变。

候选内容：

> **吐字速度怎么算**
>
> 单次请求的输出 Token ÷ 估算响应耗时。带 ≈ 表示根据历史记录估算；耗时包含首字等待，可能包含请求准备与日志写入延迟。仅统计输出不少于 200 Token、耗时不少于 1 秒的完整请求。
>
> 平均值使用可计算请求的输出总量 ÷ 同一批请求的耗时总量。思考和回复可能属于同一次请求，共享请求速度，汇总不会重复计数。

帮助内同时注明：可计算覆盖以历史中已识别的请求为准；不能可靠确认起止或结束的请求显示数据不足。不同客户端的记录时间语义可能不同，跨客户端数值保留估算边界。

单请求详情同时展示可核对的代入算式，例如 `480 Token ÷ 12.0 秒 ≈ 40 tok/s`，并显示输出用量、估算响应耗时及起止记录依据。显示的秒数是格式化后的值，实际计算使用毫秒原值；明显受舍入影响时保留足够的小数精度。起止记录可明确定位时提供现有记录定位入口。

帮助不展示后端字段名、原始请求 ID 或客户端实现细节；详细技术证据保留在可展开依据中。缺少计时或被过滤时不造算式，显示具体原因。

## 执行轨迹命名

术语已统一。实施时将共享翻译键 `sessions.mode.trace` 的中文从“执行过程”改为“执行轨迹”，英文从 `Execution` 改为 `Execution trace`。切换按钮与加载提示使用该键，会随目录统一更新；轨迹区域的中文无障碍名称已经使用“执行轨迹”。稳定 API 枚举、URL 模式及 CLI JSON 的 `trace` 保持原有身份。

相关现行设计文档同步统一可见名称，不重写旧任务记录或原始会话正文。已有模式参数测试继续验证 `trace`，新增文案与可访问名称验收覆盖中英文。

## 设计确认

用户在第六轮确认本规格已达到共同理解，并选择形成待实现任务。统计门槛、请求结束判断、第一版来源、四处展示、算法帮助与命名均已收敛；后续按实施任务推进。若原生字段校准发现无法支持约定边界，需明确报告实际支持范围并保留缺失，不静默放宽证据标准。

独立速度趋势图未纳入第一版；现有 Token 纵轴不混入 Token/s，只在请求提示中补速度。

## 接入与实施任务

复用现有请求用量 JSON、Profile 和版本化刷新，只读现有历史，不修改原始历史或启用新的运行时采集。解析时保存计时与请求消息组关联，前端按同一索引版本建立请求、消息和轮次映射，保持分页和虚拟滚动。

| 任务 | 责任与接入点 | 验证 |
| --- | --- | --- |
| [03 请求计时与关联](issues/03-request-timing.md) | 扩展 SessionUsage 计时、结束依据、缺失原因和模型消息组关联；适配前三类来源；保留既有 `messageId` 对原始用量记录的定位语义 | 来源分块／快照去重、工具调用响应、取消与未知结束、门槛边界及复制／重置 |
| [04 汇总与回填](issues/04-profile-refresh.md) | Profile 同范围合格子集汇总、全部请求明细、客户端计时规则指纹与正常刷新回填 | 长历史全部请求一致性、分支／子会话、部分覆盖、旧索引可用与原子发布 |
| [05 视图与帮助](issues/05-speed-views.md) | 会话页统一准备映射，轮次／消息卡／轨迹／用量复用展示；HelpPopover 纯图标选项；中英文文案与执行轨迹命名 | 四视图数值一致、缺失、折叠、定位、分页、虚拟滚动和可访问名称 |
| [06 综合验收](issues/06-validation.md) | 完成源码校准、自动检查与隔离合成数据的真实浏览器验收 | 深浅主题、窄屏、中英文、帮助的鼠标／键盘／触屏语义及产品状态保留 |

从索引扩展可选字段，不为本功能另建历史存储或请求日志系统。没有新计时字段的旧用量对象保持缺失，受影响客户端在正常刷新中重解析后回填；范围外客户端不因该规则升级强制重建。Profile 查询不读取原始历史，Web 与 CLI JSON 共用稳定契约。

计时与消息关联的具体字段名由实施选择，证据含义以本规格为准。保留原始起止记录定位、解析方法和结束判断；可关联多个模型消息，但不通过同轮身份或最近时间直接分配请求用量。汇总与界面不能重复计数这些关联。

## 验收

使用合成样本验证分块与快照去重、工具等待、并行工具、中断、复制历史、压缩重置、时间无效、门槛等号与上下边界、消息关联、分支及子会话范围、平均值与全部请求明细一致性。界面验收覆盖各视图、中英文、深浅主题、窄屏、折叠与详情、帮助图标的键盘和触屏语义。

真实历史校准只在本机进行，公开文档和测试保留方法、结论与合成输入，不写真实正文、来源身份或本机路径。来源边界无法通过校准时不为该请求输出数值，应报告实际支持范围；实现成功不能仅以构建通过或导入无报错认定。

本阶段不创建 ADR：目前确认的命名、帮助布局与显示门槛可直接调整，已有索引与版本边界继续遵循现有架构决策。
