# 请求计时、结束依据与模型消息关联

Type: task
Status: resolved
Blocked by: 02

## 范围

按[规格](../spec.md)扩展单次请求用量的可选计时、结束依据、缺失原因及模型消息组关联。负责 SessionUsage 契约、请求归组和 Codex／Claude Code／CodeFlicker CLI 来源解析，保留原始用量记录的定位身份。

## 验收

- 多消息片段与重复快照归为一个请求，不因输出数相同合并不同请求。
- 可靠识别起止边界，排除工具执行等待，明确结束与推断结束保留依据。
- 工具调用响应结束不要求整轮最终回答；轮次中断不整体剔除之前已经完成的请求。
- 部分响应、未知结束、无效时间、缺失用量、短请求分别保留原因。
- 输出 200 Token 与耗时 1 秒的等号合格；上下边界有合成测试。
- 复制历史、压缩重置与来源投影不新增请求或速度。
- 原始历史只读；桌面镜像和新运行时采集不在本任务范围。

## Answer

已实现可选请求计时契约、无运行时依赖的统一门槛／汇总计算，以及前三类来源的请求消息组关联。既有 `messageId` 仍定位原用量记录，`requestMessageIds` 仅保存有依据的模型正文／思考关联，不为工具执行记录分配模型速度。

- Codex 使用响应项事件组与独立用量身份／累计检查点。序列化工具请求与对应快照、终答响应与快照分别保留结束推断；工具返回后的旧用量补写回到最后模型项，排除工具等待。只有用量而无响应项的记录仍保留用量，不为后续正文补配。未保存用量但有明确模型事件组的请求保留缺失，不补零。
- Claude 按原生模型消息身份合并分块。有效终止原因作为明确结束，实际配对工具结果可证明工具响应已提交；仅有用量而没有结束证据时保持未知。明确关联的中断可覆盖为部分响应，工具执行失败或超时不直接取消模型请求。
- CodeFlicker CLI 仅在原生成功流式结果写入身份齐备时推断结束。源码核验显示流式异常与取消检查先于助手记录提交；助手记录携带完整输出块、最终用量和请求基线。缺少该写入证据或出现取消标记时保留未知／部分。桌面累计时长未接入。
- 复制事件不进入请求组，压缩后的累计零快照不新增请求，重复投影不改变原轮次或用量记录定位。不同请求即使用量相同也分别保留。

验证：合成速度／解析测试共 41 项通过；服务端类型检查、公开内容检查与差异空白检查通过。覆盖门槛等号、加权平均、分块、投影顺序、并行工具、延迟补写、取消、未知结束、复制、重置和无效时间。两处旧解析断言改为包含已识别但未保存用量的工具请求，原 Token 总量不变。

限制：历史计时仍包含首字等待及可能的准备／写入延迟；无终止依据的普通过程回复不计算速度，不把未见中断当作结束。各来源未来格式仍须独立校准。本任务未修改存储、刷新或前端，未进行浏览器验收。
