# 会话库吐字速度设计地图

## 目标

基于原生历史的单次模型请求用量和时间证据展示吐字速度，并在多个会话视图复用同一统计口径。

## 已作决策

- [01 可行性研究](issues/01-feasibility.md)已完成：有合格用量及时间线索的请求可以做历史估算；桌面缓存累计时长不能直接作为请求耗时。
- 显示范围包括对话、全部记录、执行轨迹和右侧用量；轮次平均与单请求速度明确区分。
- 通过帮助图标说明算法；标题统一为“执行轨迹”；相关术语见[根术语表](../../CONTEXT.md)。
- 输出门槛为 200 Token，估算耗时下限为 1 秒，边界包含等号。
- 不计算部分响应速度；已经完成的请求即使所属轮次后来中断，仍可参与统计。
- 算法帮助使用区域问号图标，请求详情显示代入算式；复用统一 HelpPopover。
- 第一版启用 Codex、Claude Code 和 CodeFlicker CLI，桌面镜像作为下一阶段。
- 请求结束可采用明确证据或经过校准的可靠推断，保留判断依据；未知结束不计算。
- [02 设计访谈](issues/02-design-interview.md)已完成：用户确认整体规格达到共同理解，[首版规格](spec.md)已定稿，四个实施任务按依赖准备就绪。

- [04 汇总刷新](issues/04-profile-refresh.md)已完成：全量请求加权、会话内身份去重、明确分支投影、三来源正常刷新回填及旧版本原子性均有合成验证；画像和 Token 原口径保持。

## 设计树

```text
历史估算吐字速度
├─ 请求身份与计时证据：沿用来源核验结论，合并片段、去重快照
├─ 合格请求
│  ├─ 输出 ≥ 200 Token、耗时 ≥ 1 秒：已确认
│  ├─ 部分响应不计算：已确认
│  └─ 历史边界的结束推断：已确认，无法可靠确认时保留缺失
├─ 展示
│  ├─ 对话／全部记录：轮次平均、模型记录的请求速度
│  ├─ 执行轨迹：速度列、选中详情
│  ├─ 右侧用量：请求速度、范围内平均值
│  └─ 算法帮助图标：区域入口与请求详情代入算式，已确认
├─ 首版来源支持范围：Codex、Claude Code、CodeFlicker CLI；桌面下一阶段
└─ 规格收敛与共同理解确认：已确认
```
