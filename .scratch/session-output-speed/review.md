# 吐字速度独立审查与修复

审查日期：2026-10-09。实现审查基线为 `40b6f6b`，已确认设计基线为 `5f91406`。本记录分别保存规范审查与规格审查的发现和修复，不将判断建议当作仓库硬规则。

## 规范审查

| 级别与性质 | 发现 | 修复与复核 |
| --- | --- | --- |
| P3，仓库硬规则 | 速度详情与轮次折叠的端到端操作直接依赖原生 `summary` 标签，未验证控件的角色与可访问名称。 | 改为容器范围内按共享中英文名称定位；每次操作前通过 CDP 获取同一 DOM 节点的局部可访问树，核对 `DisclosureTriangle` 与预期可访问名称，再点击或触摸。轮次折叠使用同样方式，布局测量仍保留容器选择器。 |
| P3，重复代码判断建议 | 原生解析对已识别请求的判定在计时归组与缺失用量处理处各写一次，后续容易出现条件分歧。 | 在内容块循环前计算局部 `identified`，由计时归组和用量处理共同复用。没有引入新抽象或改变请求身份规则。 |

实际 Chrome 的可访问树将原生折叠控件报告为 `DisclosureTriangle`；Playwright 的 ARIA 角色定位未暴露该原生角色，按 `button`、`generic` 或 `group` 加名称均不能命中。测试因此保留原生控件，用共享名称选中操作节点，并绑定该节点的 CDP 对象核对角色与完整名称。隔离浏览器中临时覆盖该节点的 `aria-label` 后，断言实际拒绝错误名称且没有操作控件，随后恢复原值；页面上的其他同名节点不能代替通过。没有为测试改变产品控件或产品 ARIA。

## 规格审查

| 级别 | 发现 | 修复与复核 |
| --- | --- | --- |
| P2 | 非空中断目标未匹配原生身份时仍回退当前或最近请求，可能把已明确结束的 Claude 请求改为部分响应并从平均值剔除。 | 显式目标只查匹配请求，未知目标直接保留原有请求状态。新增原生解析回归覆盖之前完整请求、当前其他未知请求与无目标中断；原有明确目标取消回归继续验证部分响应被排除。 |
| P3 | Codex 明确用量结束边界只保存时间与行号，缺少已有真实用量记录的消息身份，详情不能使用现有记录定位入口。 | 现代 `token_usage_record` 与旧 `token_count` 路径均传入已有用量记录 ID。解析断言验证真实记录身份与行号、双向投影去重和无消息上下文边界；工具结果先完成时仍保留最后模型记录，不将工具等待算入请求。HTTP 与真实 Chrome 验证结束入口指向保存用量的轨迹记录。 |

## 修复验证

新增回归在原实现上有三项断言失败，分别复现未知中断目标和两类 Codex 用量结束定位缺口；生产修复后速度解析测试 17／17 通过。相关解析、用量、速度与 HTTP 测试 46／46 通过，完整测试 541／541 通过。新增 HTTP 定位断言按对应测试单独复核。类型、国际化与构建通过；构建仍有已有前端包体积提示。

最终浏览器与公开检查结果见[验收报告](validation.md)。修复任务见[09 独立审查修复](issues/09-review-fixes.md)。
