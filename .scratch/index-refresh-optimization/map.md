# 索引增量、自动刷新与页面性能

## 已确认目标

- 优化历史检查、索引更新和页面加载，减少数据库重复写入与存储占用。
- 网页打开期间能够自动看到新历史，自动检查应与增量刷新结合。
- 已释放空间不应长期占用磁盘，采用后台分批回收。
- 用户已于 2026-10-09 授权实施；优先验证数据正确性和性能。

## 设计树

- 空间回收策略（Q1）→ 现有数据库的初始化／转换方式、回收预算与验收条件。
- 新版阅读行为（Q2）→ 阅读锚点、分页、筛选与地图视野保留、定位失效反馈。
- 自动检查范围（Q3）→ 可见页面调度、跨标签页合并、来源优先级与地图更新条件。
- 来源增量能力取证 → 各格式支持范围、解析状态、不可增量时的回退和存储共享方案。
- 上述决定确定 → 分阶段任务、性能预算、最终规格核对。

## 已作决策

- 未逐项选择的首轮选项按推荐方案实施：INCREMENTAL 后台分批回收；自动应用完整新版并保持稳定消息锚点；可见网页每分钟检查全部 Agent。
- 来源依赖完整且变化指示可靠时跳过正文读取；否则保留完整校验。无变化检查不发布新版本。
- 地图消除重复 Git／路径查询并差量写缓存；会话变化来源保留完整解析，以用量、分支和最终回答的一致性为先。
- 先优化重复工作与载荷；未引入 CPU 解析分片、跨模块正文结构迁移。

- [05 实施结果](issues/05-visible-auto-refresh.md)：可见调度、同版复用、完整新版切换和消息锚点／末尾接续；首屏与明细有界，完整内容可读取，跨页工具与聚合投影保持正确；真实 Chrome 9 组通过。
- [03 实施结果](issues/03-session-incremental-query.md)：来源依赖复用与同版检查、画像摘要及有界正文；完整轮用量保持正确，实测慢 SQL 已修复。
- [04 实施结果](issues/04-map-incremental.md)：变化来源缓存差量写入，路径／Git 校验共享，完整回退与发布边界保留。
- [06 实施结果](issues/06-space-scheduling.md)：旧库受控转换、新库启用增量回收，空闲 Worker 分批回收；多页面自动任务合并。
- [07 最终验收](issues/07-integration-review.md)：全部任务与独立审查修复完成，603 项测试和真实查询／页面／空间对照通过。
