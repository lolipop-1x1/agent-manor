# 请求明细翻页时清空已有结果与分页栏

Type: task
Status: resolved
Priority: P2

## 触发条件

打开具有多页请求的会话明细，切换请求页码；请求耗时较长或返回错误。

## 复现

使用合成会话与真实 Chrome，在第二页请求注入受控延迟：

- 翻页前显示 20 行，分页栏存在；无头复核弹窗高度约 672 像素，有界面复核约 876 像素，取决于视口。
- 等待期间行数变为 0，分页栏消失，弹窗高度变为 232 像素，仅保留加载内容。
- 请求成功后重新显示 11 行与分页栏。
- 下一次翻页返回合成 HTTP 503 时，表格和分页栏继续缺失，重试入口存在。

## 预期

遵循统一组件规范：分页等待和失败保留上一份完整结果及布局，等待期间暂停旧结果的下钻，成功后整体替换；失败保留可重试错误。

## 位置

- `web/features/usage/Usage.tsx:133-137`：每次请求明细查询立即执行 `setRequests(null)`。
- `web/features/usage/UsageRequestDialog.tsx:33-35`：清空后仅显示加载块。
- `web/features/usage/UsageRequestDialog.tsx:51`：分页栏依赖请求结果非空。

## 验证边界

通过隔离数据、受控网络延迟与错误注入确认。没有改动真实历史或真实价格配置。

## 修复

同会话分页保留旧表格和分页，固定标题槽位显示更新图标；查询身份不匹配、等待或失败时，旧行暂停下钻。成功整体替换页码与数据，失败保留重试。会话及索引、价格版本共同约束可见结果，取消或关闭前的响应不污染新页面。新增无头 Chrome 回归覆盖慢请求、失败重试、快速回首页、关闭后切换会话、英文窄屏及长选择 POST 下钻。
