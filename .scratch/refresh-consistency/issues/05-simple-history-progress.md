# 简化历史更新与可见进度

Type: task
Status: resolved

## 目标与决策

- 日常 Web 仅保留“更新历史”，始终检查全部客户端；移除手动范围和重复更新、重新检查动作。
- 会话库自动刷新继续在顶栏直接显示，代码地图保留独立设置。
- 状态弹层仅展示时间、进度和错误；失败支持原操作重试，不新增诊断页面。
- 按钮原位显示阶段或百分比及细进度条，详细阶段、处理数量和已用时间按需展开。没有处理总量时显示不确定进度，不估算剩余时间。
- 保留内容重新检查的服务端与 CLI 能力，不更改后台算法。

## 验收计划

1. 验证主按钮忽略浏览筛选；状态弹层不再提供范围选择或重复动作，Escape 恢复焦点。
2. 验证请求开始、来源发现、处理中、发布、完成、失败和进度查询重试；处理中不允许重复提交，完成后收起进度。
3. 使用隔离合成历史验证中英文、深浅主题、桌面及窄屏进度和布局；回归独立自动刷新与阅读状态。
4. 执行翻译、类型、构建、定向测试和公开内容检查，同步使用和验收文档。

## Answer

- 日常 Web 仅保留全局全部客户端更新，范围和重复检查动作已移除；会话筛选不再向顶栏传递更新范围。
- 按钮原位显示阶段或处理百分比及细进度条，状态弹层显示阶段、处理数量、已用时间或更新时间，实际错误可重试。没有可计算总量时使用不确定进度，完成后收起，进度查询失败不沿用旧百分比。
- 内容重新检查的服务端及 CLI 能力保持；两份自动刷新偏好、可见调度、完整版本联动和阅读锚点保持。
- 28 项定向测试、11 组历史更新 Chrome 验收、12 组独立自动刷新 Chrome 验收通过；已核对中文桌面明亮与英文窄屏深色的运行及完成截图。翻译、类型、构建、公开内容与差异检查通过。
