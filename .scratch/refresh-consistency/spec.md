# 刷新入口与状态一致性

状态：已实现并通过隔离验收。

## 用户目标

用户在任意页面都能更新新增会话历史，明确各个更新动作的范围；更新成功后当前页面取得对应的完整结果，失败后能够重试原操作。

## 已确认范围

1. 修复资源盘点失败后的重试：重试再次执行盘点；列表查询失败仍重试对应查询。
2. 语言、主题固定在全局页头最右侧；代码地图的分析、自动刷新和来源诊断操作放入页面操作区。
3. 提供所有页面可访问的“更新历史”入口，复用现有会话检查任务、快速检查和完整校验能力。
4. 历史更新完成后重读当前可见页面的相关数据；隐藏页面在切回时更新。保留筛选、选中项、阅读位置和地图视野。
5. 统一页面刷新控件的外观、运行状态、完成反馈与失败重试。来源检查时间、结果发布时间和页面查询时间保持各自含义，详细范围按需查看。
6. 总览与用量的页面更新读取已发布结果；代码地图更新当前仓库分析；资源清单更新执行本地盘点。
7. 会话库与代码地图的自动刷新设置继续独立、默认关闭，保留对应页面可见时触发的现有规则。
8. 本轮不新增常驻文件监听或服务端周期历史同步；相关性能与兼容性评估留待后续需求。
9. 公开文档、代码、任务记录和提交说明只描述本产品的能力与决策。

## 操作决策

- 全局“更新历史”始终对全部客户端做快速检查，客户端、项目、日期与搜索筛选只限制页面展示。
- 会话库原手动刷新入口合并到全局入口；在会话库选择具体客户端时，菜单提供该客户端的快速检查与完整校验，并始终保留全部客户端完整校验。

## 一致性边界

- 原始历史只读；新结果完整发布后才能切换，失败继续提供上一完整结果。
- 历史更新不自动重算所有仓库，也不自动触发本地资源盘点或强制价格目录联网更新。
- 后续联动区分检查成功与页面查询成功；历史检查成功、页面读取失败时，明确失败阶段，重试页面读取。
- 同范围的在途历史检查复用现有任务；运行中保留旧布局并暂停过期结果的下钻。
- 现有自动刷新生命周期沿用 ADR 0010。待确认的入口变化不能静默改变客户端局部检查能力及 ADR 0006 的范围语义。

## 实施与验收顺序

1. 修复重试并统一操作布局与控件 → 验证失败后重试相同操作，中英文、深浅主题、键盘及窄屏一致。
2. 提供全局历史更新及任务状态 → 验证在五页均可发起检查，实际范围与显示范围一致，在途任务合并和失败反馈正确。
3. 接入完整版本发布后的页面联动 → 使用隔离合成历史验证新增会话、用量和资源使用记录更新，筛选与阅读状态保留，地图分析仍独立。
4. 完成相关自动化与真实浏览器验收，并执行公开内容检查；未通过的检查明确记录。
