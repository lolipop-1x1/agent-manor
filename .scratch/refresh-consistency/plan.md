# 刷新入口与状态一致性实施计划

目标：统一历史检查任务与页面反馈，让任意页面都能更新历史并跟进完整结果。

## 1. 应用层历史任务

- 新增 `web/shared/refresh/useHistoryRefresh.ts` 管理历史检查、任务轮询、失败重试及完成通知。
- 新增全局控件并接入 `web/app/App.tsx`；默认全部客户端，菜单保留当前客户端检查与完整校验。
- `Sessions.tsx` 移除独立手动任务入口与轮询，继续保留自动检查和阅读恢复逻辑。
- 验证：完成通知仅发送一次；请求失败与任务查询失败重试各自操作；自动刷新范围及可见性不变。

## 2. 页面操作与联动

- 新增共享刷新按钮与状态详情；接入总览、用量、代码地图及资源管理。
- 历史检查完成后，当前页面重新读取；隐藏页面切回再消费通知。固定版本的会话阅读由页面解除固定并恢复消息锚点。
- 将地图来源诊断、自动刷新及分析更新移入地图页面操作区，语言与主题保持全局右端。
- 资源盘点失败后再次执行盘点，查询失败仍重试查询。
- 验证：同版读取、旧数据保留、失败恢复，筛选、阅读位置及地图视野保持。

## 3. 验收与文档

- 增加隔离合成历史的专项浏览器脚本，覆盖五页操作范围、跨页数据联动、盘点重试、菜单键盘、中英文与窄屏。
- 更新已有浏览器脚本中迁移的按钮定位，运行受影响的回归。
- 同步产品、设计、使用文档和任务状态；补充边界决策，保持词汇表只包含领域定义。
- 执行 `npm run check`、相关单元测试、构建、浏览器验收、`npm run check:public` 和差异空白检查。
