# 快速停止后台

Status: resolved

## 目标

`am stop` 默认取消正在执行和排队的任务并关闭后台，不再返回忙碌错误。停止已完成才返回成功；重复执行保持幂等。`--wait` 显式等待任务完成后再停止，升级继续保留忙碌保护。

## 实现计划

1. 在 `tests/service-stop.test.ts` 增加默认停止正在准备服务的回归用例，先确认旧实现失败。
2. 修改 `src/service/runtime.ts`、`src/server.ts` 和 `packages/cli/src/commands/lifecycle.ts`，让普通停止主动取消工作；在独立服务控制 Worker 中接受经实例身份验证的停止请求，主线程无法响应时仍可停止。正常清理有短时限，超时由当前进程自身退出，不根据未核验 PID 杀进程。
3. 各独立模块同时启动关闭，按依赖顺序关闭数据库；保留完整发布快照和启动恢复标记。升级入口显式保留不打断任务的策略。
4. 用隔离子进程测试正常、忙碌、主线程卡住、清理卡住、重复停止、身份不符、事务回滚和重新启动。同步 CLI 中英文帮助、使用文档与 Skill 生命周期参考。
5. 运行生命周期、CLI、升级、类型、国际化与公开内容检查，实际执行构建后的命令验收。

## 取舍

只删除忙碌拦截无法解决主线程无响应；直接按磁盘记录杀 PID 无法可靠区分失效记录和其他进程。独立控制 Worker 只绑定本机地址、核对实例身份，负责有界关闭。后台重任务与数据库读写的其余并发优化不纳入本次。

## 验收

默认停止不等待后台任务完成；主线程或清理卡住时数秒内退出；错误身份不触发停止；SQLite 未提交事务回滚，已发布数据仍可读取；停止后可重新启动。

## Answer

默认停止改为主动取消；独立控制 Worker 核验身份、触发关闭，并在2秒后兜底退出。控制通道失联可在主 HTTP 重新核验身份后降级停止；并发停止中的连接中断必须结合实际退出确认，锁清理完成后才移除实例记录。显式等待与升级继续通过主服务复核在途任务。

回归覆盖默认忙时停止、等待超时、重复及并发停止、错误身份、浏览器请求拒绝、控制通道失联、主线程阻塞、关闭挂起、事务回滚、完整版本保留和重新启动。正常停止约0.1秒，阻塞或挂起约2.0–2.2秒；构建后中英文 CLI 约0.33–0.39秒。生命周期、升级、CLI、语义、知识、用量、总览及资源相关检查通过；类型、国际化、构建、交付入口及公开内容检查通过。未运行全量测试或其他操作系统实机验收，未更换用户的全局安装或日常后台。

## 本机交付验证

按后续授权完成本地打包与全局安装，核对实际安装的控制 Worker 与构建产物一致。使用已有真实数据，在会话同步运行、仓库任务排队时执行实际 `am stop`，约2.4秒退出并确认旧进程消失；重复停止返回未运行。再次启动后保留原有完整会话结果，知识列表及静态网页入口可读，后台继续进行增量准备。详细输入、原始标识和运行日志只保留在本机忽略目录。该操作没有发布新的 npm 版本。
