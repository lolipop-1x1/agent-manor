# 修复请求用量去重与输入归一化

Type: task
Status: resolved

## 范围

- Codex 原生响应后的旧式投影在累计基数不同、字段顺序不同或上下文压缩后仍只计一次；反向关联须累计进度一致，独立请求不得按相同 Token 数值合并。
- WorkBuddy 根据已记录总量核验输入口径，读取数组形式的缓存与推理分项，不再丢弃已确认的总输入。
- DSH 仅在总量恒等式确认缺省缓存桶为零时恢复输入；没有总量或分项冲突时保留未知。
- 升级受影响客户端的来源规则指纹，使旧请求事实和派生汇总重新计算，范围外客户端继续复用；原始历史和用户价格配置保持只读。

## 验证

先运行失败的合成回归，再验证修复、身份边界、缺失字段及索引失效。完整自动测试、类型、国际化、构建和公开内容检查通过后，用本机真实历史核对固定日期范围与来源记录；公开记录不包含真实路径、身份或原始会话。

## Answer

已修复三类来源归一化，并通过来源规则指纹重算旧请求事实及派生汇总。721 项自动测试、类型、国际化、构建及公开内容检查通过；70 项隔离合成浏览器检查通过。三个主要 Codex 差异样本与原生响应独立求和完全一致；25 个 WorkBuddy 来源与原生请求独立核验一致。DSH 输入分桶合同已核实，缺总量、无效值及冲突继续保留未知。

本机受影响来源已全部刷新并发布新版索引，固定价格版本的 API 与真实页面已回读验证，未受影响的客户端汇总保持一致。跨工具总量不能强制相等：继承前缀排除、压缩请求保留及来源代际覆盖有明确边界。真实对照输入及详细输出仅留在本机忽略目录。验收见 [验证记录](../../../docs/validation/usage-statistics.md#请求用量归一化修正)。
