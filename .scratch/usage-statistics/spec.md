# 用量统计

状态：已在 main 实现并完成验收。执行结果与边界见 [用量统计验收](../../docs/validation/usage-statistics.md)。

## 目标与已确认范围

- 在顶部导航新增独立“用量统计”入口，汇总跨客户端、项目和会话的模型用量。
- 首版包含 Token 和估算费用，费用明确标记估算，不作为实际账单或订阅支出。
- 按请求已记录的发生时间统计，沿用本机时区；跨天会话的请求分别进入对应日期，缺可靠时间的用量单独保留，不归入会话开始日。
- 默认纳入主会话与子会话的自身新增用量，每条符合身份与去重规则的请求只计一次；提供全部、仅主会话、仅子会话筛选。
- 默认近 30 天，采用完整的筛选、趋势、Token 组成、归因排行、日历热力图和会话明细组合。
- 价格自动查询优先使用网络数据，获取失败时使用本地价格；无法自动定价的模型允许填写单价或设置模型映射。
- 用户可以配置任意模型的任意价格，包括已经匹配到价格的模型；手动价格的优先级最高，网络更新不会覆盖手动设置。
- 提供全面的筛选条件和清晰、可比较、可下钻的图表；沿具体会话与请求回到证据。
- 文档直接描述本产品能力、统计口径与设计决策，不包含外部实现的来源说明。
- 使用现有主题、共享控件与国际化规范，覆盖中英文、深浅主题与窄屏。

## 既有约束

- 原始会话只读，统计使用本机可重建索引，并绑定完整发布的分析结果版本。
- 不把缺失记录当作零，不把留存内容估算混入来源报告的模型用量。
- 缓存读取可能属于总输入，推理输出可能属于总输出；组成图和费用计算必须明确各分项是否重叠。
- 单次用量与累计用量不重复相加，明确复制的历史按现有依据排除，不能承诺缺失日志下的全局去重。
- 总览、趋势、分布与明细使用一致筛选范围；表格分页不改变图表统计范围。
- 筛选与下钻保留上下文，返回统计页恢复范围与位置。
- 缺失、估算、部分记录和刷新错误直接可见，公式与详细说明通过统一帮助入口按需查看。

## 已确认的实施默认值

- 跨项目子会话按自身已记录的项目归属，不把子会话项目改写为父会话项目。
- 价格默认采用 USD／百万 Token，价格快照保存获取时间、来源和内容版本；不自动做汇率换算。
- 进入用量页时后台检查价格更新，同一缓存 24 小时内复用，并提供手动更新入口；界面先显示已有结果。
- 自动价格查询顺序：网络快照 → 最近成功网络缓存 → 随包价格表；当前目录没有某个模型时也逐项检查后续来源，不把整份目录视为全部覆盖。
- 用户填写价格或设置映射后重估当前查询范围，不改原始模型名或 Token；重估保留明确价格版本。
- 时间、Token 或费用字段缺失的记录保留独立状态；不提供无法从当前本机历史确定的账号余额、套餐额度或实际账单。
- 以上默认值随完整方案已确认，用户授权开始开发，并要求直接在 main 实施。

## 验收目标

- 任一图表可说明当前范围、单位与缺失边界；图例、轴、提示和排序支持准确比较。
- 相同范围下，指标、时间序列、分组排行和明细能够核对；不能可靠归属的用量单独呈现。
- 图表支持鼠标和键盘查看精确值，通过筛选或明细进入对应会话，返回恢复上下文。
- 所有筛选条件有清晰选中与清除入口，长列表支持搜索和独立滚动，空结果与读取错误分开。
- 费用可核对到明确价格和对应模型用量；无法估价的数据保留原用量和缺失原因。
- 完成适用的类型、国际化、自动测试、构建、公开内容检查与真实浏览器验收。

## Token 计算方案

以下公式约束实现方式，不把各客户端原始同名字段视为同一种含义。

- 先按历史格式归一化为总输入、总输出、缓存读取、缓存写入和推理输出，保留原始记录与采集缺口。
- 普通输入、缓存读取和缓存写入明确互斥时：总输入 = 普通输入 + 缓存读取 + 缓存写入。
- 来源报告的输入已经包含缓存时，不再给总输入加缓存；只有缓存分项和包含关系都明确时，才计算普通输入 = 总输入 − 已包含的缓存分项。
- 总 Token = 总输入 + 总输出；推理若属于总输出，不再次累加。包含关系未知时保留原字段及原因，不靠猜测补齐。
- 组成图只堆叠互斥分项，不能堆叠“总输入”和其缓存子项。无法完整拆分时展示已确认总量与不可拆分状态。
- 缓存读取占输入比例沿用已有定义：可确认缓存读取 ÷ 对应归一化总输入；不能将其称为请求命中率。分子、分母必须来自相同可计算请求集合，缺覆盖时直接说明范围。
- 同一请求的流式快照只保留一次有效用量；累计值用于识别进度，不与单次用量重复相加。新增请求即使数值相同也不能仅凭数值去重。
- 仅有累计值、没有可靠请求边界时，不把差值强行赋给一个日期或模型；后续若扩展差分解析，必须有对应格式的合成回归依据。
- 已记录零值保留，未记录字段保持缺失。根据正文字符估算的内容体量不进入上述 Token 与费用公式。

## 费用计算方案

价格自动查询采用网络优先、本地兜底；用户手动配置具有最高优先级。计价边界沿用以下约束。

- 各互斥 Token 桶分别使用对应价格，单价统一注明货币及每百万 Token 单位。
- 估算费用 =（普通输入 × 输入单价 + 缓存读取 × 缓存读取单价 + 缓存写入 × 缓存写入单价 + 总输出 × 输出单价）÷ 1,000,000。
- 只有适用模型价格和 Token 分项含义明确时才使用公式；价格不适用、必要分项缺失或档位无法判断时报告无法完整估价。
- 来源有明确费用字段时保留为来源报告金额，不能静默替代同口径估算或当作供应商最终账单。
- 不能确认模型名或价格的请求保留原用量，并提供未定价筛选与数量；不默认套用相似模型或客户端默认模型的价格。
- 精确模型名优先匹配，只支持经过确认的别名或用户明确映射；显示原始模型名与计价模型的关系。
- 已定价请求的费用小计与未定价、部分可计算请求分别呈现；覆盖数量与原因直接可见，不能把缺价请求按零费加入完整覆盖。
- 价格快照日期不等于历史价格生效日期。按选定快照重估历史时明确写出该依据，不宣称还原历史实际支出。
- 本地价格覆盖与偏好独立于可重建会话索引保存；修改价格不改原始会话和 Token，统计结果同时说明索引版本与价格版本。
- 不通过当前汇率换算历史支出。默认货币、价格覆盖入口及是否重估由最终页面方案明确。

## 价格获取与配置方案

- 自动目录采用公开价格接口 `https://models.dev/api.json`，保留服务商和模型维度。接口说明见 [API 文档](https://github.com/anomalyco/models.dev/blob/dev/README.md)，价格单位和档位见 [价格数据约定](https://github.com/anomalyco/models.dev/blob/dev/AGENTS.md)。它是公开维护的价格目录，不能宣称每个条目都等于实际服务商账单。
- 下载请求使用固定公开地址，不携带会话正文、标题、本机项目路径、请求用量或客户端凭据。
- 获取成功且结构及价格有效后保存完整快照；请求失败或无效响应保留上一成功快照，不覆盖成空目录。
- 后台更新不阻塞 Token 和已有费用结果。显示来源、更新时间、网络失败后的兜底状态，支持手动重试。
- 用户配置的全局模型价格最高优先，其次是模型与已记录服务商的专属价格；不同服务商覆盖可共存，编辑或恢复只影响选中身份。之后按用户映射查目标模型价格；没有配置或映射时，使用精确匹配和已核验别名查询自动目录。
- 映射的目标明确到计价模型及服务商；原始模型名保持不变。网络更新不删除或改写用户价格及映射，清除覆盖后恢复自动价格查询。
- 用户可以修改已经识别的模型，也可以添加未识别模型。配置提供输入、输出、缓存读取和缓存写入单价，明确单位、保存、取消和恢复自动价格入口。
- 同一模型在不同服务商的价格不任意混用，来源明确服务商时精确选择该服务商。未记录服务商且无服务商前缀的标准 OpenAI 系列且目录有精确原厂条目时，采用 OpenAI API 价格基准并在界面说明；其它多服务商同名模型要求明确映射。带服务商前缀保持精确匹配，未知前缀不移除，不能用模糊前缀无提示地套价。
- 已核验的 `deepseek-official` 原生 API 路由可回退到 `deepseek` 的同一精确模型单价，但明细必须保留原渠道并标为 API 估算基准，不解释为实际端点或账单。渠道自身精确价格及用户设置优先。订阅渠道 `openai-codex` 不自动借用 API 单价。
- 目录中的缓存单价缺失不默认视为免费；对应 Token 为确认零时无需该分项价格，非零且缺价格时保留无法完整估价。
- 保留上下文档位规则，不把档位价格压成一个常数；缺少选择档位所需的数据时标明估价限制。推理或多模态独立计价同样要求对应分项及包含关系明确。
- 随包价格表使用可审阅快照并保留实际数据来源及日期，不能只记录抓取时刻而伪称历史生效价格。
- 手动价格、映射、最近成功当前目录与历史目录缓存及其元信息保存在本地数据目录，与可重建会话索引分开。
- 历史区间来自固定公开数据 `https://raw.githubusercontent.com/pydantic/genai-prices/main/prices/data.json`，只导入精确服务商与模型的明确日期序列。按请求时间使用开始包含、结束排他的 UTC 区间；缺时间、缺区间或未知约束时回退当前快照，并区分历史、当前快照与手动依据。
- 两个目录独立保留成功缓存，首次缺历史缓存时继续检查网络；网络失败不清除有效数据。无价格保持未知，明确零价才能表示免费。

## 筛选与视觉方案

### 筛选

| 条件 | 呈现与语义 |
| --- | --- |
| 日期 | 今天、昨天、近 7／14／30／90 天、全部、自定义区间；默认近 30 天，本机时区，开始包含、结束采用明确边界。 |
| 客户端 | 多选、排除、清空；选项以有效索引实际客户端为准。 |
| 项目 | 多选、排除及名称／完整路径搜索，同名项目显示完整路径，无法归属项目保留选项。 |
| 模型 | 多选、排除及搜索，使用原始模型名称，未知模型保留入口；计价映射不改变模型筛选值。 |
| 主／子会话 | 全部、仅主会话、仅子会话；默认全部。分叉沿现有会话类型定义。 |
| 会话类型 | 交互、自动化、分叉等已有明确类别，不根据标题或频率补造类型。 |
| 用量覆盖 | 已记录完整分项、部分记录、未记录；完整性针对当前查看指标，不混合无关采集缺口。 |
| 定价覆盖 | 可完整估价、部分可估价、未定价，能够进入对应价格配置。 |
| 数值范围 | 会话在当前范围内的 Token／费用最小值与最大值，不能误作为单请求阈值。 |

常用日期、客户端、项目和模型放在顶部；较少使用的条件放入“更多筛选”，显示激活数量。所有条件提供可见选中项、移除及清除全部，保存在地址中以支持返回与复现。多选能力补在现有共享控件体系中，不在页面手写一套键盘及焦点管理。

“未记录”用于检查覆盖缺口，不能补造请求数或费用。没有可确认请求时间的会话不靠会话开始日混入请求日期统计；其列表明确表示日期无法判断，可回到已有会话记录检查。已记录请求数与符合其他条件的会话数分别保留，不能以消息数替代模型请求数。

### 主区

- **指标行：**已记录 Token、估算费用、已记录请求数、活跃会话数、缓存读取占输入比例和必要的覆盖状态。数字与单位对齐，使用紧凑分隔而非大面积卡片。
- **时间趋势：**主图占全宽，切换 Token／费用／请求数；按小时、日、周、月聚合，可按项目、模型、客户端分组。柱状用于离散区间，折线用于变化；默认不通过平滑插值补造峰值。
- **组成与归因：**同一行展示互斥 Token 分项和横向排行；排行可切换项目、模型和客户端。长标签、精确数值及占比可读，前若干项之外保留其余合计，不静默截断总量。
- **日历热力图：**按所选日期范围显示日强度，支持 Token／费用／请求数。颜色阈值与单位可见，键盘和鼠标均能查看具体日期；点击日期追加日期条件。
- **会话明细：**展示当前范围内会话自身新增用量和费用，支持排序、完整分页和父子关系下钻；明细页数不改变主图和总量。

### 交互与可读性

- 图表纵轴从零开始，标清单位；Token 与费用使用指标切换，避免双轴制造不可比关系。
- 悬停与键盘选择展示当前区间、分组、精确值和适用缺失状态，支持触屏访问；不能只依赖颜色或只在 hover 显示关键信息。
- 日期选择、区间选择、排行点击和明细下钻使用明确筛选反馈；图例隐藏系列只改变显示，若作为排除筛选则同时更新所有统计并显示条件。
- 数据颜色复用既有主题，并以类别图例和稳定排序区分系列；异常和部分记录沿现有语义色，不把品牌色与异常色混用。
- 桌面保持开阔主图和对齐的两列分析；窄屏改为单列，筛选进入有界浮层或抽屉，表格局部滚动，不让整页横向溢出。
- 深浅主题、中英文、长名称、空结果、读取失败及部分记录均属于验收场景。当前查询取消或版本改变时不显示旧范围的数据。

## 设计阶段核查

- 当前源码已经核对：现有画像只覆盖单会话或明确子会话树，全局请求聚合、价格管理及独立页面尚未实现。
- 公开价格接口已完成一次实际读取：收到完整 JSON 并成功解析，包含服务商、模型、缓存单价及上下文档位字段。一次成功不能代表持续可用，离线兜底仍属于实施验收条件。
- 设计阶段没有启动功能服务、运行应用测试或进行浏览器验收；不能将规格视为已交付页面。
- 文档公开内容与空白检查通过。后续实施须以合成输入核对公式、范围、版本、去重及价格优先级，再进行真实浏览器验收。

## 数据查询与下钻方案

- 增加全局请求聚合，复用已有有效来源选择、复制排除和请求身份规则；不能依次请求每个会话的完整画像并在浏览器拼接汇总。
- 客户端、模型和时间按实际记录归属；项目沿现有会话项目定义。跨项目子会话建议按自身项目归属，父子关系用于下钻，不擅自改写子会话项目。
- 主、子会话只统计自身新增请求；分叉继承副本按已有明确复制依据排除，缺身份不根据正文相似或时间接近自动合并。
- 全局日期区间过滤请求发生时间，不能复用会话列表的起止时间过滤。多模型会话按每条请求模型筛选，不能把全会话 Token 分摊给各模型。
- 查询固定分析结果版本、筛选范围、时区及价格版本；指标、趋势、分布与明细基于相同有效请求集合。
- 日期有限时，缺时间用量只作为“日期无法判断”的独立提示，不计入该日期范围总量。全部日期时可单独展示其小计，趋势图仍不伪造日期。
- 缺模型、缺项目与缺时间保留明确入口，不因价格匹配要求而从 Token 总览丢弃。
- 点击时间区间或分组追加明确筛选，显示可清除条件；从会话返回时恢复筛选、显示指标和滚动位置。
- 明细按稳定顺序分页，保留所属会话、请求时间、模型、Token、费用及覆盖状态；能够定位请求的记录进入具体消息，缺定位依据时只进入对应会话并说明原因。
- 缓存和索引优化以实测为依据，派生聚合可以重建。不能为趋势性能删除旧请求明细或改变原始来源生命周期。
