# 服务状态活动作业查询与历史保留

Type: task
Status: resolved
Priority: P2（长期历史作业积累时触发）
Review: R11
Spec: [总规格](../spec.md)

## 问题

精简状态和停止预检为查活动作业同步读取并解析全部历史作业，长期运行后可能健康检查超时。

## 实施范围

- 活动作业使用可索引的窄查询，必要迁移遵循既有写权限和启动顺序。
- 常用历史作业读取分页，确定终态作业有界保留策略与过期访问语义。
- 保护活动任务、等待者和启动准备引用，保留现有状态字段及调用方契约。

## 验收标准

- [x] 固定活动作业数量，增长已完成历史不会导致状态请求解析全部历史 JSON。
- [x] 状态、停止预检、任务等待和重启恢复正确；需要兼容的完整响应仍可显式读取。
- [x] 清理不触及在途或有效引用作业，访问已清理作业明确报告不存在。
- [x] 旧库可启动，迁移和清理不将长锁等待引入 HTTP 主线程。
- [x] 验收记录具体保留上限、保护规则、实际规模、响应耗时与内存，不新增配置界面。

## 测试与数据

复用服务生命周期、Worker 和 CLI 状态测试；真实数据只读查询，同规模隔离副本验证迁移、清理与等待，合成大历史补充负载。

真实数据使用范围沿用总规格：直接读取实际数据进行核对；写入与故障场景使用隔离副本。具体样本与截图只留本机。

## 协作与范围约束

索引和查询改动与既有短命令 Worker 对齐；不要通过放宽健康检查超时掩盖全表扫描。

## Answer

- 活动作业改为带表达式索引的身份/状态窄查询，精简 HTTP 状态和恢复不再加载全部历史 JSON；增加独立分页作业接口，显式完整状态响应继续兼容。
- 按仓库保留最近 1,000 条终态作业。作业仅用于近期诊断，长期活动证据仍由完整分析版本和原始来源保存；千条上限控制元数据规模，不缩减历史证据。
- 当前两份完整版本的最近成功检查、管理线程中的活动任务/等待者，以及启动准备固定引用额外保护；启动任务在登记时即绑定引用，准备结束后释放。清理每批最多 1,000 条，通过异步写权限协调并在批次间让出。
- 既有数据库仅增建索引，沿用现有 JSON 与版本契约；清理只处理终态，已清理作业明确返回不存在。
- 10 万条合成作业全量读取过滤约 87.5 毫秒，活动窄查询约 0.17 毫秒；99,000 条分批清理后保留 1,000 条，模型与原始来源未参与。
- 326 条真实作业只读分页及状态核对通过；新增保留/引用/在途保护、旧库重开、HTTP 精简状态禁用全量读取回归通过。相关联合 91 项通过，最终全项目验收由任务 12 汇总。
