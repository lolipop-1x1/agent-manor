# 地图历史路径与单条证据查询优化

Type: task
Status: resolved
Priority: P2（大量历史删除或改名路径时触发）
Review: R09
Spec: [总规格](../spec.md)

## 问题

不在当前基线中的历史路径逐条全扫描已知路径，单条证据与分页也承担全部筛选成本。

## 实施范围

- 为完整分析版本建立有界的路径、目录后代及事件身份索引。
- 单条证据先定位事件，再核验筛选；列表查询保留顺序、总数和过滤交集。
- 索引缓存随版本淘汰，遵循既有内存与快照生命周期。

## 验收标准

- [x] 目录、类别、无路径、失败、删除和改名场景与修复前结果等价。
- [x] 5 千、1 万、2 万事件的增长曲线消除逐事件全路径扫描退化。
- [x] 单条证据不因无关历史数量增长承担同样的全量筛选。
- [x] 慢查询不再长期堵塞同 Worker 的其他地图读取，缓存不会无界增长。

## 测试与数据

复用地图查询 API 与覆盖计算模块；本地真实仓库只读测量，合成边界样例验证结果等价和规模曲线。

真实数据使用范围沿用总规格：直接读取实际数据进行核对；写入与故障场景使用隔离副本。具体样本与截图只留本机。

## 协作与范围约束

优先消除重复计算，不以增加 Worker 数量或缩减历史证据替代修复。

## Comments

- 2026-10-26：由项目全面审查及修复讨论生成，已标记为 ready-for-agent。此状态表示规格可实施，尚未修复或完成验收。


## Answer

- 为地图快照构建路径排序、类别前缀计数及事件身份索引；目录范围与类别按同一交集判断，单条证据先按身份定位再应用筛选。
- 索引沿用最多两份快照的缓存生命周期，已淘汰版本不能借缓存继续查询。
- 三万条删除文件回归修复前约 13.8 秒，修复后单次约 82–111 毫秒；5 千/1 万/2 万合成事件独立探针约 19/27/49 毫秒，数字仅限该本机合成输入。
- 小规模本地真实地图的 8 组目录/类别筛选与旧实现完全一致。新增单条证据路径交集及范围外拒绝验证；地图查询专项 5 项通过，后端联合 91 项通过。
