# 补读证据的完整检查点与恢复

Type: task
Status: resolved
Priority: P2
Review: R02
Spec: [总规格](../spec.md)

## 问题

补读引用没有保存对应来源，分片完成后恢复无法解释候选证据，重试同一检查点持续失败。

## 实施范围

- 将补读消息身份、哈希、范围、必要来源快照与已消耗额度纳入检查点。
- 恢复时重建引用表并核对来源，沿用既有候选、处理位置和审阅边界。
- 定义旧检查点的格式识别和安全恢复；无法确定恢复时明确要求重新预览。

## 验收标准

- [x] 补读成功后在分片检查点暂停、重启、后续阶段失败，再恢复均与连续执行保持证据等价。
- [x] 恢复不重置补读额度，不重复发布已完成结果，不以当前正文替换失配来源。
- [x] 来源变化和不兼容旧检查点返回可理解诊断，不进入重复失败循环。

## 测试与数据

复用沉淀 pipeline 和任务服务的检查点入口、临时知识存储及假生成模型；在真实会话隔离副本中验证恢复及来源变化。

真实数据使用范围沿用总规格：直接读取实际数据进行核对；写入与故障场景使用隔离副本。具体样本与截图只留本机。

## 协作与范围约束

检查点格式调整与现有任务恢复保持兼容，变更说明记录可恢复和需重新预览的边界。
