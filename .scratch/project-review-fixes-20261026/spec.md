# 全项目可靠性与性能修复

Status: resolved
Created: 2026-10-26
Baseline: 901e68ae033547f3479762c87356f03417cecf83

## Problem Statement

用户需要可靠地回查 Agent 历史、沿统计结论打开同一版本的证据，并在知识沉淀、搜索和资源管理中连续操作。当前实现存在 11 项已确认问题：知识向量维护在规模增长时阻塞服务；沉淀检查点遗漏补读证据；知识索引并发启动重复调用；证据跳转丢失版本；来源读取与版本淘汰并发时返回部分结果；语义搜索切页后保留忙状态；知识审批后页码越界；资源来源变化被旧扫描结果覆盖；历史路径筛选出现平方级扫描；任务页持续轮询完整历史结果；状态查询随历史作业积累增长。

这些问题影响结果可信度、恢复能力和持续使用体验。修复需要让版本、任务、检查点、请求状态和计算边界由明确接口保证，并保留既有统计口径及用户整理形成的内容。

知识向量维护列为 P1，触发条件是已启用知识向量索引且知识规模增长；其余列为 P2。性能证据来自隔离样本，不能据此宣称用户当前真实数据已经出现相同延迟。

## Solution

修复 11 项问题，让用户获得以下行为：

- 知识向量维护按变化修订处理，普通查询在索引维护期间继续响应。
- 沉淀任务暂停、重启和失败恢复保留完整证据及已消耗预算；知识索引同一时刻只有一个有效执行者。
- 统计、来源、原文及跨页链接绑定同一完整版本，版本不可用时明确提示。
- 搜索取消、末页审批和资源来源变更后，界面与后台状态自动恢复一致。
- 地图筛选、任务列表和服务状态只处理本次查询所需的数据，成本随有效范围增长。

以现有本地 HTTP API 作为主要行为验收入口，跨页交互使用真实浏览器；在已有检查点、数据库和计算模块入口补充确定性的恢复、并发与规模验证。用户已明确允许直接使用本地真实数据，实际查询、证据对照和性能测量采用本地真实数据；需要写入或故障注入的场景使用真实数据的隔离副本。

## User Stories

1. 作为知识库用户，我希望知识内容未变化时后台快速结束索引检查，以便浏览其他功能时没有周期性停顿。
2. 作为知识库用户，我希望只对新增或变化修订维护向量，以便知识库增长后仍能持续使用。
3. 作为知识库用户，我希望索引维护期间状态、会话和资源查询继续响应，以便后台工作不阻断前台操作。
4. 作为知识库用户，我希望审阅、发布、废弃或恢复后检索覆盖正确变化，以便搜索结果遵循当前可用性和修订状态。
5. 作为知识沉淀用户，我希望补读证据后暂停任务仍可继续，以便不必重复沉淀整个会话。
6. 作为知识沉淀用户，我希望程序重启后保留补读来源和范围，以便恢复结果仍能回查依据。
7. 作为知识沉淀用户，我希望失败重试沿用已花费的补读额度，以便重试不绕过调用限制。
8. 作为知识沉淀用户，我希望来源改变时得到明确诊断，以便不会使用失配证据继续生成知识。
9. 作为知识索引用户，我希望重复点击或多个页面同时启动构建只形成一个有效任务，以便避免重复模型请求。
10. 作为知识索引用户，我希望暂停覆盖当前任务的全部执行，以便操作反馈与实际调用一致。
11. 作为知识索引用户，我希望旧任务结束不会覆盖新任务状态，以便进度和错误可信。
12. 作为知识索引用户，我希望恢复和自动维护遵循同一互斥规则，以便不同入口不会重复编码。
13. 作为用量统计用户，我希望从某个报告进入原文时仍使用该报告的历史版本，以便金额、请求和证据可以对应。
14. 作为资源管理用户，我希望从使用记录进入会话时携带记录版本和消息位置，以便直接核对同一份证据。
15. 作为历史回查用户，我希望复制链接、新窗口打开与普通点击具有相同定位语义，以便跨窗口调查结果一致。
16. 作为历史回查用户，我希望旧版本被淘汰时收到版本不可用信息，以便不会把新历史误当成旧证据。
17. 作为代码地图用户，我希望读取来源期间发生新版本发布仍得到完整的所选版本，以便来源与缺口没有被截断。
18. 作为代码地图用户，我希望不存在的版本明确失败，以便空列表只表示实际没有来源。
19. 作为语义搜索用户，我希望请求期间切走再返回后搜索按钮可以正常操作，以便继续查询。
20. 作为语义搜索用户，我希望取消旧搜索不清除新搜索的忙状态或结果，以便连续操作没有竞态。
21. 作为语义搜索用户，我希望页面失活取消请求后保留已有完整结果和输入，以便回到原来的工作上下文。
22. 作为知识审阅用户，我希望审批末页最后一项后自动进入有效页，以便继续处理剩余内容。
23. 作为知识审阅用户，我希望 URL、分页区间、总数和列表来自同一查询，以便导航状态可理解且可恢复。
24. 作为知识审阅用户，我希望审批失败时保留原列表与错误，以便重试而不误判处理完成。
25. 作为资源管理用户，我希望新增手动来源成功后盘点包含新来源，以便配置与清单一致。
26. 作为资源管理用户，我希望移除来源或变更项目范围后旧扫描不覆盖新状态，以便界面没有过期入口。
27. 作为资源管理用户，我希望普通并发读取仍能共用盘点，以便修复一致性时不引入重复扫描。
28. 作为代码地图用户，我希望大量文件删除或改名后活动筛选仍可用，以便调查长期仓库历史。
29. 作为代码地图用户，我希望打开单条证据不等待全部历史筛选，以便从汇总快速下钻。
30. 作为代码地图用户，我希望路径优化保留类别、目录、失败和未知范围的原有语义，以便性能提升不改变统计。
31. 作为知识沉淀用户，我希望任务列表只加载摘要和当前页，以便任务历史增加后页面仍然轻量。
32. 作为知识沉淀用户，我希望打开任务后按需读取详情，以便完整结果仍可查阅。
33. 作为知识沉淀用户，我希望任务状态筛选与服务端分页共同生效，以便页数和总数准确。
34. 作为 CLI 或 Web 用户，我希望状态查询只读取活动任务及必要计数，以便长期运行后仍能判断服务是否可用。
35. 作为 CLI 或 Web 用户，我希望历史作业保留策略不清理运行中或仍被引用的作业，以便等待、停止和恢复不受影响。
36. 作为维护者，我希望修复前后在同一份本地真实数据上核对结果和性能，以便确认收益及实际支持边界。
37. 作为维护者，我希望真实历史和验证截图保存在本机，以便可复现调查而不公开私人内容。
38. 作为维护者，我希望通过行为和版本边界测试约束后续扩展，以便新入口不再遗漏取消、事务或版本传递规则。

## Implementation Decisions

1. **总体边界。** 沿用本地服务、SQLite、独立 Worker、完整版本发布和共享契约。仅实施 11 项修复及其必要局部重构，统计口径、人工审阅和资源管理身份继续遵循既有领域约定。

2. **R01：知识索引增量维护。** 以知识修订身份和编码配置指纹识别已处理输入，记录待维护修订或等效内容版本；创建、修改、审阅、发布、废弃和恢复正确影响待处理范围。无变化的暖检查不重新读取、切块全库。切块、批量扫描和索引计算进入可停止的后台 Worker，HTTP 只协调任务和读取必要状态。重启补齐未完成变更；配置切换沿用预览、同意和预算边界；向量是可重建派生数据，不删除知识正文或必要证据。

3. **R02：完整沉淀检查点。** 保存补读引用、消息身份、正文哈希、读取范围、必要来源快照以及已消耗额度，和候选、处理位置共同形成可恢复状态。恢复重建与首次执行相同的引用表；来源变化明确停止或报告已有的来源变化错误。检查点格式升级需识别旧记录；可确定恢复的旧记录继续恢复，缺少必要补读依据的记录明确要求重新预览，不能无限重试同一坏状态或静默替换证据。保留按具体修订审阅、后台建议不直接覆盖已发布知识的边界。

4. **R03：知识索引单执行者。** 构建、恢复、暂停和自动维护的状态检查、转换与启动共享串行操作边界。并发重复启动至多产生一个任务，其他请求返回既有忙碌诊断；不新增第二套公开错误语义。进度和取消绑定任务身份，旧任务的完成、失败或清理不修改新任务状态。已停止的任务不继续发布向量或成功状态；已发出的外部请求只能按现有可取消能力处理，不承诺服务商撤销计费。完成进度不能超过分母。

5. **R04：版本化会话证据定位。** 用量报告和资源使用记录的跳转目标包含所选历史版本、会话身份及可选消息锚点。统一应用回调与地址序列化，普通点击、复制链接和新窗口打开使用同一规则。会话阅读明确采用目标版本，保留原筛选、分支和返回位置。已淘汰版本使用明确的版本不可用错误，不回退最新版本；无版本的既有普通会话入口继续采用当前版本。

6. **R05：来源一致快照。** 来源列表的版本确认、来源分块及缺口分块共同在一个只读快照内完成。读操作与发布、淘汰交错时，要么返回完整的所选版本，要么在建立快照前明确拒绝不可用版本；不以缺失分块冒充正常空结果。不延长版本保留数量，不用全量正文加载替代窄字段读取，读取事务及时结束。

7. **R06：页面请求生命周期。** 搜索成功、失败、取消和页面失活都结束该请求拥有的忙状态。采用请求身份或等效所有权检查，旧请求不能清理新请求状态或覆盖新结果。页面保持挂载，保留输入、筛选和上一完整结果；待更新期间继续暂停旧结果下钻，结束后按实际查询范围恢复操作。重新激活无需切换模式、按 Enter 或刷新页面来解除遗留忙状态。

8. **R07：有效分页。** 知识列表在操作或刷新后根据总数计算最后有效页，越界则更新查询页、URL 并重读。总数为零时页码归一。翻页重读成功后整体替换结果，等待和失败保留上一完整列表；分页显示、查询页码与实际结果保持一致，不通过只修改显示数字掩盖越界。复用已有分页和焦点规范，不新增分页控件。

9. **R08：盘点输入版本。** 资源扫描身份包含影响盘点的来源配置及项目范围版本。同输入普通读取继续合并。扫描中发生新增、移除来源或相关输入变化，修改后的刷新等待一轮覆盖新输入的扫描；旧扫描不能作为新配置的完成结果或重新写回最新缓存。连续变更可合并为最新必要扫描。失败保留上一完整快照并明确可重试，收藏、操作记录和恢复材料继续独立保留。

10. **R09：历史路径查询索引。** 为完整地图版本建立可复用的路径、目录后代及事件身份索引，消除对每条缺失路径遍历全部已知路径的过程。单条证据先定位事件，再验证当前筛选范围；分页活动结果保留现有排序和总数。索引随结果版本切换失效，设置与现有快照缓存一致的生命周期，避免以无界缓存换性能。目录、类别、无路径事件、删除文件、改名和失败证据的语义保持等价。

11. **R10：有界任务列表。** Web 任务列表和轮询接入已有摘要响应与服务端分页；所需状态筛选在分页之前由服务端统一应用，沿用已有查询能力，缺少的最小筛选契约再补齐。当前任务页仅传必要计数、状态和定位信息，详情和结果按需读取。运行任务保持必要刷新，闲置、隐藏和无任务场景避免持续传输完整历史。当前完整接口继续可用，摘要与完整查询的范围和总数语义一致。

12. **R11：有界服务状态与作业保留。** 状态查询直接筛选 queued/running 作业及必要计数，使用可索引字段或等效索引；窄查询不反序列化全部历史作业。索引结构变化兼容既有持久记录，短写命令和迁移继续遵循既有写权限协调，不回到 HTTP 主线程执行长写事务。历史作业列表采用分页并设定有界保留，清理仅针对终态作业，保护活动等待者、启动准备及仍需引用的记录。具体保留上限在实现时按现有契约与真实规模确定并写入验收记录，不增加未讨论的用户配置入口。已清理作业的直接访问明确报告不存在，普通服务状态和停止预检不受历史积累影响。

13. **公共规则收拢。** 围绕上述修复提取必要的证据定位、请求所有权和任务串行机制，优先复用已有实现。保持各业务领域的筛选、审阅和预算含义独立；接口不暴露数据库或线程实现细节。

14. **兼容与展示。** 复用现有 API 字段及稳定错误码，必要新增字段遵循现有 Web/CLI 摘要和完整响应约定。产品错误同时提供中英文描述，不改变原始历史、资源正文或稳定标识。刷新保留完整结果和布局，错误可见且可重试。

## Testing Decisions

### 测试边界与样本

- 以现有本地 HTTP API 验证结果、任务状态、版本和错误契约，不为测试创建新的公开端点。
- 页面生命周期、跨页证据和分页采用正式构建产物及真实浏览器验证；受控延迟只用于稳定触发竞态，不替代真实 API 结果核对。
- 检查点恢复、SQLite 交错和路径复杂度优先复用现有模块测试入口，必要的同步屏障留在测试内部，避免依赖碰巧发生的时序或固定睡眠。
- 直接使用本地真实数据进行只读查询、统计与原文对照、暖维护观察及性能测量；先记录实际规模、版本、配置、时区、缓存状态和查询范围。实现前后采用同一有效输入；来源持续变化时使用一致快照对照。
- 审批、资源来源变更、恢复、构建、重启和故障注入使用真实数据的隔离副本及独立数据目录；数据库副本使用能包含已提交 WAL 的一致方式生成。代码仓库和原生来源保持只读，写场景不指向实际资源入口。
- 并发计数和故障恢复使用可控本地模型响应；真实数据授权不自动扩大外部模型调用范围或预算，既有配置、同意和预算继续有效。
- 自动化回归保留可公开的最小合成样例；真实数据、数据库、正文、定位清单和截图仅保存在本机忽略目录或仓库外，公开记录只写方法、规模和结果。

### 每项修复的完成标准

| 问题 | 可观察验收标准 |
| --- | --- |
| R01 | 同一知识库暖维护无变更时不再出现随全库正文增长的周期性计算停顿；新增或状态变化修订最终正确检索，后台维护时并发状态和会话查询持续可用；停止与重启不遗漏待处理变化。 |
| R02 | 补读完成后在分片检查点暂停、进程重启或后续阶段失败，再恢复均得到与连续执行等价的候选及证据；额度不重置；来源变化及无法恢复的旧检查点给出明确诊断。 |
| R03 | 同一预览并发提交三次构建至多接受一个任务，所需一块仅新增一次模型请求，完成进度不超过总数；暂停/恢复/自动维护交错后仅当前任务可发布状态。 |
| R04 | V1 报告或证据存在、V2 发布后，从用量和资源普通点击及新窗口链接仍读取 V1 的同一消息；V1 淘汰后明确失败；返回原页保留浏览上下文。 |
| R05 | 在读取版本头与分块的边界并发发布并淘汰旧版，响应要么与旧版完整结果相等，要么是明确的版本不可用错误；不能成功返回缺失来源或缺口的旧版本。 |
| R06 | 慢搜索期间切页并返回，旧请求结束后按钮和结果按当前状态恢复；连续查询中旧请求取消不覆盖新查询；保留输入、筛选及已有结果。 |
| R07 | 21 条待审、每页 20 条，在第 2 页审批唯一项后自动显示剩余 20 条所在有效页；URL、区间和页码一致；覆盖最后一项删除、总数为零及请求失败。 |

## Out of Scope

- 全量重写服务、引入新的全局状态框架、动态插件系统或远端多用户架构。
- 将整个会话存储拆成新架构，或统一所有客户端的能力注册；本次仅做修复需要的接口收拢。
- 根据发现压缩事件就扩大“未压缩会话”的可观测分母；该能力仍需独立证明完整性。
- 改变 Token、费用、轮次、资源使用和证据强弱的统计定义，或扩大当前客户端支持承诺。
- 改变知识审阅与发布规则、自动覆盖人工知识、永久复制完整会话、扩大外部模型调用同意。
- 自动修改实际 Skill/MCP 配置、删除真实历史或公开真实数据。
- 新增任务保留策略的用户配置页、界面视觉重设计、为构建体积提示单独开展分包工程。
- 在规格生成阶段实施修复、提交、推送或发布。

## Further Notes

- 本规格由本次审查和后续修复讨论整理。用户已确认可直接使用本地真实数据进行验证；本次生成规格不代表这些真实数据验收已经完成。
- 遵循完整版本发布、有限版本保留、增量复用、历史后台同步、知识及必要证据独立保留、知识修订快照、独立任务 Worker 和写权限协调等既有 ADR。此规格没有提出覆盖这些决定的新架构。
- 审查基线：全量测试 1,792 项中 1,790 通过、2 失败；失败所在文件独立复跑 17 项通过；CLI 工作区 47 项通过；类型、国际化、公开检查和构建通过。上述是历史基线，不是本规格实现后的结果。
- 任务编号对应审查 R01–R11；联合验收单独成文。可以并行处理互不影响的领域，知识索引增量维护与生命周期修复应协调接口并顺序合并，避免同时覆盖同一执行状态。
- 建议先收束知识索引生命周期、检查点和增量维护，并完成版本一致性；随后修复界面与盘点边界、查询规模问题，最后联合验收。具体实现顺序可按依赖调整，不能遗漏任何一项验收标准。
