# 最近七天复盘指标草案

本方案已经整版确认，按用户要求直接在 main 完成实现、测试与真实页面验收。实现状态见关联任务；未完成任务不代表指标已经交付。

## 已确认范围

- 本机时区最近七个完整日历日，不含今天，不做前七天对比。
- 一次真实用户需求对应一个会话轮次；明确结束不等同于任务成功。
- 模型请求数为步骤；工具调用数单列。
- 轮次耗时为用户请求到明确终答的经过时间，包含工具、排队与等待。
- 未观测压缩会话取逐会话峰值总输入，再对会话平均；输入包含缓存，不包含输出。
- 展示实际未缓存输入与假设缓存价差，不宣称可兑现的节省金额。
- 替换当前重点洞察区域，采用四组固定核心指标与重点记录。区域日期独立固定，客户端与项目筛选继续生效，显示具体起止日期。
- 用户会话与独立用户需求的分叉为核心；子 Agent 与有明确触发依据的自动执行单列，未知来源不按正文猜测。
- 单轮投入按结束日在统计期内纳入整轮；窗口内事件指标按实际发生时间纳入。
- 无压缩样本按整个留存会话未见压缩、有可用压缩支持且无相关缺口判断，输入峰值只取最近七天。
- 分位数、排行、样本覆盖、来源与解释放在按需详情，主界面保留清晰名称、数值和动作。

## 呈现分组

| 分组 | 固定指标 | 详情与动作 |
| --- | --- | --- |
| 会话与压缩 | 活跃用户会话、已结束轮次、发生压缩的会话与压缩次数 | 会话与轮次列表、压缩位置、样本与支持范围 |
| 单轮投入 | 平均模型步骤、平均工具调用、平均 Token、平均轮次耗时 | 各项中位数与 P90、最长轮次、高 Token 轮次 |
| 缓存与输入 | 零缓存请求、缓存读取占输入比例、普通未缓存输入、假设缓存价差、无压缩会话平均峰值输入 | 部分命中与缺字段、价格与上下文档位、大输入低缓存请求 |
| 偏好与节奏 | 常用 Agent 客户端、常用模型、常用思考程度、平均用户提示词长度、用户交互集中时段 | 完整排行、用户消息星期与小时分布、设置与文本支持范围 |

采用四组平铺指标，沿用现有字号与组件，四组不采用额外装饰卡片。重复提出的常用模型只保留一个指标。

## 核心指标定义

| 指标 | 展示与定义 | 方案讨论时的支持基础 |
| --- | --- | --- |
| 活跃用户会话 | 最近七天有真实用户轮次新增交互或执行活动的去重用户会话；新建会话可在详情另列 | 有消息、会话及事件时间基础；需要限定用户范围 |
| 压缩会话与事件 | 最近七天发生压缩的会话数、压缩事件数；压缩率保留可观测样本分母 | 有压缩事件；需明确压缩记录支持与范围 |
| 已结束轮次 | 有明确终答结束证据的真实用户轮次；未确认结束和时间缺失单列 | 有轮次与 explicit/inferred final 字段，需新增统计 |
| 每轮模型步骤 | 已结束轮次中已识别模型请求数的平均值；工具调用数另列 | 有请求身份和 turnId；记录缺失仍须保留 |
| 每轮 Token | 单轮归一化输入加输出之和，再对用量完整的已结束轮次平均；推理与缓存子集不重复累加 | 有逐请求用量，需轮次聚合与完整性判断 |
| 轮次耗时 | 平均值、中位数、P90；最长轮次可打开需求与执行轨迹 | 有消息时间，需轮次聚合；不能替换为请求计时平均 |
| 缓存与未缓存 | 明确零缓存的请求数、未缓存普通输入、缓存读取占输入比例；部分命中与缺字段分别保留 | 有缓存事实与归一化计价桶 |
| 缓存价差估算 | 普通未缓存输入乘以适用普通输入单价与缓存读取单价之差，按请求价格与档位求和 | 价格基础可复用；缺任一单价或输入分项不补零，不将缓存写入当普通输入 |
| 无压缩观测的峰值输入 | 整个留存会话未见压缩且具备观测支持的合格会话，取最近七天内最大请求总输入，再对会话平均 | 总输入可用；不能直接复用语义混合的 contextTokens；无支持或有相关缺口的样本排除 |
| 用户交互时段 | 真实用户消息按本地星期与小时分布，显示最集中时段 | 有事件时间；需排除 Agent、子任务、自动执行与注入；不能称真实工作时长 |
| 常用 Agent | 当前按 Agent 客户端理解；默认按最近七天真实用户发起轮次数排行，展示名称、轮次数与占比；会话数、模型请求数、Token 与费用在详情 | 已有客户端身份和分布基础，需新增用户轮次口径；不按模型名或子 Agent 名推断客户端；术语解释与排名口径待整版审阅 |
| 常用模型 | 默认按实际模型请求数排行，展示前几名与占比；Token、费用在详情 | 已有模型分布；未知模型保留 |
| 常用思考程度 | 仅根据来源明确记录的设置，按请求或有效设置区间归属；缺失单列 | 尚无统一结构字段，需要补充解析与时间生效关系 |
| 平均用户提示词长度 | 真正用户输入的可见文本字符数均值；附件、系统注入及工具结果排除 | 消息正文可回查，但现有总览窄事实不含文本；需计算可复用长度事实 |
| 最长轮次 | 按可测轮次耗时排名，关联原需求、步骤、Token 和具体会话 | 需新增轮次聚合；不以整条会话跨日跨度替代 |

## 扩展详情

1. 轮次投入分布：除平均数外，查看步骤、Token、耗时的中位数与 P90，避免少数大轮次扭曲平均数。
2. 高投入轮次与集中度：分别列耗时最长和 Token 最高的轮次；前五轮占完整样本 Token 的比例。
3. 大输入与低缓存记录：按普通未缓存输入规模定位重点请求，提供上下文与价格依据；不直接认定缓存异常。
4. 压缩集中度：哪些会话反复压缩、每个会话压缩几次、何处发生；不将压缩后的耗时变化解释为因果。
5. 项目投入分布：各项目的用户轮次、已记录请求、Token 与估算费用；并行轮次耗时不相加为工作时长。
6. 子 Agent 投入：按最近七天自身事件计算委派会话的请求、Token 和费用占比；不分摊到无明确关联的父轮次。
7. 工具负担：每轮工具调用数、涉及明确工具失败的轮次与同工具后续调用；不称返工率或任务失败率。

优先建议前 1–3 项；后续项通过详情按需调查。缺少结束证据或用量分项时，不把剩余记录冒充完整均值。所有指标保留样本、缺失、时间、来源及版本详情，主页面沿用紧凑名称与必要状态图标。

## 数据与样本推荐规则

- 已结束轮次主样本只纳入来源明确的结束证据；推断终答和未确认结束保留在详情，不静默混入主均值。按客户端和具体采集覆盖说明可用样本。
- 同一指标的请求身份去重、继承复制排除以及 Token 子集关系沿用既有事实；缺请求、缺用量、缺时间和缺价格分别处理。
- 平均单轮 Token 只基于能确认用量完整的已结束轮次，不把部分请求之和当作完整均值；无法判明请求留存完整性的来源保留观测边界。
- 模型偏好默认按请求数计，思考程度只按来源明确记录且可绑定到请求的设置计，不能用推理 Token 数倒推思考等级。
- 新增常用 Agent 指标，暂按 Agent 客户端解释；推荐按真实用户发起轮次数反映使用频率，子 Agent 与自动执行沿用单列边界，客户端身份未知时保留未知。
- 用户交互时段不根据会话跨度推算工作时长；提示词统计只包含可可靠识别的真实用户可见文字，不对无法拆分的注入内容声称已清洗。
- 事件窗口的七天总用量与结束轮次的完整投入可能不同；两者不要求数值相等，详情展示统计单位与时间归属。
- 当前自动触发身份不完整；子会话身份、静默执行模式与自动触发是不同概念，未知来源须保留。
