# 后台任务隔离与异步索引写入

Status: resolved

## 目标与边界

先拆开会话同步与代码地图的执行队列、失败和重试，再让 HTTP 主线程不再同步等待 `index.sqlite` 写锁。保留完整版本发布、来源只读、仓库删除取消边界、任务去重和现有 Web／CLI 返回契约。停止仍使用独立控制通道。

## 方案

- 地图和会话各有一个按需启动的长期 Worker。地图内部跨仓库仍串行；自动会话同步只看会话队列是否忙碌。任意一类 Worker 失败只结算自己所属任务，显式重试只重建对应线程。
- 轻量索引命令放到独立 Worker，拥有任务管理和短写事务；HTTP 通过异步命令登记、删除、关联和创建任务。重计算仍在各自 Worker，不进入轻量命令队列。HTTP 查询保留读取已发布版本的连接。
- 登记和关联提交后才能派发刷新；删除成功后才撤销任务；发布继续在事务中复核任务身份。单写者竞争仍存在，但等待发生在后台，状态和控制请求能继续响应。
- 自动同步适配异步任务创建，保留范围合并、完成通知结算、失败退避与时钟测试接口。后台关闭先收束任务及状态写入，再关闭对应连接。
- 所有后台索引写连接共享写权限，仅协调写语句和事务，不串行整项分析。管理线程异步等候并回收退出线程的权限；地图查询、用量派生缓存和空闲回收纳入同一边界。失败结算遇外部写锁时重试，不能从错误回调终止管理线程。

## 执行与验证

1. 新增可控 Worker 隔离回归，先证明慢地图挡住会话、失败相互牵连和地图繁忙延迟自动同步。
2. 拆分两类 Worker，保持现有地图、会话与仓库生命周期测试通过。
3. 新增跨进程 SQLite 持锁 HTTP 用例，验证主线程状态请求在写命令排队时保持可响应。
4. 引入轻量异步索引命令边界并迁移 HTTP／启动入口，验证登记、刷新、删除、失败恢复及返回结构。
5. 运行相关自动化、类型、构建、国际化和公开内容检查；用隔离数据及已有真实数据检查增量结果、停止和恢复后推送 main。真实诊断材料仅保存在忽略目录。

## 不变量

任务成功落库后才回传和派发；失败不覆盖上一完整结果；地图删除不影响全局历史；读状态不创建任务；地图和会话并行不表示 SQLite 同时存在多个写事务。

验证：全量 1767 项、CLI 专项 45 项、构建、国际化、公开内容检查及真实安装运行通过。详见 `docs/validation/backend-task-isolation.md`。
