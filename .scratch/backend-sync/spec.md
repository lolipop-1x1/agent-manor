# 后台历史自动同步规格

状态：已按用户确认方案直接在 main 实施并完成验收。任务图见 [issues](issues/)，测试、性能与边界见[验证记录](../../docs/validation/refresh-workflow.md)。

## 目标

由本地服务统一决定自动历史检查的时机并执行同步，页面只观察统一状态、配置策略和提交明确的手动操作。多个页面不会各自启动周期扫描，关闭全部网页也不关闭后台调度。本轮只迁移历史自动同步，不增加系统登录自启，不迁移代码地图自动分析。

## 现有边界

历史更新读取客户端来源并发布完整会话库；页面更新读取完整结果；语义索引维护消费已发布历史，不代替来源检查。原始历史只读，失败保留上一完整版本，未变化检查可以沿用版本。历史同步、地图分析、资源盘点与价格更新保持各自含义。

本轮替代 ADR 0010 中可见网页发起周期检查、所有网页隐藏时停止新增检查的约定；完整发布、来源只读和地图范围继续保留。产品当前行为与验证程度分别记录于 PRODUCT.md 和验证文档。

## 已确认的方案

- 每个本地数据目录由对应后台统一调度，所有入口取得同一任务与状态；状态读取不启动历史更新。
- 网页继续保留开关、间隔和手动同步入口，仅移除前端自动触发责任。页面是否可见只影响状态读取频率和页面结果更新，不影响已启用的后台周期。
- 首版用轻量、只读状态轮询接入已有进度与完整结果通知，不增加 SSE 或 WebSocket。
- 沿用已有开关和周期；原来关闭的保持关闭，原来开启的交由后台接管。后台显式停止后停止调度，后台再次运行时恢复已保存策略，复用原有启动检查。
- 历史自动同步与代码地图自动分析的策略保持独立。系统登录自启、资源盘点和价格目录更新不属于本轮改造。
- 历史完成且发布内容变化后，已有语义后台根据独立范围和调用策略维护；首次构建仍显式开始，暂停、预算及模型连接边界不变。

## 已确认的运行规则

| 场景 | 行为 |
| --- | --- |
| 首次开启 | 立即请求一次全局快速检查，可复用足够范围和强度的在途任务 |
| 正常周期 | 上一轮成功的全局检查完成后，再等待设定间隔 |
| 单轮耗时超过周期 | 不积压每个错过的周期；本轮完成后再按间隔安排 |
| 后台启动 | 保留已有一次性启动检查，自动策略复用该任务，避免重复扫描；自动策略关闭不取消既有启动检查语义 |
| 睡眠恢复 | 已到期只补查一次，未到期继续等待，不重放睡眠期间每个周期 |
| 关闭策略 | 取消未来自动周期和未开始的自动补查，让在途检查正常完成；手动任务保留 |
| 范围不足 | 局部任务不能代替全局检查，最多保留一轮合并后的必要自动补查 |
| 整项失败 | 保留上一完整版本和可见错误，自动退避，手动可立即重试 |
| 完成但有诊断 | 保留来源诊断，按正常周期继续检查，不作为整项失败退避 |

退避等待为 `max(当前周期, min(30 秒 × 2^(连续失败次数 - 1), 10 分钟))`，从失败任务的完成时刻开始等待，成功后清零失败计数并恢复原周期。仅结算本策略已提交或明确复用的全局检查，同一任务只结算一次，局部任务失败不影响全局自动退避。退避仅限制后续自动检查，手动操作不因此被拒绝；手动全局检查满足覆盖要求并成功时，同样更新成功基准。语义模型调用的失败与预算继续由语义维护策略处理，不混入历史检查退避。

## 后台调度与任务覆盖

- 后台任务需要按请求覆盖范围合并，局部客户端检查不能替代尚未检查的全局范围；不为每个浏览器建立一条扫描队列。
- 自动策略只安排全客户端快速检查；沿用当前来源发现与快速复用能力，不新增文件监听、按消息追加或来源格式改造。
- 复用判断同时比较客户端范围、快速／完整检查强度和清缓存等操作意图。较弱检查不能替代用户请求的完整校验或清缓存，已有手动请求不会被自动策略关闭或合并丢失。
- 全局手动检查、启动检查与自动检查共用成功基准；局部检查只更新相应客户端检查状态，不重置全局周期。全局检查运行时不会因定时到期再创建一条重复全局任务。
- 必要补查先保留在调度器中，合并为单一自动需求，待 Worker 空闲且仍启用时提交，避免在 Worker 中积压自动队列；关闭策略后撤销尚未提交的自动需求。真正提交执行的检查按在途任务收尾，用户手动参与或依赖的任务按手动请求保留，不能因为它最初由自动策略发起就被取消。
- 调度时间不能以结果版本创建时间判断，因为无变化的成功检查会复用旧版本。任务成功／失败均有完成时间，使用前须结合终态与实际覆盖范围；可保留的来源诊断与整项失败分别展示。
- 后台退出或异常恢复时保留既有未完成任务收尾规则，不盲目重放旧队列；正常启动检查与保存的自动策略共同恢复来源检查。计时器、未开始的自动需求和状态观察不持有额外服务实例。

## 网页观察与偏好共享

- 页面通过只读摘要观察当前策略、后台任务和完整发布版本，空闲时也能发现后端新任务；不能只轮询某个已知旧任务。
- 工程初值沿用运行中约 1.1 秒的进度观察，空闲时约 5 秒读取轻量状态；隐藏页面暂停观察，恢复可见立即读取最新快照。不受是否打开会话库页面影响，也不因多页观察增加扫描。
- 页面断线、后台重启后重新读取当前快照和版本，保留错误与上一份结果；断线不等于策略已关闭，不用旧页面的本地值反写后台。
- 偏好仍通过服务端串行、原子保存，页面只提交主动修改的字段，以后端成功保存的结果为准。其他页面在后续状态读取时同步策略，不依赖重新获得焦点；状态读取本身不写偏好。
- 更改已开启的间隔时，按最近成功全局检查完成时间和新间隔重算到期时点；已经到期则合并一次必要检查。运行中的检查不被中断，下一次按完成时间使用新间隔。重复保存相同设置不作为再次手动同步。
- 设置保存成功后由后台接管调度，关闭提交设置的网页不撤销该策略。保存失败保持旧策略和可见错误，不把未保存设置显示为已生效。
- 旧自动检查接口保留兼容响应，但不再因网页周期请求新建检查任务或推动调度截止时间；显式手动同步及 CLI 入口继续提交操作。旧标签页不会与新后台定时器叠加扫描。

## 页面数据与语义联动

- 保留既有完整发布、无变化不更版、失败保留上一版，以及页面更新保留筛选和阅读位置的语义。页面读取期间可合并通知、待读取结束后再消费新结果，页面读取不再阻止后台按策略检查历史。
- 无论哪个入口发布新历史版本，已打开页面均能发现变化，不要求先观察到某个任务的运行阶段。自动检查无变化时只更新检查状态，不重读页面报告；手动同步保留主动重读语义。
- 后台历史更新无需等待某个页面读取完成，页面仍按同一完整版本读取正文及画像，新结果整体准备后切换；等待期间保留旧布局并暂停失效结果的下钻。
- 语义后台消费已发布版本，继续等待现有维护静默时间或最长延后时间，并复用有效输入；不因历史每次检查完成就强制重新编码。关闭历史自动策略不关闭已经开启的语义维护。

## 状态展示

- 复用全局自动同步控件、同步按钮和状态弹层，不增加独立设置页、常驻说明条或每字段小字；运行中的图标及实际失败保持可见。
- 状态摘要区分自动策略、正在执行任务的范围和完整历史版本，不能把最新局部任务的成功时间当作全局最近成功检查。
- 状态弹层按需显示最近全局成功检查时间、下一次检查时间、当前阶段／处理数量，以及连续失败后的下一次重试和错误。运行时尚不能确定下次检查时间，显示完成后按间隔安排，不制造准确倒计时。
- 帮助说明关闭网页仍继续同步、显式停止后台和系统睡眠的边界，以及历史同步和语义维护的区别。沿用统一帮助组件、中英文、日期格式、键盘、触屏和窄屏约定。

## 实施边界

Q1—Q9 的产品选择和整体工程细则已确认，用户已授权实施。此文不授权系统登录自启、SSE／WebSocket、地图后台周期、资源盘点联动、来源格式优化或自动取消用户手动任务。

## 验收要求

1. 后台无浏览器连接时，新增合成来源后按周期检查并完整发布；两个以上页面同时打开或关闭不改变检查次数。
2. 可控时钟验证完成后计时、长任务不积压、首次开启、修改间隔、睡眠恢复只补一次和未到期等待。
3. 关闭策略时在途任务完成、自动补查撤销、手动请求保留；手动与自动全局任务合并，局部任务不吞掉全局检查，快速检查不吞掉完整校验或清缓存。
4. 任务失败保留旧版和错误，退避及上限生效，手动可重试，成功恢复周期；无变化完成与带诊断完成按正常成功基准处理。
5. 后台重启复用启动检查，不重放中断队列；显式停止后台后不继续调度，不因网页只读观察启动新服务。
6. 多页观察、服务重连、跨页修改偏好、旧自动接口、慢页面读取与持续发布均不重复扫描或丢失最新版本；阅读位置、筛选、主题与语言保持。
7. 历史发布后语义增量按原策略触发，同内容复用、暂停及预算保持；没有新发布内容不强制编码。
8. 浏览器验证状态、错误和重试、中英文、深浅主题、键盘与窄屏；配置写入使用隔离合成环境，真实历史只读验证的原始证据留本机。
9. 更新产品与设计文档中的当前行为、ADR 0010 的被替代范围和使用说明；完成相关检查、构建及公开内容审查，不将设计记录视为已完成测试。
