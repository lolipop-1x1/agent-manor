# 后台调度与范围覆盖

Status: resolved
Type: task
Blocked by: 01

## 范围

按完整规格实现单一后台调度器、偏好保存后即时应用、完成后计时、失败退避、关闭和恢复；完善任务范围／强度合并、Worker 外必要补查、启动任务复用及旧自动接口只读兼容。负责 src/server.ts、src/index/worker-manager.ts、新调度器、必要的 store 查询和偏好通知，以及专用可控时钟与 Worker 合并单测。共享状态合同由 01 提供。

## 验收

无浏览器也检查；状态读取和旧接口不新增任务；时间、开关、任务覆盖、失败和重启符合规格。避免修改前端、翻译、HTTP 集成测试与文档。

## Answer

- 新增 `SessionAutoSyncScheduler`，按全局任务的真实完成时间维护单一周期，最多保留一轮 Worker 外必要补查；关闭不取消在途或手动任务。整项失败退避，手动全局成功恢复正常周期，局部任务不改变全局基准。
- 偏好串行原子保存后、响应返回前通知同数据目录后台；启动检查先提交，策略再复用；后台关闭时撤销计时器和订阅。只有一个最多五秒的绝对截止唤醒，用于睡眠恢复后补一次，不扫描来源。
- Worker 任务同时按客户端范围、快速／完整强度和清缓存意图复用。新摘要附带 `autoSync`；它的 `job` 仅为覆盖全局策略的任务，摘要原 `job` 优先实际运行的局部或全局任务。旧自动接口保持只读，重复访问不提交检查或改截止时间。
- `SessionStore.globalCheckState()` 仅初始化读取最近全局完成基准和失败计数，不按发布版本时间计时，不把任务历史查询放到状态轮询中。
- 新增可控时钟与真实受控 Worker 等十四项定向测试全部通过；现有四项 Worker 回归通过，后端类型检查通过。真实 HTTP、无人网页周期、重启和语义联动的整体证据由集成任务补充。
