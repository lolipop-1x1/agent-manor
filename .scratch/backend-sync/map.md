# 后台同步设计访谈

Status: resolved
Type: grilling

## 用户目标

将历史自动同步的触发移到本地后台，多个网页共享同步状态，关闭网页后仍能自动同步。用户已确认完整规格，授权直接在 main 实施、测试及重启本地服务；本轮已完成，验证详见任务 05。

## 实施前核对的现状

- 历史自动同步目前由可见网页调度；后台执行来源检查并发布完整会话库版本。这个生命周期记录在 ADR 0010，并已进入实现。
- 页面更新只读取已发布结果；语义索引维护观察已发布会话库版本，已有独立后台周期。三者不能用“同步”混称。
- 现有后台按需启动，关闭网页后仍运行，支持显式停止；不默认配置开机启动。
- 历史自动同步与代码地图自动分析的偏好独立，默认关闭。资源盘点和价格目录更新具有各自操作范围。

## 设计阶段源码核对

- 后台按数据目录持有单实例锁，常规启动默认进行一次历史检查；关闭网页不关闭后台。见 [后台生命周期](../../src/service/runtime.ts)、[服务启动](../../src/server.ts)与 ADR 0002。
- [自动请求合并](../../src/index/worker-manager.ts)当前发现任意活动的会话任务就返回它，没有核实局部任务能否覆盖全部客户端；本次设计必须保留范围覆盖判断和相应回归，不能只把前端定时器搬到后端。
- 当前已保存客户端最近成功检查、任务阶段／错误与完整发布版本；下次运行时间和调度器状态没有持久化，不能用最新局部任务直接代表全局自动同步状态。重启不重放旧队列，当前服务以启动检查重新核对来源。
- 网页状态读取与自动触发已分为两条链，但当前仅针对已知活动任务轮询。改造后需要持续发现后台新任务和新发布版本，空闲时只读状态也应能观察；读取不能隐式创建检查任务。
- 多页共用数据目录中的偏好，页面初始和重新获得焦点时读取；跨页偏好状态的及时同步仍需纳入观察方案。

## 第二轮选项记录

- Q5：已选 A，成功检查完成后等待设定周期，再做下一次；未选 B，从计划触发时刻计算固定节奏，过期合并并尽快执行。
- Q6：已选 A，首次开启立即检查一次，后台重启复用原有启动检查，睡眠恢复时已到期补一次、未到期继续等待，不逐轮补跑；未选 B，开启或睡眠恢复后重新等待完整周期。
- Q7：已选 A，关闭时取消后续周期和未开始的自动补查，让正在执行的检查完成，手动请求保留；未选 B，同时尽快停止正在执行的自动检查。关闭历史周期不关闭独立语义维护。
- Q8：已选 A，覆盖足够的在途检查直接复用，覆盖不足最多合并一轮必要的全局补查；未选 B，忙碌时略过自动检查，空闲后等下一周期。
- Q9：已选 A，整项检查失败后自动退避，30 秒起逐次增加、最多 10 分钟，并不快于用户设置的周期；成功后恢复原周期，手动可立即重试；未选 B，始终按原周期重试。已完成但保留解析诊断的任务沿用正常周期与可见诊断。
