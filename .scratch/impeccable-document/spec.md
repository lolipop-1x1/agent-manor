# 记录现有设计体系

## 目标

依据当前 Web 实现生成根目录 `DESIGN.md` 与 `.impeccable/design.json`，供后续界面工作沿用现有设计体系。

## 范围

- 提取当前深浅主题、字体、形状、共享控件、布局、响应式及交互反馈。
- 两轮确认描述现有体系的意象、气质、语义色名称、层次和组件语言。
- 使用隔离合成资源查看实际构建产物，不改变产品界面或个人配置。
- frontmatter 保存规范支持的原始 token；sidecar 保存阴影、动效、断点、组件预览和一致的叙述。
- 在 `AGENTS.md` 中补充产品与设计上下文的阅读入口，明确文档职责和制作流程配置来源。

## 验收

- `DESIGN.md` 遵循八个规范章节顺序，所有数值来自现有实现。
- 用户确认的描述与当前界面相符，不把改进建议写成已经存在的规则。
- sidecar 使用 schemaVersion 2，基础 token 不重复定义；预览组件独立渲染。
- 检查文档结构、JSON、token 引用、公开内容和行末空白。
- 结束时关闭本次隔离服务与浏览器，记录实际查看范围。
- 按明确文件清单提交并推送到 `main`，核对远端提交与本地一致。
